# 236: A Tasks group header reads like a note

**Origin:** Tasks view UX research, 2026-11-12 (`.scratch/tasks-view-ux/research/`, `synthesis.md` T05 as corrected by `critique.md` D2, D12 and D20) and its review, then the deep dive of 2026-11-12 (`.scratch/tasks-view-ux/research/deep-dive/SUMMARY.md`, `refute-236.md`, `dossier-236.md`). Issue numbers in this text keep the open-itens numbering: the Tasks view Issues live in `.scratch/tasks-view-ux/issues/`, the others (030, 085, 151, 198, 204, 205 and the rest) in `.scratch/open-itens/issues/`. It takes over the Tasks view site of Issue 198.

**What to build:** Each note's header in the Tasks view looks like the note it stands for, and the view stops using a raw purple.

Today the header is the file name in `text-purple-400` (a raw palette class, not a theme token, and the only one in `src/lib/features/tasks/`), the modified date in parentheses and the task count in parentheses. The toggle circle is a 16 px hit target.

- **Header anatomy** for a note group:
  - **The note's file icon**, rendered exactly as the `fileTabIcon` snippet in `src/lib/app/EditorView.svelte` does it, at `size-4`: `{@const resolved = resolveIconForPath(group.filePath)}` (`features/file-icons/icon-resolver.ts`); when `resolved?.icon` is set, `<IconRenderer icon={resolved.icon} class="size-4 shrink-0" color={resolved.color} />` (`IconRenderer` applies the color itself and takes no `style` prop); else `<FileText class="size-4 shrink-0 text-muted-foreground" style={iconColorStyle(resolved?.color)} />` (`iconColorStyle` from `features/file-icons/file-icons.logic.ts`). The icon sits next to the title button, outside it, so an emoji never joins the button's accessible name. This adds a `tasks -> file-icons` feature pair; `features/file-icons` imports no other feature, so no cycle forms.
  - **The title:** `group.fileName` in `text-foreground`, medium weight, underlined on hover, still a button that opens the note. Neither the resolver's `color` nor its `titleColor` ever tints the title.
  - **A muted, truncated subtitle** with the note's folder, from a pure exported `noteFolder(vaultPath: string | null, filePath: string): string` in `tasks.logic.ts`: the part of `vaultRelativeKey(vaultPath, filePath)` (`#lib/utils/path.js`) before its last `/`, for example `Projects/Clients` for `Projects/Clients/ACME.md`. It returns `''`, and the header renders no subtitle element, for a note at the vault root, for a path outside the vault (`vaultRelativeKey` returns null) and when no vault is open (`vaultStore.path` is null; `relativePath` takes a `string` and returns the absolute path outside the vault, so it is not the helper). Issue 111 reuses `noteFolder` for its `folder` row field.
  - **The count** as "N of M open", muted, from a pure exported `noteTaskCounts(tasks: TaskItem[]): { open: number; total: number }` in `tasks.logic.ts`, where `open` counts `isTaskOpen(task.status)` (`task-status.logic.ts`, Issue 110). The view looks the note up by `filePath` in `tasksStore.fileTaskGroups`, not in the filtered group: `filterCompleted` returns copies with fewer tasks, so `group.tasks.length` in the render loop is already filtered. M is the note's task count before the view's own filters (date and hide-closed); with a section tag set, Rust has already limited the list to the tasks under matching headings, so M counts those. With hide-closed on, a note with 2 open and 1 done task still reads "2 of 3 open". The count renders as one text node, so its `textContent` is exactly `2 of 3 open`. Issue 111 moves these counts onto its row fields (`noteTaskCount`, `noteOpenCount`, filled through `noteTaskCounts`).
  - **The modification date** only as the title button's `title=` hover text: `formatDate(modifiedAt, 'MMM D')` from `#lib/utils/date.js`, or `'MMM D, YYYY'` when its year differs from the current year. `group.modifiedAt` is in milliseconds (`buildTaskIndex` converts the IPC's seconds). A zero timestamp renders no `title` attribute (not `title=""`). Delete the view's local `formatDate` helper (its name clashes with the import) and keep its zero guard.
- **Test hooks:** `data-task-group` on the header's group wrapper, `data-task-group-title` on the title button, `data-task-group-subtitle` on the subtitle and `data-task-group-count` on the count. Tests find the header parts through them, not by position (Issue 110's rule for rows). Issues 112 and 240 read the same hooks.
- **The toggle circle** (`[data-task-toggle]`, Issue 110) gets a 24 px hit area: replace its `mt-0.5` with `p-1 -mx-1 -mb-1 -mt-0.5 rounded-full`, keep `shrink-0 cursor-pointer`, 110's attributes and the `size-4` icon, and add `outline-none` plus the shared focus ring `focus-visible:ring-[3px] focus-visible:ring-ring/50` (the `components/ui` button recipe). Do not write `-m-1` next to `mt-0.5`: Tailwind 4 emits `margin-top` after `margin`, so `mt-0.5` overrides the negative top margin, the icon moves 4 px down and the row grows 2 px; `-m-1` alone moves the icon 2 px up. With the classes above the icon stays where it is (top margin -2 px + padding 4 px = 2 px, as today) and the button's margin box stays 16 x 18 px.
- No raw Tailwind palette class remains in `src/lib/features/tasks/`. Colors come from theme tokens (`text-foreground`, `text-muted-foreground`, `text-primary` and the like).
- The "N open in M notes" count line (Issue 110) stays in the list body. Issue 111 moves it into the toolbar when the filters leave it.
- `help/documentation/10-tasks-and-todoist.md`: the line about clicking a file name says a note's header shows its icon, title, folder and "N of M open", and that the title opens the note and shows its modification date on hover. The screenshot near the top is not regenerated; say so in the delivery.
