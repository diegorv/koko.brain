# 240: Tasks groups collapse and stay collapsed, and long groups show 50 rows

**Origin:** Tasks view UX research, 2026-11-12 (`.scratch/tasks-view-ux/research/`) and its review. The collapse and volume part of Issue 112's first draft, split out as `critique.md` D4, D7 and D9 asked. Then the deep dive of 2026-11-12 (`.scratch/tasks-view-ux/research/deep-dive/SUMMARY.md`, `refute-240.md`, `dossier-240.md`, `cross-state-chain.md` M6). Issue numbers in this text keep the open-itens numbering: the Tasks view Issues live in `.scratch/tasks-view-ux/issues/`, the others (030, 085, 151, 198, 204, 205 and the rest) in `.scratch/open-itens/issues/`.

**What to build:** A long list needs to fold. Groups collapse with a chevron and stay collapsed when you glance at a note and come back, and a group with hundreds of tasks shows the first 50.

- **Collapse.** Each group header (note and other groupings, Issue 112) starts with a chevron button with `aria-expanded` and an `aria-label` of `Collapse <label>` or `Expand <label>`, where `<label>` is the group's `label`. Copy the recipe in `FilesNavigator.svelte` (the `ChevronRight` icon with `rotate-90` when open, the same label wording). The title button of a note group still opens the note. A collapsed group's rows leave the DOM (`{#if}`, not `hidden` or a CSS class), and its header and count stay as they are.
- **Collapsed state in the store.** `tasksStore` gains a `collapsedGroups` getter (`ReadonlySet<string>`) and `toggleGroupCollapsed(key: string)`. Hold the keys as a `$state.raw` set that the toggle replaces with a new set, as `event-calendar.store.svelte.ts` does: Svelte 5 does not proxy a `Set`, so mutating one in place is not reactive. JSDoc on the state, the getter and the toggle. The key is `` `${groupBy}:${group.key}` `` (`tasksStore.groupBy` and the raw `group.key` from Issue 112's `groupTaskRows`, for example `note:/vault/A.md`, `due:overdue`, `folder:` for the vault root), built by one pure `collapseKey(groupBy: TaskGroupKey, key: string): string` in `task-query.logic.ts` that the view and the tests share. Because the key holds the grouping, collapsing Overdue under Due date leaves Note grouping expanded, and Overdue is still collapsed on the way back. The keys survive the view's unmount and remount on tab activation (`TasksView` mounts inside `{#if isTasksTab}` in `EditorView.svelte`). They are not saved across restarts, and no Issue persists them: Issue 123 saves only `globalExcludes` and migrates the saved section tags (owner, 2026-11-12, Q3). `tasksStore.reset()` clears them, so a vault switch starts expanded.
- **Volume** (PRD A9). A group shows at most the first 50 entries of `group.rows` (dimmed parent rows of note groups count, as they render), then a `Show N more` button with N = `group.rows.length - 50`, which shows all of that group's rows. A group of 50 rows shows no button; 51 rows shows `Show 1 more`. The cap is `GROUP_ROW_CAP = 50`, exported from `task-query.logic.ts`. Which groups are expanded this way is a view-local `$state.raw` set keyed by `collapseKey`, so it resets when the view remounts. The header count (`group.count`, or "N of M open" for note groups) does not change with the cap or a collapse. The button sits after the group's row container, never inside it (`button.closest('[role="list"]')` is null; Issue 112 gives every group's container `role="list"`), and it is not a `[data-task-row]`, so the list's keydown handler ignores it. After `Show N more` the button leaves the DOM, and focus moves to the first newly shown row (row 51), so a keyboard user keeps their place.
- **Keyboard** (Issue 113). Collapsing never moves focus by code. Focus stays where it was: on the chevron when the user pressed Enter or Space on it, and on `<body>` when a mouse click collapsed the group that held the focused row. WebKit (the macOS webview) does not focus a clicked button, and jsdom's `click()` does not focus either, so no code and no test may assume a click focused the chevron; tests call `chevron.focus()` first when they need focus there. Keys on a chevron are not handled by the list: `resolveTaskKey` gets `onRow: false` and returns `null`, so Enter and Space keep their native click.
  - **A collapse or the cap is not a removal.** The current row stays a `{ filePath, lineNumber }` in the store. Collapsing a group, or a row falling past the cap, does not change it: Issue 113's `nextCurrentRow` runs when a row leaves the group rows (a refetch or a filter change), never when it only leaves the rendered set. Issue 113's `order` (every row in display order, the flattened `tasksStore.groups` rows since Issue 112) keeps collapsed and capped rows; its `rendered` list leaves them out. `resolveTaskKey`'s `index` and `count` already come from `querySelectorAll('[data-task-row]')` (Issue 113), which holds only rendered rows once collapsed and capped rows leave the DOM. Expanding the group again puts `tabindex="0"` back on the current row.
  - **One fallback.** When the current row is in `order` but not rendered, Issue 113's `tabStopRow(rendered, order, current)` (`tasks-keys.logic.ts`) returns the first rendered row after it in `order`, else the last rendered row, and `null` when no row is rendered. This Issue extends `tabStopRow` with that rule and its tests. The roving `tabindex="0"` (and the `tabindex="0"` of that row's controls), the focus on open, and Issue 113's focus-follow after a refetch all read that one result. With no row rendered, no row has `tabindex="0"`, and the focus on open goes to the first group's chevron. When the current row is in no group at all (filtered out or gone), Issue 113's rules apply, not this fallback.

**Tests that change on purpose** (name them in the commit): Issue 112's "no `svg` inside a bucket header" assertion in `TasksView.grouping.test.ts` becomes "no file icon in a bucket header" (the chevron is an `svg`).
