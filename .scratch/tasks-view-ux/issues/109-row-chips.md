**Origin:** `tasks-view` Issue 05, moved here on 2026-11-08 and rewritten on 2026-11-12 from the Tasks view UX research (`.scratch/tasks-view-ux/research/`) and its review, then the deep dive of 2026-11-12 (`.scratch/tasks-view-ux/research/deep-dive/SUMMARY.md`, `refute-109.md`, `dossier-109.md`). **What to build:** Rust already sends each task's metadata (`src-tauri/src/vault/task.rs`, `TaskMetadata` in `#lib/contracts`), and the row ignores it: the emoji signifiers show as raw text. "Send invoice 📅 2026-11-03 ⏫ #work ^abc123" should read "Send invoice" followed by chips for Nov 3 (overdue), high and #work.

- **Three pure exports in `tasks.logic.ts`** decide the text. All take `Pick<TaskItem, 'text' | 'metadata'>`, so Issue 111's `TaskRow`, Issue 112's breadcrumb and Issue 239's search pass rows unchanged.
  - `stripTaskTrailers(text: string): string` trims trailing whitespace, then removes a trailing block id (`/(?:^|\s)\^[\w-]+$/`), then a trailing Todoist anchor (`/(?:^|\s)🆔️?\s*td-\S+$/u`), and trims again. The order matters: a synced line ends in `🆔 td-x ^abc` (`todoist-sync`'s `addAnchor` puts the anchor before the block id). The first trim matters too: task lines are split on `\n` only, so the raw text of a CRLF note ends in `\r`. The block id class `[\w-]` matches the sync's own regex. Use local regexes, not `todoist-sync`'s anchor logic, which would add a `tasks -> todoist-sync` feature pair. Issue 241's Copy task text calls it on the raw text.
  - `usesRawTaskText(task): boolean` is true when the raw `task.text` holds a `#` directly after a non-space character (`/\S#[A-Za-z0-9_]/`), or when `stripTaskTrailers(task.metadata.description)` is empty (a tag-only task such as `- [ ] #todo` or `- [ ] #todo ^abc`). The Rust tag regex (`TASK_TAG_RE`) strips a `#word` anywhere, so `[[Book#Chapter 2]]` becomes `[[Book 2]]` (PRD B7), `[doc](notes/a.md#sec)` loses its anchor and `page#section` loses its tail, each leaving a false tag. A real tag starts after whitespace or at the line start, so it never trips the test (`Fix C# bug` does not either: no word character follows the `#`).
  - `taskDisplayText(task): string` returns `stripTaskTrailers(task.text)` when `usesRawTaskText(task)`, else `stripTaskTrailers(task.metadata.description)`. The description has dates, priority, recurrence, ids and tags removed by Rust, but keeps a trailing block id.
- **Text.** The row renders `parseTaskTextSegments(taskDisplayText(task))` instead of the raw `task.text`. On the raw-text path the signifiers stay in the text, and the date, priority and recurrence chips still show; that duplication is accepted for these rare rows. Wikilinks and URLs keep working, and the raw text keeps a link such as `[[Book#Chapter 2]]` pointing at the right note. The parser defect itself is Issue 075 (PRD B7 (a)); this fallback stays harmless after it.
- **Chips** after the text, from a pure `taskChips(metadata: TaskMetadata, today: string, options: { tags: boolean; open: boolean }): TaskChip[]` in `tasks.logic.ts`, with `today` as `YYYY-MM-DD`. The view passes `{ tags: !usesRawTaskText(task), open: isTaskOpen(task.status) }` (`isTaskOpen` from `task-status.logic.ts`, Issue 110). `TaskChip` is `{ kind: 'due' | 'scheduled' | 'start' | 'priority' | 'recurrence' | 'tag'; label: string; title?: string; overdue?: boolean }`. Chips come in this order, each only when its field is set:
  - `due`: label `MMM D` (`formatDate(date, 'MMM D')` from `#lib/utils/date.js`, for example `Nov 3`), `MMM D, YYYY` when the year differs from today's; `overdue: true` only when `open` and the due date is before `today` (string comparison); `title` `Overdue, due YYYY-MM-DD` when overdue, else `Due YYYY-MM-DD`. A done or cancelled task with a past due date is not overdue.
  - `scheduled`: label `Scheduled Nov 3` (same date rule).
  - `start`: label `Starts Nov 3` (same date rule).
  - `priority`: the level word (`highest`, `high`, `medium`, `low`, `lowest`), none for `none` or a missing priority.
  - `recurrence`: `metadata.recurrence.text` without a trailing block id (`/\s\^[\w-]+$/`; the Rust recurrence regex swallows a block id that follows it), for example `every week`.
  - `tag`: one chip per tag, label `#<tag>` (Rust tags carry no `#`). None when `tags` is false: on the raw-text path the tags are visible inline, and the Rust tag list holds false tags taken from links (`Chapter`, `b`).

  Rust accepts any `\d{4}-\d{2}-\d{2}`, and dayjs rolls an impossible date such as `2026-02-30` forward (`Mar 2`), so its label disagrees with its title; that is accepted.
- **Chip markup.** Each chip renders with `data-task-chip="<kind>"` and its `title` when set; an overdue due chip also carries `data-overdue`. Tests and the e2e spec find chips through these hooks, never by position or by color class alone (Issue 110's `important` glyph also carries `text-destructive`). Chips use `text-label` (the chip and badge size in `src/app.css`'s chrome type scale) with the label in `text-muted-foreground`. The due chip starts with a small `Calendar` icon (`@lucide/svelte/icons/calendar`). An overdue due chip colors only that icon with `text-destructive` and shows its label in `text-foreground`: `text-destructive` as text is about 3.4:1 on the editor background.
- **`today`.** The view keeps `today` in a `$derived` that reads `tasksStore.fileTaskGroups` and returns `formatNow('YYYY-MM-DD')` (`#lib/utils/date.js`), so it is re-read on every refetch; a view left open past midnight updates on the next refetch, which is accepted. No store getter is added. Issue 111 points the derived at `tasksStore.rows` (the store's `visibleRows` reads its own clock from Issue 238 on).
- **The circle's label** (Issue 110) uses `taskDisplayText(task)` instead of the raw text. The toggle keeps sending the raw `task.text` and `task.status` as `expectedText` and `expectedStatus`.
- **Narrow pane.** Mark the view's root `@container`. Below 560 px container width (`@max-[560px]:` variants; `EventBlock.svelte` uses the same syntax as `@max-[84px]:`) the chips wrap onto one meta line under the text instead of trailing it.
- Chip colors use only theme tokens, no raw Tailwind palette classes (Issue 236's `tasks-palette.test.ts` checks it).
