## Refuted or corrected (claim + why + correct fact)

1. **Scout 16 problem 7: "Group collapse and chosen filters reset on every open."** Wrong on both halves. There is no group collapse to reset. Filters are module state and survive closing and reopening the tab within a session; they reset only on app restart and vault switch (`tasks.store.svelte.ts:4-12`, `resetTasks` only from teardown). Scout 15 has it right.
2. **Scout 15: "a tag typed less than 400 ms before closing is lost."** Understated. `TasksView` sits inside `{#if isTasksTab}` (`src/lib/app/EditorView.svelte:72-73`), so switching to any other tab unmounts it. The pending tag is dropped on any tab switch, not only on close, and every return to the tab remounts, loses scroll position and refetches through the `$effect` at `TasksView.svelte:73-78` (the heavy section scan while the default tag is set).
3. **Scout 16: "Completed tasks are only struck through (`:191`)" and "in-progress, question, forwarded, important ... have no visual identity".** Incomplete in a way that matters. Strike-through and muting key off `task.checked` (`TasksView.svelte:191`), and Rust sets `checked: check_char != ' '` (`src-tauri/src/vault/parsing.rs:1649`, `:1666`). So `[/] [?] [>] [!]` tasks render struck through like done tasks while showing an open circle (`completes` is true, `:171`, `:182-183`), and with hide-completed on by default `filterCompletedTasks` hides them entirely (`tasks.logic.ts:40`). Scout 16 calls out only "done and cancelled are lumped". This is already ticketed as Issue 110 (`110-open-closed-rule.md`, owner answer PRD B2 (a)).
4. **Scout 16 rec 8: inline edit of due date and priority "needs a new Rust command".** Partly wrong. `write_task_lines` exists (`src-tauri/src/commands/vault.rs:956`, `src-tauri/src/vault/task_lines.rs:84`), atomic, indexed, emits `vault-index-updated`, used by Todoist sync (`closed-note-writer.service.ts:43`). Its gap is the locator: it finds lines by `🆔 td-…` anchor plus expected line, not by line number. Issue 122 (`122-row-menu-edits-with-undo.md:12-13`) records exactly this and says "adds no Rust command of its own"; the open choice is anchor-first or a line-number locator. Status changes need nothing new: `toggle_task_status` already takes a `target` (`tasks.service.ts:147-153`).
5. **Scout 16 and scout 15: group order "as the IPC returns them" / "`get_all_tasks_v2` order".** Vague; the fact is mtime descending in both commands (`vault.rs:648-649` doc, `vault.rs` `out.sort_by_key(|g| std::cmp::Reverse(g.modified_at))` in `tasks_in_section`). Consequence neither scout states: toggling a task rewrites the note, bumps its mtime and moves its group to the top, so the list reorders under the cursor. PRD A3 already decided "Files sort by path, not mtime" (`PRD.md`, A3).
6. **Scout 16 rec 3 default sort "status (in-progress first)".** Conflicts with the ticketed order in Issue 112 ("Todo, In progress, Question, Important, Forwarded, Done, Cancelled") and with PRD A3's priority rule ("none" between medium and low). Not wrong as an opinion, but it re-decides something the backlog settled.
7. **Scout 16 rec 7 "a key to focus the filter box".** If that is a bare letter (for example `/`), it conflicts with PRD A8 ("No bare-letter shortcuts in v1"); Issue 113 owns keyboard.
8. **Scout 16 rec 5 "collapse state persisted per group key ... persist ... in settings".** Under-specified against project rules: settings persistence must be opaque in `core/` (layer rule, `layer-rules.test.ts`), sequenced after Issue 030, and file keys are absolute paths (indexing rule 9), which go stale on rename. The precedent `layout.railExpandedFolders` stores absolute paths (`settings.types.ts:66-71`) and needs both a rename follower (`files-navigator.service.ts:15-16`, `followFolderPathChange`) and a once-per-open prune (`lens.logic.ts` `staleFolderPickFix`). Scout 15 rec 6 mentions pruning only.
9. **Scout 15 line references, minor drift** (not substantive): persistence constant is `:10` not `:9`; `toggleTasksTab` is `tasks.service.ts:211-220`; `list-prefs.logic.ts` functions start at `:46` and `:63`, not `:41` and `:58`; `parseExpandedFolders` is `lens.logic.ts:1016`. Scout 16: the indent style is `task.indent * 1.25 + 0.25rem` at `TasksView.svelte:175`, not `:174`.
10. **Scout 15 rec 3 (a): "`updateTasksView(patch)` that does `Object.assign` in place like `updateLayout`".** Does not fit an opaque slice. If `tasksView` is typed `unknown` and the file holds `42` (scout 15's own test case), `Object.assign` onto it is wrong. Assign the whole slice (`settings.tasksView = withTasksView(raw, patch)`) on the deep `$state` proxy; that also avoids replacing the root.
11. **Scout 15 rec 9 / Issue 123: "`tasksView: 42` ... is not written until the next change".** Holds only if `parseSettings` passes the raw value through (`parsed.tasksView ?? DEFAULT_SETTINGS.tasksView`, the `dockBadgeInboxCount` shape at `settings.service.ts:195`). Issue 123 names the `todoist` merge (`{ ...DEFAULT_SETTINGS.todoist, ...parsed.todoist }`, `:160-163`) as the model; with a spread, a non-object becomes defaults and `loadSettings` immediately writes them back (`:66-71`), breaking Issue 123's own "not overwritten until the user changes the view" rule. Scout 15's passthrough suggestion is the correct one; Issue 123's "like `todoist`" wording is the inconsistency.

## Net recommendations that survive

1. **Do not write a parallel ticket set.** Start from Issues 108-126: re-anchor line references, decide which are still wanted, and write new tickets only for gaps (visual hierarchy and theming tokens, sticky headers, group collapse, scroll retention). Scout 16's external survey is useful as rationale inside those tickets, not as a new plan.
2. **Fix the open/closed rule first (Issue 110).** Today the default view hides in-progress, question, forwarded and important tasks and strikes them through when shown. Any visual redesign built on `task.checked` inherits this.
3. **Stable group order early.** Sort groups by path (PRD A3) so a toggle does not move its group to the top.
4. **Persistence: per-vault `tasksView` in `.kokobrain/settings.json`, opaque in core, parsed in `features/tasks`** (scout 15 recs 1-2, Issue 123, ADR-0019). Requirements that survive validation: add the key to `parseSettings` as a raw passthrough (not a spread), default `{}`; `parseTasksView` never throws and keeps unknown keys; write by assigning the whole slice, not `Object.assign`; sequence after Issue 030; no new `writeTextFile` site; no new `layer-baseline.json` entry.
5. **Keep the tag input debounce, flush on destroy** instead of dropping it, since unmount happens on every tab switch.
6. **Collapse is session state in `tasksStore` first.** Persist it only on owner request, and then copy the `railExpandedFolders` pattern in full: follow path changes and prune once per vault open.
7. **Row chips from `metadata` need no IPC change** (Issue 109). Inline due/priority editing reuses `write_task_lines` once the locator gap in Issue 122 is decided; no new Rust command is required for status.
8. **Leave the `#to-list` default alone** until Issue 124 / owner decision B1 (a) lands; store an empty tag as `''` so it differs from "never set".
