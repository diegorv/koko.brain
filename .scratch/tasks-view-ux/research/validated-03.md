# Validated 03: scout 05 (sibling views) and scout 06 (UI primitives)

Adversarial check of `scout-05-sibling-views-patterns.md` and `scout-06-ui-primitives.md` against the code at `main` (`23f6c1f91`). Read-only: nothing was run (no check, vitest, cargo, build, E2E or app). "Fact" means opened and read in the repo; "Opinion" is marked.

Verdict in one paragraph: both scouts are accurate on the current Tasks view markup, the sibling markup and the primitive inventory; most line references hold within one to three lines. Four claims are wrong in ways that matter for tickets: (1) a Tooltip does NOT work without `Tooltip.Provider` in bits-ui 2.20.4, and the one "proof" (`DailyNoteButton`) is dead code; (2) showing `metadata.description` instead of `task.text` is not a safe swap, because the Rust tag strip breaks heading wikilinks and empties tag-only tasks; (3) the Kanban proximity palette is not a model to copy (raw palette classes, an open Issue plans a test that forbids them); (4) "keeping circles is consistent with the other task surface" ignores the editor, which draws square checkboxes. The biggest miss is that neither scout reconciled with the existing, detailed `ready-for-agent` backlog in `.scratch/open-itens/issues/` (108, 109, 112, 113, 125, 198, 204), which already specifies most of their recommendations, sometimes with different choices.

## Refuted or corrected

1. **"bits-ui Tooltip works without a Provider (as `DailyNoteButton` does)"** (scout 06, Problems 7). Wrong. `TooltipRootState.create` reads `TooltipProviderContext.get()` (`node_modules/bits-ui/dist/bits/tooltip/tooltip.svelte.js:192`), and the runed `Context.get` that bits-ui resolves (runed 0.35.1) throws `Context "Tooltip.Provider" not found` when it is missing (`.../runed/dist/utilities/context/context.js:37-42`). `DailyNoteButton.svelte` (`plugins/periodic-notes/`) has no importer anywhere in `src` (grep), so it never renders and proves nothing; it is dead code (mention, do not delete). Correct fact: any Tooltip in TasksView needs a `Tooltip.Provider` ancestor (the only one is `EventCalendarView.svelte:237-265`), or the view throws on mount. Wrapping the view in `<Tooltip.Provider delayDuration={400}>` like the Calendar is required, not optional.
2. **"Show `metadata.description` instead of raw `text`"** (scout 05, Rec 3). Overstated. `parse_task_metadata` removes tags with `TASK_TAG_RE = #([A-Za-z0-9_][A-Za-z0-9_-]*)` over the whole text (`parsing.rs:1579`, `:1873`), so `[[Book#Chapter 2]]` loses `#Chapter`, a URL fragment loses its `#...`, and a tag-only task (`- [ ] #todo`) gets an empty description. Issue 109 (`.scratch/open-itens/issues/109-row-chips.md`) already specifies a `taskDisplayText(task)` fallback to `task.text` for these cases. The Calendar's `description || text` (`event-calendar-tasks.logic.ts:59`, not `:56`) only covers the empty case.
3. **"Use the Kanban proximity palette for due date"; extract `getDateProximity` and the badge map to `utils/`** (scout 05, Rec 3 and 4). The palette is raw Tailwind classes (`bg-red-500/15 text-red-400` etc.), against ADR-0002 Consequences ("components should read tokens, not hardcode colors"), and open Issue 198 (`198-status-colors-use-theme-tokens-test-forbids.md`) plans `palette-classes.test.ts`, which fails on any palette class outside `components/ui`. Scout 06 (Rec 4) is right and scout 05 is wrong here. Tokens exist: `--color-warning`, `--color-success`, `--color-type-*`, `destructive`, `primary` (`src/app.css:63-74`). Issue 109 already settles due chips as "overdue = string compare with today, `text-destructive`", which needs no proximity function, so the extraction slice has no consumer. Also "three slightly different copies of the same mapping" is loose: the list and table copies are identical, the picker map is a badge, the card map is a left border.
4. **"The circle idiom is shared by Tasks and Calendar, so keeping circles is consistent with the other task surface"** (scout 05). Incomplete. The main task surface is the editor, whose live-preview checkbox is an 18 px rounded square (`border-radius: var(--radius-xs)`) with theme variables `--lp-task-border`, `--lp-task-checked`, `--lp-task-checkmark` (`core/markdown-editor/extensions/live-preview/styles.ts:231-260`; defaults at `src/app.css:313-315`). Kanban also uses squares. Circles are 2 of 4 surfaces. This stays an owner question, but the scout's framing tilts it.
5. **"Of the 14 candidates, 9 exist ... and 4 do not"** (scout 06, Summary). Arithmetic: it lists 10 that exist (collapsible, select, dropdown-menu, context-menu, tooltip, input, popover, scroll-area, separator, command); 10 + 4 = 14.
6. **"Hardcoded palette colors exist (14 sites in features, e.g. `BuildInfo.svelte:30`)"** (scout 06). Wrong count and wrong layer. `features/` has 5 sites in 2 files (`TasksView.svelte:154`, `file-history/DiffViewer.svelte` x4). Across `src/lib` (outside `components/ui`) there are 37 matches in 9 files, mostly `plugins/kanban` (22), `core/settings/BuildInfo.svelte` (9, core, not features) and `UpdateSection.svelte` (1).
7. **"Native checkboxes in 6 places"** (scout 06). There are 7: the list misses `collection/CollectionTableView.svelte:65`.
8. **Line drift (minor)**: `ScrollArea` import is `TasksView.svelte:8`, not `:10`; debounce is `:31-40`, not `:30-39`; the Calendar segmented control is `EventCalendarHeader.svelte:99-123` (file ends at 124), not `:100-125`; type roles are `src/app.css:89-99` (comment from `:76`), not `:80-98`/`:80-100`; radius `:107-113` and shadows `:122-127`, not `:101-125`; `--color-type-*` runs `:63-71` (scout 06 omits `type-gray` and the `warning`/`success` tokens at `:72-73`). Search states are a sidebar panel (`AppShell.svelte:46`) using `file-explorer-*` tokens, so like Backlinks they are not directly reusable in the center pane; scout 05 flags this only for Backlinks.
9. **"Make the group collapsible with the Backlinks chevron pattern (`BacklinksPanel.svelte:64-70`)"** (scout 05, Rec 2). In Backlinks the whole header row is the `Collapsible.Trigger`. In Tasks the file name is a button that opens the note (`TasksView.svelte:153-158`), and a button cannot nest in a button. The fitting in-repo model is `TagItem.svelte:28-44`: a small separate chevron `Collapsible.Trigger` next to a separate click target. Issue 112 already asks for "a chevron button with `aria-expanded`" plus the name button kept.
10. **Segmented date filter as `role="tablist"` copied from the Calendar** (scout 05 Rec 1, scout 06 Rec 2a). Opinion, correction of fitness: tabs imply tab panels; a filter over one list is better a radio group or `aria-pressed` buttons, which the repo already uses (`TodoistSyncLogDialog.svelte:36-43`: `Button variant={selected ? 'secondary' : 'ghost'} aria-pressed`). A `DropdownMenu` radio group is the existing pattern for one-of-N settings (Issue 112 uses it for Group by).

## Missed by scouts

1. **An existing, detailed backlog already covers most recommendations.** `.scratch/open-itens/issues/`:
   - 108 (ready-for-agent, blocked by none): list stays mounted during refetch with a toolbar spinner, a rule sentence, an empty state that names the cause with Clear / Show completed / All time actions, explicit `aria-label="Section tag"`. This is scout 05 Rec 5 and 7 and scout 06 Rec 6, already specified.
   - 109: status glyphs per status with token tones (`text-success`, `text-warning`, `text-destructive`), `taskDisplayText` fallback, chips for due/scheduled/start/priority/recurrence/tags, `@container` wrap below 560 px.
   - 112: Display menu (DropdownMenu radio), group by note/folder/due/priority/status, collapse via chevron with session-only `$state` set, 50-row cap with "Show N more".
   - 113: roving focus over rows, `resolveTaskKey` pure logic, `role="list"`/`listitem`, `aria-pressed` on toolbar toggles, moving `isTypingTarget` to `utils/`.
   - 125: smart lists and their empty states; 198: palette classes to tokens plus a guard test.
   - 204 (ready-for-agent): `EmptyState`, `InlineAlert` and `Badge` primitives in `components/ui/`. This directly contradicts scout 05 Rec 8 ("do not build a bespoke EmptyState") and overlaps scout 06 Rec 4 ("generate badge"). 108 says to use `EmptyState` if 204 has landed.
   New tickets must extend or supersede these, not duplicate them. Several of those Issues quote stale TasksView lines (e.g. 108 cites `:169-170` for what is now `:139-140`; 198 cites `:184`/`:252` and a `text-green-400` that no longer exists in the file).
2. **Tooltip Provider is a hard requirement** (see Refuted 1). Any ticket that adds Tooltips to the Tasks toolbar must include the Provider, or keep `title=` (the dominant convention and what the E2E selector `button[title*="completed"]` relies on).
3. **Collapsible vs windowing conflict across scouts.** Scouts 05 and 06 propose the `Collapsible` primitive per file group; scout 14 proposes flattening into one row array rendered by `virtua` `VList` (`package.json:76`). `Collapsible.Content` wraps child DOM, which a flat virtual list cannot do. If windowing is on the roadmap, collapse should be a filter over the flat row array (as Issue 112's `$state` set implies), not `Collapsible`.
4. **Toolbar width budget.** `pane-toolbar` is a fixed 40 px row and `flex-wrap` is banned on it (`pane-toolbar.test.ts:30`). Adding a title, count, segmented filter, icon toggles, tag input, spinner (108) and a Display menu (112) can overflow a narrow center pane. The Calendar handles this with `min-w-0 flex-1 truncate` on the title block (`EventCalendarHeader.svelte:36-39`); container queries are already used in `RailNoteList.svelte:717` and `EventBlock.svelte:75`. A second row must be its own non-`pane-toolbar` element.
5. **Background inconsistency.** TasksView paints `bg-card` (`TasksView.svelte:90`) inside a `bg-editor-bg` host (`EditorView.svelte:71`); Tags, Kanban and Calendar inherit the editor background, only Collection also uses `bg-card` (`CollectionView.svelte:501`). On themes where card and editor backgrounds differ, Tasks looks like a different surface.
6. **File icon in group headers.** The app resolves per-note icons and colors through `features/file-icons` (`IconRenderer.svelte`, `icon-resolver.ts`), used by `NoteRow.svelte:8-10` and the tab strip (`EditorView.svelte:60-61`). Scout 05 suggests a plain `FileText`. Using the resolver keeps group headers consistent with tabs and the note list; `features/tasks -> features/file-icons` is allowed while acyclic (`feature-cycle.test.ts`, ADR-0003), and `file-icons` does not import `tasks` today.
7. **Test hooks a redesign silently breaks.** `TasksView.test.ts:96` takes the FIRST `span` in a row and `:133` the FIRST `button`: adding a chip `<span>` or a chevron/menu `<button>` before them changes what the tests click. `:232` asserts no `<a>` in the row: a chip rendered as a link would fail it. Scouts list the selectors but not this ordering trap.
8. **Adding shadcn primitives has a supply-chain step.** ADR-0002 says to run `pnpm dlx shadcn-svelte@next add ...`; the repo enforces a package-age quarantine (ADR-0014, `pnpm-workspace.yaml` `minimumReleaseAge`). Whether `pnpm dlx` honors it for an `@next` tag was not checked; a ticket that generates `checkbox`/`toggle-group`/`badge` should pin the CLI version and say so. No new npm dependency is needed (bits-ui already ships the parts).
9. **CLAUDE.md layer note is stale on one point.** It says known violations include `features/` importing `plugins/`; the baseline now holds none (`layer-baseline.json`), so any such import fails CI. This strengthens the "do not import Kanban" conclusion.
10. **Dark-mode check is code-level only.** Both scouts call Kanban colors debt; the planned tokens (`text-destructive` about 3.4:1 on the default card per Issue 198 Notes) also have a contrast caveat. Chips that use `text-destructive` for overdue inherit it.

## Net recommendations that survive

Opinions, grounded in the facts above.

1. Reconcile first: map each new ticket onto 108, 109, 112, 113, 125, 198, 204 (update, supersede or depend on them). 108 is the natural first slice: it is unblocked, small, and fixes the worst visible defect (list unmounts on every refetch) plus the silent `#to-list` default.
2. Toolbar: one `pane-toolbar` element with no overrides; title "Tasks" plus a muted count on the left with `min-w-0 truncate` (Tags/Calendar convention), actions in an `ml-auto` cluster of `Button variant="ghost" size="icon-sm"`, active state `text-primary` (Tags, Collection). Hints stay `title=` unless the ticket adds `Tooltip.Provider`. Date range as `aria-pressed` buttons or a DropdownMenu radio group, not `role="tablist"`. Keep `title*="completed"` on the hide toggle or update the E2E in the same slice.
3. Group header: file name in `text-foreground font-medium` (token, drops `text-purple-400`), file-icons resolver icon, right-aligned `ml-auto text-meta text-muted-foreground` count, modified date as secondary muted text, and a separate chevron button with `aria-expanded` (TagItem model). Implement collapse as state over rows, compatible with later windowing.
4. Rows: keep the toggle as the first button and the text as the first span, or rewrite those tests in the same slice. Show text via a `taskDisplayText` with the raw-text fallbacks from Issue 109. Chips with tokens only (`text-destructive` overdue, `text-muted-foreground` others, NoteRow-style pill shape for tags); no Kanban palette, no `getDateProximity` extraction.
5. Empty and loading states: three-way cause (Search pattern) with actions, as 108 specifies; render through `EmptyState` only if 204 has landed.
6. Accessibility: focusable row or text control with the NoteRow ring classes; `aria-pressed` on toggles; explicit `aria-label="Section tag"` (keeps the E2E name).
7. Primitives: a first slice needs none beyond what exists (Button, Input with a height override, DropdownMenu radio items, Popover, Separator, Collapsible if no windowing). Generating `checkbox` is justified only if the owner wants distinct visuals for in-progress/cancelled tasks; the circle-vs-square choice should be put to the owner with the editor's square checkbox as context.
8. Do not copy Kanban color code, do not import from `plugins/`, do not add a bespoke feature-local EmptyState while 204 is open.
