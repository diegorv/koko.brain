## 4. Ambiguities (guess points) and most likely reading

- **A1. Clause wording in the sentence is unspecified.** The ticket fixes only "from every note", "from notes ", " and ", "; or ", ", except ", and the four exclude names. Likely reading, pinning 108/242's heading wording: heading `under a heading containing #to-list` (substring card: `under a heading containing "text"`), folder `in folder X` / `not in folder X`, type `of type X` / `not of type X`, tag `tagged #x` / `not tagged #x`. Listed excludes: `folder X`, `note X`, `tag #x`, `type X`. Default sentence then reads "Open tasks from notes under a heading containing #to-list, except archived notes, type definitions, templates, the system folder". Tests pin whatever is chosen; the ticket leaves it open, so state it in the commit.
- **A2. Sentence vs quick-filter order.** "Open tasks" (status) leads (111), then sources, then excludes, then Due/priority/tag/search parts (238/239). Most likely reading.
- **A3. When does Clear show?** 108's Clear tag hid in the empty state; 116 says "when `sources` is not empty" and the e2e criterion clicks it while the fixture list is empty (default `#to-list` hides all fixture tasks). So: show whenever `sources.length > 0`, including the empty state, but not while "Indexing tasks..." (sentence hidden).
- **A4. Empty-value clauses.** The ticket says an empty folder path matches every note, silent on empty type/tag/heading text, and silent on `negate` plus empty. Typing a fresh clause must not blank the list. Most likely reading: any clause with an empty (trimmed) value is inactive (true), `negate` ignored for it. State it in tests. A literal reading (negated empty folder matches nothing) is possible; pick one.
- **A5. Case sensitivity of folder, note and excluded-note paths.** Only type, tag (and types/tags excludes) are called case-insensitive. Reading: folders and note paths exact, case-sensitive.
- **A6. `matchesHeading` signature.** 115 says `matchesHeading(headings, tags, 'tag')` with a tags array; 116 says `matchesHeading(row.headings, text, match)` with one text. Contradiction between tickets. Likely: the delivered function accepts what 115 built; 116 passes `[text]` or the function takes `string | string[]`. Check the landed code.
- **A7. What exactly is written back to `tasksView.sectionTag`.** "The texts of the heading cards ... space-joined." Open points: heading cards that carry other clauses (include them); `substring` cards (written the same, reloaded as `tag` cards, a lossy round trip until 123); cleared sources (no heading cards) writes `''`, but 243 reads `''` as "every task" while 116 says the default is `#to-list` when "nothing saved". Most likely reading: on load, an empty parsed list gives the `#to-list` card (the view never defaults to every task), so Clear is session-only until 123. Say so in the help doc and a test.
- **A8. Write timing.** 243 wrote after a 400 ms textbox debounce. A heading-card text field edits per keystroke; writing `settings.json` per keystroke is wrong. Likely reading: debounce the write (400 ms) or write on `change`/blur; write only when the joined heading texts differ from the last loaded/written value (also keeps 243's "invalid value is not written back until the user changes the field").
- **A9. Note tag format.** Ticket says "value without a leading `#`" and compares to `row.noteTags`. Rust `extract_tags_strict` (`src-tauri/src/vault/parsing.rs:513`) merges frontmatter and inline tags; I did not verify that all entries are `#`-free (the auto-organize tests carry `tags: ["#work"]`). Safe reading: strip a leading `#` on both sides before comparing.
- **A10. Where the heading clause sits in "note fields".** It is row-level (a task's ancestor headings), not note-level, unlike folder/type/tag. Reading: `selectSourceRows` evaluates all clauses per row, as the signature takes rows.
- **A11. Where "Edit excludes" scrolls/focuses.** One panel; the action opens it and focuses (or scrolls to) the Excludes section. Not specified; opening is enough for the test.
- **A12. `describeTaskQuery` and an empty template/system setting.** Signature has no folders, so the sentence names "templates" even when the setting is empty and excludes nothing. Accept, or add an optional second parameter (the ticket's signature is `describeTaskQuery(query)`).
- **A13. TaskQuery carries no `group`/`sort`.** The ticket's `TaskQuery` is `{ version, sources, exclude, quick }`; 112's `group`/`sort` stay separate store fields until 123. Reading: do not move them.
- **A14. "Counts: the total only."** Reading: the toolbar/sentence total from 111 stays; no per-card badge in the panel.
- **A15. Where `TaskQuery` types live.** 111 puts `TaskRow` in `task-query.logic.ts`; 123 requires `core/settings` not to import them. Reading: keep them in `task-query.logic.ts`.

## 5. Risks and contradictions

- **R1. 243's persistence is keyed on the section tag; removing `tasksStore.sectionTag` breaks its load and save unless re-pointed** (plan step 7). Same for 243's own tests. This is the biggest cross-ticket seam.
- **R2. Pending-save race on a vault switch.** If the heading-text save is debounced, `resetTasks()` (`tasks.service.ts:227-231`, called from `app-lifecycle.service.ts:664`) must clear the timer, or vault A's tags are written into vault B's settings. This is the same hazard 234 describes for the textbox flush.
- **R3. Do not delete the reset-generation counter 234 added.** 241's Undo depends on it; only the view's textbox use goes away.
- **R4. Per-keystroke recompute.** `visibleRows` re-runs `selectSourceRows` on every panel keystroke. Fine for thousands of rows if clauses are pre-normalised once per call (do not lowercase inside the row loop). PRD says revisit only if `TASK-PROFILE` shows stalls (PRD "Why not Rust").
- **R5. Architecture tests** [F]: `pure-logic.test.ts` (no store/service/framework reachable from `task-query.logic.ts`; the settings folders therefore arrive as an argument, which the ticket already does); `layer-rules.test.ts` (tasks imports only core, fine); `feature-cycle.test.ts` (it rewrites `featurePairs` and does not fail; do NOT import `isTypeDefinition` from `type-definitions`, that would add `tasks -> type-definitions`; inline `noteType === 'Type'` with a comment naming the rule); `pane-toolbar.test.ts` (the panel and sentence row must not carry the `pane-toolbar` class, only one per file, and no `h-/p-/gap-/border-/flex-wrap` overrides on the real toolbar); `ipc-mirrors.test.ts` (no new `TaskHeading*` type names; 116 adds no DTO). 236's source scan forbids raw Tailwind palette classes under `src/lib/features/tasks/**`, so the panel uses tokens only (`text-muted-foreground`, `bg-accent`, `border-border`, `text-destructive`).
