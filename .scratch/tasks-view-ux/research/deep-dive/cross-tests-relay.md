Scope: every Tasks view chain ticket (108 -> 242 -> 110 -> 234 -> 236 -> 109 -> 111 -> 238 -> 239 -> 113 -> 112 -> 240 -> 241 -> 115), 243, the tickets that share their files (074, 075, 116, 121, 122, 129, 198), and the dossier for 129 + 198 + 205. ## What relay-lite actually runs (F)

- `.agent-relay-lite/config.json:5-9`: the only checks are `setup`, `typecheck` (`pnpm check`), `testFile` (`pnpm vitest run <file>`) and `suite` (`pnpm vitest run`). `:17` adds cargo when `src-tauri/` changes. No rule names `scripts/e2e.sh` or `pnpm build`.
- The generated role prompts (`.agent-relay-lite/launch/open-itens-001.js:36`, a local, gitignored file): build and fix run the "targeted checks" (the typecheck, the test files of every touched file, and tests that assert a changed name); review and re-review run the typecheck and the targeted test files, "plus any probe you need", and must not run the full suite; deliver runs only `checks.suite`. After `relay deliver sync` reports `clean` or `rebased`, deliver runs "no check and no suite again".
- `CLAUDE.md:259-263`: inside a relay-lite run the role's targeted checks replace Quick Reference rule 6, so a ticket's `**Gate:**` line is not what runs.
- `pnpm check` type-checks `src` and `e2e` (`tsconfig.json:23` `"include": ["src", "vite.config.js", "e2e"]`), so an e2e mock that no longer compiles is caught. Mock behavior is not.
- E2E in CI: relay delivers with `merge` straight onto `main`; `pr.yml` only fires on pull requests. On `main`, E2E runs post-merge in `main-checks.yml:6-8,37-39`. So an e2e regression from a relay delivery surfaces only after it is on `main` (and after the next chain ticket may already be running on top of it) (F for the triggers, I for the timing).
- Playwright in CI installs Chromium only (`.github/workflows/e2e.yml:48-50`); the app runs in WebKit. Focus behavior that differs in WebKit (refute-240 point 1) is not observable in e2e (F for the install step, I for the consequence).
