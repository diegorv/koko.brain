## Findings

1. **major**, src/lib/features/todoist-sync/task-line.logic.ts:42-45 (also `tagMatches` :226-235, `pull.logic.ts:326-327`, `src/tests/fixtures/todoist-vault.fake.ts:93,101`): Todoist sync still uses the removed ASCII rule, and the Rust change now makes the two disagree in a way that changes remote data. This is a regression from this branch, not just a gap. Here is the trace for a Todoist label `2026` (or `2024-goals`, or any digit-first label):
   - `isTaskTagName('2026')` is true, so pull writes `- [ ] content #2026 🆔 …` with `localBase.tags = ['2026']` and `description = content` (pull.logic.ts:356-372).
   - Rust now reads that line as tags `[]` and description `content #2026`.
   - On the next cycle `localTagsChanged` is true and `tagsChanged` is false. fields.logic.ts:388-397 then builds `labels` without `2026` (a mapped label missing from `lineTags`) and pushes it, so the label is removed in Todoist.
   - The content changes too, so `content #2026` is pushed as the Todoist content (fields.logic.ts:349-363).

   The fake vault in the tests copies the old rule, so no test sees this. The reverse case (`revisão` is pushed as a label, then dropped as unmapped on pull) looks stable from the trace. Both comments at :42 and :228 also name `TASK_TAG_RE`, which no longer exists. The owner does not use Todoist sync, which keeps this from being a blocker. The build report and discovery.md record it as out of scope. Fix: do not change Todoist code in this Issue. In the delivery comment, the main session files a follow-up `.scratch` Issue that moves `isTaskTagName`/`tagMatches` (and the fake) to the note rule, or rejects digit-first labels on pull. It names this label-removal loop as the case to test first and lands before the next release.
2. **minor**, src-tauri/src/vault/parsing.rs:1565 (`RECURRENCE_RE` stop `#[A-Za-z0-9_]`): The recurrence text still stops only at an ASCII-first `#`. A tag whose first letter is not ASCII after `🔁` (`🔁 every week #über`) stays inside the recurrence text and gives no tag, although the note rule now accepts it. This is not a regression, since the old `TASK_TAG_RE` rejected it too, and it is outside the Issue. The build report and discovery.md give `#ação` as the example, which is wrong: `#a` matches the ASCII stop, so `#ação` does stop the recurrence and becomes a tag. Fix: correct the example in the follow-up note to a tag with a non-ASCII first letter, and track the stop-list change with finding 1's follow-up or on its own. No code change here.
3. **nit**, e2e/mocks/vault-index.ts:217: the mock now collapses whitespace and trims the description of every task, not only tasks with a due date. This matches Rust (`MULTI_SPACE_RE` + trim) and is correct, but it changes mock output for untagged tasks with double spaces. No e2e spec asserts such a description (grep of e2e/specs), and `bash scripts/e2e.sh`, the Issue's gate for the mock change, is deliver's to run.
