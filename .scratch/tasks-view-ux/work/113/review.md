## Findings

1. nit, `src/lib/features/tasks/tasks-keys.logic.ts:57` and `src/lib/features/tasks/TasksView.svelte:324`. A held Space toggles once. Each repeat then returns `null`, so the handler does not call `preventDefault()`, and the browser's default Space action on the focused row scrolls the list viewport down a page per repeat. This follows the Issue as written ("on a non-null action it calls `preventDefault()`"), so it is not a defect of this branch. Fix, if the owner wants it: a follow-up Issue that makes a repeated Space or Enter on a row a no-op action that still prevents the default.
2. nit, `help/documentation/10-tasks-and-todoist.md:129`. "The task list takes one stop in the Tab order" overstates the change: the tab-stop row's checkbox and links, and each note's title button, are tab stops too. The next paragraph does describe the Tab walk correctly. Fix: "Only one task row is in the Tab order at a time".
