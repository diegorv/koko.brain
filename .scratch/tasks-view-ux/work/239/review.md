## Findings

1. nit, `src/lib/features/tasks/task-query.logic.ts:149`: `tagMenuOptions` matches a chosen tag against the options by exact spelling, while `taskTagOptions` de-duplicates without regard to case. Example: the user picks `Work`, and a later edit makes `work` the first spelling in the rows. The Tag menu then shows both `#Work` (checked) and `#work` (unchecked) for the same tag. Filtering stays correct because `matchesNestedTag` ignores case. Possible fix: when `taskTagOptions` holds a case-variant of a chosen tag, keep the chosen spelling in that slot. Leaving it as is also works; it needs a vault with mixed-case spellings of one tag.
2. nit, `src/lib/features/tasks/TasksView.svelte:397`: the folded `Filters (n)` menu puts each separator between a group's label and its items. Nothing separates the last Status checkbox from the `Due` label, or the last Due option from the `Priority` label. This follows the Issue's "a label and a separator before each group", the default recorded in discovery.md. Add it to the owner's narrow-split check, which the Issue already requires. If it reads poorly, move the separator above each label after the first.
