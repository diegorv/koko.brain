## Findings

1. **blocker** `src/lib/features/tasks/task-query.logic.ts:660` (and `SourcesPanel.svelte:125`): the heading suggestions are full heading texts (`Inbox #to-list`, `Calls`), but the heading clause's value is a tag in both modes (`matchesHeading` in `task-headings.logic.ts:63-71`: Tag mode compares against the heading's inline tags, Contains mode looks for `#<value>` in the text). Picking any suggestion therefore produces a clause that matches nothing and empties the list. Probe (temporary test, removed): rows from one note with headings `Inbox #to-list` and `Calls`; for each heading suggestion, `selectSourceRows` with a heading clause of that text returned 0 rows in `tag` and in `substring` mode. Only a heading that is a bare tag would work. Fix: build the heading list from the inline tags of the heading chains (`findInlineTags`, offered as `#tag`, de-duplicated case-insensitively and sorted), so a picked value is one the clause can match; update the `sourceSuggestions` test and the help line ("headings") to say heading tags, and add an assertion that a picked heading suggestion keeps the rows under that heading. The Issue's "the texts in `headings`" was written before the heading clause became tag-only; if the owner wants texts kept, the heading picker should be dropped rather than ship a picker whose every pick empties the list.
2. **minor** `src/lib/features/tasks/task-query.logic.ts:669`: `keys` is de-duplicated case-insensitively, but the property clause matches its key exactly, case included (`propertyTest`, help text "The key must match the property name exactly, case included"). A vault holding both `Status` and `status` offers only the first spelling, and the other key, which `values` still holds under its exact spelling, can never be picked (the test at `task-query.logic.test.ts` asserts `keys` without `Status` while `values.get('Status')` exists). The Issue asks for case-insensitive dedupe on every list, so either keep keys exact (dedupe by exact string) or note the limit in the help text; ask the owner if unsure.
3. **minor** `src/lib/features/tasks/task-query.logic.ts:1134-1144`: with only a lifecycle Archived card, the sentence reads "Open tasks from notes that are archived, except archived notes, type definitions, ..." (asserted in `TasksView.sources.test.ts`), which contradicts itself. When every active card holds a lifecycle `archived` clause the archived exclude removes nothing, so `describeExcludes` could leave "archived notes" out in that case (it needs the sources); otherwise accept the wording knowingly.
