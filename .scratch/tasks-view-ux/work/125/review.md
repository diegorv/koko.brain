## Findings

1. minor — `src/lib/features/tasks/TaskLists.svelte:51-63`: `counts` reads `tasksStore.visibleRows` in the same `$derived.by` that runs `taskViewCount` for every other list, so each search keystroke and each session edit re-runs `selectSourceRows` + `applyQuickFilters` over all rows for every non-active list, though their counts depend only on `rows`, `globalExcludes`, `savedViews` and the folder settings. The column is rendered (CSS-hidden) at narrow widths too, so it always runs. Fix: compute the non-active counts in their own `$derived` that does not read the session, and add the active list's `visibleRows` count at render time.
2. minor — `src/lib/features/tasks/TaskLists.svelte:216-222`: Save, Revert, Reset and a committed Save as view make `modified` false, which unmounts the marker while focus is on the clicked button, so focus falls to `document.body` and a keyboard user loses their place (discovery.md records it as a choice). Fix: after the action, `flushSync()` and move focus to a stable control (the sentence's Edit button or the active list's column button).
3. nit — `src/lib/features/tasks/task-query.logic.ts:1492`: on "No date", the empty state "Every open task has a due date" keeps the "Reset Due filter" action, which turns the No date list into "All open" plus a "modified" marker. Consider an action that opens "All open" (`selectTaskList(ALL_OPEN_ID)`) or no action there; owner call.
4. nit — `src/lib/features/tasks/TaskLists.svelte:210`: the marker's name input (Save as view) stays open, with "modified", after the user picks another list in the column, and Enter then saves the newly selected list's session as the new view. Fix: reset `editing` in the marker when `tasksStore.activeList` changes.
5. nit — `.scratch/tasks-view-ux/work/125/discovery.md` says the column count is linked to its list button by `aria-describedby`; `TaskLists.svelte:164-166` renders a plain sibling `<span>`. Fix the record or add the attribute.
