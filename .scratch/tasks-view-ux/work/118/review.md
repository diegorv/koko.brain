## Findings

1. minor, `src/lib/features/tasks/task-query.logic.ts:879`: under Heading grouping, a dimmed parent whose matching child sits under another heading is never shown above that child. The PRD's Parents rule says that in heading grouping a failing parent "stays visible, dimmed, while a child matches". The code drops the parent when its group holds nothing else. When the group also holds other matching rows, the parent stays there as an orphan dimmed row, with no child below it. Meanwhile the child shows indented in its own group, with no parent and no breadcrumb. The case is rare (a heading between a parent task and its indented child), and discovery.md records the choice. Fix: either give such a child its parent's `breadcrumb`, or drop a dimmed row from a heading group when none of its children is in that group. Add a test for the orphan case either way.
2. nit, `src/lib/features/tasks/task-query.logic.ts:738`: `property:<name>:<key>` can collide when a property name contains `:`. Property `a:b` with value `c` and property `a` with value `b:c` both give `property:a:b:c`, so collapsing one collapses the other. Fix: encode the pair, e.g. `property:${JSON.stringify([groupBy.property, key])}`.
3. nit, `src/lib/features/tasks/task-query.logic.ts:883`: `labelOrder` compares labels as plain lower-cased strings, so numeric property values sort `10` before `2`. Note and folder order compare numbers as numbers (`compareTaskPaths`). The Issue only says "sorted by label", so this meets it. A natural compare would match the rest of the view.

## Resolution

1. Fixed. `headingGroups` keeps a dimmed row only when a kept child of it follows in the same group (checked backwards, so a dimmed grandparent above a dimmed parent of a match stays). A dimmed parent whose matching child sits under another heading is dropped from its group, and any kept row whose parent task is among the rows but not kept in its group gets that parent's `taskDisplayText` as `breadcrumb`, as flat groupings do. Tests: the existing "only a dimmed parent" case now asserts the child's breadcrumb; new cases for the orphan dimmed parent in a group with other matches, and for a dimmed grandparent chain kept in one group.
2. Fixed. `collapseKey` writes a property grouping as `property:` plus `JSON.stringify([name, key])`. Test: `a:b`/`c` and `a`/`b:c` give different keys.
3. Fixed. `labelOrder` uses `compareTaskPaths` (numeric, case and accents ignored, raw order on ties), the same order as note and folder groups, for both type and property labels. Test: values `10`, `2`, `'1'` order `1, 2, 10`. The collator places `{"a":1}` before letters, so the object/mixed-list test's expected order swapped.
