## Findings

1. minor, `src/lib/features/tasks/SourcesPanel.svelte:203-211, 232-234, 288-295`: focus is lost when a user removes something in the panel. "Remove clause", the last card's "Remove card" (cards are keyed by index, so the last DOM block is the one dropped) and an exclude entry's remove button all delete the focused button. Focus falls to `<body>`, and when the list order then changes, the order effect in `TasksView.svelte:382-399` sees `focusIsFree(false)` and moves focus into the list. A keyboard user who removes a clause ends up on a task row, not in the panel. Fix: after the removal, `flushSync()` and focus a neighbour: the next clause's remove button or the card's Add clause button, the previous card's Remove card or Add card, or the list's input.
2. minor, `src/tests/lib/features/tasks/TasksView.sources.test.ts`: no test clicks "Remove card", a control this Issue adds (a recorded default). Fix: add a case that removes a card and asserts `tasksStore.query.sources` and the listed rows. If the removed card was a tag heading card, also assert the `tasksView.sectionTag` write.
3. nit, `src/lib/features/tasks/SourcesPanel.svelte:288`: each exclude entry's remove control is a raw `<button>` with hand-written focus classes. The Issue says the panel is built from `#lib/components/ui/` `button`. Fix: use `<Button variant="ghost" size="icon-sm">` like "Remove clause".
4. nit, `src/lib/features/tasks/SourcesPanel.svelte:137-139`: exclude edits call `tasksStore.setExclude` from the component. The Issue says edits go "through the service". This is a recorded default with no behavior difference, since excludes stay session-only. Fix, optional: a `setTaskExcludes` passthrough in `tasks.service.ts`, or leave it until Issue 123 saves excludes.
5. nit, `src/lib/features/tasks/task-query.logic.ts:628-637`: a tag heading clause whose text holds a space or a comma (`#a #b`) is one card in the session, where it matches no heading. `tagHeadingCardText` writes the text as typed, so after a restart `parseSectionTags` turns it into two cards that match both tags. The list then differs after a restart. This needs an unusual input. Fix, optional: write `parseSectionTags(only.text).join(' ')` per card, or leave it until saved views replace this write-back.

## Resolution

1. Fixed. `SourcesPanel.svelte` `refocus()` runs `flushSync()` after a removal and focuses a neighbour in the panel: Remove clause goes to the next clause's remove button, else the previous one, else the card's Add clause; Remove card goes to the next card's Remove card, else the previous one, else Add card; an exclude entry's remove goes to the next entry, else the previous one, else the list's input. Tests in `TasksView.sources.test.ts` failed before the fix (focus on a task row and on `<body>`).
2. Fixed. New case "Remove card drops the card and its rows, ..." asserts `query.sources`, the rows, the `tasksView.sectionTag` write (`''` once the `#to-list` card is removed) and focus.
3. Fixed. The exclude entry's remove control is `<Button variant="ghost" size="icon-sm">`.
4. Rejected for now. A recorded default with no behavior difference: excludes stay session-only, and a service passthrough would hold no logic until Issue 123 saves excludes.
5. Rejected. Writing `parseSectionTags(text).join(' ')` gives the same `#a #b` string, so it does not change the restart split the finding describes; the session/restart difference for a tag text holding a space needs a validation rule for the heading field, which is out of this Issue's scope and an unusual input.
