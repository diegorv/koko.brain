# 02: Guarded, status-preserving toggle

**What to build:** Two defects in one command. `toggle_task_status` flips whatever line number it receives and never checks that the line still holds the task the list showed (`src-tauri/src/commands/vault.rs:760-829`), while the list can be up to 10 s behind disk (open Issue `audit-2026-11-05/122`, migrated from `file-io-audit/24`). And unticking writes a space for every status that is not a space (`src-tauri/src/vault/parsing.rs:1895-1900`), so one click turns an important `[!]`, in-progress `[/]`, question `[?]` or forwarded `[>]` task into `[ ]`.

**Rust**
- `toggle_task_status` gains `expected_text: String`, `expected_status: TaskStatus` and `target: TaskStatus` (Tauri maps them to the camelCase args `expectedText`, `expectedStatus`, `target`). It keeps its name, so `audit-2026-11-05/135` (which confines this command by name; migrated from `audit-2026-11-04/16`) applies unchanged. If 135 has already landed, keep its outside-vault check in front of the new logic.
- `toggle_task_status_inner(idx, path, line_number, expected_text: &str, expected_status: TaskStatus, target: TaskStatus)` (`commands/vault.rs:760-786`) re-parses the line at `line_number` with the existing task-line parser `parse_task_line` (`parsing.rs:1619`), which becomes `pub(crate)` (it is private today; `commands/vault.rs` is in the same crate). When the line number is 0 or past the end, the line holds no task, its `text` differs from `expected_text`, or its `status` differs from `expected_status`, nothing is written and the result carries `stale: true` with `updated_content` equal to the file content and the no-op `UpdateResult` the function already builds (`:770-778`). `Task.text` excludes the checkbox (`task.rs:23`), which is why the status is compared too.
- Otherwise the checkbox char at the task marker is set to the char for `target`. Add `pub fn status_checkbox_char(status: TaskStatus) -> char` next to `map_checkbox_char` (`parsing.rs:1589`): todo `' '`, done `'x'`, cancelled `'-'`, in progress `'/'`, question `'?'`, forwarded `'>'`, important `'!'`. Replace `toggle_task_in_content` (`parsing.rs:1873-1906`) with `pub fn set_task_status_in_content(content: &str, line_number: usize, status: TaskStatus) -> String`, which keeps the marker-group logic (`:1881-1893`) and writes `status_checkbox_char(status)` into group 2. Port its unit tests (`parsing.rs:3252-3330`) to the new function (same inputs, with the target status each old case implied), and update the import at `commands/vault.rs:6` and the doc comments at `commands/vault.rs:792-799`. When the target char equals the current one the content is unchanged and the result is the no-op with `stale: false`.
- Every other caller of `toggle_task_status_inner` passes the new arguments: `src-tauri/tests/vault_task_test.rs:61`, `:102`, `src-tauri/tests/vault_file_ops_test.rs:167`, `:183`, `:198`, `:206`, `:225`, `:241`, `:245` and `src-tauri/tests/commands/vault_test.rs:713`, each with the text and status the file holds at that line, so they keep testing what they test today.
- `ToggleTaskResult` (`task.rs:187`) gains `pub stale: bool` with a doc comment ("true when the line no longer held the expected task, so nothing was written"). It is `#[ts(export)]`, so the bindings in `src/lib/contracts/generated/` regenerate. `src/lib/contracts/commands.ts:84` gains `expectedText: string; expectedStatus: TaskStatus; target: TaskStatus`, and `:228` becomes `['path', 'lineNumber', 'expectedText', 'expectedStatus', 'target']`.

**TS**
- A pure `toggleTarget(status: TaskStatus): TaskStatus` in a new `src/lib/features/tasks/task-status.logic.ts`: `done` and `cancelled` go to `todo`, every other status goes to `done`. Issue 06 later rebuilds it on `isTaskOpen`.
- `toggleTask(filePath, lineNumber)` (`tasks.service.ts:121`) becomes `toggleTask(filePath: string, task: TaskItem)` and sends `{ path: filePath, lineNumber: task.lineNumber, expectedText: task.text, expectedStatus: task.status, target: toggleTarget(task.status) }`. Update its doc comment (`:99-120`). `TasksView.svelte:66-68` and `:207` pass the task.
- After the call, check `result.stale` before the existing `!result.updateResult.changed` return (`:141`). On `stale: true`: `await buildTaskIndex()`, then `toast.info('The task changed on disk, so the list was refreshed. Click it again.')`, then return.
- Keep the dirty-tab save and line check at `tasks.service.ts:123-136` as they are.
- The circle's icon and `aria-label` follow `toggleTarget(task.status)`, not `task.checked` (`TasksView.svelte:206`, `:209`): `Mark task as done` and the open circle when the target is `done`. Without this, until Issue 06 lands, a `[/]` or `[!]` row looks ticked and says "Mark task as not done", while a click now writes `[x]`. Issue 05 later adds the status word.
- The e2e mock follows: `e2e/mocks/vault-index.ts:486` (`toggleTaskStatus`) takes `(path, lineNumber, expectedText, expectedStatus, target)`, parses the line with the mock's own `TASK_LINE_RE`/`STATUS_BY_CHAR`, returns `stale: true` and the unchanged content when the text or status differs, and otherwise writes the target char; every result it returns carries `stale`. `e2e/mocks/tauri-core.ts:156-160` passes the new args through.
