## Findings

1. minor — `src/lib/features/todoist-sync/fields.logic.ts:232` — The strip of the block id from `localBase.description` (a brain-born create keeps `Call Bob ^abc` raw in `local_base`, `create.logic.ts:191`) is untested on the pull side: with it removed, every todoist-sync test passes, while a Todoist content edit of such a task would log a spurious `conflict` ("The text changed on both sides; Todoist wins"). The current code is correct; the guard is unproven. Fix: add a `planFields` unit test with `localBase({ description: 'Plan ^abc' })`, a line ending in ` ^abc`, and `item({ content: 'Plan the launch' })`, asserting the written line keeps ` ^abc` last and `plan.log` is empty (or the same as a `syncNow` test on a brain-born line).
2. nit — `src/lib/features/todoist-sync/create.logic.ts:381` — The message tells the user to "run a rebuild", which is the Issue's wording, but no UI action triggers one (rebuild runs only when the link table is empty, `pull.logic.ts:441`), and in the scenario logged (no Todoist task) a rebuild would only log `unmatched`. Fix: keep only "remove its 🆔 to create it in Todoist", or say how a rebuild is reached; owner's call since the Issue named it.
3. nit — `src/lib/features/todoist-sync/task-line.logic.ts:295` — `trailingBlockId` (single space before `^`, trailing whitespace allowed) duplicates `TRAILING_BLOCK_ID` in `create.logic.ts:26` (`(?:^|\s+)`, no trailing whitespace) with slightly different rules, so creates and field sync can disagree on rare inputs (tab before `^id`, a description that is only `^id`). Fix: have `planCreates` use `trailingBlockId`, or note why the two differ.

## Resolution

1. Fixed. `fields.logic.test.ts` "pulls a Todoist text edit without a conflict when the local base of a create kept the block id": local base `Plan ^abc`, line ending in ` ^abc`, Todoist content `Plan the launch`; asserts ` ^abc` stays last and the log is empty. With the reviewer's mutation (`baseDescription = localBase.description`) it fails; restored.
2. Fixed. Rebuild mode starts only when the link table is empty (`pull.logic.ts:441`), so the user cannot reach it, and with no Todoist task it would only log `unmatched`. The orphan message now ends at "remove its 🆔 to create it in Todoist"; `create.logic.test.ts` asserts the message ends there.
3. Rejected. The two read different text: `trailingBlockId` reads the raw line, which may end in whitespace, and `TRAILING_BLOCK_ID` reads the parsed description. They disagree only on a tab before `^id` or a description that is only `^id`. Changing `planCreates` would change what a create sends for those lines, which needs its own tests, and the project rules say not to add code for rare edge cases. Left as is.
