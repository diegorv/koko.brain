## Findings

1. **Medium: a forced rebuild during a mouse drag now collapses a block that was revealed before the drag.** `core/check-update-action.ts:19-25` returns `'rebuild'` for `forceDecorationRebuild` before it checks for a drag. The block computes now ask `revealPredicate`, which returns `() => false` while `mouseSelectingField` is set (`core/reveal.ts:25`). On main the blocks used `shouldShowSource`, which ignored the drag flag, so a revealed block stayed revealed. Concrete failure: the cursor is inside a long fenced code block (shown as source), and the user drag-selects downward past the viewport edge. Autoscroll moves the viewport, and when it stops `scrollDebouncePlugin` (`core/scroll-debounce-plugin.ts:33-40`) dispatches `forceDecorationRebuild` 150 ms later with the button still held. All 11 block decorators rebuild, and the block holding the drag anchor collapses into its widget under the pointer. The rest of the drag maps to a different layout, and the block only comes back on mouseup. The collection-index and tag-colour `$effect`s in `MarkdownEditor.svelte:433,454` can do the same mid-drag. The probe above shows it: 0 decorations become 7 for a code block. Issue 04's review accepted this for inline syntax (one line). For blocks it hides many lines at once and moves the content the drag is selecting. The `block-reveal.test.ts` drag case only covers a block that was already rendered; a pure `compute` test cannot express "stays revealed". **Fix:** in `checkUpdateAction`, move the drag handling (`wasDragging && !isDragging` → `'rebuild'`, `isDragging` → `'skip'`) above the `forceDecorationRebuild` check. Keep `docChanged` and `reconfigured` first. The release rebuild already redraws everything, so a skipped forced rebuild loses nothing. Add a `check-update-action.test.ts` case ("forceDecorationRebuild during a drag returns 'skip'") and a jsdom `EditorView` test next to `keyboard-reveal.test.ts`: a code block revealed by the cursor, then drag on, then `forceDecorationRebuild`, and the block stays revealed until `setMouseSelecting(false)`. Check that both fail before the reorder. The `rebuildOn` path in `core/block-decorator.ts:80-85` (callout fold) still bypasses the gate; a fold toggle is a widget click and does not arm a drag, so leave it. If the orchestrator would rather keep `check-update-action.ts` for Issue 06/11, file this as a new Issue blocking 06 instead. Do not ship it unrecorded.

2. **Low: ADR 0008 still states per-element reveal.** `docs/adr/0008-codemirror-live-preview-architecture.md:29` reads "Reveal source markdown when the cursor touches the element." After this Issue no construct reveals per element. The 2026-10-29 decision (`.scratch/live-preview-analysis/findings-2026-10-29.md`, "Reveal granularity: resolved") chose whole touched lines for every handler and block. **Fix:** change that goal line to the line-based rule, or add a sentence to the existing 2026-10-29 amendment that points at `core/reveal.ts`, so the ADR matches `docs/LIVE-PREVIEW.md:34`.
