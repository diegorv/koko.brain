# Migrate to SvelteKit 3

Move `@sveltejs/kit` 2.70.3 -> 3.1.0 and `@sveltejs/adapter-static` 3.0.10 -> 4.0.0.
Driver: the two low advisories `pnpm audit` still reports (GHSA-pfhg-q3qv-9q6r,
GHSA-27mw-82g8-phjj), both fixed only in kit >= 3.0.0. Neither affects this app
in practice (no enhanced forms, no prerendered pages: `ssr = false` SPA under
Tauri), so this is hygiene, not an incident.

Source for every breaking change below:
https://svelte.dev/docs/kit/migrating-to-sveltekit-3 (read 2026-10-26).

## Complexity assessment

**Overall: medium. One change is large (the `$lib` imports). The rest is small.**

What the app actually uses from SvelteKit (measured 2026-10-26):

| Surface | Usage in repo | Kit 3 impact |
|---|---|---|
| `$app/*`, `$env/*`, `@sveltejs/kit` imports in `src/` | **zero** | none (navigation, paths, stores, forms, errors, cookies, CSRF, remote functions all N/A) |
| Routes | `+layout.svelte`, `+layout.ts` (`ssr = false`), `(app)/+layout.svelte`, `(app)/+page.svelte`, `composer/+page.svelte` | none expected |
| `hooks.*`, `src/params/`, service worker, `+server.ts` | none | none |
| `svelte.config.js` | adapter-static `fallback: "index.html"` + `vitePreprocess()` | **must move** into `sveltekit({...})` in `vite.config.js`; file is no longer read |
| `tsconfig.json` | `extends: "./.svelte-kit/tsconfig.json"` | **must change** to `$app/tsconfig` plus own `include`/`exclude` |
| `$lib/...` imports | **1749 import sites in 554 files** (257 source, 297 tests), 184 inside `vi.mock()`, 1399 without file extension | **largest item**: `$lib` is no longer generated; replacement is `#lib` via `package.json#imports` with explicit extensions |
| `vitest.config.ts` | own `$lib` alias, uses `vite-plugin-svelte` directly | unaffected if `$lib` alias is kept; must learn `#lib` otherwise |
| `components.json` (shadcn-svelte) | aliases all `$lib/...` | only matters when generating new shadcn components |
| `pnpm-workspace.yaml` override `cookie: '>=0.7.0 <2'` | caps cookie below 2 because kit 2 crashes on cookie 2 | **conflicts**: kit 3 depends on `cookie ^2.0.1`; override must be removed or changed |
| `pnpm check` script | `svelte-kit sync && svelte-check ...` | unknown: the guide does not mention `svelte-kit sync` |

Peers, all already satisfied: vite `^8.0.12` (8.3.4), svelte `^5.57.1` (5.57.2),
typescript `^6.0.0` (6.0.3), vite-plugin-svelte `^7.0.0` (7.3.1), Node `>=22.17`
(local 26.3.0; CI node version still to confirm).

Transitive: bits-ui pulls runed 0.23.4 / 0.28.0 / 0.29.2 / 0.35.1. Only 0.35.1
declares a kit peer (`^2.21.0`), so it will emit a peer warning on kit 3 until
bits-ui moves to runed >= 0.38 (peer `^3.0.0`). Runtime impact unknown; runed
only uses kit for optional helpers.

adapter-static 4.0.0: only breaking change is "require SvelteKit 3"; `fallback`
option unchanged per the changelog.

### The deciding unknown

Whether `$lib` can keep working through an explicit alias (kit `alias` option or
Vite `resolve.alias`). If yes, the migration is a config change of a few files.
If no, it is a 554-file mechanical rewrite (`$lib/x` -> `#lib/x.ts`, plus every
`vi.mock('$lib/...')` path), which must be codemodded and lands as one large
commit. Task 1 answers this before anything else is touched.
