## Review block

Copied from `.scratch/design-review/review.md` (line 469 onward):

```
#### P24. Lists have no keyboard model except Tasks, and every row is its own Tab stop
- **Problem:** The note list and search results have no arrow-key navigation, and Escape in search only blurs.
- **Evidence:** SearchPanel.svelte:35-38; NoteRow.svelte; tasks-keys.logic.ts; KanbanView.svelte:255-290.
- **Proposal:** Extract a roving-list action from `tasks-keys.logic.ts` and apply it to the note list and search results first: one Tab stop, Up/Down/Home/End, Enter, Cmd+Enter for a new tab, F2 to rename. In search, ArrowDown moves from the input into the results, and the first Escape clears the query. The Files and Types trees and collection rows come second.
- **Impact:** The largest keyboard gain in the app. **Effort:** L
- **Validation:** revise. Kanban already has a keyboard model.
```

## Verdict

**still real: partial.** Confirmed: note rows are native `<button>` Tab stops with no roving tabindex (NoteRow.svelte:67-81); SearchPanel has no arrow keys and its Escape only blurs (SearchPanel.svelte:41-44, 253); Tasks already has the pure model to extract (tasks-keys.logic.ts:46-112); Kanban has an arrow model (KanbanView.svelte:236-300). Partly stale or wrong: F2 rename already exists (NoteRow.svelte:73); Enter already opens a focused row through the native click; Escape already clears and closes the rail list search (RailListSearch.svelte:79-81, RailNoteList.svelte:511-514); Cmd+Enter has no separate new-tab path in code to build on; the review's SearchPanel line range is off by a few lines. Blocking: SearchPanel Escape is asserted by one E2E spec (search.spec.ts:39-51) and one unit test (SearchPanel.test.ts:153-158), so the proposed Escape rule is a deliberate behaviour change that needs owner approval. Tier also disagrees: prototype tags it "moderate", review says Effort L.

Not checked: no tests or E2E were run; the arrow-key behaviour in the real app was not exercised (the prototype is the only evidence of intended behaviour); the Cmd+Enter semantics and the rail list's Alt+ArrowDown E2E target were not confirmed; the CollectionView path and the Files and Types tree touch list were not read in depth.
