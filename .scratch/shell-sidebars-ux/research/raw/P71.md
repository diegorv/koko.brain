## Review block

Copied from `.scratch/design-review/review.md:301-307`:

```
#### P71. The Backlinks and Outgoing panels collapse on every note switch, with no counts
- **Problem:** Both panels reset to collapsed on every path change.
- **Evidence:** BacklinksPanel.svelte:33-39; OutgoingLinksPanel.svelte:29-35; commit 77c8cbcda (on-demand panels).
- **Proposal:** Keep the open or closed state across switches. While a panel is open, refetch for the new note. While it is closed, fetch nothing.
- **Impact:** Saves two clicks per navigation. **Effort:** M
- **Validation:** revise. Dropped the count badge, because it would bring back the eager fetch that 77c8cbcda removed.
```

Review-side notes: the title says "with no counts", and the Validation line drops the count badge. The proposal's "while it is closed, fetch nothing" already holds at HEAD (see Current code), so the real change is narrow: stop the collapse on path change and refetch while open.

Today's `vaultIndexVersion` effect is the pattern to copy. The `+layout.svelte` comment at `src/routes/(app)/+layout.svelte:97-98` describes these two effects and will need updating if their shape changes.

### Commit 77c8cbcda (verified with `git show --stat`)

Subject: `refactor(sidebar): on-demand panels for Backlinks, Outgoing Links, TOC` (2026-05-25). The commit body states the collapse-on-switch was deliberate: "Zero IPC calls until user clicks to expand. Switching tabs auto-collapses and resets." The stat lists `src/lib/core/layout/AppShell.svelte`, which has since moved to `src/lib/app/AppShell.svelte`. P71 therefore reverses a documented decision from that commit. The reason was IPC cost; the proposal keeps the cost bounded by fetching only while open.

### SidebarSection.svelte (`src/lib/core/layout/SidebarSection.svelte`)
