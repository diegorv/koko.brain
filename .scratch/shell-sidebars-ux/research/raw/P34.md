## Review block

```
#### P34. The tab strip has no overflow cue or control, fixed 160 px titles, and no reorder
- **Problem:** The macOS overlay scrollbar is invisible at rest, so there is no cue, no list of tabs and no wheel mapping. Tabs never shrink, cannot be reordered and have no tooltips. Pinned tabs show only an icon.
- **Evidence:** EditorTabs.svelte:36-41, 45, 52, 84-85, 98-109; [tabs-bar-several-light.png](screens/tabs-bar-several-light.png).
- **Proposal:** Tabs flex from about 220 px down to about 100 px. Map the wheel to horizontal scroll, add edge fades and a list-all-tabs menu with dirty dots, support drag-to-reorder with a marker, and give every tab a full-path tooltip.
- **Impact:** Multi-tab work keeps its context. **Effort:** M
- **Validation:** keep. The active tab already scrolls into view.
```

Related block, same prototype and same surface: P98 (`review.md:665`), "The right sidebar toggle covers the tab strip and is not accessible". Its evidence is AppShell.svelte:190-196, 276; EditorTabs.svelte:41, 45. The task brief folds it into the sh-tabs cluster, so it is covered in Current code below.

## Prototype

Source: `prototypes/shell-tabs-navigation.html`, section `#P34` at lines 378-404; mock JS `tabsMock` at 759-~920; P34 wiring at 1004-1015; CSS at 158-180.

- **Layout:** a fake window (default 900 px, slider 600-1100) with a band: a "Projects" stub, the tab strip, a chevron button (`data-tip="List all tabs"`) with a count badge, and a right sidebar toggle (`panel-right` icon, `data-tip="Show right sidebar"`, `data-tip2="Cmd+B"`) at the far right of the band.
- **Sizing:** `.tab { flex: 0 1 220px; min-width: 100px }`; `.tab.pinned { flex: 0 0 auto; min-width: 0; padding 0 8px }`. Non-pinned titles are not capped at 160 px in the prototype. Read-out text: `N tabs, tab width W px (max 220, min 100)`, plus `, strip scrolls` when overflowing.
- **Strip reserve:** `.win:not(.legacy) .strip.reserve { padding-right: 40px }`. It is set when the sidebar is hidden (`reserve()`), so the strip keeps 40 px clear of the toggle.
- **Edge fades:** `.fade` 34 px wide, shown on the left when scrolled and on the right when more content lies beyond the edge.
- **Hidden count:** the chevron shows the number of tabs whose rects fall outside the visible scroller.
- **Copy:** tooltip is `<b>name</b><span>path</span>` plus "Unsaved changes" and "Pinned" lines. Tooltip appears after 400 ms (`showTip(..., 400)`). Menu button label "List all tabs". Dirty dot title "Unsaved changes". Toast on add when the sample vault is exhausted: "No more tabs in the sample vault".
- **Interactions:** Wheel: vertical delta becomes `scrollLeft`, `preventDefault` (only when the strip overflows). Drag: `draggable="true"` (not on the legacy variant), `dragstart`/`dragover` compute an insertion index from tab midpoints, and a drop marker is drawn. Pinned tabs stay first. Keyboard: Enter or Space activates a tab. Reveal: the active tab scrolls into view with 30 px padding.
- **Controls under the prototype:** "Open another tab", "Close last tab", "Reset", window-width range. Note text: "open tabs until they shrink to 100 px and the strip starts to scroll (edge fades appear, the chevron shows a hidden count), drag a tab to reorder (pinned tabs stay first), hover a tab for the full path, scroll the wheel over the strip, open the list with the chevron."
- **Not shown:** the chevron menu's contents are not implemented in the prototype (the button only shows a count), so the list-all-tabs menu's items and behavior are unspecified there.
- **Legacy variant:** the P98 "before" uses the same mock with `legacy: true` (no fades, no chevron, no drag, no tooltip, `flex: 0 0 auto`).

## Verdict

**still real: yes**. Every code claim in the Review block holds at HEAD: no overflow control or list menu (`EditorTabs.svelte:46`, `:37-42`), tabs `shrink-0` (`:53`), title `truncate max-w-40` (`:88`, 160 px), pinned shows icon only (`:67-69`, `:87`), no tooltip (no `title=` in file), no drag or reorder (no drag handlers; no store move API), no wheel handling (none in the markdown-editor or EditorView). Caveats: the "scrollbar invisible at rest" is OS default overlay behavior, with no code hiding it (**unconfirmed on screen**). Line numbers drift (the strip is `:46`, the tab element `:52-53`). The right-sidebar toggle overlap is real in code (`AppShell.svelte:189-197` over the strip end, no reserve in `EditorTabs.svelte:46`) but belongs to P98 and is **unconfirmed visually**. Overlap with open-itens 153 is the main ownership question: 153 is ready-for-agent in an abandoned folder and must be replaced, and it carries the `.md` extension hiding that P34 omits.
