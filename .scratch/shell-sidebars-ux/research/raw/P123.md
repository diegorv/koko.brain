## Current code

### Evidence line 1: note-info.logic.ts:15-21 (HOLDS, lines moved by 1)

`src/lib/features/properties/note-info.logic.ts` (35 lines at HEAD):

```
14	/** Formats an index timestamp in seconds; `0` means the filesystem does not expose it. */
15	function formatTimestamp(seconds: number): string {
16		if (!seconds) return PLACEHOLDER;
17		const moment = new Date(seconds * 1000);
18		const date = moment.toLocaleDateString('en-US', { month: 'long', day: 'numeric', year: 'numeric' });
19		// The system locale, not en-US: it is what carries the 12-hour or 24-hour clock setting.
20		const time = moment.toLocaleTimeString(undefined, { hour: '2-digit', minute: '2-digit' });
21		return `${date}, ${time}`;
22	}
```

Claim holds: the date is formatted with `month: 'long'` (line 18) and the result is `"<Month> <d>, <yyyy>, <hh:mm>"`. The time is the system locale (line 20, comment at 19). Lines 15-21 cover the function body; line 22 is the closing brace.

Note for the proposal: the time portion is locale-dependent (12h or 24h). The short-month form only changes the `month` option (`'short'` gives "Nov"). The `toLocaleTimeString` call is unchanged.

Precedent for the short form already in the repo (same en-US short-month style): src/lib/core/trash/trash.logic.ts:91 (`month: 'short', day: 'numeric', year: 'numeric'`) and src/lib/features/file-history/file-history.logic.ts:38 and :95 (`month: 'short'`).

- The value is `truncate` (overflow hidden, ellipsis, nowrap), so a long date is clipped with "...". Holds.
- The label is `shrink-0`, the value is `min-w-0 flex-1`, so the value gives up width and the label keeps it. Holds.
- The tooltip is `title={row.value}` (line 51). It is the same string as the visible value, not a separate full value. So the review's statement "The tooltip already holds the full value" holds only while `row.value` is not shortened. Changing `formatTimestamp` to short month also shortens the tooltip.
