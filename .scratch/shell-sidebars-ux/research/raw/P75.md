## Prototype

Source: `.scratch/design-review/prototypes/right-sidebar.html`. P75 article at lines 469-472 (copy: "Unresolved links are dead, dimmed red rows with no action. Group them under 'Broken links', make each a button that creates the note, and drop the opacity. Click one."). Demo block `#d75` at lines 1254-1263 (`/* ---------- P75 ---------- */`).

- Demo: a Before and After pair of the same sidebar (one section, "ol", open), built by `renderSidebar` with the `p75` legacy flag toggled. Captions: Before = "Dimmed red divs, no action, mixed in with real links."; After = "Click a broken link to create the note; it moves to the resolved list."
- Before (`olBody`, lines 796-801 with `s.legacy.has("p75")`): all outgoing rows, resolved and broken, in one flat column. Broken rows are `div.lrow.l-inline.dead` with an alert-circle icon, title and optional "› heading". `.lrow.dead` is `opacity: .6`, `cursor: default`, no hover background, icon and title in `--destructive` (CSS lines 310-312).
- After (`olBody` lines 802-811, default path): resolved rows first (same `outRow` button as before: file-text icon, title = alias or basename of target, sub-line = folder of target plus "› heading", title attribute = full target). Then, only when there are broken rows, a group label `div.glbl` with "Broken links" and a count pill, then one `button.lrow.broken` per broken row.
- Broken row markup: alert-circle icon in destructive colour (CSS line 313), title = alias or basename, sub-line = folder of target (or "Vault root") plus "› heading", and a right-aligned "Create" pill with a file-plus icon (`.mk`, CSS lines 314-315; pill turns to primary colour on hover or focus). `title="Create <target>.md"`, `data-click="create"`.
- Interaction: clicking a broken row sets `l.ok = true` and shows a status toast "Created <basename>.md in <folder or the vault root>" (lines 988-990). The row then moves into the resolved list on the next render. Note the prototype's toast is driven by `s.toast` (line 811) and does not describe failure.
- Layout note: the demo's "After" has no opacity on broken rows; the destructive colour is kept on the icon and title only.
- Not shown in the prototype: the unresolved state of an empty target, embeds, or a failed create. The prototype's baseline outgoing data (`baseOut()`, line 652 area) is not inspected in detail here.

## Verdict

still real: **yes**. The dead, dimmed unresolved rows (`opacity-60`, no click handler, no grouping) are still at HEAD in `OutgoingLinksPanel.svelte:73-80`, and the prototype's grouped "Broken links" with Create buttons is a valid target. Caveat for the ticket: a Create button on a broken row is only safe after the 046 classification fix (empty-target heading links and embeds of existing files are currently reported as broken, `index.rs:157-158`); otherwise P75 would offer to create wrong notes. Creation can reuse `appEditorHost.createNote` (`editor-host.ts:152`), the same path as a wikilink click.

Not checked: I did not run the app, the tests, or the E2E suite. Rust behaviour for embeds was taken from the 046 issue text plus `resolve_with_cache`; the parser's empty-target split (`parsing.rs`) was not re-read in full. The "moves to resolved list" behaviour in the prototype depends on a refetch after `create_note`, which I traced through the comments in `note-creator.service.ts:66-78` but did not run.
