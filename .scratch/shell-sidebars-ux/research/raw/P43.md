# P43 raw research: Properties collapse, sticky headers, empty Relationships

Read-only research at HEAD ab143a411 (branch main). No source, tests or git state were changed.

## Review block

Verbatim from `.scratch/design-review/review.md` line 110:

```
#### P43. Properties is a tall static section that pushes TOC and Backlinks below the fold, with empty Relationships chrome
- **Problem:** Properties cannot collapse, and the empty Relationships block takes about 100 px on every note. Section headers scroll out of reach.
- **Evidence:** PropertiesView.svelte:153, 156, 243-290; SidebarSection.svelte:31, 56-72; AppShell.svelte:277-292; [editor-live-preview-light.png](screens/editor-live-preview-light.png), [right-sidebar-all-expanded-light.png](screens/right-sidebar-all-expanded-light.png).
- **Proposal:** Make Properties collapsible, remember the state, and make section headers sticky. Replace the empty groups with one "Add relationship" row, and render a group only when it has links.
- **Impact:** Saves about 100 px per note and keeps Backlinks reachable. **Effort:** M
- **Validation:** keep.
```

Scope note: the cluster name in the task also lists "section title indentation" and "narrow-sidebar truncation of names and info values". Neither appears in the P43 block. In the prototype they belong to P177 (Info header and Relationships child labels) and P121 (key/value stacking at narrow widths). They are covered below only where they touch the P43 code.

Behaviour encoded in the prototype code:
- `section()` (lines 660-666): a collapsible section renders its header as a `<button class="sec-h" aria-expanded>` with a chevron and an `<h2>`. A non-collapsible one renders a `<div class="sec-h">`. Properties defaults to open (`open.props: true`, line 650).
- Sticky: `.sec-h` has `position: sticky; top: 0; z-index: 4; background: var(--bg)` (CSS around lines 136-141). `.sbx.nostick .sec-h` makes it static. The "before" state adds class `nostick` when legacy flag `p43` is set (`renderSidebar`, line 840 area) and makes the Properties section non-collapsible (`section(..., !L.has("p43"))`, line 849).
- Relationships "after" (`relBlock`, line 748): no separator and no heading when a note has no links. One `Add relationship` add-row button opens an upward popup menu listing "Belongs to", "Related to", "Has many" (`RELS`, line 603; `relPick`). When links exist, a "Relationships" heading (`h3.slabel`) and only the non-empty groups render, each with its own plus button.
- Relationships "before" (`relBlock` legacy branch, lines 740-746): a separator, the "Relationships" heading and all three groups always rendered, each with a label and a plus button.
- Strings to reuse: "Collapse Properties", "Expand Properties", "Add relationship", "Belongs to", "Related to", "Has many", "Relationships", "Empty (daily case)", "Has links".
- Not read in full: the body of `toggleSec` (line 884). It exists and is the header-click handler.
