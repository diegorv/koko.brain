## Review block

```
#### P38. Creation has many entry points with different destinations and names, and Files has no visible "+"
- **Problem:** Folder, canvas and table creation exist only on right-click. "New File", "New Canvas" and "New Kanban Board" write to the vault root, and the names drift.
- **Evidence:** FilesNavigator.svelte:80-91, 304-310, 346-403; commands.ts:148-192, 371-376; note-composer.service.ts:20-55; new-note.service.ts:26-46; RailNoteList.svelte:808-819; TypesNavigator.svelte:218-230.

- **Validation:** keep.
```

## Prototype

Source: `.scratch/design-review/prototypes/note-list-rail.html`, section `<!-- P38 -->` at lines 382-402 (markup) and the `/* ---------- P38 ---------- */` script at lines 959 onward. Headline: "Creation has many entry points with different destinations and names, and Files has no visible +". Tier: moderate.

- Problem copy in the prototype: "Folder, canvas and table creation exist only on right-click. Palette commands write to the vault root, labels drift, and "New table" and "New view" create the same file."
- Note copy (AFTER): "a + menu in the Files header targets the selected folder and uses one wording, "New kind". ... The note-list + keeps creating a note in the listed folder; Cmd+N stays capture."
- Two side-by-side panels per variant (before and after), each a mini stage: a 190px Files navigator (header with title "Files"; the after variant adds an icon button `aria-label="New in folder"`, `aria-haspopup="menu"`, title "New in <folder>/" or "New in vault root"), a tree (`test-vault` root plus folders Areas, Daily, Events, Inbox, Meetings, People, Projects, with sub-folders created at runtime), and a list pane with a header-less mock list.
- Before footer: button "Palette: New canvas" and message "Right-click a folder to create inside it." Palette create writes "Untitled canvas" to the vault root; the message then reads "Palette wrote to the vault root, not to Projects/."
- After footer message: "Click + to create in the selected folder."
- After + menu: heading "Create in <folder path>", then five items with icons and labels: New note (fileplus), New folder (folderplus), New canvas (grid), New board (kanban), New table (table); footer "Cmd+N still captures to Inbox."
- Right-click on the tree in the before variant shows: New note, New Canvas, New Kanban Board, New table, New view, New folder, Rename (F2), Move to Trash. The after variant right-click shows the five-kind menu with Rename and Move to Trash.
- Creation: the new row is prepended to the list with class `newrow`, a toast reads "Created <Untitled name> in <folder>", and folder creation adds a sub-folder row to the tree. Selecting a tree row changes the target folder and resets the list.
- Names in the prototype's KINDS map: note "New note" (Untitled), folder "New folder" (Untitled folder), canvas "New canvas" (Untitled canvas), board "New board" (Untitled board), table "New table" (Untitled table, file kind `view`).
- Tables in the prototype: "Names today" lists Palette New File, New Folder, New Canvas, New Kanban Board (all "vault root"), Files right-click items (clicked folder), and New table and New view as "same .view file". "Names after" lists Files + and right-click as New note, New folder, New canvas, New board, New table (selected folder); Palette "Same five, same wording" (follows the lens, and says where); Note-list + "New note here" (listed folder); Cmd+N "Quick capture" (unchanged); New view "Merged into New table".

Prototype vs code differences (factual, not judgements):
- The prototype footer says "Cmd+N still captures to Inbox". At HEAD, Cmd+N writes to `<vault>/_notes/<YYYY/MM-MMM>/capture-note-....md` (see Current code, note-composer). Inbox is a lens filter (`isInboxEntry`), so a capture shows in Inbox only when the note carries the unorganized flag.
- The prototype writes sentence-case labels ("New canvas", "New board"). Code uses title case ("New Canvas", "New Kanban Board", "New table"). The prototype's "New board" has no code equivalent yet.
- The prototype says the Files right-click set has New Canvas, New table, New view, New folder. At HEAD it also includes the plugin-registered "New Kanban Board" (kanban.service.ts:27-35 registers it into `railRegistryStore.folderCreators`, which FilesNavigator merges at line 80-91).
- The prototype models "Files + targets the selected folder". At HEAD the Files navigator already tracks the picked lens (`picked` prop, `lensFor`), so the selected folder exists in the component (FilesNavigator.svelte:61-72, 108-111).

## Verdict

**still real: partial**

Why: the missing Files "+" (FilesNavigator.svelte:304-310) and the root-targeting palette commands (commands.ts:149-190) are confirmed, and the naming drift is real ("New File" / "New note", "New Canvas" / "New canvas", "New Kanban Board" / "New board"). The Problem sentence is wrong in part: palette has "New Folder" and "New Canvas", so only table creation is right-click only. The note-list "+" already exists as "New here" (RailNoteList.svelte:790-801), so that half of the proposal extends a control rather than adding one. The Evidence range RailNoteList.svelte:808-819 no longer points at creation code, and the Cmd+N destination in the prototype ("Inbox") does not match code (`_notes/YYYY/MM-MMM/`).

Unconfirmed: the proposal's claim that "New table" and "New view" write the same file (they write different `.view` files, with different names and templates, so only "same file kind" holds); the "Boards and canvases land where the owner works" impact (not measured); and the colour-only sort/filter point, which is in the cluster brief but not in the P38 block (code confirms it at RailNoteList.svelte:756-762 and RailSortMenu.svelte:106-119).

Not checked: rail-registry.store.svelte.ts internals, canvas.service.ts body, and the full test bodies listed above. No test or build was run (read-only brief).
