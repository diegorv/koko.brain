- **Problem:** The top band is copied into 10 places. Kanban, Collection and Canvas have no title. The source toggle sits in a different corner for each file type, and Cmd+\ flips only the markdown flag. The canvas toolbar uses a magic offset.

- **Validation:** revise. Favorite and pin stay off non-markdown files, because they write frontmatter.

## Prototype

Source: `.scratch/design-review/prototypes/shell-tabs-navigation.html`, section `#P18` at lines 417-438 (markup and "Before/After" captions), script block at lines 1236-1301.

Layout and copy:

- Before row: three screenshots of the real app (kanban-board-light, canvas-view-light, view-file-table-light) with annotations "no title", "source: bottom-right", "floating, magic offset", "view tabs, no title", "source: top-right", "source: bottom-right".
- After caption: "one slim header row (the existing pane-toolbar) with title, view controls and the source toggle at the same end; Cmd+\ flips the tab's own source mode".
- Controls: a three-button segmented control (Board.kanban / Brainstorm.canvas / Active.view), a "Show band heights" toggle (redline overlay), and a note: "Click the source button or hover the window and press Cmd \ . Favorite and pin-to-rail are not added for these files (they write frontmatter)."

Interactive mock (script):
- A mock window with a tab strip (three tabs, each with its file name, 180 px basis) and a `.pane-toolbar` row. Each tab's toolbar starts with a crumb: icon, kind ("Kanban", "Canvas", "View") and the name ("Board", "Brainstorm", "Active") separated by a chevron.
- Kanban toolbar: a board/list/table segmented group (aria-labels "board view", "list view", "table view"), a Sort icon button, and a static "Filter cards" chip.
- Canvas toolbar: five add buttons (Add text, Add note, Add link, Add image, Add group), a divider, then Zoom out, Zoom in, Fit view.
- View toolbar: a "Projects" chip (pressed), an Add view button, a "4 results" count, then Sort, Filter, Columns.
- Source button: last item in the same row, after a divider, `aria-pressed` reflecting the mode, muted background when on, tooltip "Show source" or "Back to the <kind> view", with `data-tip2="Cmd+\"`.
- Body: kanban board (three lanes, Backlog 2, In progress 2, Review 1, cards with #design tags), list and table variants; canvas with groups, text nodes, file node and a minimap; view as a 4-row table (file.name, status, priority, due). Source mode renders the raw file as numbered lines (kanban markdown, canvas JSON, view YAML).
- Interactions: clicking a tab switches the tab and repaints the toolbar and body; clicking the source button toggles that tab's source flag only and shows a toast "<file>: source mode (this tab only)" or "rendered view (this tab only)"; the Cmd+\ handler is attached to the window (`root._onKey`), so it works while hovering the mock.
- Prototype state is per tab (`S.src[S.tab]`), so each tab keeps its own source flag while others are open.

Notes for the ticket:
- The prototype's "this tab only" semantics are per tab. The current code resets all three flags on every tab switch (see Current code, EditorView.svelte:46-53). Keeping the prototype behaviour would be a change, not a preservation.
- The prototype's Filter for kanban is a static chip. No filter behaviour is shown.
- The prototype does not show canvas or .view in a narrow pane, nor the Favorite/Pin menu states (explicitly excluded in the note).
