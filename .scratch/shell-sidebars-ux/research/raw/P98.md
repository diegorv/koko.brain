# P98 raw evidence: right sidebar toggle covers the tab strip

## Review block

Copied from `.scratch/design-review/review.md:665-672`:

```
#### P98. The right sidebar toggle covers the tab strip and is not accessible
- **Problem:** While the sidebar is hidden, the absolutely positioned toggle covers the last tab. It has no `aria-pressed` and no focus ring.
- **Evidence:** AppShell.svelte:190-196, 276; EditorTabs.svelte:41, 45; [tabs-bar-several-light.png](screens/tabs-bar-several-light.png).
- **Proposal:** While the sidebar is hidden, pad the end of the tab strip by the toggle's width. Add `aria-pressed` and the shared focus ring.
- **Impact:** No covered tabs. **Effort:** S
- **Validation:** revise. `title` already gives the toggle a name.
```

### 1. Toggle markup (Evidence: AppShell.svelte:190-196, 276)

`src/lib/app/AppShell.svelte`:

- Lines 188-197:
  ```
  188  <!-- The tabs in hidesRightSidebar always hide the right sidebar, so its toggle would do nothing there. -->
  189  {#if !hidesRightSidebar(editorStore.activeTabPath)}
  190  	<button
  191  		class="absolute right-2 top-[7px] z-20 shrink-0 rounded-md size-6 inline-flex items-center justify-center hover:bg-accent hover:text-accent-foreground dark:hover:bg-accent/50 cursor-default"
  192  		onclick={toggleRightSidebar}
  193  		title={settingsStore.layout.rightSidebarVisible ? 'Hide right sidebar' : 'Show right sidebar'}
  194  	>
  195  		<PanelRight class="size-3.5" />
  196  	</button>
  197  {/if}
  ```
- Confirmed: the button is absolute (`absolute right-2 top-[7px] z-20`), has `title` and no `aria-label`, no `aria-pressed`, and no `focus-visible` class. Its only text content is the SVG icon, so the accessible name comes from `title`. The evidence lines hold exactly.
- Line 276 (`src/lib/app/AppShell.svelte:276`): `<div class="h-10 shrink-0 bg-tab-bar" style="box-shadow: ..." data-tauri-drag-region></div>`. This is the 40px header spacer of the right sidebar, which is where the toggle sits visually while the sidebar is shown. Still present; still relevant.
- Container: `src/lib/app/AppShell.svelte:187` is `<div class="relative flex h-screen flex-col" ...>`, so `right-2` is relative to the window's right edge, not to the editor pane. When the right sidebar is hidden the editor pane runs to that edge, so the toggle lands over the editor's tab band.
- Visibility rule: the toggle is not rendered when `hidesRightSidebar(activeTabPath)` is true (canvas, kanban, view, tasks, tags, graph and event-calendar tabs). Covering can therefore only happen on note-like tabs with the sidebar hidden, and only while at least one tab is open (the strip renders only when `tabs.length > 0`).

### 2. Tab strip (Evidence: EditorTabs.svelte:41, 45)

`src/lib/core/markdown-editor/EditorTabs.svelte`:

- Lines 40-42 (the evidence's line 41 is in this block): `$effect` that calls `scrollIntoView({ block: 'nearest', inline: 'nearest' })` on the active `[role="tab"]`. Line 41 is now the `querySelectorAll(...)[index]?.scrollIntoView` call.
- Line 45: `{#if editorStore.tabs.length > 0}`. Line 46 is the strip itself:
  ```
  46  <div bind:this={strip} class="editor-tabs-bar flex items-end h-10 bg-tab-bar overflow-x-auto pt-1 px-1 gap-0.5" role="tablist" data-tauri-drag-region>
  ```
- The strip is `overflow-x-auto` with `px-1` (4px) on both ends. No right padding is reserved for the toggle, and no class or prop changes when the sidebar is hidden. Each tab is `shrink-0` (line 53), so the strip overflows and the last tab sits at the strip's right edge.
- Each tab's close button (lines 89-96) is `opacity-0` until hover or focus-within, so the covered close button is only visible on hover of the last tab.
- Claim "covers the last tab and its close button": geometry supports it (the strip ends at the window edge, the toggle sits at `right: 8px` and `top: 7px` over the tab band, z-20). Not visually confirmed at runtime here (see Verdict).
- Evidence line 45 holds as the strip root (now line 46 for the `<div>`; line 45 is the `{#if}`).

### 3. Layout logic and service

- `src/lib/core/layout/layout.logic.ts:23-28` `hidesRightSidebar(activeTabPath)`: true for `EVENT_CALENDAR_VIRTUAL_PATH`, `TASKS_VIRTUAL_PATH`, `TAGS_VIRTUAL_PATH`, `GRAPH_VIRTUAL_PATH`, and canvas, `.view` and kanban files.
- `src/lib/core/layout/layout.logic.ts:37` `isRightSidebarShown(visible, activeTabPath)` = `visible && !hidesRightSidebar(...)`.
- `src/lib/core/layout/layout.service.ts:30-34` `toggleRightSidebar()`: no-op when `hidesRightSidebar(editorStore.activeTabPath)`; else flips `settingsStore.layout.rightSidebarVisible` via `updateLayout`.

### 4. Other entry points to the same toggle

- `src/lib/app/global-keybindings.ts:144-149`: `{ command: 'layout:toggle-right-sidebar', key: 'b', meta: true, handler: toggleRightSidebar }`. So Cmd+B is a keyboard path that does not depend on the button. This mitigates "not accessible" for keyboard users.
- `src/lib/app/commands.ts:327`: command palette action `toggleRightSidebar()`.

### 5. Accessibility claims

- "No aria-pressed": confirmed (AppShell.svelte:190-196 has none).
- "No focus ring": confirmed that the toggle has no `focus-visible:` classes and that `src/app.css` has no global `:focus-visible` rule (grep for `focus` in `src/app.css` returned only `--ring` tokens at lines 29, 174, 235). The shared pattern is per-component: 24 files under `src/lib` use `focus-visible:ring-ring`. Whether the WebView draws any default outline on Tab focus was not checked (macOS WKWebView does not focus buttons on Tab by default in Safari-style configs; unconfirmed for this Tauri build).
- "Not accessible" overall: the button does have an accessible name (title), so the review's own note "title already gives the toggle a name" is accurate. The state is conveyed only by the changing title ("Hide"/"Show"), not by a pressed state.
- Test coupling: `e2e/specs/sidebars.spec.ts:70` clicks `button[title="Hide right sidebar"]`, so the title must stay as is if the label is kept.

## Verdict

Still real: partial.

Why: the covering is real by layout geometry (absolute toggle at `right: 8px; top: 7px; z-20` in AppShell.svelte:190-196, over a tab strip that runs to the window edge when the sidebar is hidden), and `aria-pressed` is absent (confirmed). Not confirmed: the covered tab at runtime, since the evidence screenshot does not show it (below). The "no focus ring" part is partly true (no explicit ring classes; WebView default outline unconfirmed). The "not accessible" part is overstated because the button has an accessible name from `title`, and Cmd+B is a keyboard path.

Evidence screenshot check: `.scratch/design-review/screens/tabs-bar-several-light.png` was opened. It shows the right sidebar visible (the "Properties" header and the toggle at the far right of the top band, x around 1418), not the hidden state. The clipping visible in that image is the left tab ("ap.md") cut by the strip edge, which is the overflow issue of 153, not the toggle covering a tab. So the cited screenshot does not demonstrate P98's problem and should be replaced with a hidden-sidebar capture before the ticket cites it.

Unconfirmed: whether the padding approach (`padding-right` on the overflow strip) adds trailing space to the scrollable width in the Tauri WebView (WebKit on macOS); the proposal needs an in-app check. Also unconfirmed: the Tab-key focus outline in the WebView.

Not checked: no runtime run, no E2E run, no screenshot of the hidden state (read-only research).
