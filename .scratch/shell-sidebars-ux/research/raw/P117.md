## Current code

Each claim from the Evidence line, checked at HEAD.

1. lens.logic.ts:258-260, `noteSubtitle` (still holds, the lines are the function body):
   ```
   export function noteSubtitle(entry: NoteEntryV2, vaultPath: string | null): string {
   	return [formatRelativeTime(entry.modifiedAt), vaultFolder(entry.path, vaultPath)].filter(Boolean).join(' · ');
   }
   ```
   `vaultFolder` (lens.logic.ts:272-279) returns the vault-relative folder of the file, so for a note in Projects/ it returns "Projects". Nothing checks the lens, so a folder lens always gets the folder. **Claim holds: a folder lens repeats its folder.**

2. lens.logic.ts:291 (cited as 291). At HEAD the line is **290**: `subtitle: noteSubtitle(entry, vaultPath),` inside `toLensNote` (about 284-299). `toLensNote` builds every markdown LensNote (called from fileToLensNote for indexed markdown). **Line is off by one; logic holds.**

3. lens.logic.ts:924-932 (cited), `FILE_KIND_LABELS` at 924-933 (the const is on 925):
   ```
   const FILE_KIND_LABELS: Record<FileKind, string> = {
   	markdown: 'Note',
   	canvas: 'Canvas',
   	kanban: 'Kanban',
   	view: 'View',
   	pdf: 'PDF',
   	image: 'Image',
   	other: 'File',
   };
   ```
   The doc comment (924) says "The row subtitle of a file the entries snapshot does not describe." **Claim holds: canvas, kanban and view (and pdf, image, other) rows get a kind word, no time.**

4. lens.logic.ts:960-962 (cited), `fileToLensNote` starts at 960. Subtitle set at 973: `subtitle: FILE_KIND_LABELS[kind],`. Its modifiedAt (line 967-969 area) is already computed from the tree node: `modifiedAt: Math.floor((node.modifiedAt ?? 0) / 1000)`, so the time is available for the proposal. The 'markdown' branch only applies when there is no entry (`if (kind === 'markdown' && entry) return toLensNote(...)`), so the word "Note" appears only for a markdown file the entries snapshot has not indexed yet. **Holds, with the nuance: "Note" is not what an indexed note shows.**

5. lens.logic.ts:1003-1006 (cited), `resolveFolderLens` (986-1009): builds the folder lens rows from the tree's direct files and maps each through `fileToLensNote(n, byPath.get(n.path), root)`. Folder lens rows therefore come from two paths: indexed markdown (toLensNote, with the folder) and everything else (FILE_KIND_LABELS, no time). **Holds.**

6. The row renders the subtitle as is: RailNoteList.svelte:901 `subtitle={note.subtitle}`, and NoteRow.svelte:92-93 `{#if subtitle}<div class="truncate text-[11px] text-muted-foreground" data-note-row-subtitle>{subtitle}</div>{/if}`. No folder logic in the component. **Holds: the fix can live in lens.logic.ts.**

7. The icon: RailNoteList.svelte:904 `fallbackIcon={KIND_ICONS[note.kind]}`, with `KIND_ICONS` in kind-icons.ts:16 (`Record<FileKind, Component>`). The icon already encodes the kind for non-markdown rows when no custom icon is set (NoteRow.svelte fallback branch). **Holds: "icon carries the kind" is already true for the fallback icon.** A custom file icon (`resolveNoteIcon`) replaces it, so the kind is then not shown by the icon; unconfirmed how common that is.

8. Screenshot references: files-note-list-light.png and narrow-1024x700-today-light.png both exist in .scratch/design-review/screens/. MANIFEST.md has no P117 or nl-rows-sections entry (grep found none), so the mapping of these images to P117 is by the review text only.
