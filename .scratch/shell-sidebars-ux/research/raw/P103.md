## Prototype

Source: `.scratch/design-review/prototypes/shell-tabs-navigation.html`, section `#P103` (lines 502-510), JS at lines 1516-1575.

Layout:
- Two mock macOS menu bars in a 760px window. "Before" has `KokoBrain`, `Edit`, `Window` (height 240px). "After" has `KokoBrain`, `File` (marked as new), `Edit`, `Window` (height 270px). File is inserted after KokoBrain.
- Before caption: "Open the menus: there is no File menu and nothing about vaults."
- After caption: "The vault stays open while you switch: the app asks to close the current one first."

Copy and items (JS lines 1518-1523):
- KokoBrain: About KokoBrain, Settings... (Cmd+,), Services (disabled), Hide KokoBrain, Hide Others, Show All, Quit KokoBrain (Cmd+Q).
- File (after only): "Open Vault..." (opens a toast "Opens the native folder picker") and "Open Recent" (submenu).
- Open Recent submenu hard-coded to three vaults: `personal` (`/Users/me/Notes/personal`, shown with a check mark as current), `second-brain`, `archive-2024`.
- Edit: Undo, Redo, Cut, Copy, Paste, Select All. Window: Minimize, Zoom, Enter Full Screen.

Interactions:
- Clicking a menu opens a dropdown; hovering another menu bar item while one is open switches the dropdown (`bar.onmouseover`, line 1557).
- Clicking a recent vault: `personal` gives toast "personal is already open"; the other two give toast "Closing the current vault, opening <name>". No real switch, no confirm dialog.
- Palette (`pal()`, lines 1561-1574): query "switch" with items "Switch vault" (Vault), "Open vault..." (Vault), "Open Settings" (Settings, Cmd+,). Choosing "Switch vault" replaces the list with the three recents, `personal` marked "Current", title "Select a vault...". Choosing a recent gives the same toast as the menu, no real switch.

States: before/after menus; open/closed dropdown; hovered submenu; current-vault check mark; disabled Services item. No loading, error, or confirm states.

Discrepancy to note: the After caption says "the app asks to close the current one first". The current `switchVault` does not ask to close. It saves dirty tabs, drains writes, then opens, and asks only when a save failed (see Current code, vault.service.ts:22-27). The prototype does not show the real flow.

## Verdict

still real: **yes**. Confirmed at HEAD: only three top-level menus (lib.rs:212-247, set once at lib.rs:284-286); no palette command to switch or open a vault (commands.ts has none); vault UI only on the picker page, which AppShell.svelte:184 hides while a vault is open; `vaultStore.close()` has no non-test caller. Caveat for the ticket: the switch service path already exists (`switchVault`, vault.service.ts:22-27, used by deep links), so the work is entry points and a dynamic Open Recent source, not new switching logic. The prototype's "asks to close the current one first" copy does not match the current flow (which saves tabs and prompts only on a failed save).
