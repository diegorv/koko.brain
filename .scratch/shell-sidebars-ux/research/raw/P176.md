# P176 raw evidence: status bar height and save indicator

Cluster: sh-empty-zoom-status. Repo HEAD at research time: ab143a411 (main). Read-only research; no source, test or git state changed.

Scope note: the cluster name also mentions "empty editor dead end" and "zoom feedback and persistence". The P176 block itself covers only the status bar. Zoom is a different proposal (P99, zoom chip, present in the prototype's second section); it is not evaluated here.

## Review block

Copied verbatim from `.scratch/design-review/review.md:779-785`:

```
#### P176. The status bar is tall for passive text, and the save indicator pulses and shifts
- **Problem:** The bar is 32 px tall for 12 px text, and "Modified" pulses and changes width on every autosave.
- **Evidence:** app.css:212; SaveStatus.svelte:14-23; StatusBar.svelte:9.
- **Proposal:** Lower `--status-bar-height` to about 24 px, remove the pulse, and give the save slot a fixed min-width.
- **Impact:** More space and a calmer writing surface. **Effort:** S
- **Validation:** revise. Clickable items are left for later.
```

3. Save indicator, `src/lib/core/status-bar/SaveStatus.svelte:7-11` and `:14-23`:
   ```
   let status = $derived.by(() => {
   	const tab = editorStore.activeTab;
   	if (!tab || isVirtualTab(tab)) return null;
   	return isTabDirty(tab) ? 'modified' : 'saved';
   });
   ```
   ```
   {#if status === 'modified'}
   	<span class="inline-flex items-center gap-1 text-muted-foreground">
   		<Circle class="size-3 fill-current animate-pulse" />
   		Modified
   	</span>
   {:else if status === 'saved'}
   	<span class="inline-flex items-center gap-1">
   		<CircleCheck class="size-3" />
   		Saved
   	</span>
   {/if}
   ```
   Claims: `animate-pulse` on line 16 holds (the pulse). No `min-width` or fixed-width slot exists; the span has `inline-flex items-center gap-1` only, so the width follows the text. The `animate-pulse` keyframes are Tailwind defaults; a project override was not checked (unconfirmed). Status is null for virtual tabs, in which case nothing renders (the slot disappears).

4. Dirty definition, `src/lib/core/editor/editor.logic.ts:45-47`:
   ```
   export function isTabDirty(tab: Pick<EditorTab, 'content' | 'savedContent'>): boolean {
   	return tab.content !== tab.savedContent;
   }
   ```
   `isVirtualTab` is at `editor.logic.ts:18`.

5. Autosave timing, `src/lib/core/editor/editor.service.ts:276-279`:
   ```
   const debouncedSave = debounce(saveDirtyTabs, 2000, { maxWait: 10_000 });
   ...
   const debouncedSaveFrontmatter = debounce(saveDirtyTabs, 500);
   ```
   So "Modified" appears on the first keystroke (content diverges from savedContent) and flips to "Saved" only after the debounced save: about 2 s after the last edit, or at most 10 s under continuous typing. The claim "pulses and changes width on every autosave" is imprecise: the state changes once per dirty episode, not on each autosave tick. The core claim (pulse plus width change during the Saved/Modified flip) holds. Frontmatter edits use the 500 ms debounce.

6. Right group composition, `src/lib/app/AppShell.svelte:302-312`:
   ```
   <StatusBar>
   	{#snippet left()}
   		<SearchStatus />
   		<SemanticIndexStatus />

   	{#snippet right()}
   		<TodoistSyncStatus />

   ```
   `WordCount` renders only for markdown tabs (`src/lib/plugins/word-count/WordCount.svelte:32`, `{#if isMarkdown}`), so the items to the right of the save slot also change with the tab type. The shift of the right group therefore comes from the save text width and from which items render. The shift is structurally real; the pixel amount is unconfirmed (not measured).

## Verdict

still_real: yes. The height token is 2rem (app.css:212, 32 px at the default root size), the pulse is `animate-pulse` (SaveStatus.svelte:16), and the save span has no fixed width (SaveStatus.svelte:15-22). Detail to correct in the ticket: the Modified state appears from the first edit until the debounced save (2 s quiet, 10 s max wait, editor.service.ts:276), not "on every autosave". Unconfirmed: exact px of the width shift and whether Tailwind overrides exist in this project.
