```
#### P37. The keyboard can open a lens but not enter it; rail items have no shortcuts
- **Problem:** After "Go to X", focus stays where it was, and "+ New here" has no command.
- **Evidence:** rail-navigation.ts:14-24; global-keybindings.ts:133-141, 181; commands.ts; ADR-0033 (Cmd+1 and Cmd+2 assigned).
- **Proposal:** Selecting a lens moves focus to its active or first row. Add a "New note here" command. Owner decisions: direct keys for rail items (Ctrl+1..9 or Cmd+Opt+1..9), merging the three panel bindings, and an optional F6 focus cycle.

- **Validation:** revise. Cmd+1..9 would reverse ADR-0033.
```

## Prototype

Source: `.scratch/design-review/prototypes/shell-tabs-navigation.html`, section `#P37` at line 468-480 (markup), script block at lines 1340-1413.

Layout and copy:
- Heading: "The keyboard can open a lens but not enter it; rail items have no shortcuts". Badge "moderate". Problem text: "After "Go to Inbox" focus stays in the editor, "New here" has no command, and rail items have no direct keys."
- A row of palette-command buttons: "Go to Inbox", "Go to Today", "New note here", "Reset".
- Two side-by-side mock windows, each about 290px high, labelled "Before (recreation)" and "After (focus lands on the first row; hover then press Up, Down, Enter)".
- Each mock has: a 130px rail with four items (Inbox, Today, Types, Files); a 170px note list column with a header (lens name and count, plus a round "+" button with aria-label "New note here" in the After mock only); an editor pane showing a heading "# <current note>" and two paragraphs. Under each mock: "Focus now: <chip>".
- Data: Inbox (4 captures and "Meeting scribbles"), Today (dated note, "1-1 with Ana", "Dashboard", "Design review"), Types, Files.

Behaviour, Before mock (`after = false`):
- Clicking a rail item (or "Go to X") sets the lens and the focus chip does not change; the toast reads "Go to <lens>: focus unchanged".
- No "+" button in the list header; the "New here" button is absent.
- ArrowUp and ArrowDown are not handled by the list; the toast reads "The arrow keys move the editor cursor, not the list".
- Rail items show no key hints.

Behaviour, After mock (`after = true`):
- "Go to <lens>" sets focus to `list`; the chip reads "first row of the list" and the first row gets a `kfocus` outline.
- ArrowDown and ArrowUp move the highlighted row; Enter opens that row in the editor and moves focus to the editor (chip "editor").
- Clicking a row opens it and sets focus to the editor in both mocks.
- Each rail item shows a key badge (for example "⌃1" or "⌘⌥1") when the key mode is not "None".
- The "+" button opens an inline input prefilled with "Untitled" and selected. Enter commits, adds the note at the top of the lens, makes it current, moves focus to the editor and toasts `Created "<name>" in <lens>`. Escape or blur cancels.
- Key mode segmented control (owner decision block): "Ctrl+1..9" (default, `aria-pressed=true`), "Cmd+Opt+1..9", "None". Its handler matches `Digit1` to `Digit4` only (`/^Digit[1-4]$/`), so the prototype wires four rail keys, not nine. Ctrl mode requires ctrlKey without metaKey or altKey; Opt mode requires metaKey and altKey.
- Reset button restores lens Today, focus editor, empty extra notes.

Prototype does not show: the palette itself (the buttons stand in for it), F6, any Cmd+1 or Cmd+2 behaviour, or the Calendar, Tags, Graph or Tasks entries (those are P36).
