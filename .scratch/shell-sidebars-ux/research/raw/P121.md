## Review block

```
#### P121. A narrow right sidebar truncates property names to one letter
- **Problem:** The key, the value and a reserved remove button squeeze each other.
- **Evidence:** PropertyField.svelte:108-164; PropertiesView.svelte:203 (spacer that aligns with the remove slot); AppShell.svelte:271; [narrow-1024x700-editor-light.png](screens/narrow-1024x700-editor-light.png).
```

## Verdict

still_real: yes. The key input is `truncate` with `flex-[2] min-w-0` (PropertyField.svelte:114), the value and key compete for the same row with an always-present `opacity-0` remove button in flow (PropertyField.svelte:157-164), and the type row keeps a 16 px spacer (PropertiesView.svelte:203). No container query exists for this row. The "one letter" severity at 166 px is from the review's screenshot, not re-measured in the app (unconfirmed for the exact threshold: 220 px in the proposal, 215 px in the prototype CSS, 234 px in the prototype copy).

Caveats for the ticket writer:
- Confirm the threshold in one place (the prototype's CSS, the proposal and the caption disagree).
- Confirm PaneForge size units before expressing the threshold as a percentage.
- No E2E covers a narrow sidebar; a Playwright check at a narrow viewport would be new coverage.
- Not checked: the Tauri window minimum width and the sidebar behaviour at other widths.
