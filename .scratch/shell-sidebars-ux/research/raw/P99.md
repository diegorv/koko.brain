## Prototype

Source: `.scratch/design-review/prototypes/shell-tabs-navigation.html`, section `#P99` at lines 527-535 (markup) and script IIFE at lines 1477-1507 (`/* P99: zoom chip */`). CSS for `.zoomchip` at line 275-279.

What it shows:
- Two side-by-side mock windows, "Before" and "After", each with a fake editor (tab "Roadmap.md", a heading, three lines of text) and a 24 px bottom bar with "37 notes indexed" and "Saved". The mock bar is inline in the window, not the real status bar.
- Controls: "Zoom in Cmd =", "Zoom out Cmd -", "Reset Cmd 0", "Relaunch the app", and a readout line `zoom N% | stored in settings: Before none, After N%`.
- Levels: `[0.5, 0.67, 0.75, 0.8, 0.9, 1.0, 1.1, 1.25, 1.5, 1.75, 2.0]`, start index 5 (100%). Same list as `ZOOM_LEVELS` in the code.
- Before: zoom applies to the content (`style.zoom`) with no chip. Relaunch sets the zoom back to 100% in the Before window, which matches "silent, resets on launch".
- After: a pill chip (`.zoomchip`, `aria-label="Reset zoom to 100%"`) with a zoom-in icon, the percentage, and a "click to reset" hint that shows on hover. It is absolutely positioned at `right: 12px; bottom: 36px`, so it floats just above the bottom bar. It appears on every keyboard change for 1500 ms, then fades. Clicking it calls `change(5)`, which resets to 100%.
- Persistence in the After window: the saved index is set on each change, and Relaunch restores `savedIdx`, so the zoom survives. The Before window ignores it.
- Keyboard handling in the prototype (`root._onKey`) accepts `=` and `+` for zoom in, `-` for out, `0` for reset, all with Meta or Ctrl. The real code also accepts Cmd+Shift+= (global-keybindings.ts:179).
- Gap: the prototype does not show a chip for the palette or the menu, and does not show a loading state for the first paint at startup.

## Verdict

still real: **yes**. Silent change: no UI is wired to `zoomIn`, `zoomOut` or `resetZoom` (`zoom.service.ts` has no subscriber, `global-keybindings.ts:177-181` discards the result). Not persisted: no zoom key in `AppSettings` or `DEFAULT_SETTINGS`, no zoom code in `src-tauri/src`, and no `setZoom` call at startup, so the webview comes back at its default after a relaunch. The claim that zoom resets on launch is supported by the absence of any restore path; the runtime behaviour of WKWebView was not run, so "resets on launch" is confirmed from code, not from a launch.

Not checked: the runtime behaviour of the native webview zoom across relaunch (no app run, no tests run); where the vault picker renders and whether it needs the zoom too; whether the E2E harness maps the Tauri webview module to `e2e/mocks/tauri-webview-window.ts`.
