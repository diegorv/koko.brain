### Proposal wording vs code

- "Make the breadcrumb clickable: the type opens the Types lens, a folder opens the Files lens, and the name drops '.md'." The type and folder targets exist as lens picks (see above). "The name drops .md": the bar takes `basename(path)` (logic.ts:35) and the test `src/tests/lib/features/note-action-bar/note-action-bar.logic.test.ts:22` and `NoteActionBar.test.ts:169` assert "Launch plan.md". Dropping ".md" changes the value the E2E spec asserts (`e2e/specs/note-action-bar.spec.ts:36` expects "Welcome.md"), so that spec changes too.
- Open question for the type segment: a note with no `_type` shows "Note" (logic.ts:33). The Types lens for "Note" does not exist as a type unless the user defined one. The matching lens for untyped notes is `UNTYPED_LENS` (lens.logic.ts:100), and `parseTypesPick` accepts it (line 528). Whether the "Note" segment should open the Untyped lens is unconfirmed as a product decision; the prototype always opens `{kind:'types', value: 'Note'}` for type "Note" (prototype line 1081 onward, NOTES welcome has type "Note").
- "Reveal in note list" in the overflow menu: the More menu is built from `fold.folded` (NoteActionBar.svelte:192-198). Adding an item means a new `FoldableAction` value or a separate item. The fold tests (`note-action-bar.logic.test.ts:67-102`) pin the fold order and widths; any new foldable changes those expectations.
- Palette: the palette command list is in `src/lib/app/commands.ts`. A new command must follow its existing shape (id, label, category, shortcut, action).

## Verdict

Still real: yes.
