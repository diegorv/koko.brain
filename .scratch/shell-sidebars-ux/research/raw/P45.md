### 2. The type dropdown writes through an update that does not add a missing key - CONFIRMED (new finding, relevant to the proposal)

- PropertiesView.svelte:121-127 `handleUpdate(key, value, type?)` returns `updateProperty(key, value, type)`.
- src/lib/features/properties/properties.service.ts:124-133 `updateProperty` resolves the canonical twin, then calls `updatePropertyValue(propertiesStore.properties, targetKey, value, type)`.
- src/lib/core/frontmatter/properties.logic.ts:719-727 `updatePropertyValue` is a `properties.map` that only changes an existing key (`if (p.key !== key) return p;`). It never appends.
- Consequence: if `_type` is absent, `updateProperty` produces an unchanged list. A "Set type" action built on `handleUpdate('_type', ...)` would silently do nothing for untyped notes. The proposal needs the upsert path: properties.service.ts:136-149 `upsertProperty(key, value, type?)` already appends when missing (uses `updatePropertyValue` only when a twin exists, otherwise appends `{ key, value, type: t }`). Actual append branch is in `upsertProperty` lines 136-149; verified by reading lines 136-149 before the file's `commitChanges` call.
- Callers of `upsertProperty` in the properties feature: PropertiesView.svelte:74 (relationship removal path). Callers of `updateProperty`: PropertiesView.svelte:76, 87, 126.

### 3. addProperty hard-codes text - HOLDS

- src/lib/core/frontmatter/properties.logic.ts:699-705 doc comment "Adds a new empty text property with the given key." Line 703 `export function addProperty(properties: Property[], key: string): Property[] {`, line 704 `return [...properties, { key, value: '', type: 'text' }];`. Evidence range 703-705 is accurate.
- Also `addProperty` callers: src/lib/features/properties/properties.service.ts:192 (`addNewProperty`) and src/lib/features/file-icons/frontmatter-icon.service.ts:23 (uses `addProperty` then `updatePropertyValue(..., 'text')`).
- Second text-only path: properties.logic.ts:664 `setPropertyByBindTarget` appends with `typed ?? 'text'`, inferring number/boolean from the value. Not the panel's add path, but the only other place a non-text type is set on creation.
- Service entry: properties.service.ts:184-196 `addNewProperty(key)`: trims, returns false on empty key or canonical duplicate, then `commitChanges(addProperty(...))`. Return value is `boolean` only; no reason is returned (this is the silent-refusal part, P44).

No type input exists. Add form markup at lines 221-237 has one `<input placeholder="Property name...">` and no type control.
- The `updateProperty` type parameter is wired to nothing in the UI (only `handleUpdate` passes it through; PropertyField never passes a third argument, see below).
