## Review block

```
#### P46. The relationship picker cannot be used from the keyboard
- **Problem:** Only Escape works. Rows select on mousedown, there are no arrow keys or Enter, and `trapFocus` is false.
```

## Prototype

Source: `.scratch/design-review/prototypes/right-sidebar.html`, article `#P46` at lines 461-463 (header "The relationship picker works from the keyboard and lists recents first", badges Moderate / Effort S, mount point `#d46` at line 464). Script section `/* ---------- P46 (custom) ---------- */` at lines 1181-1245, mounted at line 1223.

What it shows:

- Two side-by-side popovers in a `.cmp` compare block, captions from `cell(...)` calls:
  - **Before** ("recreation of the current popover"): a "Belongs to" label with a "+" button (`aria-label="Add link"`), a `Search notes...` input, and a list of the first 20 notes sorted alphabetically (`alpha.slice(0,20)`), with no active row. Caption: "First 20 files alphabetically, no active row. Arrow keys and Enter do nothing; only a mouse press picks."
  - **After**: same header. With an empty query the list is split into a "Recent" group (three hardcoded notes: Roadmap, Q4 OKRs, 2026-11-09 Design sync) and an "All notes" group (every other note, not capped). Typing filters by a prefix/substring/subsequence score. The input carries `role="combobox"`, `aria-expanded`, `aria-controls="pk-list-a"`, `aria-activedescendant="pk-a-{act}"`, `aria-autocomplete="list"`. Rows are `role="option"` with `aria-selected`. Caption: "Type to filter, Up and Down to move, Enter to link, Esc to close. Recent files come first for an empty query."
- Keyboard model in `pkKey` (prototype lines 1218-1222 in the handler block): Escape closes; ArrowDown/ArrowUp move `act` clamped to the flat list; Enter calls `pick` on the active row; any other key is not prevented. Mouse: rows pick on `mousedown` (`pkPick` with `preventDefault`). Hover sets the active row (`pkHover`).
- A footer on the After side only: "Up Down move", "Enter link", "Esc close" (`.pk-foot`). The footer is not named in the review proposal.
- After a pick, a status line `Linked {name} under Belongs to` (`.pk-res`, role=status) is shown and the popover closes. The proposal does not mention this feedback line.
- Scroll-into-view of the active row inside `#pk-list-a` (the `mk` post-render callback, prototype lines 1239-1244).

Gaps between prototype and proposal text, for the ticket writer:
- The prototype's "All notes" group is not capped at 20; the real component caps the combined list at 20 (see Current code).
- The prototype's Recent list is hardcoded. The real source of recents is `quickSwitcherStore.recentPaths` (see below).
- The prototype adds a key-hint footer and an inline "Linked ..." status message; neither is in the review proposal.

### file-entries.logic.ts (`src/lib/core/filesystem/file-entries.logic.ts`)

The review Evidence says `file-entries.logic.ts:36-46`. That range is wrong at HEAD: lines 36-42 are the `entryFolder` function body and lines 44-46 are the start of the `splitRecentFiles` JSDoc. The code that matters is:

- Lines 67-75, `filterAndRank`:
  ```
  export function filterAndRank(query, files, recentPaths): FileEntry[] {
  	if (query.length === 0) {
  		const { recent, rest } = splitRecentFiles(files, recentPaths);
  		return [...recent, ...rest];
  	}
  ```
  With `recentPaths = []`, the empty query returns every file sorted by `nameWithoutExt` via `localeCompare` (`splitRecentFiles` lines 60-63), capped at `MAX_RESULTS = 100` (line 30, lines 59 and 63). The component then slices to 20. So "an empty query already lists 20 files, alphabetically" holds (the component cap is the 20; the helper cap is 100).
- Lines 51-65, `splitRecentFiles(files, recentPaths)`: returns `{ recent, rest }`. Already exists at HEAD (added by finders-ux 07, resolved). Quick Switcher uses it (see below). The RelationshipSearch can call it without new logic.
- Lines 79-104: fuzzy ranking with a recency bonus. Uses `fuzzyMatch` from `#lib/utils/fuzzy-match.js`.
