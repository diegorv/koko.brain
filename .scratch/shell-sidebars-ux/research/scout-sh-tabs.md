## P34. Tab strip: overflow cue, widths, wheel, list-all, reorder, tooltips

**Still real: yes (all parts).**

Current behaviour (all re-read at HEAD):
- Overflow: scroller is a plain `overflow-x-auto` (`:46`), no fade, no count, no list control, no wheel mapping (grep `wheel` in `core/markdown-editor/` and `EditorView.svelte`: none). No code hides the scrollbar, so the "invisible at rest" claim is the macOS overlay default: plausible, unconfirmed on screen.
- Width: tab is `shrink-0` (`:53`) and the title `max-w-40` (`:88`, Tailwind 4 `10rem` = 160 px). Tabs never shrink, so 6 tabs overflow a ~1000 px strip.
- Reorder: no `draggable`/`ondrag*` in the file; no store move API.
- Tooltips: no `title=` and no Tooltip in the file. The dirty dot (`:65`) has no `title`. Pinned tabs render icon + Pin only (name is behind `{#if !pinned}` at `:87`), so a pinned `role="tab"` has NO accessible name at all (not in the review; the ticket should add `aria-label={tab.name}` on the tab).
- Active reveal already works (`:38-42`), covered by `EditorTabs.test.ts` and `e2e/specs/tabs.spec.ts:42-75`.

What the prototype wants:
- `.tab { flex: 0 1 220px; min-width: 100px }`, pinned `flex: 0 0 auto`, title `flex:1; min-width:0; ellipsis`. Readout "N tabs, tab width W px (max 220, min 100)".
- Edge fades: 34 px, left shown when `scrollLeft > 2`, right when more content lies beyond (`scrollLeft + clientWidth < scrollWidth - 2`), only while overflowing; `pointer-events:none`.
- Chevron button "List all tabs" (`aria-label`, `aria-haspopup="menu"`, `aria-expanded`) with a count badge of tabs whose rect lies outside the visible scroller (4 px slack). The menu contents are NOT implemented in the prototype's button handler for P34 beyond a popover listing `N open tabs` header, one row per tab: dirty-dot slot, kind icon, name, pin mark, active row marked; click activates and closes. (The raw scout said unspecified; the `listbtn.onclick` at ~line 940-950 does render this list.)
- Wheel: vertical delta becomes `scrollLeft`, `preventDefault`, only when the strip overflows and `|deltaY| > |deltaX|`.
- Drag: `draggable="true"`; `dragover` computes an insertion index from tab midpoints, clamps pinned to `[0, pinCount]` and unpinned to `[pinCount, n]`, draws a `.dropmark` and autoscrolls within 40 px of the edges (14 px per event); `drop` moves (`to--` when `to > from`); tooltip hidden while dragging.
- Tooltip: after 400 ms, `<b>name</b><span>path</span>` plus `Unsaved changes` and `Pinned` lines; path is vault-relative in the mock.
- Reveal padding 30 px so the active tab is not under a fade.
- The prototype also moves the close button to an absolute overlay at `right: 4px` so the title uses the full width. That is NOT in the review's proposal text; keep the inline close button unless the owner wants the overlay (it changes the hover target and the `Close <name>` button's layout only).

Design points a ticket must settle:
1. Strip structure. The list button must sit OUTSIDE the scroller and left of the toggle's 40 px reserve, so the single `div.editor-tabs-bar` becomes a wrapper (`bg-tab-bar h-10`, divider box-shadow, `data-tauri-drag-region`, reserve padding, relative for the fades) around the scroller plus the button. Keep the class `editor-tabs-bar` on the SCROLLER: `e2e/specs/tabs.spec.ts:42-75` reads its `scrollWidth/clientWidth`, and several other specs select `.editor-tabs-bar` or `[role="tab"]` (collection-block, note-action-bar, keyboard-shortcuts, rail-styles, editor-state-persistence). The inset divider currently lives on `.editor-tabs-bar` (`:119-121`) and must move to the wrapper or it stops under the reserve.
2. Reveal vs fades: with a 34 px fade, `scrollIntoView({inline:'nearest'})` leaves the active tab under it. Use `scroll-padding-inline` (about 30 px) on the scroller instead of changing the call (`EditorTabs.test.ts` asserts the exact `{block:'nearest', inline:'nearest'}` arguments).
3. Flex widths: `flex-[0_1_220px] min-w-[100px]` on non-pinned tabs, `shrink-0` on pinned; title needs `min-w-0`; drop `max-w-40`. Re-run the 640 px overflow E2E: 100 px min means 6 tabs plus the list button still overflow at that width (the spec asserts it does).
4. Hidden-count and fade state: pure helpers (e.g. `edgeFades(scrollLeft, clientWidth, scrollWidth)` and `countHiddenTabs(scrollerRect, tabRects)`) in a new `src/lib/core/markdown-editor/editor-tabs.logic.ts`, fed from `scroll` and a `ResizeObserver` on the scroller. jsdom has no layout, so the logic is unit-tested and the component test stubs `getBoundingClientRect`/`scrollWidth` on the elements (a DOM stub, allowed; no store or logic mocks).
5. List menu: shadcn `DropdownMenu` (not the context menu). `src/tests/lib/menu-item-anatomy.test.ts` scans every `.svelte` menu item (no horizontal margins, no `text-xs`, shortcut hints via `formatShortcut`), so build the rows with that test in mind. Dirty dot only when `isTabDirty(tab) && !isVirtualTab(tab)` (same rule as `:64`).
6. Reorder model: pure `moveTab(tabs, activeIndex, from, to)` next to `reorderTabsAfterPinChange` in `editor.logic.ts` (clamp into the pinned or unpinned group using `getPinnedBoundary`, follow the active tab by PATH like `reorderTabsAfterPinChange` does, return `{tabs, activeIndex}`), plus `editorStore.moveTab(from, to)` that reassigns `tabs` and `activeIndex` the way `togglePin` does. The `{#each editorStore.tabs as tab, index}` (`:47`) is unkeyed; either leave it (a reorder rerenders by index, but per-index `ContextMenu.Root`/tooltip state then belongs to a different tab) or key by `tab.path` (paths are unique per `openFileInEditor`, but `addTab` itself does not dedupe and a duplicate key throws in Svelte 5 dev). Recommended: key by `tab.path` and add a store test that a duplicate path is not produced by the paths that call `addTab` (`path-change.service.ts:~176` restores closed tabs after a failed delete). Decide in the ticket with a test, not by guess.
7. Tooltip tech: bits-ui `Tooltip.Root` (DailyNoteButton precedent) with a local `Tooltip.Provider delayDuration={400}` wrapping the strip, composed with `ContextMenu.Trigger` via the `child` snippet; or the native `title`. Native `title` is far simpler and testable by attribute but cannot show the "Unsaved changes" and "Pinned" lines styled and its delay is not controllable. Recommended: pure `tabTooltip(tab, vaultPath)` returning `{ name, path, notes[] }` (vault-relative via `relativePath` in `utils/path.ts:98`, virtual tabs show the view name only) so the content is unit-tested, and the Tooltip rendering asserted in one component test (bits-ui tooltips also open on focus; if the portal does not render under jsdom, assert the helper plus an E2E hover check). Hide the tooltip on `dragstart`.
8. Pinned and dirty accessibility: `aria-label` on the tab (the full name) so pinned tabs are announced; `title`/tooltip text for the dirty dot ("Unsaved changes").
9. Wheel handler must be a non-passive listener (`addEventListener('wheel', fn, { passive: false })`; Svelte's `onwheel` attribute is passive), attached in an effect on the scroller, and only `preventDefault` when the strip overflows and `|deltaY| > |deltaX|` so a trackpad's horizontal swipe is untouched.
10. Keyboard reorder: the prototype is mouse-only. Not proposed; record as a known gap (owner question 3).

Tests and seams:
- `src/tests/lib/core/markdown-editor/EditorTabs.test.ts` (jsdom, real `editorStore`, `invoke` mocked; describes at `:21` active scroll, `:114` tab menu which asserts the context menu entries are exactly `Pin tab`/`Close tab`, so do not add menu items; `:161` icons). New cases: list menu rows and activation, fade/count via stubbed geometry, wheel mapping (`WheelEvent` dispatch, `scrollLeft` change, `defaultPrevented`), pinned tab has `aria-label`, `dragstart`/`dragover`/`drop` reorder (jsdom `DragEvent` is limited: dispatch plain `Event` with a stub `dataTransfer` and `clientX`, the way a drop handler reads them).
- New `src/tests/lib/core/markdown-editor/editor-tabs.logic.test.ts` and extend `src/tests/lib/core/editor/editor.logic.test.ts` (`moveTab`: forward, backward, to the same slot, pinned clamp both ways, active follows) and `editor.store.test.ts` (`moveTab` keeps `activeIndex` on the same tab; invalid indices are a no-op).
- E2E `e2e/specs/tabs.spec.ts`: re-run the overflow test (`:42-75`, sub-pixel tolerance already handled by Issue 254) and add a real-mouse drag reorder (precedent `e2e/specs/event-calendar-day-drag.spec.ts:47` `dragTo`). `tab-pinning.spec.ts` and `sidebars.spec.ts:70` (`button[title="Hide right sidebar"]`) must stay green.

## P98. Right sidebar toggle covers the strip, no pressed state, no focus ring

**Still real: yes (the covering and `aria-pressed` hold; "no focus ring" is partly true; "not accessible" is overstated).**

Current behaviour:
- `AppShell.svelte:190-196`: absolute (`right-2 top-[7px] z-20`), 24 px, `title` only (no `aria-label`, no `aria-pressed`, no `focus-visible` class). The accessible name comes from `title`, and Cmd+B and the palette are keyboard paths, so the review's own "revise" note is right.
- The strip (`EditorTabs.svelte:46`) has `px-1` and nothing reserved, and the editor pane runs to the window edge when the sidebar is hidden, which is the DEFAULT (`settings.store.svelte.ts:65` `rightSidebarVisible: false`). So with enough tabs, or any single tab wide enough, the toggle sits over the last tab and its (hover-only) close button. Geometry-proven, not run in the app; the cited screenshot shows the sidebar open and is the wrong evidence (the ticket should cite a new hidden-sidebar capture or none).
- When the sidebar is shown the toggle sits in the right pane's empty 40 px header band (`:276`), covering nothing.
- No global focus-visible rule exists in `src/app.css` (grep "focus": no hits). The repo pattern is per component (`focus-visible:ring-ring/50 focus-visible:ring-[3px] outline-none` in `components/ui/button/button.svelte:7`). Review P23 (a 100% `--focus-ring` token and utility, another batch) will replace those classes; use the current Button classes now and let P23's sweep rewrite them.

What the prototype wants: strip gets `padding-right: 40px` (8 px inset + 24 px toggle + 8 px gap) while the sidebar is hidden; toggle gets `aria-label`, `aria-pressed`, a pressed fill (`--accent`) and `outline: 2px solid var(--ring); outline-offset: 1px` on focus-visible; a custom tooltip "Show right sidebar" + "Cmd+B" (not in P98's text).

Design points:
1. Where the reserve lives. Padding on the scroller (`overflow-x-auto`) may or may not add trailing scroll space in WKWebView (unconfirmed, the raw scout flagged it). Put the reserve on the non-scrolling wrapper from P34 point 1 (`pr-10`), which is also where the list-all button must sit left of the toggle. Hence P98 and P34's overflow work are one ticket.
2. The reserve condition is exactly "toggle rendered and sidebar not shown": `!hidesRightSidebar(activeTabPath) && !rightSidebarVisible`, i.e. toggle present and `!isRightSidebarShown(...)`. Add a pure `rightSidebarToggleCoversTabs(visible, activeTabPath)` in `layout.logic.ts` (test in `layout.logic.test.ts`), read from `EditorTabs.svelte` via `settingsStore.layout.rightSidebarVisible` and `editorStore.activeTabPath` (both already importable from `core/`, no layer violation), instead of a prop through `EditorView`.
3. Accessible name and state: a toggle with `aria-pressed` should keep a STABLE name. Recommended: `aria-label="Right sidebar"`, `aria-pressed={rightSidebarVisible}`, keep the dynamic `title` ("Hide/Show right sidebar") because `AppShell.test.ts:368-385` asserts the titles exactly and `e2e/specs/sidebars.spec.ts:70` clicks `button[title="Hide right sidebar"]`. The existing test filters by `${title} ${aria-label}` matching `/right sidebar/i`, so it still finds one button.
4. The toggle can still cover a tab if the tab strip is narrower than the reserve; the reserve makes that impossible for the scroller, so no further overlap logic is needed.
5. Claude panel (`claude-code-integration` issue 03, `layout.claudeVisible`) may change what the toggle controls; it is `ready-for-agent` in an active folder, so a dependency note only: do not rename the toggle's meaning here.

Tests and seams:
- `src/tests/lib/app/AppShell.test.ts` `describe('AppShell with a Markdown note open')` (`:~367-395`, real stores): add `aria-pressed` follows `rightSidebarVisible`, stable `aria-label`, focus-visible classes present (jsdom does not compute Tailwind, so assert the class string the way `pane-toolbar.test.ts` does), and with the sidebar hidden the tab wrapper has the reserve class (mount `AppShell` so both are present) while with it shown or on a `hidesRightSidebar` tab it has not.
- `EditorTabs.test.ts`: reserve class on the wrapper driven by the real `settingsStore` and `editorStore`.
- `layout.logic.test.ts` for the pure helper.
- E2E `sidebars.spec.ts`: with the sidebar hidden and several tabs open, assert the toggle's bounding box does not intersect the last tab's close button (real layout, the only layer that proves the reserve).
