## P33. Note-list header loses "+" at narrow widths

**Still real: yes, with three corrections to the review's wording.**

Current behaviour:
- Control count: the review says "up to eight". At HEAD the header holds title, count and at most FIVE controls. List lenses (`listToolbarReady`): Sort (`:709`), Search (`:718-733`), Properties (`:734`), Archive only for Untyped or a type lens (`offersArchivedFilter`, `:138`), the header action (`:778-789`, Today when an opener is registered, or the day lens), then "+" (`:790-801`). View lens: Sort, Search, Properties, Filter (`:754-776`), "+". Archive and Filter are mutually exclusive; the header action and Filter never co-occur. The sort popover at `:739-753` has no trigger of its own.
- The title keeps `min-w-16` (64 px, `:705`); the count hides below 12 rem (`:707`); the sort label hides below 16.5 rem (`RailSortMenu.svelte:119`). Everything else is `shrink-0` buttons of 22 px (p-1 + size-3.5) with `gap-1`. Nothing wraps, and the pane clips the overflow, so the right-most control (the "+") goes first.
- Arithmetic from the classes, NOT measured: pad 12+12 px, title 64, five buttons 110, six gaps 24, count about 14 gives roughly 214 px of content, so a type lens, Untyped, Today or a day list (five controls) loses "+" below about 215 px, and a first pane has a larger left pad (`--rail-header-pad`, `AppShell.svelte:187`) so it loses it earlier. The existing e2e `e2e/specs/rail-list-toolbar.spec.ts:240-280` (narrow list about 220 px, asserts `[data-note-list-new]` visible and no header child overflows) runs on the Inbox, which has four controls, so it does not cover the five-control lenses.
- The title text in the review ("New note and Daily note") does not match the code: the "+" is labelled "New here" (`aria-label`, `:795`; `title="Create a note in this list"`, `:794`). "Daily note" is a header action only on Today (when `eventCalendarDailyNoteStore.available`, `:613-631`) and on the day lens (`calendar-rail.service.ts:37-44`).
- Glyph ambiguity is real: Sort has `title`/`aria-label` (`RailSortMenu.svelte:109-110`), Properties has "Show in note list" (`RailPropertiesPicker.svelte:109-110`), Archive's accessible name is the current mode (`RailArchivedMenu.svelte:24,37-38`). Native `title` tooltips only.

1. **Panel keyboard models collide when merged.** `RailSortMenu` is a menu-radio roving list with Left/Right setting direction and `onOpenAutoFocus` focusing the active row (`RailSortMenu.svelte:90-110,123+`); `RailPropertiesPicker` has a search input, drag reorder and ArrowUp/Down row moves with its own auto-focus (`:115-125`); Archive is three `aria-pressed` buttons. 3. **Which sections exist per lens.** Archive only when `offersArchivedFilter`; Sort and Properties for every ready list; `onMultipleSort` only for a view. The popover is built from the same conditions.
4. **Narrow mechanism.** CSS-only duplicates (Tasks precedent: `TasksView.svelte:971-1050`, `@max-[560px]:` with a folded `Filters (n)` and an e2e because jsdom has no layout, resolved Issue 239) versus a measured width in script. A width in script is unit-testable (the toolbar tests already stub `ResizeObserver`, `RailNoteList.toolbar.test.ts:12-32`, reporting width 240) but the header's `@container` root is what the existing classes key on. Pick one; if CSS-only, the e2e must cover 150, 225 and 320 px and all three five-control lenses.
5. **Threshold and what moves.** Prototype: below about 220 px, Display and the daily-note action move into one overflow menu; Search, Filter and "+" stay. Below the prototype's 150 px floor nothing fits; the pane's `minSize={3}` allows that. State it as out of scope or raise the minimum (owner question 3).
6. **Reusing registry-provided actions.** The daily-note action comes from the registry (`headerAction`, a `RailHeaderAction` with `icon`, `run`); the overflow menu must render it generically, never import the plugin (layer rule, comment at `RailNoteList.svelte:610-612`).

Design points a ticket must settle:

Recommended default: count rows as the panel shows them (one function, no new predicate) and let 013 define drafts; a helper that skips unfinished rows (`isUnaryOperator` exists in `filter.logic.ts:203`) is possible but couples to 013.
2. **One counting function.** `CollectionView.svelte:222-225` duplicates `countActiveFilters`. Put the helper in `collection/toolbar/filter.logic.ts` (type-definitions already imports collection types; `collection` importing `type-definitions` would invert the direction) and have the other call site reuse it. Check `feature-cycle.test.ts` before moving.
3. **Hidden-column count.** `visibleColumns = localColumns ?? allColumns` (`CollectionView.svelte:674`), so with no saved order every column counts as visible even when the table infers fewer (open-itens 139, ready-for-agent, blocked by 138 and 069). 4. **Accessible name carries the state.** A badge is decoration unless the name includes it: "Filter, 2 active", "Sort, 1 column", "Columns, 3 hidden", "Archive: Only archived". Because these buttons currently have no name at all in `CollectionView`, this also decides the label recipe that open-itens 140 wants. Recommended: this ticket owns the four toolbar labels, 140 keeps the keyboard and calendar parts.
5. **Shared mark.** One small component (count pill and dot) used by the rail header and `CollectionView`. Home: `src/lib/features/collection/toolbar/` (rail-shell already imports `FilterPanel` from there). If 204's Badge lands first, use it; do not block on it.
