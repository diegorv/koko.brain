## Where the scout is wrong or incomplete

1. **The Rust pure function, as written, breaks the events parity test.** Scout T2 criterion 1 has the pure function "map `"settings"` to `menu:settings`", that is, return an event name for `on_menu_event` to emit. `events-parity.test.ts` "names a registry const at every emit site" (`:125-127`, with `emitOffenders` at `:94-109`) flags any emit whose first argument is not a const declared in `events.rs`. `app.emit(event, ())` with a local `event` is an offender, so that design fails `pnpm vitest run`. The pure function must return an enum (`MenuAction::OpenSettings | OpenVault | Quit | None`), and each `match` arm in `on_menu_event` emits its own const (`MENU_SETTINGS_EVENT`, `MENU_OPEN_VAULT_EVENT`).
2. **Open-itens 090 does not edit `build_menu` or `on_menu_event`.** Its "What to build" (`090:33-41`) adds `applicationShouldTerminate:` to the app delegate and answers from `confirm_exit`. It never touches the menu items or the menu handler. The overlap is the file `lib.rs`, not the functions. It is not a dependency and needs no merge-order note.
3. **Splitting P103 into T1 (palette) and T2 (native menu) splits one change across two tickets that edit the same lines.** Both list `help/documentation/01-getting-started.md` and `20-keyboard-shortcuts.md`. The accelerator decision (owner question 1) spans both. The precedent for an accelerator declared in both places is Settings: `CmdOrCtrl+,` in `build_menu` and `settings:open` in `GLOBAL_KEYBINDINGS` (`global-keybindings.ts:154-158`), which also gives the palette its shortcut label through `shortcutFor`. So the Cmd+Shift+O binding belongs with the palette command, and the menu item reuses it. One ticket for the whole of P103.
4. **Scout T2 criterion 4 is vacuous.** "A test asserts no other binding in `global-keybindings.ts` uses the same combination" can see nothing if the accelerator lives only in Rust. With the binding mirrored in `GLOBAL_KEYBINDINGS` (point 3), the real failing test is `shortcutFor('vault:open')` returning `{ key: 'o', meta: true, shift: true }`. That test throws today. The existing "every shortcut the palette shows is bound by a registration" test (`global-keybindings.test.ts:761-772`) then covers the label. The fixed-count pin "registers all 25 fixed global keybindings" (`:142`) must change on purpose. The scout did not list it.
5. **Missed count pin.** `commands.test.ts:148-152` pins exactly 43 built-in commands (vault closed, no recents). Every new fixed command moves it, and the dynamic recent-vault commands must not appear in that state (`vaultStore._reset()` empties `recentVaults`). rs-links-toc T6 ("Go to heading") moves the same line. Its conflicts are textual, but each ticket must change the number on purpose.
6. **The listener test can hit the real switch path.** Scout T2 criterion 2 asserts only that a mocked `openVaultDialog` was called. That is a sole `toHaveBeenCalled`, which `docs/TESTING.md:100` forbids. `tauri-listeners.service.test.ts` already mocks `@tauri-apps/plugin-dialog` (`:42-44`, `ask` only) and `saveAllDirtyTabs` (`:57-59`). Add `open` to that mock, resolving `/vaults/b`, leave `vault.service` real, and assert `vaultStore.path === '/vaults/b'` after the event. A cancel (`open` resolves `null`) leaves the path unchanged.
7. **The File menu must not gain the predefined Close Window item.** Open-itens 023 (`:7,29`) records that the native menu has no Cmd+W item, so Cmd+W reaches `editor:close-tab` (`global-keybindings.ts:81-85`). A File submenu built with the usual `.close_window()` would take Cmd+W from Close Tab, the same trap as Cmd+O (`:69-73`). The ticket must list exactly one item.
8. **Recommendation flipped for Open Trash with no vault.** With no vault, `TrashSection.onMount` skips `loadTrash` (`TrashSection.svelte:17-21`), so the sheet says "Trash is empty", which is false for any vault on disk. Gating costs the same as not gating: `...(vaultStore.isOpen ? [openTrash] : [])`, the pattern of `eventCalendarStore.canUndo` (`commands.ts:254-265`). Recommended default: hide the command while no vault is open. This also keeps the 43 pin's "vault closed" state free of it.
9. **The help page to rewrite is "Switching Vaults", not "Recent Vaults".** `01-getting-started.md:146-152` is wrong today (point P103 above). `:42-48` only needs one sentence.
10. **Header menu vs the sticky heading of rs-properties-layout Ticket 1.** That ticket (`verdict-rs-properties-layout.md:46`) puts `sticky top-0 z-10 bg-*` on an `h2` that wraps the header button. A menu trigger placed inside that `h2` becomes part of the heading's accessible name ("Backlinks Backlinks menu"), and `BacklinksPanel.test.ts:169` style checks read `h2.textContent`. A trigger outside the `h2` is not sticky. The header-menu ticket must pick one: keep the trigger outside the `h2` in a sticky wrapper that holds both (and update Ticket 1's `h2`-is-sticky assertion), or leave the heading as is and position the trigger absolutely inside the sticky element with no text node. Recommended: a sticky wrapper `div`, `relative`, holding the `h2` and the trigger. The heading name stays exactly the title. Either way this ticket edits lines Ticket 1 writes, so it is strictly after Ticket 1.
11. **`claude-code-integration` 03 is not on main.** The owner's Claude MVP Issues deliver on `mvp-claude`, not on main (the rs-properties-layout verdict also notes this, `:34`). The all-hidden helper on main counts four flags. Adding `claudeVisible` is a merge-time edit on that branch, not a blocker here.
12. **Native Open Recent is dropped from this batch, not kept as a deferred ticket.** At most two other recents exist (`vault.logic.ts:13` `MAX_RECENT_VAULTS = 3`, minus the current one), and the palette commands cover them. The submenu needs a new IPC command with a `#[ts(export)]` DTO, regenerated bindings, and a second copy of a localStorage list in Rust. If the owner wants it, it gets its own Issue after the File menu ships.
13. **Smaller citation fixes.** `rightSidebarVisible: false` is `settings.store.svelte.ts:65`, not `:62`. `SettingsPanel.svelte` is `src/lib/app/SettingsPanel.svelte`. `pane-toolbar.test.ts` is `src/tests/lib/pane-toolbar.test.ts`. The new Rust test registers in `src-tauri/tests/commands/mod.rs`, not `commands_test.rs` (that file is `mod commands;`).

Checked with nothing wrong found: `menu:settings` is broadcast by `app.emit` and only the `(app)` layout listens (the composer window is `src/routes/composer`, outside that layout), so a second unit event behaves the same. `(app)/+layout.svelte` mounts its listeners with and without a vault, so the File item works on the picker page. The palette catches a rejected action and toasts (`CommandPalette.svelte:41-51`), and `splitRecentCommands` skips unknown ids (`command-palette.logic.ts:7`), so a `vault:open-recent:<path>` id that disappears once that vault is current does not break the Recent group. `Cmd+Shift+O` is unbound in `GLOBAL_KEYBINDINGS`, the quick-capture registry (`quick_capture/shortcuts.rs`) and every `Mod-Shift-o` grep under `src`. ADR 0003 names `src/lib/app/` as the home of the palette's built-in commands, the Tauri listeners and the global shortcuts, so every file A and B touch is in its layer. No rule in `docs/agents/*-rules.md` covers menus, palette commands or panel flags. The four panel flags are read only by `AppShell.svelte:278-291`, `LayoutSection.svelte`, `commands.ts:334-335` and `toc.service.ts:23`, plus the settings types and defaults.
