## Findings

1. **minor**, `src/lib/core/zoom/ZoomChip.svelte:12-21`: the `role="status"` `aria-live="polite"` span is created in the same render as its text, because the whole button sits inside `{#if zoomStore.chipVisible}`. VoiceOver and other screen readers usually announce only changes to a live region that already exists, so the first zoom change after the chip hides may not be announced. Later changes while the chip is visible are announced. The Issue prescribes this markup, so this does not block. Fix if wanted: keep the status span mounted all the time (visually hidden while the chip is hidden) and render only the button conditionally.
2. **nit**, `src/lib/core/zoom/zoom.service.ts:61-62`: `localStorage.setItem`/`removeItem` runs without a guard, unlike the read in `restoreZoom()`. If storage throws (quota, blocked site data), the webview is already zoomed but `zoomStore` is not updated and the chip does not show. The keybinding's `.catch` (`global-keybindings.ts:178-181`) logs the error. The build report states this, the case is rare and recoverable, and the Issue asks for no guard, so no change is required.
3. **nit**, `src/lib/core/zoom/zoom.service.ts:51-52`: `restoreZoom()` sets `currentZoom = stored` before the await. If `setZoom` rejects at launch, the module level is the stored value while the webview is still at 1.0, so the next press steps from the stored level. This is the same one-step-off behavior the Issue accepts for `applyZoom`, and the call site logs it. No change.
4. **nit**: the chip has a fade-in (`animate-in fade-in-0`, guarded by `motion-reduce:animate-none`) and no fade-out. The Issue does not require one. Noted for the PR only.

No scope creep. The diff touches only the files the Issue names (`core/zoom/`, `app/AppOverlays.svelte`, `(app)/+layout.svelte`, `help/documentation/03-editor.md`) and their tests. It adds no layer-baseline entry and no composition root. `core/zoom` imports only `core/zoom` and `utils/debug`. `ZOOM_LEVELS` and the synchronous assignment before the await are kept, with a comment explaining why.
