## Findings

1. **blocker** `src/lib/features/rail-shell/FilesNavigator.svelte:339` — The header menu runs an item twice when a second click lands on it during the exit animation, so a double click on "New note" creates two notes (and on "New folder" two folders). Reproduced with a temporary probe built on the `FilesNavigator.menu.test.ts` harness: open the header menu, click "New note", click the same item again while it is still in the DOM with `data-state="closed"`: `create_note` was invoked 2 times. The same probe on the folder context menu invoked it once, because `context-menu-content.svelte:16-28,39-42` absorbs pointer moves, presses and clicks while closing (b962ecc30, which reproduced the double run 5/5 and the rename ending on a press during the fade). `dropdown-menu-content.svelte` has no such guard, so the new menu brings back a bug the context menu already fixed, for the same creator list. Fix: give the header `DropdownMenu.Content` the same closing guard (capture handlers for pointermove, pointerleave, mousedown and click that stop and prevent while `data-state="closed"`), either locally in `FilesNavigator.svelte` or in the shared `dropdown-menu-content.svelte` wrapper (the latter touches every dropdown; state which was chosen and why), and add a test like `NoteRowMenu.test.ts:468-477` ("runs an item once when its second click lands during the exit animation") for the header menu, plus one for a press on the closing menu keeping the New folder rename input focused.
2. **nit** `src/lib/features/rail-shell/FilesNavigator.svelte:172` — The `focusRenameInput` JSDoc says "once the context menu has given focus back"; New folder now also runs from the header dropdown, whose close returns focus to the "+" trigger. Fix: say "once the menu has given focus back".
3. **nit** `src/lib/features/rail-shell/FilesNavigator.svelte:340` — The heading reads "Create in Projects/" (trailing slash), while the Issue text says "Create in <folder>" next to a title "New in <folder>/". The prototype (`note-list-rail.html:998`) uses the same `label(sel)` for both, and discovery recorded the default, so this is consistent; noted only so the owner sees the choice.
