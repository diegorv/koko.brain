## Findings

1. **minor** `src/lib/features/rail-shell/RailNoteList.svelte:803,894-897` (with `src/lib/features/note-list/NoteRowMenu.svelte:153`): `onRename` records `renamed` before `renameItem` runs, and nothing clears it when the rename fails. Reproduced with a probe on the real component: Inbox with alpha, beta, gamma, delta; F2 on beta, type `delta`, Enter, `renameItem` rejects (as `TargetExistsError` does when the name is taken); then beta leaves the list while focused. Focus lands on `delta` (the failed rename's target, which exists) instead of the neighbour `gamma` ("expected 'delta' to be 'gamma'"). The same stale record also lingers after a context-menu rename of a row that is not the current one. Fix: clear `renamed` when the rename does not apply (e.g. have `onRename` fire after `renameItem` resolves, or pass a failure signal and reset it), or reset `renamed` on the first key change the effect sees whatever the outcome; add the probe as a test.
2. **nit** `src/lib/features/rail-shell/RailNoteList.svelte:894`: `current.endsWith(renamed.from)` is a suffix match, so a flat key such as `/vault/sub/vault/a.md` matches a rename of `/vault/a.md`. Fix: match `current === renamed.from` or `current.endsWith(':' + renamed.from)` (the grouped `${group.id}:${path}` key), folded into finding 1's change.
3. **nit** `e2e/specs/rail-shell.spec.ts:287`: focus after a committed rename is checked only in jsdom with one entries snapshot carrying the renamed note. In the app, `rename_note` emits one `vault-index-updated` with both paths (`src-tauri/src/commands/vault.rs:1406`), but the disk rename (`path-change.service.ts`, `diskOp` before `rename_note`) can also reach the list through the watcher; if the old path drops in an earlier snapshot, the effect clears `renamed` and focus stays on the neighbour. The build report names this as unverified. Fix: one E2E assertion that F2, a new name and Enter leave the renamed row focused.

## Resolution

1. Fixed. `NoteRowMenu`'s `runOrToast` resolves to whether the operation succeeded; a failed inline rename calls the new `onRenameFailed(from)` prop, and `RailNoteList` drops the `renamed` record for that path. `onRename` still fires before `renameItem`, since the index event can arrive before it resolves. The probe is now the test "a failed rename leaves no record: the row leaving later moves focus to its neighbour" in `RailNoteList.keyboard.test.ts` (failed before the fix with "expected 'delta' to be 'gamma'").
2. Fixed. The match is `current === renamed.from || current.endsWith(':' + renamed.from)`.
3. Fixed. `rail-shell.spec.ts` adds "F2, a new name and Enter leave focus on the renamed row"; `bash scripts/e2e.sh e2e/specs/rail-shell.spec.ts`: exit 0, 43 passed.
