## Findings

1. **major**, `e2e/specs/word-count.spec.ts:49-57`: the E2E never runs with Todoist sync's status item before the slot, although the E2E vault can show it. The Issue says to run once with it when it can; the build report's reason ("no spec drives the sync", `e2e/mocks/tauri-core.ts:188`) only means the sync itself is not mocked, not that the status item cannot render. The item renders on `settingsStore.todoist.syncEnabled` alone (`TodoistSyncStatus.svelte:17`). Fix: open the note with `openMarkdownFile(page, ..., { todoist: { syncEnabled: true } })` from `e2e/fixtures/live-preview.ts` (or seed the setting in the test vault's settings.json), assert `[data-todoist-sync-status]` is visible, and run the same height/width/x checks with it before the slot. The injected `data-test-chip` can then go, or stay as a second run for the mod case; either way the case should not depend on a node inserted by hand into Svelte-owned DOM as its only "item before the slot".
2. **minor**, `e2e/specs/word-count.spec.ts:69-87`: `x` is never compared between Saved and Modified, only between Modified and the autosave. The reason given (the word count to the right grows and shifts the right-aligned group) is real, but the check can still cover the first flip: compare the gaps that do not depend on the word count, for example `slot.x - (chip.x + chip.width)` (or the Todoist item's right edge) and `counter.x - (slot.x + slot.width)`, across all three states. Width equality across all three states already catches the failure the Issue describes, so this only tightens the test.
