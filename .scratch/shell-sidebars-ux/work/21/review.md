## Findings

1. **minor**, `src/lib/core/markdown-editor/EditorTabs.svelte:77-81`. The fades and the hidden-tab badge go stale after a pin or unpin. A pinned tab is `shrink-0` at icon width (about 44 px), while an unpinned one sits at a 220 px basis. `togglePin` changes the strip's `scrollWidth` but not the scroller's size or `tabs.length`, so neither the `ResizeObserver` nor the length effect runs. The reveal effect only raises a scroll event when the position actually moves. Example: in an overflowing strip, pinning a tab can bring the last tab into view, and the badge keeps counting it until the next scroll or resize. The Issue names only three triggers, so this is in spec, but it is a visible glitch. Fix (optional): have the length effect also read the pinned states, for example `void editorStore.tabs.map(isTabPinned).join()`, or observe the tab items with the same `ResizeObserver`.
2. **nit**, `src/lib/app/AppShell.svelte:191`. In dark mode, hovering the pressed toggle weakens its fill: `dark:hover:bg-accent/50` overrides the pressed `bg-accent`, so a pressed toggle looks less pressed under the pointer. Fix (optional): skip the hover fill while pressed, for example by putting the `dark:hover:bg-accent/50` class in the unpressed branch only.

No blockers. No scope creep. These changes are all needed: the shared `kindIcon` snippet, which the menu rows reuse; the `tab-strip` class and `data-tab-strip` hook, which carry the moved divider and serve as the test selector; the `title` on the list button; and the codemap line-number update, which follows the moved AppShell call sites. The diff does not edit `layer-baseline.json`, `BASELINE_SIZE` or the composition roots. `ledger.md` is untouched. `{#each}` stays unkeyed and the inline close button stays.

## Resolution

1. **minor (pin/unpin leaves fades and badge stale): rejected, not reproduced.** `editorStore.togglePin` and `setPinned` reassign the `tabs` array (`editor.store.svelte.ts:147-162`), and the length effect reads it through the plain `tabs` getter (`editor.store.svelte.ts:34`), so the effect re-runs on every pin change even when the length stays the same. A regression test, "updates the count when a tab is pinned or unpinned, with no resize or scroll", now pins and unpins tabs with pinned-width geometry and checks the badge and the right fade. It passes as the code is, and fails when the length effect is disabled. No source change.
2. **nit (dark hover weakens the pressed toggle): fixed.** `dark:hover:bg-accent/50` now applies only while the toggle is unpressed (`AppShell.svelte:191`). `AppShell.test.ts` asserts the class is present while unpressed and absent while pressed. The test failed before the change.
3. **Full suite (deliver), not a review finding: fixed.** `chrome-type-scale.test.ts` failed on the hidden-tab badge's `text-[9px]` (`EditorTabs.svelte:198`), below the chrome's 11 px floor with no badge allowance. The badge is now `text-[11px]`.
