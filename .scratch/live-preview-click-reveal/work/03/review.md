## Findings

1. minor — `src/lib/core/markdown-editor/extensions/live-preview/plugins/frontmatter-field.ts:79-80`: when the first body line is a block widget, a padding click now reveals that block's source. Probe (jsdom, real `livePreviewExtensions`, press mapped to 0): with a code block, table or `$$` math block right after the closing fence, the press puts the cursor at `BODY_START`, and the widget turns into raw markdown (```` ```js ````, `| a | b |`, `$$`). Before the fix the block stayed rendered, although the cursor was then on a hidden line. That is a blank-space click revealing a block, the thing Issue 01 (`blockBandClick`) prevents for the bands, and nothing tests it. It does not violate the Issue text ("the cursor must land on the first body line") and it is visible and recoverable, so it is not a blocker. Fix (here or in a follow-up Issue): when the first body line holds a sole block widget, keep the selection unchanged, as `bandClickTarget` does when the neighbour is a block (`{ pos: null }`), or send the cursor to the line after the block. Add a unit test with a block right after the frontmatter.
2. nit — `src/tests/lib/core/markdown-editor/extensions/live-preview/plugins/frontmatter-field-click.test.ts`: the drag path of `get()` has no test: a press in the padding, then a pointer move whose position maps into the frontmatter, should give the head `bodyStart` (`frontmatter-field.ts:90-95`, not extend). Only press and shift-click are covered. Fix: add a mousemove case to the jsdom test.
3. nit — `docs/LIVE-PREVIEW.md:35` documents `blockBandClick` as a `mouseSelectionStyle`, but there is no matching note for `frontmatterClick`, which is the second style and is installed by the `frontmatter` kill-switch. Fix: add one bullet next to the `blockBandClick` one.

Typing or pressing Backspace then deletes frontmatter bytes the user cannot see. The build report lists this as left undone. Fix: a follow-up Issue. The same clamp `frontmatterClick.get()` uses would have to apply to every drag, for example through a transaction filter on pointer selections.
