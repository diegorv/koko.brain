# Calendar App as a built-in Kokobrain feature (event-calendar)

This plan ports the calendar from the Calendar App design prototype (`/home/user/calender-app-design`) into Kokobrain as the always-loaded feature `src/lib/features/event-calendar/`. The prototype is built on Next.js 16, React 19, Zustand 5 `persist` (to localStorage key `calendar-app:state`), Radix and Tailwind 4. What ports:
- day, week and month views, including the narrow-pane behaviour of the time grid;
- drag to create, move and resize; overlap layout; the all-day lane; the now-line;
- the popover and the event dialog;
- delete with undo, undo/redo of every tracked change, the feedback toasts and the keyboard shortcuts.

The prototype's people-ops pages stay out (time off, leave, holidays, dashboard, invoices and the rest; see Notes > Source feature coverage).

An event is an ordinary Markdown note whose `_type` matches the configured event type (default `Event`), with flat frontmatter: `date`, `start`, `end`, `all_day`, `event_color`, `location`, and `event_title` only when the typed title cannot be the filename. The calendar stores nothing of its own.
- **Reads:** a projection of the Rust `VaultIndex` snapshot that the `vault-index-updated` listener already fetches (`core/vault/vault-entries.service.ts:22-34`, `core/layout/tauri-listeners.service.ts:121-140`). The calendar adds no IPC. Notes under the templates/system folder and archived notes are left out.
- **Writes:** only through existing owners: `saveFileByPath` / `notifyAfterSave`, `createFile`, `renameItem`, `deleteItem`, `restoreItem`. Typed-note creation is shared with the type sidebar (Task 14). `applyNoteChange` stays the single owner of note changes. Its one new source row, `restore` (Task 15), fixes a core gap that Trash panel restores have too.
- **What comes for free:** backlinks, wikilinks, QueryJS, collection views, file history, trash, the type sidebar (built-in `Event` type, `features/type-definitions/type-definitions.logic.ts:38`) and vault sync. Search covers an event from its first calendar edit on. A newly created event reaches FTS5 the same way every created note does today: at the next vault-open reconcile (D19, follow-up).
- **What does not change:** no Rust production code, no new npm dependency, no new note-change consumer.

Strategy: the winning proposal is "vertical-slice", with grafts from the other proposals (see Notes > Decisions). The order is:
1. Pure ports with ported tests.
2. The shared frontmatter writer, E2E mock parity, and the two owner-side fixes (typed-note creation, Trash restore indexing).
3. The stores and a read-only Calendar tab (first user-visible value at Task 20).
4. Writes, proven on the edit dialog before pointer drag reuses them.

Each task is one green commit that can be reverted on its own. Gate shorthand:
- "frontend" means `pnpm check` + `pnpm vitest run` + `pnpm build`.
- "Rust" means `cargo test --manifest-path src-tauri/Cargo.toml`.
- E2E specs always run through `bash scripts/e2e.sh <specs>`.

## Notes

### Decisions
- **D1 Storage: events are typed notes (`_type: Event` by default).**
  - Rejected `.kokobrain/calendar/events.json` (proposal "dedicated-store"):
    - Events would be invisible to search, backlinks, QueryJS and collections.
    - ADR-0019 tells users to exclude `.kokobrain` from sync.
    - It needs a new Rust write command plus a merge and reconcile subsystem, because the watcher drops dot directories (`src-tauri/src/vault/watcher.rs:74-82`).
    - ADR-0027 already rejected sidecar JSON for icons.
  - Rejected localStorage (the prototype's store): it is per webview and not per vault.
- **D2 Schema: split keys.** `date` (`YYYY-MM-DD`), `start` / `end` (`HH:mm`, `24:00` allowed), optional `all_day`; `end_date` is reserved and flagged.
  - Rejected one ISO datetime per bound ("vault-native"): `PropertyField.svelte:123` renders every `date`-typed value as `<input type="date">`, so `T` values show blank, and fixing that changes a shared component.
  - Rejected integer minutes: unreadable when editing by hand.
  - A present but unparseable value is an issue, never a default (Task 6), so the calendar never overwrites a hand-written value it cannot read.
  - Cost: no cross-midnight or multi-day events in v1.
- **D3 Placement: a new `features/event-calendar` that coexists with `plugins/calendar`**, bridged in Task 32.
  - Rejected promoting and merging `plugins/calendar` and `plugins/periodic-notes` into `features/calendar` ("evolve-existing"):
    - About 35 files move before any user value appears.
    - It extends a TypeScript mirror of vault metadata (against CLAUDE.md Indexing rule 1).
    - It changes the month grids used by collection views and the live-preview widget.
  - Rejected reusing the name `calendar`: it collides with `calendarStore`, the `calendar` consumer, the SidebarMode value and `features/collection/calendar.logic.ts` (whose `CalendarEvent` is why the event type is named `EventNote`).
  - Accepted cross-layer imports, all with existing precedent, are listed in ADR-0032 from a grep of the final tree (Task 34).
    - Precedent: `global-keybindings.ts:9-19` already imports four features and two plugins; `type-definitions.service.ts:12-20` imports `features/properties` and `features/collection`; `command-palette.service.ts` imports seven features; `tauri-listeners.service.ts:7-16` imports a plugin and four features.
  - The only core-owner change is the `restore` row (D20). `path-change.service.ts` is untouched; `tauri-listeners.service.ts` gains only the close-handler drain (Task 24). A tab-kind registry is filed as a follow-up.
- **D4 Read path: project `getVaultEntries()`, keyed on `vaultIndexVersion` and the four projection settings, while the tab is mounted.**
  - Rejected a note-change consumer: a TS mirror, a silent-registration risk, and a rename shows up only after the watcher round trip (at least 800 ms).
  - Rejected `collectionStore.propertyIndex`: records built by upsert drift from those built by rebuild.
  - Rejected keeping the raw entries in the store to re-project on settings changes: the memo in `vault-entries.service.ts:22-25` already makes a same-version re-read free, and stores hold no projection logic.
- **D5 Write path: one shared `updateNoteFrontmatter` in `features/properties` that saves immediately, refuses lossy frontmatter, fences vault switches and never re-creates a vanished note.**
  - Rejected a feature-local writer: it would duplicate logic that belongs to the owner.
  - Rejected deferring dirty tabs to the 500 ms autosave ("vault-native"): a save failure could never reach the caller, so the overlay could not roll back (CLAUDE.md rule 7).
  - Rejected disk-direct writes like `frontmatter-icon.service.ts`: they clobber dirty tabs and skip the after-save observers.
  - Refusing instead of dropping is a deliberate departure from ADR-0029's "callers must accept" drops, scoped to this writer and to calendar creation from a template (Task 27), and recorded in ADR-0032 plus an ADR-0029 amendment (Task 34). The sidebar's "New Event" keeps a commented template verbatim because it never rewrites it; the calendar must merge fields into it, so it refuses instead.
- **D6 Filenames and titles: the sanitized title is the filename, deduped by the typed-note owner; the typed title lives in `event_title` only when it differs from the filename base.**
  - `eventFileBase` replaces the characters `isValidFileName` rejects (`fs.logic.ts:108-112`) with `-`, so the prototype's own seed title "1:1 with manager" (`seed.ts:63`) and titles like "Lunch w/ Bob" work. Repeated titles get `Standup 1.md`, `Standup 2.md` while all display "Standup". A case-only title edit renames nothing, because `renameItem` refuses it on a case-insensitive volume (`fs.service.ts:194-198`).
  - Rejected refusing forbidden characters in the title: blocks common titles, including the prototype's seed.
  - Rejected `YYYY-MM-DD Title.md`: the name goes stale after any drag.
  - Rejected writing a plain `title` key: many vaults and tools already use `title` with other meanings, and writing it would change how they display the note.
- **D7 Color: `event_color` with six named hues.**
  - Rejected `color`: it is an alias of `_color` (`src/lib/utils/frontmatter-aliases.ts:17`), the file-icon tint.
  - Rejected a `_color` hex value: it couples icon color and event color.
- **D8 Hosting: a singleton virtual tab.**
  - Rejected a left-pane SidebarMode: the pane is capped at 40% (`src/lib/core/layout/AppShell.svelte:115`).
  - Rejected a route: Kokobrain has no routes for views.
- **D9 Undo: calendar-only and session-only, covering every tracked change.**
  - The Cmd+Z stack holds `update` (move, resize, edit including title), `create` / `duplicate` and `delete` ops. Each is guarded by a precondition, and create/delete undo through the Trash. File History is the durable fallback.
  - A path that vanished through a rename or move outside the calendar drops its ops with a toast; history follows only the calendar's own renames.
  - Rejected keeping create and delete off the stack (the previous draft): Cmd+Z right after a delete would silently revert an older, unrelated move while the deleted event stayed gone. An edit's title change would also have stayed after undoing that edit.
  - Rejected clearing the stack on create or delete: it loses history the prototype keeps.
  - Rejected the prototype's global undo over all app data (`app-store.ts:147-231`).
  - Rejected following external renames through a note-change consumer: a new consumer for one feature's history (D4 rejects consumers for the same reasons).
- **D10 Keyboard: bare keys only on the focused view root, plus a `document` fallback that acts only when focus is on `<body>`; one global Meta binding that yields to the user's `cycleSidebarView` binding.**
  - Rejected `registerKeybinding` for bare keys.
  - Rejected relying on focus restoration alone: the palette, toasts and unmounted triggers can each leave focus on `<body>`, which silently disables every shortcut.
- **D11 Rust: no production change; only a contract test.** Rejected a `get_events_in_range` command: premature, because the snapshot is already fetched on every bump.
- **D12 UI primitives: the shadcn wrappers in `$lib/components/ui` (popover, dialog, tooltip, switch, input, button), unedited.**

### Event note schema (reference)
```markdown
---
_type: Event
date: 2026-11-10
start: 09:30
end: 10:30
event_color: green
location: Room 4
---
Agenda, [[Project X]], - [ ] follow-ups
```
- The type is the configured `eventTypeName` (default `Event`), compared ignoring case.
- All-day: omit `start` and `end`, or set `all_day: true`. An empty `start:` counts as absent.
- A present but unreadable `start`, `end` or `all_day` makes the note a Needs-attention item, never a defaulted event. A missing or non-day `date` makes it "Unscheduled" (informational).
- `end_date` is reserved for multi-day spans: rendered on the start day, read-only, with a notice.
- `event_title` holds the display title only when it differs from the filename (for example `1:1 with manager` in `1-1 with manager.md`, or `Standup` in `Standup 1.md`).
- Notes under the templates/system folder are never events; archived events are hidden.
- The identity of an event is its absolute note path (CLAUDE.md Indexing rule 9).
- New notes go where "New Event" in the type sidebar puts them: `<vault>/<typesBaseFolder>/<event type _folder>`, from the event type template, named by the sanitized title.
- `_organized` defaults to true when absent (`src-tauri/src/vault/entry.rs:240-243`), so event notes do not inflate the inbox badge.
- Times are floating wall-clock times with no timezone (same as the prototype).

### Risks
1. **Data loss on write** (dirty-tab clobber, loss of unusual YAML, interleaved writes, cross-vault writes, writes after close, zombie re-creation).
   - Mitigations:
     - `updateNoteFrontmatter` patches `tab.content` and saves it, re-checks for a tab and for the file's existence before a disk write, and syncs after it.
     - It refuses frontmatter with comments, nested values, duplicate keys, conflicting aliases, anchors or parse errors; calendar creation refuses such a template.
     - It throws `vault-changed` across a switch, and runs behind a per-path queue that is drained before teardown and before the window closes.
     - Delete saves a dirty tab first.
   - The ADR-0029 canonical coercions still apply and are documented (Task 33).
   - Residual: a tab opened between the post-write sync and `openFileInEditor`'s own read could hold stale bytes, and a delete landing between the `exists` re-check and `writeTextFile` can still re-create the note; each window is a single IPC.
2. **Index lag and snap-back** (300 ms debounce, fire-and-forget `update_note_in_index`).
   - Mitigation: the pending overlay prunes on a matching snapshot, or only after two newer versions (Task 6), plus the ghost held until the write resolves (Task 29).
   - Auto-move can relocate a note right after a write; the version fallback drops entries whose path vanished.
3. **Hand-written events dropped or overwritten.** Mitigation: the Needs-attention list (Task 20) with reasons; unreadable values never get defaulted; `multi-day` events are read-only; plus the Rust contract test (Task 2).
4. **Unverified APIs.** Fallbacks if Task 1 says no:
   - (a) Popover anchor: a feature-local fixed-position card. `onCloseAutoFocus` missing: focus the block from the `onOpenChange(false)` callback after a `tick()`.
   - (b) Toast action: plain toasts. "Event deleted. Press Cmd+Z to undo." works because delete is on the Cmd+Z stack (D9); the Trash section is the second path.
   - (c) Icons: `calendar-days` and `alert-triangle`.
   - (d) yaml node API: a raw-line heuristic that refuses more often (any `#` outside quotes, `&`, `*`, indented `key:` under a list).
   - (e) Cmd+Shift+C: use Cmd+Shift+Y. If the native Edit menu swallows Cmd+Z / Shift+Cmd+Z: palette commands "Calendar: Undo" / "Calendar: Redo".
   - (f) jsdom pointer events: logic-only drag tests plus E2E. Runtime `process.env.TZ` ignored: the DST blocks skip through `describe.runIf`, and the Task 21 `timezoneId` E2E spec carries the DST check.
   - (h) Playwright clock: if `install` freezes time, use `page.clock.setFixedTime` in the read-only specs and drive time with `page.clock.runFor` where recent-save windows matter; if `timezoneId` is ignored, pin `TZ` for the spec through `scripts/e2e.sh` arguments and record it.
5. **Confusion with the sidebar month panel and the collection calendar views.** Mitigation: distinct names, the bridge (Task 32), and help text (Task 33).
6. **Pointer regressions.**
   - Equal-width columns are guaranteed by the min-width container (Task 21).
   - Scroll during a drag: `slotFromPoint` reads the live rect each time.
   - Covered by `page.mouse` E2E that asserts file bytes, including a cross-day move.
7. **Undo clobbering newer edits or failing on an emptied Trash.** Mitigation: equality preconditions; vanished paths drop their ops with a toast; `not-in-trash` refuses with a toast (Tasks 23, 27).
8. **Global E2E mock change (Task 13).** Mitigation: an isolated commit gated by the full suite.
9. **Performance.** The O(N) projection runs per bump (and per projection-setting change) only while the tab is mounted, and the snapshot is already fetched by the listener. Store reads are O(1) through the mutator caches (Task 16). Profile with `appendLog` before adding a Rust range command (follow-up).
10. **One file per event clutters the vault.** Mitigation: the Event type `_folder`, linked from Settings > Calendar, and the type sidebar's Event section.
11. **Collision with the kit-3 `#lib` codemod and the bits-ui bump.** Mitigation: Notes > Dependencies, Task 1 (g), and the re-check in Tasks 25 and 26.
12. **Theme contrast.** `color-mix` percentages are tuned against two themes only. A custom theme with low `--editor-bg` / `--editor-fg` contrast lowers event contrast proportionally. The theme-editor follow-up gives users direct control.
13. **Time zones and DST.** Floating times avoid conversions, but any helper that mixes elapsed milliseconds with wall-clock keys is off by an hour twice a year. Mitigation: wall-clock arithmetic only (Tasks 4, 7), DST test blocks, and a pinned clock and time zone in every calendar E2E spec.
14. **Lost keyboard focus** silently disabling the shortcuts. Mitigation: targeted focus moves (Tasks 25, 26, 28) plus the `<body>` fallback (Task 30), with unit and E2E checks.
15. **Overlapping plans.** p2p-sync touches the same settings spots and produces conflict copies that render as duplicate events. Mitigation: Notes > Dependencies, help text, follow-up.
16. **Event type renamed.** Mitigation: the `eventTypeName` setting and its hint (D25); the help page explains the step after a rename.
