# Live-preview redraw audit, 2026-11-02

Trigger: the owner saw a meta-bind select in a daily note vanish after picking a value (the value was saved; a tab switch or a far scroll brought it back).

## Root cause of the reported bug (fixed)

`metaBindInputPlugin` replaced the whole inline code, backticks included, with its widget. The inline pipeline hides those backticks with its own replace decorations, which start where the widget does and had higher precedence. A write changes the widget (its `eq()` turns false), CodeMirror redraws only that region, and in `@codemirror/view`'s tile builder (`RangeSet.spans` point callback, `openStart > active.length`) the widget is open at the region start, so it calls `continueWidget` and draws no tile. A decoration rebuild with identical decorations does not redraw it; only a full redraw does. It predates the file-io-audit work (it reproduces at c83f24ef).

- cf9bed59: first fix, `Prec.high(metaBindInputPlugin)`.
- 1f0ce850: final fix. The widget replaces only `INPUT[...]` (`range.from + 1` to `range.to - 1`) and the precedence change is reverted. The audit showed `Prec.high` made a pipe-less table whose header starts with an INPUT draw a second select and vanish after edits, and did not cover double-backtick INPUTs. The test (`meta-bind-input-redraw.test.ts`) covers every inline container, two selects on a line, double backticks and the pipe-less table.

## Audit

40 haiku mappers and interaction tracers (29 decoration sources, 11 widget interactions), then 5 opus analysts by cluster (inline, block vs inline, block vs block, interactions, fix review and completeness). Every finding needed a red test. The tests are in `repro/<cluster>/`; to run one, copy it under `src/tests/lib/core/markdown-editor/extensions/live-preview/audit/` (the `test-helpers` import paths expect that depth; adjust `../` as needed). Some click tests stub `view.posAndSideAtCoords` because jsdom has no layout.
