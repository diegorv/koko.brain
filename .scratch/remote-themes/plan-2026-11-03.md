# Remote themes

Ship two themes in the app (`KokoBrain Default`, dark, and `Lavender Haze`, light) and serve every other theme from the public repo `diegorv/koko.brain-themes`, one JSON per theme, each with its own version. Settings > Appearance lists the catalog: Install, Installed, or Update to `x.y.z`. An installed theme the user did not duplicate updates in place from the UI; a duplicate is a user theme and never updates.

## Notes

### Decisions (owner, 2026-11-03)

- Built-in: `KokoBrain Default` (dark) and `Lavender Haze` (light). The other 22 move to the repo: the 20 `PRESET_THEMES` plus `Sakura` and `Twilight Violet`.
- Update is manual from the UI, never automatic.
- Format is the source of `buildTheme`, not the expanded ~150 tokens: a token the app adds later is derived for old themes instead of being filled from the dark default by `mergeThemeWithDefaults`.
- Push to the public themes repo is authorized.

### Package format (schemaVersion 1)

```json
{
  "schemaVersion": 1,
  "id": "zettlr-berlin-dark",
  "name": "Zettlr Berlin Dark",
  "version": "1.0.0",
  "author": "diegorv",
  "palette": { "...": "CorePalette fields" },
  "overrides": { "ui": {}, "syntax": {}, "preview": {}, "wikilink": {}, "callout": {} }
}
```

- `id`: `^[a-z0-9]+(-[a-z0-9]+)*$`, stable forever; `name` may change between versions.
- `version`: plain `MAJOR.MINOR.PATCH`, compared numerically (no pre-release tags, no dependency).
- `schemaVersion` above what the app knows: the entry shows "Requires a newer KokoBrain" and cannot be installed.
- `overrides` optional; keys outside `ThemeColors` are rejected.

### Trust boundary

`applyTheme` writes every value with `style.setProperty`, and the CSP allows `img-src https:`, so a value such as `url(https://...)` in a third-party JSON would make the app fetch. Every palette and override value must match a color grammar: hex (3/4/6/8 digits), `rgb()/rgba()`, `hsl()/hsla()`, `oklch()` (used by `KokoBrain Default`), with numeric arguments only. Index size capped. The same validator is applied to the manual JSON import (`parseThemeFromImport` checks only `name` and `colors` today).

### Fetching

- One request: `https://raw.githubusercontent.com/diegorv/koko.brain-themes/main/index.json`. The index embeds every full package (22 x ~1.5 KB), so the list, the mini previews (built locally with `buildTheme`) and Install need no second request. The per-theme files stay the source of truth; the index is generated from them.
- Through `@tauri-apps/plugin-http` (already a dependency, used by `features/tasks/tauri-fetch-adapter.ts`), so the webview CSP `connect-src` does not change. Add `http:allow-fetch` / `allow-fetch-send` / `allow-fetch-read-body` scoped to `https://raw.githubusercontent.com/diegorv/koko.brain-themes/**` in `src-tauri/capabilities/default.json` (Task 4 gate is Both).
- Fetched when Appearance opens, not at boot. raw.githubusercontent.com caches for about 5 minutes, so a pushed version can take that long to show.

### Identity and names

- `activeTheme` stays a name. Install refuses a name already used by a user theme (message tells the user to rename theirs). An update that renames the theme carries `activeTheme` along.
- Uninstalling the active theme falls back to `KokoBrain Default` (existing `deleteTheme` behavior).

### Migration of the 22 ex-built-ins

Saved settings hold full colors for every built-in. After Task 3 those names are no longer built-in, so without a migration they would all turn into editable user themes.
- The active one, if it is an ex-built-in, becomes an installed package: `id` from a legacy name -> id table, `version: "1.0.0"`, source from `packageFromColors(savedColors)` (`coreFromColors` plus every token where `buildTheme` differs as an override, so the round-trip is exact; needed because `Sakura` and `Twilight Violet` carry overrides). No visual change, works offline, and later versions update it.
- The other saved ex-built-ins are dropped; they are one click away in the catalog.
- `"<name> (edited)"` copies are already user themes and are kept.
- Gated by a new flag next to `builtinsFromCode` so it runs once.

### Parity check (Task 2)

The export script builds each exported package with the app's `buildTheme` and compares `themeColorsToCssVars` against the theme in the current code; any difference aborts. The script is a one-off and is not committed to either repo.
