## Findings

1. minor — src/lib/features/deep-link/deep-link.service.ts:327 (and :337). `kokobrain://new` marks non-Markdown files. `resolveFilePath` adds `.md` only when the last segment has no dot (src/lib/utils/path.ts:46-50), so `kokobrain://new?file=board.canvas&content={...}` (or `.json` / `.kanban`) with the switch on writes `---\n_organized: false\n---\n{...}` and corrupts the JSON file. That breaks the Issue's rule that non-Markdown files never get the key. It is unlikely in practice: it needs the switch on plus a deep link with a non-`.md` extension. Fix: apply the flag only when `isMarkdownFile(fullPath)` (`core/filesystem/fs.logic.ts`) in both create branches, and add a deep-link test with a `.canvas` name.
2. nit — src/lib/core/note-creator/explicit-organization.logic.ts:19. `ORGANIZED_KEY_LINE = /^_?organized\s*:/` also accepts `organized :` with whitespace, which is slightly wider than the Issue's "starts with `_organized:` or `organized:`". It is harmless (that spelling is still that key in YAML), and the build report already names it. A quoted key (`"_organized": true`) is not detected and would get a second key. No change needed unless a test pins it.
3. nit — src/tests/lib/features/quick-switcher/QuickSwitcher.test.ts:99. The `console.error` spy is never restored in the test. `vi.resetAllMocks()` in the next `beforeEach` covers it inside this file, so this is only tidiness.
