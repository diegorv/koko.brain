## Findings

1. **minor** — src/lib/features/file-icons/file-icons.logic.ts:144 — `extractViewIcon` reads only the canonical `_icon` / `_color` / `_title_color` keys of the raw YAML, but Rust canonicalizes the ADR-0027 aliases `icon` / `color` / `title_color` (src-tauri/src/vault/aliases.rs) before `buildFrontmatterIconIndex` reads them, and the `.md` branch accepts them too (`/^_?icon:/`, `/^_?color:/`). Failure: a hand-written view with `icon: lucide:rocket` shows its row icon after a full scan; a toolbar Filter / Sort / column change (`updateViewQuery`) now runs the consumer, which computes `newRef = null` against the existing ref and clears the icon, and the self-save skip means no rebuild brings it back until the next full rebuild or restart. On main the watcher's full rebuild restored it from Rust. Same for a view with `_icon` plus an unprefixed `color:` (colour dropped). App-created views use `_`-prefixed keys, so this needs a hand edit to hit. Fix: in `extractViewIcon`, fall back to the alias key when the canonical one is absent (`fields._icon ?? fields.icon`, same for the two colours) before calling the parsed extractors, plus a logic test for `icon:` / `color:` bodies.
2. **minor** — src/lib/core/filesystem/note-change.service.ts:87 (exposed by type-definitions.service.ts:295) — source `save` runs the consumers deduped, and a `.view`'s dedupe signature is only ever refreshed by these writers: an external `.view` edit takes the watcher's full-rebuild branch, which rebuilds the icon store but never calls `markIndexed`. Failure: set icon X in the app (content A marked), change it to Y in another editor (store = Y, signature still A), set X again in the app: if the result is byte-identical to A, the consumers are skipped, the icon store keeps Y while disk and Rust hold X, and the self-save skip suppresses the rebuild. Rare, visible, recoverable on restart; no change required, but worth a line in the ADR amendment or a follow-up note (a fix would be to clear the changed paths' signatures in the watcher's full-rebuild branch).
3. **nit** — src/lib/features/type-definitions/type-definitions.service.ts:290 — "Every `.view` writer goes through here." is not true today: `createView` writes a `.view` through `createFile` (source `fs`). Reword to "Every writer that rewrites an existing `.view` goes through here" (which is what Issue 19 needs).
4. **nit** — CLAUDE.md § Indexing & Watcher rule 6 lists the write paths that route through `applyNoteChange` and does not name the `.view` writers (`type-definitions.service::writeViewFile`). Not an acceptance criterion; add it when the doc is next touched so the list does not read as exhaustive.
