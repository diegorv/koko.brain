# 15: `kb.pages()` leaves out `.view` files, type definitions and system-folder notes

**What to build:** QueryJS `kb.pages()` (and `dv.pages()`, the same object) returns notes only: `.view` files, type definitions (`_type: Type`) and notes under the system folder (Settings > Templates > System folder, `settingsStore.templates.systemFolder`) are left out of the list, also when it is filtered by `'#tag'` or `'"folder"'`. Archived notes stay in the result, as today; help 13 gains a sentence saying so and showing how to drop them (`kb.pages().where(p => !p.archived)`, where `archived` is the page-root boolean Rust always sets). The page list then matches the rail's rule (Issue 12) apart from archived notes. `kb.page(path)`, `kb.current()` and link resolution keep seeing every indexed file (see Notes).

## Notes

- **Owner decision (2026-11-04):** exclude `.view` and the system folder by default; keep archived notes and document it; QueryJS as a lens source is deferred.
- **Main-session decision (owner accepted 2026-11-04):** treat this as a fix, not a contract change: no `kb.version` bump, because `.view` files and templates were never meant to be pages (their YAML keys leak in as page properties today). Flag in the help's compatibility notes.
- **Owner decision (2026-11-04, type definitions):** type definitions leave `kb.pages()` too, so dashboard counts match the rail's lists apart from archived notes. `kb.page(path)` still finds a definition by path (lookups below).
- **Main-session decision (lookups):** the exclusion applies to the list only. `kb.page(path)` is an explicit lookup by absolute path, outlinks resolve against every property-index path (`buildResolutionCache(allFilePaths)`, `kb-api.ts:428-435`), and `kb.current()` must keep working in a template under the system folder; filtering `byPath` would return `undefined` / `null` for links and break `kb.current().file...` in those notes.
- **Today (traced):** `ensureCache` (`src/lib/plugins/queryjs/kb-api.ts:416-455`) builds the page list from `this.propertyIndex.keys()` (`:428`, `:436-446`), the `collectionStore.propertyIndex` loaded from `get_all_property_records`, which projects every `VaultIndex` entry with no filter (`src-tauri/src/commands/vault.rs:895-906`); `entries` only supply tags, tasks and outlinks per path. `.view` files are entries (`is_markdown_filename`, `src-tauri/src/utils/fs.rs:114-117`).
- **Not in scope:** Collection blocks and `.collection` / CollectionView query the same `collectionStore.propertyIndex` through `executeQuery` (`src/lib/features/collection/collection-block-widget.ts:116`, `CollectionView.svelte:220`) and still include `.view` and system-folder notes. The `"folder"` substring match (review F81) is not changed.
