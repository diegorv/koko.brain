# 07: Meta-bind writes typed values and reads alias keys

**What to build:** Meta-bind controls write typed YAML values: a toggle writes `done: true` / `done: false`, a number input writes `count: 7`, a select option that is a plain number or `true` / `false` is written typed (`humor: 3`), and a button's `updateMetadata` accepts number and boolean `value`s and writes them typed. Date inputs and every other select option still write strings. A control bound to an alias key (`INPUT[toggle():archived]`, `favorite`, `type`, `order`) shows the stored value of the canonical key (`_archived`, ...). As a result, a toggle on `_favorite` or `_archived` writes the YAML boolean the Rust index reads, so the Favorites and Archive lenses follow it like the action bar.

## Notes

- **Owner decision (2026-11-04):** fix meta-bind writes and reads; no new meta-bind features in this round.
- **Main-session decision (select rule):** only exact `true` / `false` and round-tripping plain decimals are typed, so an option value never changes spelling on disk (`"007"`, `"1.50"`, `"1e3"` stay strings) and `yes` / `on` stay strings (YAML 1.2, as `src/lib/core/frontmatter/yaml-quoting.logic.ts:17-23` says). Sample 12 (`option(1..5)`, "numeric") needs this. The Properties panel types by the existing property type (`src/lib/features/properties/PropertyField.svelte:64-82`) and is not changed.
- **Main-session decision (empty number):** an emptied number input keeps writing the empty string, as today (`isNumericString`, `widgets.ts:829-834`: "empty = clearing the property"). It never writes `0` and does not remove the key.
- **Main-session decision (legacy quoted flags):** notes that already hold `_favorite: "true"` / `_archived: "true"` are not migrated, and the Rust reader is not changed (Gate stays frontend only). Rust `extract_bool_flag` (`src-tauri/src/vault/entry.rs:373-378`) ignores a string, so those notes stay out of Favorites and Archive until the toggle is used once, which rewrites the boolean. They never worked in the lenses, so nothing regresses.
- **Main-session decision (button reasons):** a separate `buttonConfigError` helper rather than a new return type for `parseButtonConfig`, so the field plugin is the only caller that changes and the `returns null` tests (`meta-bind-button.logic.test.ts:106-246`) keep their meaning. An unknown `style` still falls back to `default`.
- **Cause (traced):** the toggle dispatches the strings `'true'` / `'false'` (`widgets.ts:917-924`), the number input dispatches `input.value` (`widgets.ts:989-996`) and the select dispatches the option string (`widgets.ts:752-758`); `dispatchMetaBindUpdate` (`widgets.ts:804-827`) hands them to `setPropertyByBindTarget` (`src/lib/core/frontmatter/properties.logic.ts:636-648`, `value: string`), and `serializeProperties` writes a string scalar quoted when it looks like a number or boolean. Rust reads `_favorite` / `_archived` with `as_bool()` (`src-tauri/src/vault/entry.rs:246-251`, `extract_bool_flag` at :373-378), so a quoted string is ignored. The alias read looks up the raw bind target (`meta-bind-input-plugin.ts:76`, `widgets.ts:258`) while parsed properties carry canonical keys (`properties.logic.ts:296`, `src/lib/utils/frontmatter-aliases.ts`). The write side already canonicalizes (`setPropertyByBindTarget`). Button validation: `meta-bind-button.logic.ts:69-118`; the button write is `meta-bind-button-widget.ts:93-95`.
- **Not in scope:** `number`, `date` and `toggle` inputs inside table cells still render as a select (review F86, candidate I25, not opened in this delivery); only the alias read of the table-cell select changes here. Button `open` links (F85) and accessible names (F99) are also I25.
