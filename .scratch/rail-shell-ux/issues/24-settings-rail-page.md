# 24: Settings > Rail: hide and reorder built-in items, Inbox badge switch

**What to build:** A new Settings page, "Rail" (section id `rail`, in the General group after Sidebar, icon `panel-left-dashed`), lets the user hide rail items and reorder them within their group. The groups are the ones the rail draws: top (Search, Inbox, Today, Favorites), navigators (Types, each registered navigator such as Calendar, Files), bottom (Archive). Search stays first and cannot be hidden or moved (it is the way into search); Today cannot be hidden (it is the fallback lens) but can be moved. Hiding a registered navigator such as Calendar hides its rail button only; the plugin stays registered, its Day lens provider included. A hidden item is not rendered and has no Go to command (Issue 23). While the saved `layout.railItem` is hidden, the rail shows Today; the saved value is kept, so showing the item again brings it back. A switch "Show Inbox count on the rail" turns the rail's Inbox badge on and off, separate from the existing dock badge switch under Quick Capture ("Show inbox count on dock"). Pinned items (Issue 21) are not listed here; they order by their own `_order`.

**Blocked by:** 21, 23

**Status:** ready-for-agent

**Gate:** frontend only: `pnpm check` + `pnpm vitest run` + `pnpm build`.

- [ ] `LayoutSettings` gains `railHidden: string[]`, `railOrder: string[]` and `railInboxBadge: boolean`, with `DEFAULT_SETTINGS.layout` defaults `[]`, `[]` and `true` (so `mergeLayout` keeps them and the badge stays on for existing users), and they round-trip through load and save (logic and service tests)
- [ ] The three keys are loaded unvalidated, so they are read only through parse helpers (for example `parseRailHidden` / `parseRailOrder`: a non-array gives `[]` and non-strings are dropped; the badge is off only for the boolean `false`), and their JSDoc says so, as for `railExpandedFolders` (logic test)
- [ ] A pure function in a `features/rail-shell` `.logic.ts` takes the rail's groups of keys in default order plus the parsed hidden and order lists, and returns the groups to render: hidden keys are dropped except `search` and `today`; `search` stays first in the top group; within each group the keys listed in `railOrder` come first in that order and the unlisted ones follow in default order (navigators `[types, calendar, files]` with `railOrder: ['files', 'types']` give `[files, types, calendar]`); unknown keys and keys of another group have no effect (logic test, one case per rule)
- [ ] `Rail.svelte` renders that result, and Issue 23's Go to commands are built from the same result, so a hidden item has neither a rail button nor a Go to command; the Inbox badge shows only while `railInboxBadge` is on (component test and command-list test, real settings store)
- [ ] `restoreRailItem` gains a last parameter `hidden: readonly string[] = []` and falls back to Today for a saved item in it, except Search and Today; `AppShell.svelte:102` passes the parsed `railHidden`, so hiding the active item shows Today at once and leaves `layout.railItem` unchanged (logic test; the existing callers keep working through the default)
- [ ] The page component lives in `features/rail-shell/` (it reads `railRegistryStore`, and `core/` must not import `features/`, ADR-0003) and is wired through `app/SettingsPanel.svelte` as `SearchSection` is: `SettingsSection` (`core/settings/settings.types.ts`) gains `rail`, `sectionIcons` and `sectionComponents` gain entries, and `SETTINGS_SECTION_GROUPS` (`core/settings/settings.logic.ts`) lists it in General after Sidebar (`SettingsPanel.test.ts` stays green)
- [ ] The page lists every rail item per group, registered navigators included, with a visibility switch (none for Search and Today) and up/down buttons (keyboard-operable, no drag-only reorder; none for Search), plus the badge switch. A switch or a move calls `settingsStore.updateLayout` (a move writes the full order of the listed items) and the rail follows without a reload (component test, real settings store)
- [ ] Hiding Calendar (key `calendar`, `CALENDAR_RAIL_ITEM`) hides its rail button only; its navigator and its Day lens provider stay registered in `railRegistryStore` (test with the navigator and provider registered)
- [ ] ADR 0033 is amended (Settings > Rail); help 19 documents the page

## Notes

- **Owner decisions (2026-11-04):** v1 has hide/reorder of built-in items and the Inbox badge switch; turning off plugin parts (Calendar navigator, My people, New Kanban Board), the start item and width reset are not in this Issue.
- **Owner decision (2026-11-04, Calendar):** the Calendar rail button can be hidden in v1; hiding does not unregister the plugin.
- **Main-session decision (Calendar detail) (owner accepted 2026-11-04):** hiding the Calendar rail button is a hide, not turning the plugin part off. The review keeps the two apart (F52: "hide Archive or Calendar" versus "disable Calendar, My people or New Kanban Board"; option B lists "Hiding Calendar keeps its Day lens provider registered" as its risk), and the deferred I31 is the unregistering. So the Calendar button is hideable and nothing is unregistered.
- **Main-session decision:** reorder within each group only, so the divider structure stays.
- **Main-session decisions (rules):** `railOrder` is one flat list of keys, applied per group; the page writes the full order of the listed items on every move, so unlisted keys only occur for a navigator registered after the last move (it goes after the listed ones). The hidden fallback is applied where the rail item is derived (`AppShell.svelte:102`), so it is live, not only at startup. A command that picks a hidden item still writes `railItem` (New Folder picks Files, `app/commands.ts:98`), and the rail shows Today while that item is hidden; accepted. `neighbourhood` and pin keys are not listed on the page and cannot be hidden.
- **Relation to Issues 21 and 23:** 21 adds the pinned group between the navigators and Archive; it is not part of this page. 23 puts the rail's item list where the rail and the Go to commands share it; this Issue applies hide and order to that shared list. If 23 left the list inside `Rail.svelte`, move it out first so both read one source.
- **Today (traced):** the built-in items are constants and the navigator group comes from `railRegistryStore.navigators` (`features/rail-shell/Rail.svelte:40-53`); no Rail section exists (`core/settings/settings.types.ts:48-92`, `settings.logic.ts:184-226`); section components already live outside `core/` (`app/SettingsPanel.svelte:9,11`); the dock badge switch is `core/settings/sections/QuickCaptureSection.svelte:80-95` and the rail badge has no switch (`Rail.svelte:90-94`).
- **Related, not fixed here:** a settings load failure writes the defaults over settings.json, layout included (`file-io-audit/10`; Issue 09 keeps a backup on a parse failure).
