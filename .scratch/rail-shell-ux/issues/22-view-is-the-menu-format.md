# 22: `.view` is the menu format: `_rail_view`, Convert to view, New view in folders

**What to build:** Three changes make `.view` the one file that defines a menu entry, while `.collection` stays an editor-only table/calendar file. (1) A top-level `_rail_view: <view name>` picks which of a multi-view `.view`'s views the rail runs (list, navigator count, the Sort/Filter toolbar seed and its writes) and which view Edit view (Issue 19) edits; missing or unknown falls back to the first view, and an unknown or non-text value is reported as an ignored-key note on the view's Types row. (2) A `.collection` row in the rail note list (the folder lens's row menu) gets "Convert to view", which renames the file to `.view` through `renameItem` (same content; open tabs follow) and refuses with a toast when the target name exists. (3) The Files navigator's folder menu gets "New view", which opens the New view dialog (Issues 17 and 18) with that folder as the target. The New Collection item gets its own icon. Help 12 and 25 say which file to use for what.

- **Today (traced):** only `.view` is indexed (`src-tauri/src/utils/fs.rs:114-117`) and listed (`features/type-definitions/type-sidebar.logic.ts:297-315`).
