# 20: The Views section has groups, hidden views and Move to Trash

**What to build:** Two `.view` keys and one menu item give Types > Views structure. `_group: Work` puts the view under a "Work" subheading inside Views; views without `_group` stay at the top, ungrouped. Groups sort by name and views inside a group (and the ungrouped ones) by `_order`, then label. `_visible: false` hides the view from Views (it stays a file: the folder lens lists it, and Issue 23's palette command reaches it). The view row menu gets "Move to Trash", with the same confirmation, Trash path and failure toast as Move to Trash on a note. View labels and group names sort naturally ("Week 2" before "Week 10"), like the file tree.

**Blocked by:** 10, 13, 17, 19

**Status:** ready-for-agent

**Gate:** frontend only: `pnpm check` + `pnpm vitest run` + `pnpm build`.

## Notes

- **Review recommendation, no owner decision needed:** option D of the review (section 5, "Owner decision: None") is step 1 of its recommended path, before pins (Issue 21). Review section 9 maps I10 to this Issue.
- **Today (traced):** views are a flat list. `collectViewFiles` sorts with `localeCompare` (`features/type-definitions/type-sidebar.logic.ts:300`) and `sortViewFiles` orders by `_order`, then the filename with `localeCompare` (:355-362), not by the shown label; `viewNavigatorRows` maps them (`lens.logic.ts:511-523`). The view row menu has no trash (`features/rail-shell/TypesNavigator.svelte:262-294`). A saved pick of a deleted view is cleared only at the next vault open (`staleTypesPickFix`, run once from `app/AppShell.svelte:147-165`).
- **Main-session decision (sort key):** rows sort by the shown label, not the filename, matching Issue 21's pins ("`_order`, then label"). For a view without `_sidebar_label` the label is the filename, so most orders do not move. Change `sortViewFiles` (or replace it inside `viewNavigatorRows`) and switch `collectViewFiles`' sort to `naturalCompare` too; the existing `sortViewFiles` tests in `src/tests/lib/features/type-definitions/type-sidebar.logic.test.ts:787-851` and the `viewNavigatorRows` tests in `src/tests/lib/features/rail-shell/lens.logic.test.ts:946-985` are updated to the new rule and the new `group` field, not deleted. `naturalCompare` lives in `core/filesystem/fs.logic.ts`, which `type-sidebar.logic.ts` already imports (allowed: features import core).
- **Main-session decision (hidden pick):** a hidden view can still be the note list's lens (picked before it was hidden, or from Issue 23's palette command); it keeps working and survives a restart, with no highlighted row. Only a view that no longer exists is a stale pick.
- **Main-session decision (trash):** reuse `deleteNoteWithConfirm` rather than copying `NoteRowMenu.svelte:124-131`; `FilesNavigator.svelte:171-177` is the folder variant ("This will include all contents") and does not apply. Trash goes through `deleteItem`, so the path-change owner closes the view's tabs and updates the indexes; do not call `trash.service.ts::moveToTrash` directly. A rename or move of a picked view is not followed here (the vault-open check still covers it).
- **Why after 13:** Issue 13 adds the `_sort` row to Issue 10's reserved-key table, changes how an unknown `_sort` is read in `type-sidebar.logic.ts`, and tests its note on `viewNavigatorRows`; this Issue rewrites `viewNavigatorRows` and adds two rows to the same table. Keep 13's `_sort` row and its note when rewriting the row builder.
- **Duplicate view names (consequence, no change):** the New view and Edit view dialogs (Issues 17, 19, 22) take their duplicate-label list from the Views rows, so after this Issue a view hidden with `_visible: false` no longer reserves its label. That follows the owner decision as written ("a name an existing view already shows is refused"); do not change the dialogs here.
- **Known, not fixed here:** the shared Trash path has open bugs that this item inherits unchanged: the Trash manifest rebuild from a stale store (`.scratch/file-io-audit/issues/11-trash-manifest-stale-rebuild.md`) and a post-disk failure in `applyPathChange` reported as a failed delete (`.scratch/file-io-audit/issues/35-path-change-post-disk-failure.md`). `_group` is not in Rust's `SYSTEM_KEYS` (`src-tauri/src/vault/entry.rs:403-409`), so a `_group` value holding a wikilink also becomes a relationship field; accepted (no Rust change, the Gate stays frontend only).
- **Out of scope:** renaming a view (label) is "Edit view" in Issue 19; a file rename of a view is dropped from option D, because Issue 19 decided a rename never changes the filename. The label frozen as "Untitled" goes away with Issue 17's name dialog. No keyboard shortcut hint on the new menu item.
