# src-tauri Audit — 2026-08-19

Full audit of `src-tauri/`: all 45 Rust source files read in full, plus `Cargo.toml`, `Cargo.lock`, `tauri.conf.json`, `build.rs`, `capabilities/`, and the test suite under `src-tauri/tests/`. Performed by 6 parallel audit agents, one per domain: `vault/`, `search/`+`semantic/`, `db/`, `commands/`+capabilities, `quick_capture/`+`utils/`+`lib.rs`, and project-level config/test coverage.

Findings ranked by severity. File:line references are from the audit date.

---

## Critical

### C1. Write commands are not confined to the vault — arbitrary file create/write from the frontend
`commands/vault.rs:803-815` (`ensure_safe_write_path`), used by `create_note` (:829), `create_folder` (:863), `toggle_task_status` (:694).

The guard only checks "is absolute" and "no `..` component". Any absolute path passes. `create_note` will `write_atomic` any non-existing file anywhere the process can write; `create_folder` runs `mkdir -p` anywhere. The file's own doc comment (:794-802) says the guard exists because `std::fs` bypasses the plugin-fs ACL, but it only stops the `[[../../x]]` wikilink vector, not a fully absolute out-of-vault path. The capability fs scopes create a false sense of confinement — they don't apply to app-defined commands.

### C2. `toggle_task_status` is an arbitrary file read
`commands/vault.rs:649-676`.

On the no-op branch (line out of bounds, no checkbox) it returns the full content of whatever `path` points at, with zero validation. `toggle_task_status("/Users/<user>/.ssh/id_rsa", 0)` returns the file content verbatim.

### Root cause of C1+C2 (fix once)
The backend has no notion of "the open vault". `validate_vault_path` (`utils/fs.rs:39-47`) only canonicalizes and checks `is_dir()`, and the `vault_path` argument is frontend-controlled per call — a compromised frontend picks the root itself (`read_files_batch("/", ...)` passes).

**Fix:** store the canonical vault root in managed state at vault open (`open_vault_db` / `scan_vault_v2` already canonicalize), and have every command verify passed paths canonicalize under the stored root — the pattern `read_files_batch` already uses (`files.rs:36-59`). This also closes:
- `open_vault_db` opening/creating a SQLite DB under any directory's `.kokobrain`
- `download_semantic_model` / `download_reranker_model` writing ~600MB-4GB into any directory
- `update_note_in_index` / `remove_note_from_index` / `rename_note` (vault.rs:293, 879, 982) accepting arbitrary paths — index pollution flows into `propagate_type_rename`'s disk writes

### C3 (related). Custom commands are not gated by Tauri capabilities
`capabilities/composer.json` is minimal, but Tauri capabilities only gate *plugin* commands. All app-defined `#[tauri::command]`s are invokable from any webview, including the composer popover. If composer content is ever rendered as HTML, XSS there gets full file write via C1/C2.
**Fix:** check the webview window label in destructive commands and reject non-`main` windows.

## High

### H1. One panic bricks the entire DB layer permanently
`db/mod.rs:63, 83, 93, 96, 114, 125, 156, 166, 192` — all `DB.lock().map_err(...)`. A poisoned mutex makes `with_db`, `with_db_transaction`, `open_database`, and even `close_database` fail until app restart. No `into_inner()` recovery anywhere.
**Fix:** `DB.lock().unwrap_or_else(|e| e.into_inner())` in all nine sites (same for `FTS_DB`). The guarded value is just `Option<Connection>` — a poisoned std Mutex still holds valid data here.

### H2. Model-hash persisted before reindex — a crash bricks semantic search permanently
`commands/semantic.rs:368-376` + `:1210-1225`. Phase 1 of `build_semantic_index` writes the new `model_hash` and clears all chunks. If the app exits/errors before Phase 3 completes, next launch computes `model_changed = false`, mtimes all match, `changed_files` is empty → early return at :412 with an **empty chunks table**. Search returns nothing forever, no trigger to rebuild.
**Fix:** on model change, also delete all `mtime:*` rows in the same transaction as `clear_all_chunks` (or defer the `upsert_meta("model_hash", ...)` until the build finishes).

### H3. Quick-capture commands and global-shortcut handler block the main thread
- `quick_capture/commands.rs:243` `capture_clipboard_now` — non-async `#[tauri::command]` → runs on the main thread; shells out to `osascript` (`source.rs:243-259`, routinely 100ms-2s, can hang on an Apple Events permission prompt). Same for `submit_composer_capture` (:356).
- `lib.rs:242-249` — global-shortcut handler runs the same blocking chain (osascript + clipboard read + RGBA→PNG re-encode) on the event-loop thread. A slow browser freezes the whole app on every hotkey press.

**Fix:** make the commands `async` / `tauri::async_runtime::spawn` from the shortcut handler.

Related contradiction: `commands.rs:291-293` documents that `NSWorkspace.frontmostApplication` belongs on the main thread, and `show_composer` wraps it — but `capture_clipboard_now` and `dispatch_shortcut` call `frontmost_bundle_id()` off the main thread. Pick one threading story.

### H4. Watcher stop path does not suppress the stale-path flush it claims to fix
`vault/watcher.rs:142-190` + `:280-315`. The comment on `start_vault_watcher` claims dropping the old watcher makes the bridge's final flush complete before a new watcher is installed. In fact: the bridge is almost always blocked in `recv_timeout`; dropping the watcher drops `event_tx`, so the loop takes the **Disconnected arm, which flushes the buffer with the old vault's paths** — the stop signal is never observed. And the flush is asynchronous (bridge never joined), so old-vault absolute paths can land in the new vault's TS handler. Protection currently depends on `read_files_batch` rejecting old-vault paths — accidental, not design.
**Fix:** in the `Disconnected` arm, check `stop_rx.try_recv()` first and skip the flush on stop; optionally join the bridge thread under the lock (bounded by `DEBOUNCE_MS`).

### H5. Shortcut registration failure aborts the whole app
`lib.rs:259`: `register_multiple(shortcuts)?` in `setup` — if another app owns the hotkey, Tauri aborts startup entirely.
**Fix:** register one-by-one, log failures, continue.

### H6. No single-instance guard
`lib.rs` never registers `tauri-plugin-single-instance`. A second launch collides on the same global hotkeys (→ H5 crash) and shares the same vault SQLite. Turns "user double-clicks the app" into crash-or-duplicate-writer.

## Medium

### M1. Embedder silently truncates every chunk to 512 tokens, contradicting the 3000-char (~700 token) chunk budget
`semantic/embedder.rs:132-135` — `max_len.min(512)` clamps the tensor width but the tokenizer has no `TruncationParams` (unlike the reranker, `reranker.rs:74-80`). Chunks over 512 tokens (routine for 3000-char prose, guaranteed for CJK >500 chars) have their tail silently dropped; naive truncation can also cut the closing special token.
**Fix:** `with_truncation` on the tokenizer; align `max_chunk_chars` with the model cap; bump `EMBED_RECIPE_VERSION`.

### M2. Heading detection ignores fenced code blocks
`semantic/chunker.rs:69-74, 246` and `search/fts_logic.rs:11-29`. `heading_level` runs on raw lines with no fence tracking — a `# foo` inside a ``` fence splits sections: (a) a note whose only "headings" are in code fences takes the heading path instead of `window_chunks`, producing a single chunk truncated at `max_chunk_chars` (the data loss the window fallback exists to prevent); (b) `strip_code_blocks` resets fence state per section so code body lines leak into chunk content; (c) FTS `extract_headings` indexes headings inside code blocks.
**Fix:** track fence state in the line loops of `split_into_sections`, `has_heading`, and `extract_headings`.

### M3. `adaptive_filter` gap threshold tuned for cosine [0,1] but fed raw reranker logits (±10)
`semantic/filtering.rs:43-53`, caller `commands/semantic.rs:717-731`. `search_semantic` overwrites `score` with the rerank logit, then filters. `gap_threshold = top.abs() * 0.04` is tiny on the logit scale (top 5 → 0.2, while normal logit gaps are 1-3), so the gap filter fires on almost every reranked query and can cut results to 1-2 items even when more are relevant.
**Fix:** skip the gap filter for logit scores (filter before rerank) or sigmoid-normalize first.

### M4. FTS rebuild skip heuristic never reconciles changes made while the app was closed
`commands/search_index.rs:47-61` — rebuild skipped when `|disk_count - existing_count| <= max(5%, 5)`. Delete 50 notes and create 50 different ones between restarts → counts equal → FTS serves deleted content forever, no self-healing.
**Fix:** fingerprint by max mtime + count, or a hash of sorted (path, mtime) pairs — `collect_markdown_paths` can produce it during the walk it already does.

### M5. `remove_from_search_index_inner` runs two-statement delete without a transaction
`commands/search_index.rs:193-196` uses `with_fts_db` (no transaction) but `fts_repo::delete_entry` (`fts_repo.rs:98-120`) is two statements. A crash between them leaves a `notes_content` row with no FTS entry — skews the count heuristic (M4) and is unsearchable until the next full rebuild. Sibling write paths correctly use `with_fts_db_transaction`.
**Fix:** one line — switch to `with_fts_db_transaction`.

### M6. `build_semantic_index` fails after the embedder idle-unloads
`commands/semantic.rs:512-519` vs `:632-634`. Phase 3 does `guard.as_mut().ok_or("Embedder not initialized")?`, but `unload_embedder()` runs after every build and on a 120s idle timer. Unlike `search_semantic` (:657) and `update_semantic_file` (:984), the build path never calls `ensure_embedder_loaded()`. Manual "rebuild index" >2 min after last search errors out.
**Fix:** one line — `ensure_embedder_loaded()?` before Phase 3.

### M7. `get_tasks_in_section_v2` holds the VaultIndex read lock across N synchronous disk reads on the IPC thread
`commands/vault.rs:599-642` — sync command, `state.read()`, then `fs::read_to_string` for every indexed note inside the lock. Stalls the IPC thread and blocks every `update_note_in_index` writer (save path). `get_unlinked_mentions_v2` (:528-561) already solved this exact shape (snapshot under lock → `spawn_blocking` → re-lock for lookups). Apply the same split.

### M8. `strip_non_body_content` pairs code fences across the frontmatter boundary
`vault/parsing.rs:911-955`. Frontmatter bytes are spaced out in `out`, but the fence-pairing scan runs over the original content from `search_from = 0`. A ``` sequence inside frontmatter pairs with the first body fence opener, spacing out everything in between — plain-text mentions in that range become invisible to `match_unlinked_mentions` / `lookup_outgoing_unlinked_mentions`. Silent missed unlinked mentions.
**Fix:** start the fence scan at `effective_end` (one line). No existing test covers a fence marker inside frontmatter.

### M9. Blocking sync commands with unbounded work on the IPC thread
- `read_files_batch` (`files.rs:22-83`): sync; N canonicalize+read syscalls; no cap on `paths.len()`, no per-file size cap — a 500MB `.md` is read fully and serialized over IPC.
- `scan_vault` (`vault.rs:69-78`): sync recursive walk; `scan_vault_v2` shows the async pattern exists.
- `save_vault_cache` (`vault.rs:1334-1353`): sync; clones and serializes the entire index on teardown.
- `save_snapshot` (`history.rs:36-57`): sync DB write of unbounded `content` on every auto-save.
- `search_fts` (`search_index.rs:120`): sync; with `fuzzy: true` runs a vocab query + up to 500 Levenshtein computations per query term on the IPC thread.

All UI-freeze vectors of the kind the `CmdTrace` instrumentation was added to hunt.

### M10. CSP allows `script-src 'unsafe-eval'`
`tauri.conf.json:29`. Required by QueryJS (executes user scripts via eval), so not removable without redesigning that feature — but any XSS in rendered markdown becomes full script execution. Comment the dependency; re-evaluate if QueryJS ever moves to a sandboxed iframe.

### M11. FTS5 schema-migration branch untested
`db/schema.rs:82-113` drops and recreates `notes_fts`/`notes_content`/`notes_fts_vocab` on version mismatch. No test exercises the mismatch path — a bad migration ships silently and wipes every user's search index at startup. **Highest-priority test gap.**
Also untested: `parent_headings` ALTER migration (:68-76), which string-matches "duplicate column name" (brittle against SQLite error text — more robust: `PRAGMA table_info(chunks)`).

### M12. `walk_dir*`: one unreadable entry fails the entire vault scan
`utils/fs.rs:135-139` (and identical :189-193, :245-249) — `read_dir`/entry errors propagate and abort the whole walk. One permission-denied subfolder kills indexing of everything. Every other per-file failure in the same loop is `continue` — inconsistent.
**Fix:** log-and-continue on subdirectory `read_dir` errors (keep the root call fatal) and on bad entries. Apply to all three walkers (they're copy-paste — see L11).

### M13. Cache reconciliation trusts second-granularity mtime alone
`commands/vault.rs:1221` (`cached.modified_at == *mtime`). A file edited twice within the same second (autosave at 500ms debounce makes this plausible) is served the stale cached `NoteEntry`. `size` is already collected and ignored.
**Fix:** require `cached.modified_at == *mtime && cached.size == *size`.

### M14. `search_semantic` clones every chunk's key/content/heading for the whole index before filtering — per query
`commands/semantic.rs:679-694` — builds a full `SemanticResult` (four heap clones per chunk) for every cached chunk, then discards most. ~10k string allocations per query on a 10k-chunk vault. `search_hybrid` (:803) already does it the cheap way.
**Fix:** score and filter on `&CachedChunk` first, clone only survivors.

### M15. Model downloads have no integrity verification
`semantic/model.rs:141-189` — 571MB / ~2GB binaries fetched from HuggingFace and executed by ONNX Runtime, only HTTP-status checked. A pinned SHA-256 per model file is a few lines. Also: progress callback never fires when `content_length()` is unknown (:179), freezing the progress bar; corrupted download only surfaces later as an ONNX load error.

### M16. `write_atomic` breaks symlink semantics and drops target permissions
`utils/fs.rs:16-32` — rename replaces `path` itself: a symlinked note is silently converted to a regular file, and a `0600` target gets umask 0644 on every save. The read-only guard follows the symlink while the rename does not — the two halves disagree about what "the target" is. (Vault walker skips symlinks, but symlinked notes are a real Obsidian pattern.)

## Low

### Config / build
- **L1.** CSP `img-src ... https:` allows any remote image (tracking pixels) — `tauri.conf.json:29`.
- **L2.** `assetProtocol.scope` includes `$DESKTOP/**`, `$PICTURE/**`, `$DOWNLOAD/**` (`tauri.conf.json:39-41`) — much wider than the capability fs scopes; inconsistent policy. Trim if vaults are truly confined.
- **L3.** `build.rs` watches `../.git/HEAD` + `../.git/refs` but misses packed-refs — GIT_HASH can go stale.
- **L4.** Duplicate transitive dep versions in Cargo.lock (`base64` ×4 — 0.13.1 via `tokenizers`, only fixable by a tokenizers bump; `hashbrown` ×5; `sha2` 0.10 alongside 0.11). Build-time/binary-size cost only. `ort = "2.0.0-rc.13"` is a pre-release pin (deliberate ONNX-runtime risk).

### db/
- **L5.** `open_database` can leave the layer half-initialized: if FTS open fails after `DB` was set, `is_open()` is true but every `with_fts_db` fails — `db/mod.rs:62-85`. Clear `*db = None` on FTS failure.
- **L6.** `search_match` converts query/runtime errors into "no results" (`fts_repo.rs:80-87`) — FTS5 syntax errors surface at step time and return `Ok(vec![])`, indistinguishable from a legit empty result; mid-iteration I/O errors silently truncate. Collect `Result<Vec<_>,_>` for `search_match` only; keep skip-and-log in the semantic repo.
- **L7.** `upsert_mtimes` re-prepares the INSERT per row inside the batch transaction (`semantic_repo.rs:67-76`) — prepare once outside the loop.
- **L8.** Dead index `idx_chunks_hash` on `chunks(content_hash)` (`schema.rs:53`) — no query reads by `content_hash` alone; costs write time per chunk insert.
- **L9.** No `VACUUM` after `clear_all_chunks` or large history prunes — file stays at high-water mark.

### vault/
- **L10.** `vault_path_hash` documented as "first 16 hex chars of sha256(...)" but stores the raw path, and is never validated (`index_cache.rs:22-23` vs `:96`). Drop the field (bump `INDEX_SCHEMA_VERSION`) or store/validate the documented hash.
- **L11.** Three near-identical `walk_dir*` functions (`utils/fs.rs:124-295`, ~170 lines) — copy-paste with one tuple-field difference; a fix to one must be applied three times (exactly how the error handling in M12 drifted).
- **L12.** `update_entry` retro-backlink inserts not reported in `UpdateResult.affected` (`index.rs:513-518`); `remove_entry` documents and honors the opposite contract. Consumers survive via the version bump.
- **L13.** `organized` doc says "Default `false`" but code returns `true` when absent (`entry.rs:187` vs `:240-243`) — tests confirm `true` intended; fix the doc.
- **L14.** Asymmetric extension-case handling in `extract_title_from_path` (`entry.rs:300-308`): strips `.md`, `.markdown`, `.view`, `.VIEW` but not `.MD`, `.Markdown`, `.View`.
- **L15.** Two full-vec clones of every entry per scan (`commands/vault.rs:1171`, `:1276`) — tens of ms + double peak memory on large vaults; write the snapshot from `idx.entries().values()` after build.
- **L16.** Stop signal silently discards buffered changes (`watcher.rs:145-147`) while the Disconnected path flushes — two stop paths, two semantics; accidental inconsistency (see H4).
- **L17.** `lookup_all_tags` display casing depends on `HashMap` iteration order (`index.rs:831-837`) — nondeterministic IPC payload when authors mix casing (documented in comment).

### search / semantic
- **L18.** `window_chunks` infinite-loops if `max_chunk_chars == 0` (`chunker.rs:183-216`) — fields are pub; only `Default` protects today. Clamp `window.max(1)`.
- **L19.** `extract_tags` hand-rolled frontmatter parser (`fts_logic.rs:36-77`): `\n---` matches `\n----` (hr), ending frontmatter early; unclosed frontmatter leaks `#tags` into the index; fence-stripping loops are O(n²) in fence count.
- **L20.** Fuzzy expansion can't match first-character typos (`fuzzy.rs:59-62`, `LIKE '<first-char>%'`) — `hte → the` never expands. Documented tradeoff; add a comment.
- **L21.** `build_semantic_index` clones all changed file contents (`semantic.rs:425`) — full vault text duplicated on first index; split into `(paths_and_mtimes, contents)` once.
- **L22.** Reranker dead code `let _ = max_seq_len;` (`reranker.rs:82`) — variable is used at :76; delete.
- **L23.** `adaptive_filter` redundant condition (`filtering.rs:44`) — always true given the loop bound; drop it.
- **L24.** `compute_model_hash` reads only the first 8KB of `model.onnx` (`semantic.rs:1187-1206`) — same-prefix model swap is invisible; acceptable given `EMBED_RECIPE_VERSION` is mixed in.
- **L25.** `update_semantic_file` silent `Ok(())` when embedder is `None` after successful `ensure_embedder_loaded` (`semantic.rs:987-992`) — practically unreachable; file just never indexes until next mtime bump.
- **L26.** Batch-size inconsistency: embedder tuned to 8 (`INFERENCE_BATCH_SIZE`, comment claims "~doubles throughput") but the bulk indexer sends 4 (`semantic.rs:482`) — the tuned batch never engages during bulk indexing.
- **L27.** RRF duplicate-key test name contradicts behavior (`rrf.rs:125-130`) — code sums both contributions (fine); rename the test.
- **L28.** Headless window chunks report `line_end = end of file` for every window (`chunker.rs:206`) — jump-to-line lands wrong for all but the last window; documented tradeoff.

### quick_capture / utils / lib
- **L29.** Logger tests share the global `DEBUG_ENABLED` atomic — order-dependent under `cargo test` parallelism (`utils/logger.rs:62-88`).
- **L30.** `tauri-debug-log` is emitted to **all** windows including the composer, and can carry vault paths / note content — gated by `DEBUG_ENABLED`, acceptable, but the broadcast isn't scoped.
- **L31.** `qc-shot-*` temp files never cleaned up by the app (`quick_capture/commands.rs:130-149`) — relies on the macOS `$TMPDIR` sweep.
- **L32.** `.expect("invalid accelerator string...")` on startup (`lib.rs:230`) — mitigated by registry tests; a match-and-skip would be more robust.

## Verified clean / non-issues

- **SQL injection:** none. Every query parameterized; the only `format!` into SQL interpolates a compile-time constant. FTS MATCH built from sanitized + quoted terms.
- **`cargo audit`:** 0 vulnerabilities. 34 "unmaintained" advisories (gtk-rs stack, Linux-only; `paste`, `proc-macro-error`, `unic-*` transitives) plus the documented RUSTSEC-2024-0429 ignore. `cargo outdated`: all direct deps current.
- **Release profile:** `lto = "thin"`, `strip = true`, `codegen-units = 1` — good.
- **Capabilities** (aside from C3): every `fs:allow-*` scoped to the two vault roots + `$APPLOG`; `opener:allow-open-path` is `$APPLOG`-only; `http:allow-fetch*` is Todoist-only. Updater endpoint HTTPS + minisign. No devtools feature.
- **Transaction correctness** elsewhere in db/: rebuild, per-file FTS update, semantic batch, orphan cleanup, history cleanup all use BEGIN IMMEDIATE + rollback-on-error, proven by `db_concurrent_test.rs`.
- **vault/ module:** all `unwrap`/`expect` in non-test code verified safe; `String::from_utf8_unchecked` in `strip_non_body_content` is sound; reverse-index lock-step maintenance (backlinks/tags/properties) correct, traced against tests; debounce loop has no busy-spin or starvation; `is_inside_hidden_dir` and `filter_ancestor_paths` correct; test coverage genuinely strong.
- **search/semantic:** UTF-8 slicing char-boundary-safe everywhere; RRF math correct (1-indexed, k=60); all ONNX load/inference inside `spawn_blocking`; no `unwrap` on user content; caches bounded (single-slot search cache, generation-countered unload timers).
- **commands:** `read_files_batch` canonicalize + `starts_with` + read-via-canonical-path is TOCTOU-safe given a trusted root (the root trust is the weak link, not this code); `update_channel.rs` endpoints are compile-time constants; `fonts.rs` FFI buffer sizing and `CFRelease` correct; no locks held across `.await`; mutex poisoning handled with `map_err` throughout the command layer.
- **quick_capture:** `url_from_trimmed` `expect` unreachable-safe; dedup anchor logic correct; no lock held during emit; shortcut registry has no duplicate accelerators; symlink handling in walkers correct (lstat + skip).

## Priority order

1. **C1+C2+root fix** — server-side vault-root state; one design closes C1, C2, C3-adjacent paths, arbitrary DB open, arbitrary model download, index pollution.
2. **H1** (poison recovery, ~9 lines), **H2** (mtime rows in the same transaction, small diff) — both "permanent damage" class.
3. **H4** (watcher stop/flush race — code contradicts its own audit comment), **M8** (cross-boundary fence pairing — silent missed mentions).
4. **H3+H5+H6** together (quick-capture threading + hotkey resilience + single-instance).
5. **M5, M6** — one-line each.
6. **M4** (FTS staleness fingerprint), **M1** (truncation — needs `EMBED_RECIPE_VERSION` bump), **M2** (fence tracking), **M3** (logit-scale gap filter).
7. **M11** — FTS migration test (failure mode: silently wiped search index for every user on upgrade).
8. Freeze class: **M7, M9, M14**.
