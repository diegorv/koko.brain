## Findings

1. **major** (not a blocker): `src/lib/plugins/graph-view/graph-view.service.ts:24-27`. The center is captured only by `openGraphTab()` and `toggleGraphTab()`. The other ways to focus the graph tab keep the previous center: clicking it in the tab bar (`editor.service.ts:255` `switchTab`), tab cycling, closing a neighbouring tab, and a session restore. Probe: open the graph from A, open note B, then `switchTab(<graph index>)`. The active tab is the graph and `centerPath` is still `/vault/A.md`, so local mode centers on A instead of B. The owner decision (D6 a) says "opened or focused", and a tab-bar click is a focus. The Issue's prescribed fix, though, names only these two functions, and the result is never worse than main (main always showed an empty canvas). Fix in a follow-up Issue: a plugin-side tracker, registered from the app layer, that records the last active markdown note whenever `editorStore.activeTab` changes. Core cannot import the plugin (ADR-0003), so it cannot live in `switchTab`.
2. **minor**: `src/lib/plugins/graph-view/graph-view.service.ts:31`. `openGraphTab()` captures before it checks whether the graph is already the active tab. Calling it with the graph active sets the center to null. Probe: A, then `openGraphTab()` (center A), then `openGraphTab()` again gives center `null`. No app code calls `openGraphTab()` directly today (`commands.ts:187` and `global-keybindings.ts:112` go through `toggleGraphTab()`, which closes an active graph), so this is latent. Fix: capture only when `editorStore.activeTabPath !== GRAPH_VIRTUAL_PATH`, or keep the old center in that case.
3. **minor**: `src/lib/plugins/graph-view/GraphView.svelte:430`. The hint is shown only when `centerPath` is null. If the center note was renamed, moved or deleted after the graph captured it, `getLocalGraph` finds no node, and local mode shows an empty canvas with no hint, which is the original symptom in a rarer form. Fix: show the hint when the center is not in `fullData`, or clear the center through a path-change consumer. Follow-up material.
4. **nit**: `src/tests/lib/plugins/graph-view/GraphView.test.ts`. The active-node highlight in global mode has no test, because jsdom has no 2D canvas and `render()` returns early. The build report says so. The change at `GraphView.svelte:230-233` is a one-line swap of the variable it reads.

## Resolution

1. Deferred to a follow-up Issue, as the review recommends. A center that follows every focus of the graph tab (tab-bar click, cycling, neighbour close, session restore) needs a plugin-side tracker of the last active markdown note wired from the app layer, which is outside this Issue's prescribed fix (`openGraphTab` / `toggleGraphTab`). The branch is never worse than main here.
2. Fixed. `openGraphTab()` returns early when the graph is already the active tab, so the center is kept. Test: `graph-view.service.test.ts` "keeps the center when called while the graph tab is already active" (failed before the fix, passes after).
3. Deferred to the same follow-up. `fullData` in `GraphView.svelte` is a plain `let`, not `$state`, so a hint keyed on "center not in fullData" needs the data made reactive or a path-change consumer that clears the center; both belong with the tracker work in finding 1.
4. Accepted as is. jsdom has no 2D canvas, so `render()` returns before drawing nodes; the change is a one-variable swap.
