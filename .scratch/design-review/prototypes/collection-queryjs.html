P48

Clicking a collection header silently stacks multi-column sorts

clear, S

Problem: a second click on another header appends a sort. The header shows only an arrow (no rank, no aria-sort), the result contradicts what the header suggests, and the stack is written to the .view file.

Try on both: click 'status', then click 'priority'.
Before (current behavior, live recreation)

				
Click appends the column to the stack. The header shows an arrow only, so the order of precedence is invisible. No aria-sort, not focusable.

			

			

				
After (proposed)

				

				

				
Click sorts by that column only. Shift+click (or Shift+Enter) adds it as the next sort. Rank badges show when more than one sort is active.

			

		

		
    
			
  • Compare: Before, status then priority stacks silently: status wins and priority only breaks ties, with no sign of it. After, the second click replaces the sort; Shift+click on 'priority' adds it as sort 2 with rank badges 1 and 2.
    • 
			
  • A11y: each th carries aria-sort (ascending, descending, none), is focusable, and reacts to Enter / Space (Shift+Enter adds a secondary sort). Inspect the DOM to see the attributes.
    • 
			
  • The cycle per column stays ASC, DESC, off. The block under each table is the exact viewSort that would be persisted to the .view file.

Before (current: onclick only)

    • 
				

			

			

				
After (proposed: mousedown stopPropagation)

				

				
    
					
  • Prev/Next handle mousedown with stopPropagation(), exactly like the Run and Run again buttons in the same widget (queryjs-block-widget.ts:211-217, 326-329). Paging works.
    •

P142
Collection tables have no sticky header or cell truncation
moderate, S

	
Problem: over 200 rows the header scrolls away, and every cell is nowrap with no max width, so one long value widens its column and pushes the rest off screen.

		

			

				
Before (current, 40 rows)

				

				
Header scrolls away; the Summary column runs off the right edge and pushes everything else.

			

			

				
After (proposed, 40 rows)

				

				
Header stays pinned with a soft shadow once scrolled; Summary is truncated with a tooltip.

			

		

		
    
			
  • Sticky header: thead th gets position: sticky; top: 0 with the card background. Scroll both tables to compare.
    • 
			
  • Truncation: text cells cap at a max width with truncate and a title tooltip (hover the Summary cells).
    • 
			
  • Implementation caveat: sticky sticks to the nearest scrolling ancestor. The wrapper today is overflow-auto with no bounded height, so the header would not stick while the outer pane scrolls. The standalone view gives the wrapper a bounded height (here 300px, in the app flex-1 min-h-0) so it becomes the scroller. Alternative: overflow-x-auto only, so sticky resolves against the page scroller.
