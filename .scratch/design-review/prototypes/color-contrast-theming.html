SHEET

Measured ratios, Lavender Haze and KokoBrain Default, before and after

Red means below its target, green meets it. Targets: 3:1 for boundaries and the faint tier, 4.5:1 for text, at most 1.5:1 for the tab strip against the editor, and a colour distance of at least 20 for bold against link.

Rows are the pairs the proposals add to READABILITY_PAIRS (theme-builder.logic.ts:105). After values are what ensureContrast would produce starting from today's token, so they are illustrative hexes, not a final palette.

P26

Control boundaries fail non-text contrast

moderate

The off switch track is 1.12:1 on a setting item and the input border 1.08:1 (Lavender); WCAG asks 3:1 for the edge of a control.

Before real app, then recreation

After --control-border at 3:1, 1px border on the off switch

Try it: click the switches. Input and select share one surface and one border token (--control-border). The On state is unchanged (primary fill).
P27

Error text is held to 3:1, and the destructive button uses literal white

moderate

Error text on setting items is 3.4 to 3.7:1; it needs a separate --error-text token at 4.5:1 on every panel surface while --destructive stays for fills.

Before real app, then recreation

After --error-text, button uses destructive-foreground

Dark theme detail: the button also loses dark:bg-destructive/60. Without that, destructive-foreground (#171717) on a 60% fill would be far below 4.5:1, so the fill goes to full strength. Muted text on hover (4.05:1 in both themes) gets its own pair at the same time, not prototyped here.
P25

Text on selected rows and alpha-faded text drops below 4.5:1

moderate

Selected-row subtitle, 11 px chips and archived rows sit at 2.4 to 3.9:1, and 28 classes fade text with an alpha.

Before real app, then recreation

After selected tokens, full-strength chips, no opacity-60, --faint-fg

Try it: click a row to select it, hover for the hover state. The archived row keeps its Archive icon, which already marks it. The faint tier (--faint-fg, 3:1) replaces the one-off alphas for out-of-month days, "Add property" and disabled text; secondary text such as snippets uses muted (4.5:1 or better). Not prototyped: a lint ban on alpha text; the proposal itself says to add pairs per surface instead.
P23

The focus ring is drawn at 50% and many controls have none

moderate

The ring measures about 2:1, the destructive ring about 1.3:1, and a dialog close rings when it opens; borderless targets show nothing.

Before real app, then recreation

After --focus-ring, 2px with 2px offset, :focus-visible only

Try it: press Tab inside either mock to walk the controls with the keyboard, or tick "Show focus on every control" to compare them at once. Click "Open dialog": Before rings the close button on open, After only when it was reached by keyboard. Bare buttons, the tags control and the text input in the list row have no style Before and get the same ring After; rows get an inset ring.
P85

One selected-row treatment across surfaces

moderate

Files, the note list, Tasks lists and settings nav each select differently (primary/25 text, primary/25 fill, bg-accent, the hover token). The rail tint stays as ADR-0033 defines it.

Before real app, then recreation

After --state-hover, --state-selected, --state-selected-fg

Try it: click and hover rows in each panel. The rail column is identical Before and After: the 18% hue tint keyed to aria-current="page" is the ADR-0033 decision, so this proposal leaves it alone. In the settings nav, selected and hover are no longer the same colour. Selected titles move from primary text (3.9:1 on the fill) to foreground; the selected pair goes into READABILITY_PAIRS. Trade-off: with foreground text the only selected cue is the 16% tint, so it is visibly quieter than today's primary-coloured title.
P19

Tag chips, rail badges and linear calendar bars are blind to the theme

moderate

Kanban chips measure 1.6 to 2.9:1 on light themes, rail badges use white on yellow and teal, and the full-tab calendar hardcodes text-white.

Before real app, then recreation

After chip text mixed toward editor-fg, badge and bar text by contrast

Rail icon colours are unchanged (ADR-0033 fixes them on purpose); only the badge text changes. Finding: the --type-* tokens would not be enough for 12 px chips: they are checked at 3:1 and measure 3.1 to 4.6:1 on Lavender (for example orange 3.14, yellow 3.19), so the chip text here is the preset mixed toward the editor foreground until it reaches 4.5:1. Chip fills (15% preset) are unchanged. Bar text uses the same black-or-white pick as barTextColor.
P20

Bold shares the link hue, section titles share the accent

moderate

In KokoBrain Default, bold (#93c5fd) sits beside the link blue (#60a5fa); right-sidebar section titles use primary, and mini calendar weekends use primary too.

Before real app, then recreation (dark theme)

After bold = editor foreground, titles = foreground, weekends = muted

This section stays on the dark theme whatever the toggle says. Lavender Haze is not touched: heading equal to primary there is left as an owner taste call, as the proposal states. The builder check (a minimum colour distance between strong/emphasis and link/wikilink) would flag the Before pairing; the distance row in the sheet shows 10.7 Before and 30.4 After. Today and the selected day in the calendar are already distinct, so they stay.
P109

The dark tab strip is the brightest surface

moderate

KokoBrain Default overrides tabBar to #5a5c79, 2.1:1 lighter than the editor, so chrome outshines content.

Before real app, then recreation (dark theme)

After tabBar derives from sidebarBg (#21222e)

Dark-only, so it stays dark. The active tab already uses the editor surface, so it reads as joined to the content after the change. Tab text keeps its contrast (inactive #d3d7e7 on #21222e is 11:1, up from 4.5:1). Lavender's #edeaf2 strip is already within 1.1:1 of the editor and is not touched.
P106

The vault picker paints dark whatever the last theme was

polish

app.html ships class="dark" and settings load per vault, so the picker never sees the applied theme; the localStorage cache the composer window already uses is not applied in the main window.

Before real app (Lavender Haze was active)

After applyStoredTheme() at boot paints the last applied theme

Try it: the recreation follows the toggle above (it stands for "last applied theme"). Tick "No cached theme" to see first launch, which falls back to the dark default, as today. The fix is one call before any vault loads; "Match system" pairing is a later feature and is not shown.
P107

The theme editor lists 128 raw tokens

polish

Before recreated from ThemeEditor.svelte (no screenshot of the editor was captured)

After Simple (core palette) and Advanced (overrides with per-token reset)

P108

A catalog failure is reported twice, and Install does not apply

polish

A failed fetch shows a toast plus an inline error, and installing a theme leaves the old one active.

Before real app, then recreation

After one inline error with Retry, plus Install and apply

Try it: use Loading / Loaded / Error in each mock. Choosing Error in Before raises the toast again. In Loaded, Before installs without applying; After offers Install and apply. Caching the catalog is left out because ADR-0035 accepts a fetch on every visit.
