# Design review: Todoist, mods, one-on-one, templates, QueryJS, quick capture, composer

Evidence: code read (file:line) plus screenshots settings-todoist-light, settings-queryjs-light, settings-labs-light, settings-quick-capture-light, settings-1-1-notes-light, landing-today-light, collection-and-queryjs-block-light. The composer window, mod dialogs, template picker and 1:1 picker are not in the screenshot set; those findings come from code only.

## Clear

1. Todoist "Root project" control overflows onto its own description (TodoistSection.svelte:123-148; SettingItem.svelte:37). The inline layout gives the control column max 50% width with shrink-0 and justify-end; "Load projects" button plus a w-44 select is wider than that, so it spills left over the text. settings-todoist-light.png shows "Load projects" covering "every project nested under it". Proposal: use the stacked layout for this row, or put the button under the select as a text link ("Refresh list"), and load the project list automatically once a token exists.
2. Capture success is nearly invisible, and clipboard captures give no feedback at all (deep-link-actions.ts:206-223 writes the note and returns, no toast; no notification code in src-tauri/src/quick_capture; composer +page.svelte:141-151 shows only a 180 ms inset ring, then hides). The user never learns which folder or file name the capture got (Folder/Filename format settings are date patterns). Proposal: after a successful capture show a toast in the main window ("Captured to Inbox/2026-11/capture-...md", with an Open action), and also for the clipboard shortcut kinds; in the composer, lengthen the confirmation to a check icon plus "Saved" in the hint line for about 600 ms.
3. Composer hint line is wrong about Esc and hides state (+page.svelte:255, 188-198, 166-186, 41, 105-110). "ESC cancels" is shown, but Esc only hides the window: the text is kept in localStorage and restored on the next summon, so the user either fears losing text or is surprised to see old text come back. There is also no cue that a draft was restored, no "Saving..." state during the up-to-3 s wait for the main window (RESULT_TIMEOUT_MS), and Cmd+Enter on an empty composer silently dismisses. Proposal: hint reads "Esc hides (draft kept) . Cmd+Enter saves"; show "Draft restored" plus a Discard link when text pre-exists; during saving show "Saving..." and disable the hint; add a small clear-draft affordance (Cmd+Backspace in an empty-selection state is enough).
4. Todoist sync status and log are not discoverable or actionable (TodoistSyncStatus.svelte:17-30; commands.ts:278, 284; AppOverlays.svelte:25). The status-bar chip is a non-interactive span; the error text is only in `title` (hover), and "Sync now" and the sync log exist only as palette commands. A user who sees "Todoist sync error" cannot click it to learn why. Proposal: make the chip a button that opens the sync log dialog (with the last error pinned at the top and a "Sync now" button), keep the title as a secondary tooltip, and add a "View sync log" and "Sync now" button next to the Sync switch in settings.
5. Template picker leaves out where the file goes and what was chosen (TemplatePicker.svelte:65-91; templates.service.ts:55-70, note-creator.service.ts:87-90). The naming step title is "New File Name" with no template name; the file is always created in the vault root (`${vaultPath}/${fullFileName}`) even when the user is in a folder, and the hint only says "Press Enter to create foo.md". If the name exists, openOrCreateNote opens the existing note with no message. There is no way back to the template list except closing everything. Proposal: in the naming step show a chip with the chosen template and the destination folder ("in /", editable or defaulting to the active folder), Backspace on an empty field returns to the list, and say "foo.md exists, Enter opens it".
6. Destructive mod confirmations focus the destructive button (ModDialogHost.svelte:132-139, 74-79). The confirm button always receives initial focus and Enter confirms, even when `dialog.destructive` is true, so an accidental Enter confirms a delete. Proposal: when destructive, give initial focus to Cancel and require an explicit click or Tab plus Enter on the destructive action.
7. QueryJS table pagination likely moves the cursor and destroys the widget (kb-ui.ts:505-545 versus docs/agents/live-preview-rules.md rule 11). Prev/Next buttons add only onclick, with no mousedown stopPropagation; the Run buttons do add it (queryjs-block-widget.ts:217, 329) and the widget's ignoreEvent returns false. The unit tests call `.click()` (kb-ui.test.ts:789), which skips mousedown, so they cannot catch it. This is a lead, not a reproduced bug: verify in the running app by paging a kb.ui.table with pageSize. Proposal: stopPropagation on mousedown for the nav buttons and add a mousedown-based test.

## Moderate

8. "My people" section: empty state, overdue state and labels (MyPeopleSection.svelte:35-38, 57-64, 47-74; landing-today-light.png). Empty state prints the raw property `_one_on_one_every` and a path; it appears for every user who has no 1:1 setup (already noted in review-note-list as item 10). Beyond that: the row label "3d" or "never" has no unit context (days since the last 1:1, cadence not shown), overdue is only a text-warning colour on 11 px text (no icon, so colour-only), the date lives in a hover title, and the two raw buttons use cursor-default with no focus-visible style and a hover-only background. Proposal: hide the section when no person has the property, or show a short "Set up 1:1 tracking" link to settings; label as "last 1:1 3d ago" or "due in 4d / 2d overdue" with an icon for overdue; add focus-visible rings; use the shared `text-meta` token instead of text-[11px].
9. Mods list in Labs shows engineering data and omits user data (ModsStatusList.svelte:94-102; mods.logic.ts:145 and 207-223 parse description/author; mods.store.svelte.ts:4-24 does not carry them). Each row shows name, version, "Loaded . 12 ms" and a switch; the manifest's description, author, colour and what the mod adds (commands, shortcuts, status chips) are not shown, so the owner cannot tell what a mod does or turn off the right one. Mods are also invisible until the Vault mods switch is on, and a mod failure on enabling is only logged (LabsSection.svelte:27-29). Proposal: row = name + description line + state badge (colour and icon, not only colour), load time inside a details/tooltip, and an inline error with a Retry when enabling fails.
10. Mod run view: status and progress are not accessible and failure is quiet (ModActionPicker.svelte:104-148). The status label is 12 px muted for Running, Done and Failed alike, the progressbar has no accessible name (:111-117), and the log has no aria-live or role=log, so screen-reader users and anyone not watching get no change announcement. Proposal: a coloured status badge with icon (spinner, check, X), `aria-label` on the progressbar tied to the label span, `role="log" aria-live="polite"` on the log box, and keep the Stop button disabled with "Stopping..." once clicked.
11. kb.ui helpers use dark-only literal colours (kb-ui.ts:118 `rgba(255,255,255,0.1)` card border, :419 `rgba(255,255,255,0.03)` stripe, :346 `#fff` badge text, :788/:881 `rgb(61,61,61)` today border, :1007 `#ebedf0`/`#333`). On the light theme (Lavender Haze, the only light built-in) card borders and zebra stripes vanish, and the dark theme's today marker in the heatmap is nearly invisible. Proposal: replace with the existing `--lp-collection-*` tokens (border, table-alt, header-bg) and add `--lp-qjs-*` tokens for heatmap and badge; compute chip/badge text contrast instead of fixed `#fff`.
12. QueryJS tables have no horizontal overflow handling and their controls lack focus styles (styles.ts:954-958 table width 100% with no overflow wrapper, :973-975 wrapper is `display:block` only; no `:focus-visible` rule for `.cm-lp-qjs-run` or `.cm-lp-qjs-table-nav-btn` in styles.ts:877-1001). Wide results force the page to squeeze columns or overflow the note; keyboard users cannot see which button is focused. The collection review already covers the sibling widget; this is the queryjs one. Proposal: wrap tables in an `overflow-x:auto` container with nowrap cells and ellipsis, and add a visible ring via `--ring` to Run and Prev/Next.
13. Todoist sync switch can be turned on with no token or root project (TodoistSection.svelte:114-121, 123-126; TodoistSyncStatus.svelte:17). The description says "With none chosen, the sync stays off", yet the switch shows on and the status bar chip appears ("Todoist not synced yet"). Proposal: disable the switch until a token is saved and a root is chosen, with helper text "Add a token and pick a root project first", or show a clear "Needs root project" state in the chip.
14. QueryJS block states are plain text only (queryjs-block-widget.ts:118-121, 203-215, 240-243, 299-330). "Building index...", "Running query…" and "Query not run yet" have no spinner or progress cue; the Run button has no disabled or "Running" state (guarded only by `runningContainers`); an error is entirely italic red with fallback `#f87171`. Proposal: small spinner for running, disable the Run button while running, make the error title non-italic with an icon and keep the stack in details.

## Polish

15. Copy and typography drift across these dialogs: title casing ("New File from Template" vs "1:1 Note" vs "Todoist sync log"), "..." in six strings vs "…" in one, "ESC" (composer) vs "Esc" (mod picker), "Stack trace" vs "Details" for the same disclosure (ModsStatusList.svelte:116 vs ModActionPicker.svelte:138), Stop/Close/Cancel used for the same concept, "Failed to" vs "Could not". Proposal: one sentence-case style, "…", "Esc", and one disclosure label; add a test like the settings copy test.
16. QueryJS settings intro shows a repo-relative help path and API identifiers as plain text (QueryjsSection.svelte:45-50; settings-queryjs-light.png). Proposal: an "Open QueryJS guide" link button; keep identifiers in the doc.
17. Motion: `animate-spin` spinners, the progress width transition and the composer ring have no `prefers-reduced-motion` handling (ModDialogHost.svelte:112, ModActionPicker.svelte:118, TodoistSyncStatus.svelte:27, +page.svelte:279); small hard-coded font sizes (text-[11px], composer 11/14 px) bypass the `text-meta`/`text-row` tokens. Proposal: `motion-reduce:animate-none` and token sizes.
