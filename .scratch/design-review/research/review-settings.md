# Design review: Settings

Area: src/lib/core/settings (18 components), src/lib/app/SettingsPanel.svelte, src/lib/app/LabsSection.svelte.
Evidence: code read plus screenshots settings-appearance-light, settings-troubleshooting-light, settings-update-light, settings-quick-capture-light, settings-trash-light.

## Clear

1. Sidebar title and active item scroll out of view (SettingsPanel.svelte:122-146). The whole nav is one overflow-y-auto column and the "Settings" h2 lives inside it. In settings-appearance-light.png the title is gone; in settings-update-light.png it is half cut and Update (the last item) sits at the very bottom edge. Proposal: pin the title band (sticky), make only the item list scroll, scroll the active item into view on open (settingsPanelStore.open(section) can target any section). Same for the section h2 inside the content ScrollArea: pin it.
2. Controls have no accessible names (SettingItem.svelte:25-27 uses spans; 15 of 18 Switches and all 35 Inputs unlabeled; Update channel Select too). Screen readers announce "switch, off" with no name; clicking the label text does not toggle. Proposal: SettingItem generates an id, renders the label as a real label tied to the control through context or aria-labelledby, and makes the label/row click toggle switches.
3. Dialog semantics are incomplete (SettingsPanel.svelte:105-120). No aria-modal, no focus move on open, no trap, no restore to the opener. Escape closes the panel even when a popover (Editor font Browse) or a native ask() confirm is the thing the user meant to dismiss. Proposal: focus the active nav item on open, return focus on close, ignore Escape when event.defaultPrevented or a popover is open.
4. No way to search settings across 19 sections in 6 groups. Finding "log to file" (Troubleshooting), "template" (Periodic, Quick Capture, 1:1, Files) or "retention" means clicking sections. Proposal: a search field under the "Settings" title that filters the nav to sections with matches and highlights matching rows; Cmd+F inside the panel focuses it.
5. Dependent settings are only described in text, never disabled (TroubleshootingSection.svelte:55-56, 67, 95; PeriodicNotesSection.svelte:58). "Save mod run messages" needs "Save debug log to file", Heartbeat "Needs a log file", Auto-pin "requires auto-open", but all switches stay live, so a user can turn them on and silently get nothing (heartbeat start is skipped without feedback, :73). Proposal: disable the child switch with a "Turn on X first" hint, or link the hint to the parent.
6. Editor number inputs write unclamped values live (EditorSection.svelte:98-104, store updateEditor has no clamp, MarkdownEditor.svelte:697 reads the raw value). Typing 14 passes through 1, clearing gives 0; the editor reflows with absurd sizes on each keystroke, clamp only runs on change. OneOnOne due days silently ignores an empty field (OneOnOneSection.svelte:10-16). Proposal: commit on blur/Enter (or debounce), show the valid range as input helper text and an inline error state, add stepper arrows or a slider for font size and line height.

## Moderate

7. Path and format fields are bare text inputs with no validation or preview. In settings-quick-capture-light.png the template paths are cut at half the row width ("_system/templates/quick-capture/C") and nothing says whether the file exists. Date formats (Periodic x5, Quick Capture, 1:1) show no sample of the resulting name. Proposal: stacked layout for path fields, a Browse/pick-note button, a red hint when the file or folder is missing, and an "Example: 2026-11-17" line computed live under every format field.
8. Periodic Notes repeats five near-identical Format and Template blocks (PeriodicNotesSection.svelte:34-131), ten rows labelled just "Format" / "Template path", daily being the only one with extra switches. Proposal: a segmented control (Daily | Weekly | Monthly | Quarterly | Yearly) over one pair of fields plus the example preview, or a compact table with period, format, template columns.
9. Theme list actions are hover-only and destructive without confirmation (AppearanceSection.svelte:190, 94-103). Delete removes a user theme at once and silently swaps the active theme to default; cards (div role=button, :172-178) have no focus-visible ring. Proposal: always show a "..." menu per card (Edit, Duplicate, Delete), confirm or offer an undo toast on delete, add focus ring.
10. Theme editor lacks the basics for a 70+ token job (ThemeEditor.svelte; theme-editor.logic.ts groups). No search, no per-color reset to the default, no unsaved-changes guard (Back and Cancel discard instantly), no miniature preview (ThemePreview exists but is unused in the editor) while the settings panel covers half the real app. Group tabs have no role=tab/aria-selected (:176-184) and the color swatch has no label or focus ring (ThemeColorRow.svelte:51-61). Proposal: sticky header with ThemePreview, token search, reset icon on changed rows, confirm on discard, proper tablist semantics.
11. Update "Check" silently downloads and installs (UpdateSection.svelte:167-210, button :276). Label says check; progress is plain text "Downloading v... (?) 40%" (:282) without a bar; failures show raw error text beside Retry. Proposal: rename to "Check and install" or split the steps, add a determinate progress bar, show the version found and release notes before restart.
12. Trash row actions are icon-only with title and no aria-label, 28px targets (TrashSection.svelte:112-129); restore has no feedback beyond the row vanishing; load runs only on mount and not at all without a vault (:17-21). Proposal: aria-labels, a "Restored <name>" toast with Open action, and text "No vault open" empty state.
13. Developer jargon in user copy: "_one_on_one_every: true" (OneOnOneSection.svelte:90), "_folder: <path>" (TypesSection.svelte:55), "kb.pages()" (FilesSection.svelte:25), "run.log"/"ctx.log" (TroubleshootingSection.svelte:56), "Needs a log file ... click-to-paint" (:67). Proposal: rewrite in plain words, move technical keys into a collapsible "Details" or a code chip with copy button.
14. Silent failure states: font list fetch failure hides Browse with no message (EditorSection.svelte:18-24, 54); Labs mod start failure is only logged and the switch stays on (LabsSection.svelte:27-29); log session start has no catch (TroubleshootingSection.svelte:44-46). Proposal: inline status line under the control, switch reverts on failure.

## Polish

15. Information architecture: "Labs" holds a single toggle and its log flag lives in Troubleshooting; Types is nav "Types" vs page "Types & Lifecycle"; Auto Organize vs Auto-organize (settings.logic.ts:267-297). Proposal: fold Labs into Advanced > Mods with the log toggle, align nav labels to page titles.
16. Typography and copy drift: intro paragraphs use text-sm in Appearance and Quick Capture but text-meta elsewhere; "Failed to" (TrashSection:28) vs "Could not" (Appearance, Sentry, Labs); Title Case "Empty Trash", "Delete Permanently" vs sentence case; "..." vs "…" ellipsis. Proposal: one style pass plus a lint test in settings-copy.test.ts.
17. Panel visuals: hard-coded shadow rgba (SettingsPanel.svelte:116), 200ms fly transition without prefers-reduced-motion handling, no scrim so the half-visible editor behind competes for attention (settings-appearance-light.png); the error toast sits on top of the panel content. Proposal: tokenized shadow, reduced-motion fallback to fade, optional light scrim.
