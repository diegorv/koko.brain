# Design review: Auto-organize and inbox

Scope: src/lib/features/auto-organize (AutoOrganizeSection, AutoOrganizeRuleRow, AutoOrganizeRuleProperty), plus the service paths that change what the UI must say. Screens: auto-organize-rule-builder-light.png, settings-auto-organize-light.png, rail-inbox-light.png. Inbox triage on the note list (row menu without Mark organized/Archive, bare empty state, italic cue) is already in review-note-list.md items 5, 8, 12 and is not repeated here.

Verified by reading code and screenshots only; nothing was run.

## Clear

1. **Type archive/unarchive rules are invisible and ride on a master switch that is off by default.** type-lifecycle-rules.ts generates `[Type] Archive` and `[Type] Unarchive` rules from each type's `archiveTo`; auto-organize.service.ts:297 appends them to the user rules, and :211 returns early unless `settingsStore.autoOrganize.enabled` (default `false`, settings.store.svelte.ts:111). The Auto Organize page (AutoOrganizeSection.svelte:107-174) lists none of them, and the toggle copy says only "Automatically move notes to folders based on rules when saved" (:112). A user who sets `archiveTo` on a type and never touched this page gets no archive move and no explanation. Proposal: a read-only "From your types" group under Rules listing each generated rule (name, condition, destination, link to the type), and one line under the master toggle: "Also runs the archive rules of your types". Show a hint in the Types and Archive surfaces when a type has `archiveTo` and Auto Organize is off.

2. **Deleting a rule is one click, immediate, with no undo.** AutoOrganizeRuleRow.svelte:316-323 trash button calls `onremove`; AutoOrganizeSection.svelte:67-70 removes it from the store and saves to disk at once. A rule is a long configuration (filter, rename, properties, create note, mod action). The button is destructive red but unlabeled, and sits 28px from the reorder chevrons. Proposal: move Delete into a "..." rule menu (Duplicate, Move up, Move down, Delete), and on delete show a toast "Rule deleted" with Undo for 8 seconds (restore into the same index).

3. **Icon-only controls in the rule header and chips have no accessible name.** Up (Row:298-306), Down (:307-315), Trash (:316-323), the rule enable Switch (:294-297), the section enable Switch (Section:114-120) and the excluded-folder chip X (Section:207-211) carry no `aria-label` or `title`. Screen readers read "button" and "switch". The chip X also has no focus style of its own. Proposal: `aria-label` "Move rule up/down", "Delete rule {name}", "Enable rule {name}", "Remove excluded folder {folder}", plus shadcn Tooltip with the same text; give the chip button the standard `focus-visible:ring`.

4. **Saves and loads fail silently, and a bad config file is overwritten by the next edit.** Save errors are only logged (Section:33-39; service:196-199 rethrows into that catch). A parse failure in loadAutoOrganizeConfig resets to empty defaults (service:132-135) and the page then shows "No rules configured" (Section:156-158) with no error; the next edit calls `saveAutoOrganizeConfig`, which writes the empty config over the unreadable file. There is also no "Saved" cue for any change, and the empty box shows before the config has loaded (`isConfigLoaded` has no consumer). Proposal: an inline banner when load fails ("auto-organize-rules.json could not be read. Your rules were not changed. Open file / Retry") that blocks saving until resolved (or backs the file up to `.bak`), a destructive toast on save failure with Retry, a small "Saved" tick next to the page title, and a skeleton in place of the empty box until `isConfigLoaded`.

5. **Rules only fire when a note is saved; there is no way to apply a rule to notes that already exist, and no trace of what a rule did.** The hook is `addAfterSaveObserver` (service:206-241) with no exported "run now" (exports: load, save, register, toggle, reset). The builder shows "Matches 4 notes now" (Row:356) which invites an action the page cannot offer. When a run succeeds, nothing is shown except the numbered-name collision toast (service:402); moves, renames, property writes and created notes are silent, so a note can change path or name three seconds after a save. Proposal: next to the match count add "Apply to N notes..." that opens a confirm sheet listing each note and its planned change (old path to new path, properties) with Apply; after any automatic run, a toast "Moved Meeting notes.md to Meetings/2026" with Undo, and an "Activity" disclosure at the bottom of the page listing the last 20 runs.

6. **Page copy describes only "move" and "first match", which is no longer how rules work.** Section:112 ("Automatically move notes...") and :152 ("The first matching rule determines the destination folder") predate rename, set properties, create note and mod actions. The service header (service:283-290) states the real order: first matching rename, first matching move, every matching rule's properties and creates, first matching action. A user who orders rules to prioritise property writes gets surprising results. Proposal: rewrite as "Rules run in order when you save a note. The first matching rule renames, the first moves, every matching rule sets properties and creates notes. The first with a mod action runs it." and show a per-rule badge ("moves", "renames", "sets 2 properties") on the card header to make the effect scannable.

7. **The destination field hides its variables, and a typo silently creates a literal folder.** Row:402-407 shows only "Empty: do not move". resolveDestination (logic:937-971) supports `{folder}`, `{parent}`, `{basename}`, `{type}`, `{status}`, `{year}`, `{month}` and "Unknown variables are left as-is", so `{yaer}/Notes` moves notes into a folder literally named `{yaer}`. Nothing previews the resolved path. There is also no folder autocomplete for this field or the excluded-folders input. Proposal: an "Insert variable" menu (or `{` typeahead) listing the seven variables with examples, an inline preview using the first matched note ("Projects/2026/11"), a destructive hint on unknown `{names}`, and folder suggestions from the vault tree.

8. **Each rule is a flat, always-open 5-section form that can run past the viewport.** In auto-organize-rule-builder-light.png one rule with a filter, rename, move and one property already pushes Create note and Run mod action off screen behind the toast; Rename, Move, Set properties, Create note and Run mod action are all always rendered (Row:367-525) even when unused, and "Then" is a bare span (:365). With 5-10 rules the page becomes a long scroll with no summary of any rule. Proposal: collapsed card by default with a one-line summary ("When file.inFolder("Projects") -> set owner = me, move to Projects/{year}"), a chevron to expand, and inside only the consequences in use plus an "Add action" menu (Rename, Move, Set property, Create note, Run mod action). New rule opens expanded.

## Moderate

9. **The filter block leaks collection-view wording and uses two different add buttons.** The rule's Filter shows a collapsible "This view" with a count badge and "All the following are true" (FilterPanel.svelte:158-162, reached through Row:332-340 with `showGlobal={false}`), then "Add filter" inside the panel and "Add expression" below it (Row:343-351). "This view" is meaningless in a rule. The label column uses "Filter" / "Then" and the `ml-[6.5rem]` offset (Row:346, 353, 355) aligns by hand with `w-24 + gap-2`. Proposal: label the block "When" (pair with "Then"), pass a prop to FilterPanel to hide the "This view" header and badge, merge both adds into one "Add condition" split menu (Property filter / Expression), and replace the arbitrary offset with a grid for the label column.

10. **Property rows pack six controls with unexplained jargon.** AutoOrganizeRuleProperty.svelte:222-352: key input, Value/Expression select, Text/Yes-no select, value, mode select ("if missing", "always", "remove", "add to list", :51-56), delete. In the screenshot the "if missing" trigger is the most prominent control while its meaning is not explained anywhere. The row wraps to a second line when narrow. Proposal: read as a sentence, "Set owner to me, only if empty" with a verb dropdown ("Set if empty", "Set always", "Remove", "Add to list") and Source/Type tucked behind an "advanced" caret that appears only when the key is not a known type; show the mode explanation in a Tooltip.

11. **Validation is color-only and unscoped to the field.** Errors are `<p class="text-destructive">` without `role="alert"`, `aria-live`, `aria-describedby` or `aria-invalid` (Row:352-353, 393-395, 451-467, 519-523, 527-531; Property:354-364), although the shadcn Input already styles `aria-invalid` (input.svelte:30). A refused path or name keeps the typed text but is not saved, and the only explanation is the trailing "It is not saved." (Row:453, 465). Field captions ("Filter", "Rename", "Move to folder", "Set properties", "Create note", "Run mod action") are `<span>`, not `<label>`, and several inputs (rule name Row:288, destination :402, excluded folder Section:184, debounce Section:127) rely on placeholders. Proposal: set `aria-invalid` and `aria-describedby` on the offending input, render errors with a small alert icon and `role="alert"`, change the sentence to "Not saved: the path must end in .md and must not start with /", and turn captions into real `<label for>`.

12. **A newly added rule or property is not scrolled to or focused.** Add rule (Section:49-60) appends below the existing cards with no `focus()` or `scrollIntoView` (no focus calls anywhere in the area); Add property (Row:435-438) and Add expression (:161-165) likewise. With a few rules the new, disabled, nameless card can land below the fold and the click seems to do nothing. Proposal: after Add rule, scroll the new card into view and focus its name input; after Add property focus the new key input; announce via a polite live region.

13. **Excluded folders: free text, no validation, no empty or duplicate feedback.** Section:177-217: the input accepts any string, a duplicate is silently ignored (:93), an unmatched folder is not flagged, the section shows nothing at all while empty (:202), and the placeholder `_templates` renders in settings-auto-organize-light.png like a typed value (no "e.g."). Proposal: folder-picker autocomplete from the vault tree, an inline "Already excluded" message, a warning chip style for a folder that no longer exists, and empty text "No folders excluded. Templates and system folders are already skipped" (only if the service does skip them; verify before shipping the claim).

14. **The per-rule "image" button next to Move to folder is an unlabeled, legacy duplicate of the `_icon` property.** Row:408-421 shows a bare picture icon with only a native `title` ("Set file icon"). The service calls it the moving rule's "legacy icon" (service:361-364, applies only when a rule moves), while the property editor already supports `_icon` and color pickers (Property:279-296, labelled "Pick icon"). Two ways to set the same thing, with different words and different conditions. Proposal: remove the standalone button and surface `_icon` through Set properties (or relabel it "Icon for moved notes" with a visible text button and migrate existing rule.icon).

15. **Property rows are keyed by index, so local error and picker state follows the wrong row after a delete.** Row:427 and :468 use `{#each ... (i)}`; AutoOrganizeRuleProperty keeps `exprError`, `refusedExpr` and `pickerOpen` as local `$state` (Property:65-79). Deleting a middle row shifts the next property into a component that still holds the previous row's refused draft or error. Code-traced only, not reproduced. Proposal: give each property a stable client id (or key by key plus a counter) so each row keeps its own draft.

## Polish

16. **Debounce input has no unit and rewrites itself while typing.** Section:127-139 clamps on every `input` event and re-derives `value` from the store (:133), so typing "0" snaps to 0.5 before the next digit arrives; the "Seconds ..." unit lives only in the description and the control shows a bare "3" (settings-auto-organize-light.png). Proposal: add a trailing "s" adornment, keep the typed text in local state and clamp on blur, and show "Allowed 0.5 to 30" as the error text instead of silent clamping.

17. **Copy and casing drift inside the rule card.** "Open it" (Row:489) names no object (use "Open the new note"); the picker is "Set file icon" (Row:412) vs "Pick icon" (Property:281); mode labels are lowercase ("if missing", "always") next to capitalised siblings ("Value", "Text", "Yes/no", "Name"); "Matches N notes now" / "Would create N notes now" (Row:356-358) repeats "now"; "ruleActions" (Row:521) and ".kokobrain/auto-organize-rules.json" (Property:302) and "Todoist routes tasks by it" (Property:362) leak implementation detail; "Empty:" vs "(empty: ...)" placeholders (Row:388, 405, 448, 460); straight quotes in "Add rule" (Section:158). Proposal: one pass using sentence case, "Open the new note", "Matches 4 notes" / "Would create 4 notes", and rewrite the three internal-term messages in user language ("Needs a mod that provides this action", "Edit this value in the rules file").

18. **No motion or hierarchy cues for rule state.** A disabled rule looks identical to an enabled one except the small switch (screenshot: rule toggle off, card unchanged), and card hover/focus has no state. Proposal: dim the card body (opacity 60%) and show an "Off" pill when `enabled` is false, and a `focus-within` border on the active card; honour `prefers-reduced-motion` for any transition added.
