# Design review: Backlinks, outgoing links, tags, file history, graph

Evidence: code under src/lib/features/{backlinks,outgoing-links,tags,file-history}, src/lib/plugins/graph-view; screenshots graph-view-light.png, right-sidebar-all-expanded-light.png, right-sidebar-crop-light.png, file-history-light.png.

## Clear

1. **Backlinks and Outgoing panels collapse themselves on every note switch.** `BacklinksPanel.svelte:33-39` and `OutgoingLinksPanel.svelte:29-35` set `expanded = false` and reset the store whenever the active path differs from the last fetched one. Walking through linked notes means re-clicking both headers each time. Collapsed headers show no count, so the user cannot tell whether a note has backlinks without opening it. Proposal: persist open state across notes, refetch on path change, and show a count badge on the header (as "Linked mentions" already does inside). Fetch counts lazily when collapsed.
2. **Relationships are hidden when there are no linked mentions.** `BacklinksPanel.svelte:61-62` shows "No backlinks found" whenever `linkedMentions` is empty, and the Relationships block is nested in the else branch (L80). A note that is only the target of `_belongs_to` or `_related_to` looks like it has no backlinks. Proposal: empty state only when both lists are empty; render each group independently.
3. **Unlinked mentions are computed and never shown.** `backlinksStore.unlinkedMentions` and `outgoingLinksStore.unlinkedMentions` are populated (`backlinks.service.ts:211-233`, `outgoing-links.service.ts:75-87`) but no .svelte file reads them (grep on `src/lib`). Proposal: add an "Unlinked mentions" collapsible under Linked mentions with a hover "Link" action that wraps the text in `[[ ]]`. This is the highest-value hidden feature for a vault-organizing workflow.
4. **Sidebar link rows truncate the information that identifies the note.** Screenshot right-sidebar-crop-light.png: "Meetings/2026-11-09 Desig...", "Projects/Websit... > Open q..."; backlink snippet shows raw markdown "# Roadmap Linked from [[Welc...". Code: `OutgoingLinksPanel.svelte:67-69` puts target and heading in one non-wrapping row; `LinkItem.svelte:25` uses `truncate` on a one-line snippet. Proposal: show the note title as the primary line and the folder as a muted second line (or tooltip with full path); render the heading on its own line; snippets: strip markdown, wrap to 2 lines with `line-clamp-2`, window the text around the link so the highlighted match is always visible (today the match can be cut off by `truncate`).
5. **Unresolved outgoing links are dead rows.** `OutgoingLinksPanel.svelte:74-80`: a non-interactive div at `opacity-60` with `text-destructive`, so dimmed red text on a small row (low contrast, no action). Proposal: make it a button with a "Create note" affordance (plus icon on hover, Enter creates `target.md` in the default location and opens it), group unresolved links under a "Broken links" subheader, and drop the opacity so the text keeps contrast.
6. **Hidden tags with a contradictory header.** `TagsView.svelte:15,35-39` hides every tag used fewer than 10 times by default (`tags.store.svelte.ts:5`), while the header at L53-55 shows the total count (`totalTagCount`). A vault with 7 tags shows "7 tags" over "No tags found". Most personal vaults have long-tail tags, which this hides without telling anyone. The only hint is a tooltip on an icon-only filter button. Proposal: header "Showing 12 of 87 tags" with a visible "Show all" text link when the filter hides something; default to showing all when total tags <= ~50; show a distinct empty message ("All 7 tags are used fewer than 10 times. Show all") instead of "No tags found".
7. **File History restore has no error or success feedback.** `FileHistoryDialog.svelte:50` awaits `restoreSnapshot` with no try/catch; the service rethrows (`file-history.service.ts:101-104`), so a failed restore is an unhandled rejection and nothing is shown. A failed history load also renders as "No history available" (`SnapshotList.svelte:26-29`), and a failed diff renders as "Select a snapshot to view changes" (`DiffViewer.svelte:34-37`), as does an identical snapshot. Proposal: toast on success ("Restored to 14:32") and error; inline error state with Retry in both panes; "No differences from the current note" for an identical snapshot.
8. **Restore confirmation is a native OS dialog and wording is inconsistent.** `FileHistoryDialog.svelte:44-47` uses Tauri `ask()`, visually unlike the app's shadcn dialogs, with titles "Restore Version" vs button "Restore This Version" (L96). Proposal: inline confirm in the footer (button turns into "Replace current note? [Cancel] [Restore]") or a shadcn AlertDialog; one wording ("Restore this version") everywhere.

## Moderate

9. **File History diff lacks orientation.** `FileHistoryDialog.svelte:83-84` shows the epoch timestamp in mono text "(1731...)" (a developer value) and `formatSnapshotLabel` (`file-history.logic.ts:46-50`) calls the newest snapshot "Current", although the live note is a separate thing. `DiffViewer.svelte:43-48` has two unlabeled line-number columns, and there is no summary of what changed. Proposal: header "Compared with current note" plus "+12 -3" chips; label the newest snapshot "Latest snapshot"; remove the epoch from the UI; add Next/Previous change buttons for long notes.
10. **Empty History dialog is 1020x720 for nothing** (file-history-light.png: two panes of placeholder text, heavy focus ring on the close button). `FileHistoryDialog.svelte:55`. Proposal: when `snapshots.length === 0`, render a single centered state ("No saved versions yet. Versions are created when you save; manage retention in Settings > File history") and shrink the dialog; keep the two-pane layout only with data.
11. **Graph labels collide and the graph is noisy.** graph-view-light.png: "Team lunch" over a capture label, "Launch rehearsal" over "Dashboard", "Website Redesign" over "Ana Souza"; 27 of 36 nodes are orphans because Orphans defaults on. `GraphView.svelte:261-267` draws a label for every node once `k > 0.8` (default zoom is 1.3, set at `onMount`), with no collision test. Proposal: draw labels by priority (highest linkCount first), skip any label whose box overlaps one already drawn, always show hovered node and neighbors; consider defaulting Orphans off in global mode, or dimming orphans.
12. **Graph controls panel permanently covers the top-left of the canvas and uses unlabeled controls.** `GraphControls.svelte:26-141`: three stacked cards (about 180x210 px), native `<select>` elements (visually unlike the rest of the app, see screenshot), icon-only mode buttons with `title` only (L29-46), switches that are plain `<button>`s with no `role="switch"` or `aria-checked` (L88-96, L131-139). The search box filters nodes out (`graph-view.logic.ts:90`) rather than highlighting a match and centering it. Proposal: collapse the filters into a single "Filters" popover (badge with active count), use the shadcn Select and Switch, give the mode buttons visible text ("All notes" / "Current note"), make search highlight and pan to the match, drop the duplicate Close button (the tab already has one).
13. **Local graph has fixed depth and no isolated or loading state.** `GraphView.svelte:100` calls `getLocalGraph(fullData, centerPath, 1)` with a hardcoded depth; an isolated note renders one lone dot with no text; no state exists before `buildGraph()` resolves, and a failure only logs (L84-86). Proposal: depth stepper (1-3) shown in Local mode, "This note has no links yet" message, a skeleton/"Building graph..." state and an inline error with Retry.
14. **Graph is mouse-only and has no motion control.** `<canvas>` at `GraphView.svelte:450` has no `role`/`aria-label`/`tabindex`; no arrow-key navigation; click opens a note but there is no modifier (Cmd-click to open in a new tab) and no name tooltip on hover when a label is culled (after fix 11). The simulation has no `prefers-reduced-motion` path. Proposal: `role="img"` with an aria-label and a visible node list alternative (the search results), keyboard focus ring on the canvas with Tab/arrows between neighbors, Enter to open.
15. **Missing focus-visible styling across this area.** No `focus-visible:` classes anywhere in scope (tag toolbar buttons `TagsView.svelte:58-75`, chevron `TagItem.svelte:30`, snapshot rows `SnapshotList.svelte:38`, graph buttons). Only `ShowInCalendarButton.svelte:67` has one, so keyboard users get inconsistent or absent rings. Several icon-only controls lack `aria-label` (tag chevron, tag color trigger, filter/sort, graph buttons) and the filter/sort toggles convey state by icon color alone (`TagsView.svelte:63`), no `aria-pressed`. Proposal: shared `focus-visible:ring-2 ring-ring` utility on every interactive element here, `aria-label` and `aria-pressed` where noted.
16. **Snapshot rows nest a button inside a button and have no list keyboard model.** `SnapshotList.svelte:49-58` is a `role="button"` span inside the row `<button>` (the code already needs a `svelte-ignore`); Space does not activate it (only Enter, L55); Up/Down do not move the selection. Proposal: make rows `role="listbox"`/`option` with arrow-key navigation and live diff update, and move the reveal action to a sibling button at the row edge (as `LinkItem` already does for the calendar button).
17. **Tags tree is hard to scan and operate at scale.** No filter box (the only controls are two icon buttons, `TagsView.svelte:57-76`); chevron hit area is about 20 px with an unlabeled `size-3` icon (`TagItem.svelte:30-32`); leaf rows have no chevron slot, so leaf dots sit about 12 px left of parent dots (L56-62 vs L29-38); the color dot opens a popover but nothing signals that (no tooltip or label). Clicking a name goes to search (`TagsView.svelte:17-19`) with no preview. Proposal: add a filter input at the top, a fixed-width chevron placeholder on leaves, `title`/`aria-label` "Change color for #tag" on the dot, and a trailing count that is the same style on parents and leaves.

## Polish

18. **Copy and pattern inconsistencies.** Empty states: "No backlinks found" / "No outgoing links" / "No tags found" / "No history available"; waits: "Indexing vault..." / "Indexing tags..." / "Loading history..."; "Not available" with no reason for non-markdown tabs (`BacklinksPanel.svelte:58`, `OutgoingLinksPanel.svelte:54`). Proposal: one pattern ("No backlinks yet", "No outgoing links yet", ...), a reason for Not available ("Backlinks apply to markdown notes"), unicode ellipsis, tooltip wording that matches visible labels ("Orphans" vs "Toggle orphan nodes"). `OutgoingLinksPanel` also has no loading state while `BacklinksPanel` has one (L59-60).
19. **Token and size drift.** `TagItem.svelte:43,67` hard-code `text-[14px]` (token `text-row` exists); `TagColorPicker.svelte:58,64,94,102` use raw rgba/hex and a scoped style block instead of tokens (white-alpha swatches are invisible in light themes); `GraphControls.svelte` uses `rounded-xs` mixed with `rounded-md`; Tags uses generic `accent` tokens while neighbors use `right-sidebar-*`. Unused `Separator` imports in both panels (`BacklinksPanel.svelte:6`, `OutgoingLinksPanel.svelte:6`).
20. **Relationship type label.** `BacklinksPanel.svelte:96` uses `replace('_', ' ')`, which only handles the first underscore (current built-in types have one, custom field names may have more); use a global replace and sentence case ("Belongs to"). The "Snapshot" vs "version" vocabulary also mixes in the History dialog; pick "version".
