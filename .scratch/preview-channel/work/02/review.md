## Findings

1. **minor**, `scripts/preview-branch.sh:41`, `docs/RELEASE-CHANNELS.md` "The preview branch" section (both manual commands). A clone with no local `preview` branch runs `git checkout preview` and detaches HEAD at the `preview` **tag** (the last *built* head), not at the branch. Probe in a scratch repo: `git checkout preview` prints "You are in 'detached HEAD' state", HEAD is the tag commit `d0a2d1b`, `origin/preview` is `62df0dc`, and `git switch preview` fails with "a branch is expected, got tag 'preview'". When the tag lags the branch (a sync pushed but its build failed, which is exactly when someone is resolving things by hand), the merge is made on a stale base and the explicit-refspec push is rejected as non-fast-forward. When the tag does not lag, the work happens on a detached HEAD. Nothing is lost, thanks to the explicit refspec, but the documented recipe misleads. The Issue prescribes the command text, so the builder followed it and named the risk. Fix: put `git checkout -B preview origin/preview` (after `git fetch origin`) in front of `git merge origin/main`, in the `::error::` and in both docs recipes, and adjust the assertion in `preview-branch.test.ts:147`.
2. **minor**, `scripts/preview-branch.sh:45` (and `preview.yml:319`). The default `GITHUB_TOKEN` cannot hold the `workflows` permission. Community reports say GitHub refuses a token push whose `.github/workflows/` contents match no existing branch tip ([discussion #151442](https://github.com/orgs/community/discussions/151442), [#27224](https://github.com/orgs/community/discussions/27224); not official docs). A plain main merge is safe while `preview` adds no workflow changes, because the merge tree's workflows equal main's tip. If a feature branch under test edits `.github/workflows/`, every later sync push fails with git's raw "refusing to allow a GitHub App to create or update workflow" error and no `::error::` guidance. Today's planned content does not trigger it: `git diff origin/main...origin/mvp-claude -- .github/` is empty. Fix: one sentence in "The preview branch" saying that a branch changing `.github/workflows/` cannot ride on `preview` with the token-based sync, or wrap the push with an `::error::` that says so.
3. **nit**, `.github/workflows/preview.yml:33-35,99`. GitHub keeps only the newest pending run in a concurrency group. A pending main-push run that is replaced by a newer push to `preview` or a manual run never syncs, so `preview` lags `main` until the next push to `main`. This stays within the criterion ("only for pushes to `main`"). Running sync on every event (it skips when main is already merged) would close the gap; otherwise document it next to nightly's "may skip intermediate commits".
4. **nit**, `GITHUB-WORKFLOW.md`. It has a section per workflow (`## Nightly (nightly.yml)` at `:261`) but none for `preview.yml`, and `docs/RELEASE-CHANNELS.md` "Related docs" still points there for "the full `release.yml` and `nightly.yml` job graphs". The file is not in the Issue's Files list, so this is a follow-up, not scope for this Issue.
