Fix (one of): reword the placeholder in the dossier so it is not a Tailwind candidate (for example `@max-[N px]:hidden` or put N in prose), or exclude the folder from Tailwind scanning in `src/app.css` with `@source not "../.scratch";` (Tailwind 4.1+ syntax, from memory; verify against the Tailwind docs). Preferably fixed on main by the main session, then this branch rebased; then rerun `pnpm build`.

The acceptance criterion limits the skip to read error and failed backup, so this is not a criterion failure; ask the owner whether the purge skip should cover every non-`'loaded'` outcome except a missing file, or record the decision in the Issue.

It keeps the 21 existing tests unchanged (as the happy-path criterion asks), and the only production caller passes it (app-lifecycle.service.ts:224). ## Resolution

1. **major, fixed in 932c9810d.** Reproduced first: `pnpm build` exit 1, `[lightningcss minify] Invalid media query`. `src/app.css` now has `@source not "../.scratch";` after the imports. The installed tailwindcss 4.3.4 parses negated `@source` patterns (`negated` in `node_modules/tailwindcss/dist/lib.mjs`). I chose the exclusion over rewording the dossier because any later note that quotes a placeholder class would break the build again. After the change `pnpm build` exits 0. The fix lives on this branch, not on main, so main stays red until this Issue merges. The main session can cherry-pick 932c9810d to main if it wants main green sooner.
2. **minor, not changed: owner decision.** The acceptance criterion limits the purge skip to a read error or a failed backup (Issue file, criterion on `initializeVault`; app-lifecycle.service.ts:292). In the parse-failed, backup-succeeded case the user's settings, retention included, are safe in `settings.broken-*.json`, and loadSettings writes defaults to the file (outcome `'defaults'`), so the session runs at the default retention by design. Skipping the purge in that case too would change behavior the Issue does not ask for. Open question for the owner: should `cleanup_history` also skip on a parse failure that was backed up? If yes, that belongs in a follow-up Issue.
3. **nit, fixed in 3cd795b9e.** Making `outcome` required would edit about 43 existing `startSettingsPersistence(...)` test calls, and the happy-path criterion asks that existing tests stay unchanged. So the JSDoc (settings-persistence.svelte.ts:44-45) now says that omitting it means the file loaded and that any caller of loadSettings must pass its result. The only production caller passes it (app-lifecycle.service.ts:224).
