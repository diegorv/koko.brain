# 015: Closing a tab with unsaved text saves it and closes; a prompt appears only when that save fails

**Origin:** `audit-2026-11-05` Issue 13, moved here on 2026-11-08. Its PRD, raw evidence and closed siblings stay in `.scratch/archived/audit-2026-11-05/`. Bare Issue numbers in the text below use that feature's numbering; `priority-2026-11-08.md` in this folder maps them to the numbers here.

**What to build:** closeTab (src/lib/core/editor/editor.service.ts:303-332, the `ask` at :313-318) asks 'This file has unsaved changes. Discard changes?' for any dirty tab, which in an autosave app means every close inside the 2 s debounce window. The debounce timers are not cancelled during the native dialog, so saveDirtyTabs (:209-220) usually writes the tab while the dialog is open: 'Discard Changes' then closes a tab whose text is already on disk, and the prompt's promise is false in its most common case. Quit and window close already do the right thing through prepareForExit (src/lib/core/vault/exit.service.ts:15-23): save first, ask via confirmDiscardFailedSaves (:32-39) only for saves that failed. Make closeTab do the same for a dirty non-virtual tab: await saveFileByPath(tab.path); on success close without a prompt; on failure ask with the failed-save wording, and on Cancel keep the tab. This changes documented behavior (help/documentation/03-editor.md:129) and three tests that pin the old prompt (src/tests/lib/core/editor/editor.service.test.ts:636, :647, :658). The owner approved the new behavior on 2026-11-06; rewrite those tests in this Issue.

## Notes

- **Priority:** daily use and UI correctness (bucket 2-ux). Cmd+W within 2 s of typing (0.5 s after a property edit) always prompts, and the debounced save can fire while the dialog is open. Impact medium: frequent trigger, low harm (nothing is lost unless the user picks Discard). The fix changes documented behavior and three pinned tests.
- **Trigger:** Type in a note and press Cmd+W (or click the tab's x) within about 2 s of the last keystroke, the normal close-right-after-editing flow.
- **Evidence (verified by reading code at `318b6e9b5`):** src/lib/core/editor/editor.service.ts:227 debouncedSave (2 s, maxWait 10 s) -> a tab is dirty at close only inside that window when saves work -> :313-318 ask(...) awaited with no debouncedSave.cancel() -> the timer fires saveDirtyTabs :209-220 -> writeTab :187-204 writes and markSavedByPath -> after the answer :323-331 only removes the tab. writeTab captures tab.content before the write (:191), so a keystroke during the write leaves the tab dirty afterwards. Contrast src/lib/core/vault/exit.service.ts:15-23 and :32-39 (save first, ask only on failure). Callers of closeTab: EditorTabs.svelte:89 (x) and :104 (context menu), closeActiveTab (editor.service.ts:335-339) from global-keybindings.ts:84 (Cmd+W) and commands.ts:112.
- **Run order:** first in the editor and filesystem chain: 015 -> 004 -> 028 -> 043 -> 077. Issue 004 runs after this one and adds a pending-edit flush in closeTab just before this save, so keep the save in one place in closeTab that a call can precede.
- **Do not import exit.service.ts** into editor.service.ts: exit.service.ts:2 already imports saveAllDirtyTabs from editor.service.ts, so importing confirmDiscardFailedSaves back makes a file-level cycle that no architecture test flags. Inline the single `ask` call in closeTab.
- **Do not cancel the debounce timers in closeTab.** saveAllDirtyTabs cancels both (editor.service.ts:276-277); doing that in closeTab would cancel the pending autosave of other dirty tabs, and the guard test at :720 cannot catch it because the debounce mock in that file runs synchronously. Leaving the timer armed is harmless: saveDirtyTabs finds no dirty tab and returns, and saveFileByPath queues behind an in-flight save of the same path.
- **Set the `writeTextFile` and `ask` mocks explicitly in every new or rewritten test.** Every beforeEach calls vi.clearAllMocks(), which keeps implementations in vitest 5.1.0: in describe('closeTab'), writeTextFile still runs the implementation set at :566 (it throws for /vault/a.md), and ask keeps whatever the previous test set.
- **Known limits, add no code for them:** after a failed close-time save and Cancel, no retry is armed (the 5 s retry exists only inside saveDirtyTabs, :217-219); the tab stays dirty until the next edit arms the autosave. writeTab also shows its 'Failed to save file.' toast (:201) before the prompt.
- **Source:** audit 2026-11-05, domain `editor`, finding `N-editor-02` (from editor-ux-3, editor-spec-3). Size S, risk low. Deep dive: `.scratch/open-itens/research/deep-dive-2026-11-12/dossier-015.md`, `refute-015.md`, `critique.md` (H2, M8).
