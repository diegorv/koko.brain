## Findings

1. minor, src/lib/plugins/quick-capture/note-composer.logic.ts:99. A placeholder followed by a YAML comment (`title: <% title %> # note`) fails the line-end lookahead. It stays raw, so the block still does not parse. Probe: `Clean Code: A Handbook` gave `title: Clean Code: A Handbook # c`, which detectLossyFrontmatter reports as unparseable. The same thing happens to a key that contains `#` (`c#: <% title %>`). Fix (optional, can be a follow-up): let the lookahead also accept `[ \t]+#` before the line end, or list the trailing comment in doc 09 among the forms the author owns.
2. nit, src/lib/plugins/quick-capture/note-composer.logic.ts:99. The regex also matches lines inside a block scalar of the template. With `desc: |\n  Read: <% title %>`, the output is `  Read: "Clean Code: A Handbook"`, so literal quote characters end up in the text value. This is rare in capture templates. Fix: leave it, or skip lines indented under a `|` / `>` header.
3. nit, src/tests/lib/app/deep-link-capture-frontmatter.test.ts:224. The `She said "hi"` case passes on main too, because a quote in the middle is valid plain YAML. The integration test therefore never checks a double quote that would break the block. Fix: add a leading-quote title such as `"Quoted" title` next to it. That input fails on main and passes here.
4. nit, src/lib/app/deep-link-actions.ts:182-187. The new comment line is wedged into an existing sentence ("... field. / processCaptureTemplate writes ... Default / missing fields to ''"), so the comment reads in a broken order. Fix: put the processCaptureTemplate sentence after the "Default missing fields" sentence.
5. nit, help/documentation/09-quick-notes-and-templates.md:50. The `note` template is shared by Cmd+N (`createNoteComposer`, which still uses raw processTemplate) and deep-link `note` captures. So `source: <% sourceUrl %>` writes `source:` from Cmd+N but `source: ""` from a capture. Both read as `""` (ADR-0029 null coercion), so no data is lost, but the doc's "An empty value is written as `""`" holds for one path only. Fix: none needed, or have the doc say "a captured empty value".
