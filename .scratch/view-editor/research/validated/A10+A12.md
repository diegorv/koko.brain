# Validation of A10 (calendar views) and A12 (Bases parity)

## A10: facts

**Confirmed**
- **View keys.** `dateProperty`, `endDateProperty`, `weekStartDay` and `colorProperty` are declared at `collection.types.ts:50-57`.
- **Which renderer reads which key.** `calendar` reads `weekStartDay` (`CollectionCalendarView.svelte:16-26`). `linear-calendar` reads `colorProperty` (`CollectionLinearCalendarView.svelte:15-25`).
- **`weekStartDay` default.** It is 1 (`calendar.logic.ts:32`, `CollectionView.svelte:605`, `collection-block-widget.ts:191`).
- **Missing date property.** A falsy `dateProperty` shows a message instead of the calendar (`CollectionView.svelte:693-720`, `collection-block-widget.ts:180-184`, `:275-279`).
- **Writer behavior.** It clears keys as described (`yaml-parser.ts:230-256`). `setViewType` keeps the calendar keys (`:416-430`).
- **Parsing and placement.** Date parsing, dropped records, the 6x7 grid, the 3-chip cap, the inert `+N more`, multi-day placement by day key, the linear layout, lanes, color mapping, the legend and the hardcoded `text-white` (`:199`) all match the report. `barTextColor` is not imported by the view (`:3-9`).
- **Inline block.** It is frozen to the current month or year, shows 2 pills, and caps lanes at 3 (`collection-block-widget.ts:64`, `:188-191`, `:248`, `:284`, `:337`).
- **Config panel.** The start date has no "None" option (`CalendarConfigPanel.svelte:60-64`). Week start is offered only for `calendar` and color only for `linear-calendar` (`CollectionView.svelte:610-611`).
- **Dialog scope.** `ViewDialog.svelte` has no calendar references (grep). The PRD keeps calendar keys out of the dialog (`PRD.md:9`).

**Corrected**
- **Property list.** `getAllKnownProperties` returns 7 `file.*` names, not all of them: `file.basename` is missing. It also skips `.view` records (`filter.logic.ts:208-237`). Every note record gets `organized`, `archived`, `favorite` and `tags`, so these always appear in the list (`collection.logic.ts:63-69`).
- **`inferPropertyType`.** The first non-null value in the index decides the type. A string starting with `YYYY-MM-DD` counts as a date (`filter.logic.ts:260-273`). Epoch numbers come out as `number`, although the calendar accepts them.
- **Date-time strings are not all engine-dependent.** ISO date-time strings are spec-defined: without an offset they are local time, with `Z` or an offset they can move to another day. Only non-ISO forms such as `2026-01-05 10:00` are implementation-defined. This comes from the ECMAScript spec from memory, not checked in this runtime.
- **Day order within a cell (answers A10 Q3).** Calendar chips follow the rail's row order. That is the view's own `sort` if it has one, else `_sort` or the default with `_order` pins on top, and `limit` is applied last (`lens.logic.ts:692-721`, `view-row-set.port.ts`).
- **Month reset (answers A10 Q1).** The calendar components are not keyed (only the table is, `CollectionView.svelte:723`). Switching between two calendar tabs keeps the shown month. Passing through a table tab remounts and resets it.
- **"Today" highlight.** The month grid re-derives it on every navigation (`calendar.logic.ts:33`). Only the linear view keeps `now` until it remounts (`:39`, `:50-51`).
- **Tests.** `CollectionView.test.ts` does render calendar views: the error case at `:546-549` and the config panel at `:741-760`. `collection-block-widget.test.ts` covers the inline calendars. No test checks the linear bar geometry (grep for left/width found nothing).
- **Quoted `"1"` for `weekStartDay`.** The grid is still correct because subtraction coerces the string. Only the labels break: `("1"+0)%7` is 3, so the headers start at Wed (`calendar.logic.ts:40`, `:169`).
- **Non-string `dateProperty`.** `column.startsWith` throws at `collection.logic.ts:407`, inside a `$derived` (`CollectionCalendarView.svelte:45`) or inside the widget's `toDOM`. I found no catch; whether an error boundary exists is not verified.

## A12: facts

**Confirmed**
- **Unused keys.** `groupBy`, `summaries` and `columnSize` are only declared or shape-checked (grep `src/lib`, `collection.types.ts:43-49`, `yaml-parser.ts:89-91`).
- **View types.** `VIEW_TYPES` lists three, and any other `type` fails the parse (`yaml-parser.ts:50-55`, `:333`).
- **No `.base` support.** The grep hits were false positives.
- **No `this` context.** `this` resolves to null (`evaluator.ts:143-150`, `:174-181`).
- **Missing functions.** `file.links` returns null (`evaluator.ts:212`). `hasLink` throws (`:585-586`).
- **Different behavior.**
  - `replace` changes only the first match (`methods.logic.ts:74`).
  - List `sort` compares as text (`:148`).
  - `number("abc")` is NaN (`evaluator.ts:383`).
  - `inFolder` is a case-insensitive prefix test on the absolute folder (`:572-575`, documented at `12-collection.md:409-425`).
  - `hasTag` is exact, so nested tags do not match (`:565-571`).
  - `date.format` supports a token subset (`methods.logic.ts:11-21`).
- **Regex literals.** There are none: `/` is only the division operator (`tokenizer.ts:21`).
- **Sort and limit rules.** `direction` must be exactly `ASC` or `DESC`, `property` is accepted for `column`, and `limit` must be a number of at least 1 (`yaml-parser.ts:60-88`).
- **Unknown keys survive saves.** All writers re-parse the raw YAML.

**Corrected**
- **`updateViewEditYaml` location.** It is at `yaml-parser.ts:286-330`, not `:260-296`. It edits the raw object, so calendar keys and unknown keys do survive a dialog save, which settles A10's "not verified". Comments are lost (`:279-280`). It edits the view the rail runs (`railViewIndex`), which is not necessarily the editor's open tab.
- **`max()` and `min()`.** They map `null` to 0 (`Number(x ?? 0)`, `evaluator.ts:407`, `:411`), so missing values become 0 rather than NaN.
- **Tags have no `#`.** They are stored without it (`tag-extraction.ts:61`, `:67`, `:110`, `:122`). So `file.hasTag("#x")` never matches.

**Refuted**
- **Gap 5 mechanism.** The report says `file.hasLink` "is reported as a filter error". It is not. `validateExpression` skips method calls (`evaluator.ts:301-305`, `:323-324`). The throw is caught in `evaluateFilterCached` and returns false (`collection.logic.ts:356-358`).
  - Any unknown method (`file.hasLink`, `x.reverse()`, `containsAll`) gives a **silent empty view**.
  - Only unknown **plain** functions (`random()`, `file()`) raise "Unknown function" as a filter error (`evaluator.ts:321`).
