## Facts for the agent reference (CONFIRMED unless marked)

**File format**
- A `.view` is one YAML document with no `---` fences (`help/documentation/25-types-and-relationships.md:381,403`).
- With fences, the closing `---` starts a second document. Rust then falls back to its line-based subset parser and the TS parse fails (`src-tauri/tests/vault_frontmatter_parity_test.rs:94-101`, `src-tauri/src/vault/parsing.rs:551-559`).

**Location**
- Any folder works, and the extension is case-insensitive (`src-tauri/src/utils/fs.rs:146-148`, `src/lib/core/filesystem/fs.logic.ts:71-73`).
- Dot folders are invisible everywhere. A15 left this open; it is resolved: the tree scan also skips dot names (`src-tauri/src/commands/vault.rs:146`), as do the watcher (`watcher.rs:71-79`) and the index (`fs.rs:284`).
- A `.view` in the system folder (`_system` by default) is still listed in Views and can be pinned. Neither list filters that folder (`lens.logic.ts:209-217,643-658`).

**Menu keys**
- The A15 table is right in full (`type-sidebar.logic.ts:337-414,453-466`, `yaml-parser.ts:118-128`).
- Aliases are listed in `src-tauri/src/vault/aliases.rs:11-26`. There is none for `_open_in_editor`, `_group`, `_rail` or `_rail_view`.
- Top-level `order:` and `sort:` are folded into `_order` and `_sort`. Query sort and order belong inside `views[]`.
- `_sidebar_label` of the wrong type is ignored with no mark, which matches the doc (`25-types-and-relationships.md:405`).

**Query keys**
- `name` must be a non-empty string, so `name: ""` fails too (`yaml-parser.ts:56`).
- `direction` must be exactly `ASC` or `DESC`. `limit` must be at least 1. The calendar keys are not checked (`yaml-parser.ts:27-91`).
- `file.inFolder()` takes an absolute path and does a case-insensitive prefix match (`evaluator.ts:572-575`). That means `/v/Proj` also matches `/v/Projects2`. Use `contains(file.folder, "...")` instead.

**Filters that fail silently**
- A YAML list or an Obsidian-style `{property, operator, value}` map passes validation and matches every note (`collection.logic.ts:232-250,317-341`).
- An unknown `file.*` method also passes validation; at run time it matches nothing, with no error shown (`evaluator.ts:300-322,591-592`, `collection.logic.ts:319-325`).

**How the app picks up an external edit**
- The chain is: 0.5 s watcher debounce, 0.3 s lifecycle debounce, a full rebuild for any batch with only `.view` files (`watcher-handler.service.ts:52-80`), then a 2 to 10 s refresh throttle (`tauri-listeners.service.ts:104-109`), then a 1 s debounce before the count updates.
- A new file appears in Views with default metadata first, and its real label, group and visibility arrive with the refresh.

**Deep links**
- `kokobrain://new?...&silent=true` writes the content as given. It marks the write as a self-save first, so the watcher skips it, and indexes it through `notifyAfterSave` (`deep-link.service.ts:322-338`).
- Without `silent`, the content passes through `loadNoteTemplate` (`note-creator.service.ts:100`). What that does to plain YAML is not verified.
- `open` always opens the editor tab (`deep-link.service.ts:185-190`).

**Meta-bind `openView`** follows the row-click rule (`editor-host.ts:148-162`).

### Corrections
- **YAML line width.** Only New view and Edit view serialize with `lineWidth: 0` (`type-sidebar.logic.ts:353`, `yaml-parser.ts:329`). Icon, pin, Show in Views, row properties, the rail toolbar and the collection editor use the default width (`type-sidebar.logic.ts:542-635`, `yaml-parser.ts:261-429`). From memory, not verified: the default of 80 wraps long filter strings onto several lines.
- **The 1.8 s figure** belongs to the full-parse `scan_vault_v2` (`vault.rs:1222-1236`). The watcher calls `scan_vault_v2_cached`, which stat-walks the vault and re-reads only files whose mtime changed (`vault.rs:1309-1318`).
- **The parse cache** is keyed by path and compares a content hash (`view-parse-cache.ts:48-54`), not keyed by hash.
- **The palette** is always mounted and rebuilds whenever the stores it reads change (`AppOverlays.svelte:15`). It is not built only when it opens.
- **Edit view** also rewrites the rail view's `name` and `_rail_view`, and drops the `sidebar_label` aliases (`yaml-parser.ts:313-319`). It checks for a duplicate name inside the file only when `_rail_view` resolves (`:308`).
- **Pins and picks after a rename or trash** follow only in-app path changes: `applyPathChange` is called only from `fs.service.ts:248,285,313`. Trash also sends the rail to Today only when the rail is on that view's pin (`lens.logic.ts:1048-1073`). After an external rename, the rail keeps `view:<old path>`, the list says "This view no longer exists", and the renamed file gets a new pin. The stale-pin cleanup runs only at the next vault open (`AppShell.svelte:160-180`).
- **Rail pins** are icon-only buttons with no context menu. The label is only in the tooltip (`Rail.svelte:138-157`).
- **Other file writers.** A08's list missed the rail toolbar (`updateViewToolbarKey`, `type-definitions.service.ts:518-533`) and the collection editor (`updateCollectionYaml`). Neither writes a reserved key.
