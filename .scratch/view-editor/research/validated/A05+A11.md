## Corrected and confirmed facts for the agent reference

- **CORRECTED: two different `_order`s.**
  - A `.view` file's own `_order` sets its position in the Views navigator and among the rail pins (`type-sidebar.logic.ts:452-455`, `25-types-and-relationships.md:410`). It has no effect on the list.
  - List pins come from each listed note's `_order` (`type-sidebar.logic.ts:136-140`).
  - `viewRowSet` reads only `_sort` from the `.view` entry (`lens.logic.ts:711,714`).
  - A view `sort` turns off both `_sort` and the note pins (`type-note-list.logic.ts:96-98`). This is documented (`25-types:411,439`).
- **CORRECTED: column and sort keys accept less than filter expressions.** `getPropertyValue` (`collection.logic.ts:406-424`) resolves only these:
  - `file.name|basename|path|folder|ext|size|ctime|mtime`
  - `formula.<name>`
  - the exact indexed key
  
  These give null as a column or a sort key, in both the editor table and inline blocks: `file.tags`, `file.properties`, the `note.`/`property.` prefixes, and aliases. Expressions do resolve them (`evaluator.ts:193-212,605-620`), and the help doc lists `file.tags` and `file.properties` as if they work everywhere (`12-collection.md:316-325`).
  
  Inline blocks also lose `file.basename` (`collection-block-widget.ts:492-506`).
- **CORRECTED: DESC sort puts notes with no value first.** A test pins this as "Known behavior" (`src/tests/lib/features/collection/collection-logic.test.ts:640-659`). The comment "null always sort last" (`collection.logic.ts:426`) is wrong.
- **CONFIRMED: parser rules.** Any one of these makes the whole `.view` or block fail to parse:
  - `type` not one of `table`, `calendar`, `linear-calendar`
  - `name` missing or not a string (an unquoted `name: 2024` fails)
  - `sort` items without a `column` string (`property` is accepted as an alias), or with a `direction` other than uppercase `ASC`/`DESC`
  - `order` not an array
  - `limit` not a number of at least 1 (a quoted value fails, a fraction passes)
  - `columnSize` not a plain object
  - `formulas` not an object of strings
  
  Unknown keys are kept but ignored. `filters` are not checked when parsing (`yaml-parser.ts:13-123`).
- **CORRECTED: `columnSize` does nothing anywhere.** Only the parser and the types file reference it. `groupBy` and `summaries` are ignored (`collection.types.ts:46-49`).
- **CONFIRMED: filter errors.**
  - The only errors reported are a parse failure, an unknown plain function, a non-list `and`/`or`/`not`, and a list item that is neither a string nor an object (`collection.logic.ts:232-250`).
  - A wrong method name never reports an error (`evaluator.ts:300-315,586`).
  - A filter that throws on one note silently drops that note (`collection.logic.ts:348-358`).
- **CONFIRMED: which view runs where.**
  - The rail, the navigator count and the toolbar run the view `_rail_view` names, else `views[0]` (`yaml-parser.ts:142-144`).
  - Each editor tab runs through `viewRowSet` with the file's `_sort` (`CollectionView.svelte:258-272`).
  - An inline block always runs `views[0]` through `blockRowSet`: records only, query order, no `_sort` or pins (`collection-block-widget.ts:110`, `lens.logic.ts:736-750`).
- **CORRECTED: the rail and the editor do not run the raw YAML filter.** Both round-trip the filter through filter groups (`lens.logic.ts:793-798`, `CollectionView.svelte:160-161,258-259`). Only inline blocks run the raw value. The round trip drops an empty `or: []` (`filter.logic.ts:117-122`).
- **CONFIRMED: archived citations.** `file.hasProperty('archived')` counts as citing archived (`collection.logic.ts:296`). Every record always has `archived`, `organized`, `favorite` and `tags` (`:63-69`), so that filter matches every note and lets archived notes in.
- **CONFIRMED: `kb.view()` is unrelated to `.view` files.** It runs a script, and QueryJS has no API that runs a `.view` (`kb-api.ts:381-386`).

## Surviving findings, by severity

### Medium

1. **[NEW] A `filters` value written as a YAML list matches every note, with no error.** [reference] [edit-dialog]
   - An array has no `and`/`or`/`not` key, so `findItemError` reports nothing and `evaluateFilterCached` returns true (`collection.logic.ts:237-249,361-374`).
   - In the rail and the editor the round trip turns the list into JSON text, which parses as a truthy array literal (`filter.logic.ts:131-134,312-314`; `parser.ts:187`). Every note matches there too.
   - Unknown keys such as `AND:` behave the same way. The reference must forbid lists, and the dialog's raw editor should reject them.
2. **[A11-1, widened] Column and sort keys that silently give null** (see above). [reference] [visualization]
3. **[A05-2] A wrong method name, or a valid method on the wrong value type, empties the list or drops notes with no message.** [edit-dialog] [reference]
   - Methods are dispatched by the value's runtime type (`methods.logic.ts:255-269`), so `status.lower()` throws on notes where `status` is a number, a list or null.
   - The comment at `collection.logic.ts:136-137` promises more than the code does.
4. **[A05-3, corrected] DESC sort lists notes without a value first.** [visualization] [reference]
   - The doc's "Top 10 by priority" `limit` example (`12-collection.md:161`) therefore returns notes with no priority first.
   - Changing this is an owner decision and means changing the pinned test.
5. **[A05-5, downgraded from high] The preview cannot show an unsaved `_sort`.** [edit-dialog]
   - `_sort` is read from the stored entry (`lens.logic.ts:711,714`).
   - The fix is small (pass a sort override into `viewRowSet`), and it only matters when the view has no `sort`. `_order` is not involved.
6. **[A11-4, understated] Every property-index change rebuilds decorations in every open editor.**
   - The `rebuildOn` effect runs in every `MarkdownEditor`, whether or not the note holds a block (`MarkdownEditor.svelte:669-675`; the renderer is always installed, `editor-host.ts:179`).
   - `forceDecorationRebuild` makes every block decorator rescan the document (`live-preview-rules.md:15`). This includes each typing pause in the note being edited.
   - Not measured.
7. **[A05-1] While a view is open in the rail, every index change re-reads the `.view` from disk and re-runs the full query.** No debounce (`RailNoteList.svelte:203-217,253`; `view-parse-cache.ts:41-55`). Not measured.
8. **[A11-2] An inline block draws only `views[0]`, with no hint**, and a mistake in any other view still breaks the block. [visualization] [reference]
9. **[A11-3] Unknown keys are ignored silently.** [reference]
10. **[A05-11, raised for the preview] Formula and filter failures on single notes are silent**, and no failure count is exposed. [edit-dialog]
