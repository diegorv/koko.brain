## Findings

1. **major**, `help/documentation/mods/14-cookbook.md:2684-2688` (recipe 21). **Problem:** the recipe changes the matched note with `ctx.vault.write` and then `ctx.app.updateNoteFrontmatter`. A rule fires a few seconds after an editor save, so that note is almost always the clean active tab. `mods/04-vault-files.md:286,331` says both calls put the caret back at its old offset on the active note: the frontmatter line added before the caret makes the next keystroke land earlier, often inside `---`. That file also says a mod changing notes from a background trigger should use the editor route or leave the active note alone. The recipe is the template that mod authors (and LLMs) copy for this feature, and it contradicts the docs' own rule. The two writes are also not atomic: if `updateNoteFrontmatter` fails after the append, the marker is never set, and the note grows by one line on every round. **Fix:** do both edits in one `editNote(ctx, toAbsolute(ctx, path), edit)` call, the append and the `summarized: true` line, as recipe 8 and `04-vault-files.md#editnote` do. At the least, set the marker first, in the same write as the append. Add a "Why" bullet on the caret.
2. **minor**, `src/tests/lib/features/auto-organize/auto-organize.service.test.ts:1980`. **Problem:** "an action that never settles ... does not hold the note" passes even when `evaluateAndMove` awaits the action (the probe above). No per-path lock covers the action, so a second save is evaluated either way. The test can pass while the regression it names, a run waiting on its action, is present. **Fix:** make the run's completion observable. For example, capture the debounce callback (`vi.spyOn(globalThis, 'setTimeout')` in that test), call it, and assert that it resolves while the action's promise stays pending, using `Promise.race` against a resolved sentinel after flushing microtasks.
3. **minor**, `help/documentation/mods/16-pitfalls-checklist.md:28`. **Problem:** the Manifest checklist, which an LLM is told to go through item by item, has no `ruleActions` line, though `01-anatomy-and-loading.md` adds the field and validation step 15. **Fix:** add "`ruleActions`, if present, is an array of non-empty action ids; each listed action is rule-safe: no `run.ui`/`ctx.ui` dialogs, and no write to the matched note without a marker or a no-change check".
4. **nit**, `src/lib/features/auto-organize/AutoOrganizeRuleRow.svelte:69,495`. **Problem:** `NO_ACTION = 'none'` can collide with a saved id. A hand-edited rule `"runAction": { "id": "none" }` passes `sanitizeRunAction`, is not registered, and so adds a `none (not loaded)` option. That option shares the key `'none'` with **None** in the keyed `{#each ... (option.value)}`, which Svelte reports as `each_key_duplicate` (a dev-mode check, from memory, not verified against the Svelte source), and the Select shows the rule as None. **Fix:** make `sanitizeRunAction` require the `mod:` prefix that every registered id has, or use a sentinel that cannot be a trimmed non-empty id (such as `''`), or skip the missing option when `actionId === NO_ACTION`.
