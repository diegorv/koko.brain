## Findings

1. **minor** — src/lib/plugins/kanban/KanbanView.svelte:308-385 (`handleBoardKeydown`). The Issue's "What to build" item 3 calls Move to "the keyboard-reachable way to change lanes", but the card menu cannot be opened from the keyboard: the board keydown handler has no `ContextMenu`/`Shift+F10` case and the card trigger is a plain `div` that only bits-ui's `contextmenu` event opens. Move to is therefore mouse/trackpad only. Not an acceptance criterion and not this ticket's scope to add a new shortcut; the help page correctly makes no keyboard claim. Fix: open a follow-up `.scratch` Issue for a key (e.g. `Shift+F10` or the ContextMenu key) that opens the focused card's menu, or a direct "move to lane" key in the ring.
2. **nit** — src/lib/plugins/kanban/KanbanView.svelte:585. The chip is limited to board view (`&& currentViewMode === 'board'`), narrower than the Issue's literal "shows while `!canReorder`". The reasoning holds (list and table views have no drag and no card menu, so the chip would point at nothing), it is recorded in discovery.md as a default, and a test pins it (:1613-1616). No change needed; deliver should note the default in the closing commit.

The title says "Drag to reorder is off", but cross-lane drag is off too while sorted or filtered (`disableDrag` removes `draggable` from every card). (no test asserts the first sentence; :1597-1599 check only "card menu" and "Move to").
