## Findings

1. **minor** `src/lib/core/markdown-editor/extensions/live-preview/styles.ts:494`: the italic restore depends on the `cm-lp-italic` class. That class comes from `inlineHighlightExtension()`, which is installed only when the `markdownStyle` decorator is enabled (`inline/inline-extensions.ts:101`). With that decorator turned off in settings, emphasis still gets its italics from `markdownHighlight`'s generated class (`highlight-styles.ts:28`, specificity (0,1,0)). The new cancel rule (0,1,1) beats that class, so `*emphasis*` inside a callout turns upright while emphasis outside callouts stays italic. This only happens under a non-default setting and is easy to see and undo. Fix: deliver may leave it as a known limit. Otherwise a follow-up can key the restore on something that is always present in live preview, or state the limit in the styles.ts comment.
2. **nit** Issue AC "Owner eye check": still pending. The owner should record it, for example in deliver's squash commit body or a follow-up note, once they have looked at the four cases in WKWebView. The heading padding values (0.6/0.5/0.4em) are the Issue's starting values and have not been tuned by eye.
3. **nit** `src/tests/lib/core/markdown-editor/extensions/live-preview/styles.test.ts:247`: "leaves the shared input rule without a width" checks one declaration and the absence of `width`/`field-sizing`. It does not compare the whole rule with today's, which the discovery planned as a snapshot. The diff shows the rule is unchanged, so the AC holds. A future edit to the shared rule would get past this test.
