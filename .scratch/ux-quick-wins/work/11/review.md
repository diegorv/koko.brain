## Findings

1. minor — `src/lib/plugins/kanban/KanbanLane.svelte:250`: the count is a role-less `<span>` with `aria-label`. ARIA 1.2 prohibits naming the `generic` role, and WebKit/VoiceOver (the Tauri webview on macOS) commonly ignores it and reads the visible "1 of 3". The test passes because it reads the attribute, not the accessible name. Fix (follow-up is fine): render the visible text `aria-hidden="true"` next to an `sr-only` span holding `countLabel`, or give the span a role that allows a name.
2. minor — `src/lib/plugins/kanban/KanbanLane.svelte:398`: the pinned add row is outside the list's drop zone, so a card dropped on the bottom ~36 px of a lane (the add row) is refused; before, the form was inside the list and the whole lane body accepted drops. This is the layout the Issue prescribes ("drop handlers are not touched"), so not a blocker; note it for open-itens 040 or a follow-up that lets the row forward `dragover`/`drop` to the list.
3. nit — `src/lib/plugins/kanban/KanbanLane.svelte:300`: double-click on the rail title now expands the lane (`startRename`), a default the build took; no test covers the double-click path, only the "Rename" menu item. Add one test dispatching `dblclick` on the collapsed `h3`.
4. nit — `src/lib/plugins/kanban/KanbanLane.svelte:256-299`: the rail layout is unverified in a real engine: vertical-title truncation under `truncate` + `[writing-mode:vertical-rl]`, a filtered count such as "12 of 30" in a 30 px content box (it will wrap), and upward suggestions staying inside the board's `overflow-x-auto`. jsdom checks only classes and the inline width; worth one look in `pnpm tauri dev` before release.
