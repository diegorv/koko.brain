## Findings

1. **major** `src/lib/plugins/kanban/KanbanView.svelte:268` — The handler still navigates into, and deletes or toggles, the cards of a collapsed lane. `KanbanLane.svelte:316` does not render the items of a collapsed lane, but `displayBoard.lanes` still holds them. My probe confirmed it: lanes `A: [a1]` and `B: [secret]` with B collapsed, ArrowRight ×2 then Backspace leaves `['a1']` in the file, so a card the user cannot see is deleted with no undo. This is the Problem the Issue states ("the keyboard deletes a card the user cannot see"). It was already there on main, and none of the criteria covers it (item 3 defines visible lanes as `board.lanes.map(displayLane)`). Fix: in `handleBoardKeydown`, treat a collapsed lane as having no items (for example `const lanes = displayBoard.lanes.map((l) => isLaneCollapsed(board, l.title) ? { ...l, items: [] } : l)`), and add a test with a collapsed lane where ArrowRight and Backspace keep its cards. Or file it as a follow-up `.scratch` Issue.
2. **nit** `src/lib/plugins/kanban/KanbanView.svelte:199-202` — The `sortLabel` JSDoc says an unknown stored mode "sorts". It does not: `sortItems` (`kanban.logic.ts:891-930`) has no default case and returns a copy in stored order. Only card drag is off (`canReorderItems`). Fix: reword it, e.g. "keeps stored order, but card drag is off".
3. **nit** `src/lib/plugins/kanban/KanbanView.svelte:48` — The `#lib/components/ui/select/index.js` import sits between the local `./kanban.types` and `./kanban.store.svelte` imports. CLAUDE.md's import order puts `#lib/` imports before local relative imports. Fix: move it above `./kanban.logic`.
4. **nit** `src/tests/lib/plugins/kanban/KanbanView.test.ts:475-492` — The calendar-day test does not assert on the save count. The build says the calendar may re-date the card that holds the picker, so the test only checks the ringed card. That is acceptable, but it would not catch a stray save from another path. Optional: assert that only the dated card's text changed.

2. Fixed. The `sortLabel` JSDoc now says an unknown mode keeps the stored order and card drag is off.
3. Fixed. The `#lib/components/ui/select/index.js` import moved above the `./kanban.logic` imports.
4. Not changed. The finding marks it optional: the date picker may legitimately save the card that holds it, so a save-count assertion would be wrong, and the test already pins what the criterion asks (the ringed card's text and checked state, and no edit).
