## Findings

1. **minor** `e2e/specs/event-calendar.spec.ts:286-287,304-308`, `e2e/specs/event-calendar-day-drag.spec.ts:94-95,139-140`: the expected chip text gains ", read-only" because Playwright `toHaveText` reads `textContent`, which includes the sr-only suffix. The edits are correct by reading (no selector changes, so the Issue's gate holds; I grepped every other exact `toHaveText` in `e2e/specs/event-calendar*.ts` and none targets a read-only event) but nobody has run them. Fix: deliver runs `bash scripts/e2e.sh` (at least these two specs) before merging.
2. **minor** `src/lib/features/event-calendar/EventForm.svelte:77` (title `onblur`): showing the message on blur inserts a 22px row (gap-1.5 plus a 16px line) under the title. When the title is focused and the user presses Cancel (or the "Open note after creating" label), the mousedown blurs the title, the paragraph appears, and the centered dialog grows so the footer moves down about 11px before mouseup; a press in the top third of the 32px `size="sm"` button then lands outside it and the click is lost. Not reproducible in jsdom (no layout; initial focus there lands on the dialog div), so this is unverified in the app. Fix if confirmed in-app: keep the message row's height reserved (render the `<p>` always with `min-h-4`, text and `id` only when `titleError`), or accept the glitch (a second click works, Escape is unaffected).
3. **minor** `src/lib/features/event-calendar/EventForm.svelte:51` (`handleSubmit`): pressing Enter in the empty, untouched title (or any field) returns silently because `valid` is false, and no message appears, since the input never blurred. Before this change the message was always visible. Fix: set `titleTouched = true` at the top of `handleSubmit` before the `!valid` return, with a test in "EventDialog: create" (submit the empty form, expect `[data-error="title"]`).
4. **nit** `src/lib/features/event-calendar/event-calendar-keys.logic.ts:88-89`: in the dialog the rows read "Drag its block to another time or day" and "Drag the bottom edge of its block"; "its" has no antecedent outside the doc table the text is tied to. Fix (optional): accept, or loosen the doc tie so the dialog text can say "an event's block".
5. **nit** `src/lib/features/event-calendar/EventBlock.svelte:122`: the lock is absolute at `top-1 right-1` over the content, with no padding reserved, so on compact or narrow blocks it overlaps the end of the truncated title (the build report says so too). Fix (optional): add `pr-4` to the content wrapper when `event.readOnly`, or accept it as decorative.
6. **nit** `src/tests/lib/features/event-calendar/event-calendar-keys.logic.test.ts:263-269` ("repeats no chord of the key table"): gesture texts are sentences and chords are single keys, so the assertion cannot fail for any plausible row. It meets the criterion as written; no change needed unless a stronger check is wanted.

No scope creep: every source change traces to items 1-4; the `READ_ONLY_TIMING_NOTE` extraction is what item 3 asks for (reuse the sentence). No layer-baseline or composition-root change.
