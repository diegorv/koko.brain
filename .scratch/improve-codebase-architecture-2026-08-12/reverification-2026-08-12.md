# Re-verification of the 2026-08-12 Architecture Review

**Date:** 2026-08-12 (same day, second pass)
**Method:** 15 independent opus-5 verifier agents re-audited all 22 candidates from `raw-result.json` — the candidate claims, the prior adversarial verdicts, AND the prior verdicts' own evidence corrections. Nothing was assumed true: every load-bearing `file:line` citation was re-opened, caller counts re-run with rg, and every deletion test re-executed. Priority order: prior Strong first, then Worth exploring, then Speculative/refuted.
**Cost:** ~1.53M sub-agent tokens, 488 tool calls, ~13 min.

## Outcome

- **19 of 22 prior verdicts confirmed** (classification unchanged; many evidence details corrected in both directions).
- **3 verdicts overturned:**
  - **[2.2] "Open a note at a position" — Worth exploring → Strong.** The re-verifier found the decisive defect both prior passes missed: semantic/hybrid search feed a 1-indexed line number into a mailbox the consumer reads as a character offset, so "jump to match" is deterministically broken today.
  - **[5.1] "Collapse note-write and index-notify" — Strong → Worth exploring.** The defect is real (and worse than claimed) but the proposed module body is unimplementable as written: it would poison the index-dedupe map and could trigger auto-move mass-relocations via afterSave observers. Ship `forgetNote` first, reshape `writeNote`.
  - **[3.2] "Vault-index readiness" — Speculative → Worth exploring.** The readiness bug is real and user-visible on the second vault of a session; the fix is ~4 additive lines. But the candidate's own "reset the counter" win would introduce a stale-autocomplete bug (completion.ts has no reset path) — the counter must stay process-monotonic.
- **All 22 findings point at a real underlying defect** (`problemReal=true` across the board). The six that stay Speculative fail on solution shape, not on diagnosis — each comes with a smaller surgical fix worth doing instead.
