# Upgrade Tauri to 3.0.0-alpha

Stage the Tauri 2 -> 3 upgrade on branch `update-tauri-to-v3` so the cost is
known and the branch is ready to follow upstream to beta/stable. Evidence and
rationale: `discovery-tauri-v3-2026-09-15.md` in this folder. The branch is not
merged while v3 is alpha (merging to `main` auto-ships to nightly users).

## Notes

- Exact `=` pins cover only the direct dependencies. The published `tauri`
  3.0.0-alpha.1 requires `tauri-runtime`, `tauri-utils`, `tauri-macros` and
  `tauri-codegen` with `~3.0.0-alpha.0`, which accepts later alphas, and open
  PR #16023 on tauri `v3` breaks both the alpha.1 crates (`run_iteration`,
  `Error::CreateWindow`) and the published opener/dialog 3.0.0-alpha.0
  (`js_init_script` rename). The committed `Cargo.lock` is the real guard: do
  not run a bare `cargo update` on this branch until upstream republishes.
- Keep `macos-private-api` on BOTH `tauri` and `tauri-runtime-wry`; the
  migration guide's snippet fails `tauri-build`'s manifest check for this app.
- Stay on wry. CEF is rejected (origin change orphans localStorage, bundle
  size, ADR-0001).
- Owner decisions 2026-09-15: report committed on this branch, exact pins,
  push the branch and open a PR, guard the runtime selection with a
  source-level Rust test (no gate launches the app, so a dropped `.runtime`
  call would otherwise pass every check and panic at startup).
