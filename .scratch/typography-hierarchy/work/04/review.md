## Findings

1. **minor**: `src/lib/features/collection/collection-block-widget.ts:354`. Timeline bars keep a fixed `height: 16px` (`BAR_HEIGHT`, :272), but the title is now `0.8em`. The editor font allows up to 32px (`settings.logic.ts:34-36`), and from about 26px the title is roughly 17px or more, so it overflows the 16px bar and `overflow: hidden` clips it top and bottom. The builder disclosed this. Fix: size the bar and lane geometry in em (height around `1.4em` of the bar font, with top offset and row height derived from it), or at least set `BAR_HEIGHT` from the title's line box. Otherwise, file a follow-up.
2. **minor**: `src/lib/features/collection/collection-block-widget.ts:296-297,312`. The comment says the Svelte day numbers sit "under a text-xs table", but `CollectionLinearCalendarView.svelte:151` has no text-xs ancestor; the header row is plain `text-[11px]`. The widget also inverts the Svelte hierarchy. In Svelte the month label (`text-xs` semibold, 12px, :166) is larger than the day numbers (11px). In the widget the month label is `0.85em` (about 12.3px) and the day numbers are `0.9em` (about 13.0px). Fix: make the day numbers smaller than the month label (for example 0.8em against the label's 0.85em), and correct the comment.
3. **minor**: `src/lib/plugins/queryjs/kb-ui.ts:741,784` and `collection-block-widget.ts:243,319,354`. The "readable floor" is a ratio chosen to give 11px at the default font, not a floor. At the 8-12px editor fonts the settings allow, heatmap text falls to about 5-7.5px. This is acceptable under the Issue's "scale with the editor font" goal and is disclosed in discovery.md. `max(11px, 0.7em)` would give a real floor, but the styles test's no-px rule would then need an exception. Owner call. No change is required for this Issue.
4. **minor**: `.scratch/typography-hierarchy/issues/04-editor-blocks-scale-with-the-editor-font.md` Comments. The owner decision in Notes asks for an LP-PROFILE run on a long note in the app. The recorded numbers come from a vitest timing of `computeCodeBlocks`, labeled as such. This measures the same JS that LP-PROFILE times and shows no change (about 1.38 ms either way), so the risk is low. The in-app run is still owed to the owner or deliver.
5. **nit**: `src/tests/lib/core/markdown-editor/extensions/live-preview/plugins/code-block-field.test.ts:43-56` and `styles.test.ts:53-57`. The field test checks the decoration's object identity, and the styles test checks the `.cm-lp-codeblock-line` rule, but nothing ties `codeBlockLineDeco.spec.class` to that selector (same for `tableLineDeco`). Renaming the class on either side would leave every test green while revealed code jumps size again. Fix: `expect(codeBlockLineDeco.spec.class).toBe('cm-lp-codeblock-line')`, and the same for the table.

The "Run again" button reuses `.cm-lp-qjs-run` (`0.8em`) inside `.cm-lp-qjs-error` (`0.95em`), so it renders at about 12.2px where it was 13px. The first-run button gets 12.8px. These are rounding-level differences, with no change needed unless the two buttons should match.
