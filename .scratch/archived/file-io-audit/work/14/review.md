## Findings

1. **blocker** `src/lib/core/markdown-editor/MarkdownEditor.svelte:273-287`. The rename-detection branch still fires on close, and that leaves the Issue's corruption reachable. Suppose the active tab A is closed (Cmd+W) and the tab activated next, B, has the same content as A's current doc (two empty notes, or two notes still at the same template text). Then `findTabIndex(lastTabPath) < 0 && doc === tab.content` is true. The branch counts this as a rename: `showTabState` is skipped, and B keeps A's `EditorState` and its history. Review probe (temporary test file, removed afterwards): A = `"Same body\ntyped in A\n"`, B = `"Same body\n"`. Delete `"typed in A\n"` in A, `closeTab(A)`, then undo 3 times in B. `undoDepth` in B is 1, and B's tab content becomes `"Same body\ntyped in A\n"`. A's text lands in B and is autosaved to B.md. B's saved state in `tabEditorStates` is also left behind, and leaving B later overwrites it with A's history. Fix: treat this as a rename only when the new path was not an open tab before. For example, `renameTabViewState` (or `updateTabAfterRenameOrMove`) records the pending `{ oldPath, newPath }`, and the branch requires `path === pending.newPath && lastTabPath === pending.oldPath`. Alternatively, keep the set of open tab paths from the previous run and refuse the branch when `path` was already in it. Add the probe above as a regression test, plus a variant where B was visited before (it has a saved state).
2. **major** `src/lib/core/markdown-editor/doc-diff.logic.ts:18` (used by `MarkdownEditor.svelte:101`). A single prefix/suffix range covers everything between the first and last changed sites, so an undo event whose position lies between two external edits is mapped to the edge of that range. Review probe: doc `"Top [[x]] line\n\nmid SENT. here\n\nBottom [[x]] line\n"`. Delete `"SENT. "`, sync with both `[[x]]` turned into `[[yy]]` (an `updateLinksAfterRename` rewrite of a note that links twice), then undo once. The doc becomes `"…mid here\n\nBottom [[yySENT. ]] line\n"`: the sentence is inserted inside the second link and breaks it. A watcher reload that edits several places hits the same path. The Issue's item 2 says to clear the history for a sync the diff cannot keep local. Fix: produce one change per changed region, for example a line-level diff where each hunk is trimmed to its common prefix/suffix. If the edit spans several regions and no such diff is available, clear the note's history for that sync. Add a regression test for the two-site link rewrite.
3. **minor** `src/lib/core/markdown-editor/MarkdownEditor.svelte:131-143`. On a first visit the fresh state is created from `mountExtensions` (mount-time live-preview and theme config) and then reconfigured in a second update. Every block `StateField` is computed twice for each newly opened note, and that happens on the tab-open hot path. Fix: build the first-visit state once with the current mode, theme and language, or skip the reconfigure effects when they equal the mount-time values. Measure it with the TAB_SWITCH perf logs before deciding.

## Resolution

1. **blocker, fixed in 3a5bf01f.** `renameTabViewState` now records the old -> new path (`pendingRenames` in `tab-view-state.ts`), and the tab-switch effect treats an active-path change as a rename only when `takeTabRename(lastTabPath) === path` (`MarkdownEditor.svelte:271-277`); the content match is gone. Every recorded rename is forgotten on each check and by `clearAllTabViewStates`. `updateTabAfterRenameOrMove` is the only caller of `editorStore.updateTabPath`, so every tab rename is recorded. Regression tests: `undo-history-across-notes.test.ts` "closing the active tab onto a tab with the same content …" (the review's probe) and the variant where B was visited before; both failed before the fix (undo depth 1 in B). `tab-view-state.test.ts` covers `takeTabRename`.
2. **major, fixed in 39e06fdb.** `docDiff` now returns one change per changed region: common whole lines trimmed from both ends, a Myers line diff of the rest, each hunk trimmed to its differing characters. Past `DOC_DIFF_MAX_EDITS` (400 line edits) it returns null and the note's history is dropped, as the Issue's item 2 asks: `replaceDoc` installs a fresh state that keeps the current language compartments, and `showTabState` discards the saved state. Regression tests: the two-site link rewrite probe ("Cmd+Z after a two-site link rewrite …"), a too-large sync on the active note and a too-large background write, all red on the previous source; `doc-diff.logic.test.ts` covers the multi-region output and the cap.
3. **minor, fixed in 39e06fdb.** A first tab visit now builds its state once with `freshState`, which calls `createExtensions` with the current settings and editor mode; no reconfigure follows (its markdown language is what the sync language effects would set; a code file still gets its parser from `applyLanguageForTab`, as before). Not measured with the TAB_SWITCH perf logs: that needs the running app, and the change removes a second update rather than tuning one. No test asserts the single build.
