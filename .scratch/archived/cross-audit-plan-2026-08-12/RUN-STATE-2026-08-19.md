## Correctness follow-ups surfaced by reviewers

- `buildIndex` swallows IPC errors, so `markIndexReady()` stays optimistic after a
  failed scan.
- `teardownVault()` racing a live scan clears `isBuilding` / `pendingRebuild`
  mid-flight, so a queued caller can resolve without its index being built.
- Stale post-teardown `vault-index-updated` events still write the old vault's data
  into typeDefinitionsStore / refreshArchivedPaths / fsStore.contentOrder. Issue 36's
  memo invalidation does NOT close this; it needs a vault-scoped guard.
- Bounded staleness accepted by issue 36: between a Rust index mutation and the
  300 ms debounced version bump, queryjs and wikilink completion serve the previous
  snapshot. Deliberate ("cache, not mirror", ADR-0025), but it is a real surface.
- `loadVaultTagMap` keeps a direct invoke on a rationale that only fits
  `loadVaultContentMap`; it issues no batch read and could route through the memo.
