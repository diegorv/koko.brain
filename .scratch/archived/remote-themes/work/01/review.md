## Findings

1. minor, `src/lib/core/settings/theme-validation.logic.ts:30`: an app-produced theme can fail to re-import. The Issue says "Everything the app itself produces still imports". If you import a partial file whose source token holds an accepted `color-mix(...)`, for example `ui.muted = "color-mix(in srgb, #ffffff 50%, transparent)"`, `mergeThemeWithDefaults` then derives `syntax.activeLine` through `alpha()` as `color-mix(in srgb, color-mix(in srgb, #ffffff 50%, transparent) 30%, transparent)`. Exporting that theme and importing it again is refused with `"syntax.activeLine" is not a valid color or token` (confirmed by the probe). The same holds for any source token that `alpha()` wraps (`ui.primary`, `ui.muted`, `syntax.link`, `preview.blockquoteBorder`). No built-in theme has a color-mix in a core source, so the built-in round-trip test cannot catch this. It matters again in Issue 03, where catalog palettes go through `buildTheme`. Fix: allow one level of nesting in the color-mix inner color (`isBaseColor(inner) || isThemeColorValue(inner)` with a depth bound, still under the 128-char cap), or make `alpha()` fold the alpha of an existing `color-mix`. Add a test that a palette with a color-mix source, built and exported, re-imports.
2. nit, `src/lib/core/settings/theme-editor.logic.ts:286-287`: the cap counts UTF-16 code units (`json.length`), but the message says "64 KB". For an ASCII theme file the two are the same. Either say "characters" in the message or leave it as is. The file is also fully read by `FileReader` before the check, which is acceptable for a local file picker.
3. nit, `src/lib/core/settings/theme-editor.logic.ts:296-299`: a missing or empty `name` and a missing, null or array `colors` all show "Invalid theme file: could not parse", although the JSON did parse. The criterion only asks for token paths, so this is not a blocker. Something like `missing "name"` or `"colors" must be an object` would tell the user what is wrong.

## Resolution

1. Fixed by folding: `alpha()` in `theme-builder.logic.ts` now scales the percentage of an existing `color-mix(in srgb, X N%, transparent)` instead of wrapping it again, so derived tokens stay one level deep and the validator keeps refusing nesting. Tests: `alpha` "folds the alpha into an existing color-mix instead of nesting it" and `parseThemeFromImport` "re-imports a theme whose color-mix source tokens were expanded and exported" (color-mix in `ui.primary`, `ui.muted`, `syntax.link`, `preview.blockquoteBorder`).
2. Fixed: the size message now says `larger than 65536 characters`.
3. Fixed: a missing or blank `name` shows `Invalid theme file: missing "name"`, and a missing, null or array `colors` shows `Invalid theme file: "colors" must be an object`. A top-level array now stays a parse error.
