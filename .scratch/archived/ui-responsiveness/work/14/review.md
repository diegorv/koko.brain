## Findings

1. minor — `src/lib/features/collection/CollectionView.svelte:116-118`: the record effect writes whatever `activeViewIndex` holds, including the 0 forced when the YAML does not parse. `restoreViewIndex()` clamps to 0 when `definition` is null (`(definition?.views.length ?? 1) - 1`), and the clamp effect at `:102-105` does the same on a parse failure while the file is open. Scenario: open A on view 3, switch to source mode, type a YAML error, switch back. The view mounts with `definition === null`, records 0, and once the YAML is fixed A shows its first view and remembers that from then on. This is rare and recoverable. Fix: record only while a definition exists (`if (definition) collectionStore.setViewIndex(filePath, activeViewIndex)`), with a test that mounts invalid YAML over a remembered index and asserts the index survives.
2. minor — `src/lib/app/EditorView.svelte:84`: keying on `editorStore.activeTab.path` also remounts the view when the active collection is renamed or moved (`updateTabAfterRenameOrMove` changes `tab.path`). Before this change, the instance kept its per-instance UI state through a rename: open popovers, an inline view-tab rename buffer, and formula rows still in `editing`. Now that state is lost. The view index survives, because the path-change consumer runs synchronously before the next flush (`path-change.service.ts:167-175`) and my probe confirmed the restore. This is acceptable under the Issue (it names the key), but it is not mentioned outside discovery.md. Fix: none needed. If it matters, note it in the Issue resolution.
3. nit — No committed test covers renaming the active collection tab end to end (EditorView remount plus the consumer carrying the index). The consumer is tested through the real `fs.service` (`collection-view-index-path-change.test.ts`) and the remount is tested on a tab switch. My probe covered the combination but is not committed. Fix: optionally add an `EditorView.test.ts` case that renames the active tab via `renameItem` and asserts that the same view stays highlighted.
