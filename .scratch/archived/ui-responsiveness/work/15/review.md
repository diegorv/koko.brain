## Findings

1. minor — `src/lib/core/markdown-editor/MarkdownEditor.svelte:485`: the `pending scrollIntoView pos=N after` line does not show the scrollIntoView's effect. `EditorView.scrollIntoView` only sets `viewState.scrollTarget`; the actual `scrollTop` write happens in CodeMirror's next measure (`index.js:8289-8293` -> `3482-3486`), a frame later, and its scroll event fires in the frame after that, by which time the `event` listener was removed in frame 3. 2. minor — `src/tests/lib/core/markdown-editor/MarkdownEditor.test.ts:359-371`: "writes no scroll line with the debug log off" passes even if `logTabScroll` dropped its `tabScrollLogOn()` guard, because `debug()` itself drops the line when both settings are off. Fix: spy on the `scrollTop` getter of `editorStore.editorView.scrollDOM` (or count `addEventListener('scroll', ...)` calls) and assert it is not read during a switch with the log off.
3. nit — `src/lib/core/markdown-editor/MarkdownEditor.svelte:427-433,453-457`: the `event` window ends at frame 3, so a scroll write from a CodeMirror measure in frame 4 or later (an image or widget height settling, the 150 ms scroll-debounce rebuild) is not logged, while the second render wave the Issue cites lasts about 170 ms. The Issue asks for two frames only, so this meets the criterion; if the owner's log shows the jump after frame 3, widen the window (for example until the first `scrollDebouncePlugin` rebuild) in the follow-up.
