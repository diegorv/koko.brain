This is within the Issue's scope, since the Issue names editor-host only, and the build report says so. Fix: file a follow-up Issue that threads `vaultStore.path` (or the vault path the caller already has) into these callers, or fold it into Issue 18, which aligns the Rust `VaultIndex`.
2. nit — `src/tests/lib/core/filesystem/wikilink-resolution.logic.test.ts:165-167` and commit `60153521`'s Problem/Behavior text: the test `does not take a root-level file for a path-style target when the vault folder shares the first segment` only proves this when `/b/b/foo.png` exists. The basename fallback would pick a `foo.*` file in that case anyway, so this does little harm, and the owner chose to keep the suffix fallback. Fix: rename the test to say the vault-relative file wins over the root-level one (e.g. `prefers the vault-relative file over a root-level one when the vault folder shares the first segment`), or limit the suffix fallback to matches that start inside the vault root.
3. nit — `src/lib/core/filesystem/wikilink-resolution.logic.ts:32`: a root that ends in `/` builds `/vault//b/foo.png` and silently falls back to the suffix rule. `vaultStore.path` comes from the folder picker without a trailing slash, so no current caller hits this. No change needed unless a caller ever passes a normalized-with-slash root.
