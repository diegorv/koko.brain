# Sentry audit and usage-analytics decision (2026-11-05)

Deep dive: 20 haiku scouts, 5 opus validators (each tried to refute its group). Raw reports: `raw/j01.md`..`raw/j25.md` (journal order; j21-j25 are the validators: j21 frontend, j22 settings/policy, j23 Rust/PII, j24 instrumentation/local, j25 vendors).

Owner constraint (2026-11-05): the owner is the only recipient of the events, so note names, paths and hostname in events are acceptable. Note content stays out.

## A. Sentry

Core is correct: off by default, strict per-vault opt-in, every `Sentry.init` option exists in `@sentry/browser` 11.9.0, integration allowlist tested against real defaults, Rust panic hook installed and opt-out unbinds the client.

Gaps, by usefulness:

1. **JS stack traces are unreadable.** No `build.sourcemap`, no upload step (`vite.config.js`, `build/` has 0 `.map`). Fix: hidden source maps + `@sentry/vite-plugin` (debug IDs) in the release workflow, needs a `SENTRY_AUTH_TOKEN` secret.
2. **Rust panics are unsymbolicated.** `strip = true`, `debug = 0`, no `debug-images` feature (`Cargo.toml:72,88`). Needs `debug-images` + dSYM upload in CI. Owner decision.
3. **Dev and prod events mix.** JS `environment` always `production` (SDK default), Rust is profile-based; a dev build shares the stable release name (`sentry.service.ts:19-22`, `build-info.js:69-73`). Fix: pass `environment` to both sides.
4. **"Send test event" always says sent.** `flush()` resolves true on 4xx, offline, 429 or CSP block (`sentry.service.ts:133`). Help copy overclaims (`SentrySection.svelte:80`, `help/documentation/19-settings.md:268`).
5. **Bare `ingest.sentry.io` DSN accepted but CSP-blocked** (`sentry.logic.ts:17` vs `tauri.conf.json:29` `*.ingest.sentry.io`).
6. **Volume / quota.** Every `error()` call is sent, not just unhandled errors (copy says "unhandled", `SentrySection.svelte:50`). A broken auto-move rule sends one event per save (`auto-move.service.ts:159-161`); Developer plan quota is 5k errors/month. `Dedupe` only drops consecutive repeats.
7. **Blind spots.** Nothing before a vault opens (design: DSN is per vault); no `svelte:boundary`; Rust `Err` reaches Sentry only when JS passes it to `error()`; some `console.error` sites bypass (`TemplatePicker.svelte:43`, `SentrySection.svelte:22,38`).
8. **Tests mock the SDK**, so `beforeSend` never runs through the real pipeline; the reconfigure queue has no concurrency test (`sentry.service.test.ts`).
9. **Versions.** `@sentry/browser` 11.10.0 is past quarantine (11.11.0 published today). `sentry` crate 0.49.5 waits in a Dependabot branch.

Downgraded by the owner constraint: paths in error messages (`vault.service.ts:44`, IPC `Err(String)`), hostname in Rust `server_name`.
Refuted: Quick Capture clipboard reaching Sentry (`quick-capture.service.ts:112` passes an object; the SDK puts it in `extra`, which `beforeSend` strips).

### Related, outside Sentry: the privacy CI gate is broken

- Skip rule `:\s*//` (`.github/workflows/privacy.yml:69`) matches the `://` of every URL, so any line with a URL is skipped. `PRIVACY.md:20` ("any new external call ... will fail the build") is false. Verified by reading `.github/actions/scan-external-calls/action.yml:84-111`.
- The gate never reads the CSP or `src-tauri/capabilities/**`, and network calls inside dependencies are invisible to it.
- Fixing the regex alone turns CI red: `theme-catalog.service.ts:9`, `UpdateSection.svelte:24,27` need `known` entries.
- PRIVACY.md is stale: Chart.js row points to a missing `dv-ui.ts` (it is bundled), no Todoist row, no updater row, remote images in notes not disclosed.

## B. Usage analytics: no third party

| Option | Verdict |
|---|---|
| Sentry Logs / Metrics | Out: 30-day retention on every plan, sampled. Fails "over time". |
| PostHog | Out: autocapture records DOM text by default, remote project settings can re-enable capture, open Tauri v2 delivery report, ~54 releases/month vs 5-day quarantine. |
| Aptabase (EU) | Best vendor if a hosted dashboard is wanted: MIT Tauri plugin, manual events only, 20k events/month free, 5-year retention. But the key is fixed at plugin construction (restart to change, not per-vault like Sentry), it duplicates crash reporting, and it breaks `PRIVACY.md:8`. |
| Self-hosted Umami / Plausible / OTLP | User-chosen host does not fit the static CSP / HTTP scope; ops cost. |
| **Local counters (recommended)** | No network, no dependency, no retention limit, no PRIVACY.md change beyond one line. |

### Recommended design

Superseded in detail by Issues 06-08 after the 2026-11-06 review: full ids are kept (no path stripping), rail clicks record `rail:go-to:<key>` in `AppShell.svelte`, and the Settings page is counted from the `SettingsPanel.svelte` sidebar click, not from a `core/` store. The Issues are the source of truth.

- Storage: `usage_counts(day TEXT, feature TEXT, count INTEGER, PRIMARY KEY(day, feature))` in the vault DB (`src-tauri/src/db/mod.rs`, `CREATE TABLE IF NOT EXISTS` pattern in `schema.rs`), UPSERT batched on a timer.
- Seams (key = `AppCommand.id`, path suffixes stripped from `rail:open-view:*` / `rail:go-to:*`):
  1. `CommandPalette.svelte:27-37` `executeCommand`
  2. `global-keybindings.ts:224` (today it discards `binding.command`; keep it)
  3. `rail-navigation.ts:14-24` `selectRailItem` (covers `opensInEditor` views that skip `updateLayout`)
  4. settings section open (`settingsPanelStore.setSection`)
- "Never used" = registered ids (commands, rail navigators, `SettingsSection` union) minus ids with count > 0.
- Toggle in Settings, off by default, next to Sentry. View: top / never-used lists; optional `kb.usage()` for QueryJS charts (Chart.js already bundled).
- Estimate: about 2 days plus the ts-rs bindings gate. Needs an ADR (ADR-0015:71 defers opt-in telemetry).
