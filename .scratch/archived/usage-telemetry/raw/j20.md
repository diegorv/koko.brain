## Summary

- **Command palette** has one dispatch point with a stable id: `CommandPalette.svelte:27-37` (`executeCommand`). Keybinding-triggered global commands never reach it, and the keybinding handler has no command id (`utils/keybindings.ts:73`, `app/global-keybindings.ts:224` strips `command`). Wrapping at `global-keybindings.ts:224` gives ids for the ~20 bindings that carry one.
- **Rail / panel open** has one decision point, `selectRailItem` (`app/rail-navigation.ts:14-24`), called from `AppShell.svelte:203`. Layout writes all go through `settingsStore.updateLayout` (`core/settings/settings.store.svelte.ts:236-241`). Keys are stable, except pinned views, which embed an absolute path.
- **Quick capture** has one funnel for deep-link and clipboard captures: `executeAction` (`features/deep-link/deep-link.service.ts:182`), with a stable `action.kind`. The palette's "Create Quick Capture Note" bypasses it (`plugins/quick-capture/note-composer.service.ts:20`).
- **Settings section** has a stable id (`SettingsSection` union, `settings.types.ts:331`), changed by click at `app/SettingsPanel.svelte:135`. Nothing calls `settingsPanelStore.open(section)`.
- **Plugin activation** has no event. Plugins register at vault open (`app/lifecycle/app-lifecycle.service.ts:247-267`), so "usage" has to be measured at each feature's entry point.
- **Leak risk:** `quick-capture.service.ts:112` passes the raw clipboard payload (text, URLs, paths) into `error()`, which forwards it to Sentry when Sentry is active. This is the most important privacy finding for instrumentation.

## Findings

**F1. medium. Clipboard payload reaches Sentry on an invalid capture.**
- Claim: a plain-object payload passed to `error()` is serialized in full into Sentry extras.
- Evidence:
  - `src/lib/plugins/quick-capture/quick-capture.service.ts:112` calls `error('QUICK_CAPTURE', 'Invalid capture payload:', payload)`. The payload has `text`, `url`, `path`, `sourceUrl`, `sourceTitle` (lines 17-34).
  - `src/lib/utils/debug.ts:27-31`: `error()` calls `captureSentryException(tag, args.find(Error) ?? args.at(-1))`, so the plain object is the exception.
  - `src/lib/core/settings/sentry.service.ts:112-118`: `captureSentryException` sends it when `activeDsn !== null`.
  - `node_modules/.pnpm/@sentry+core@11.9.0/node_modules/@sentry/core/build/esm/utils/eventbuilder.js:69-73`: for a plain object, Sentry adds `__serialized__: normalizeToSize(exception)` to the extras.
- Trigger: `buildCaptureAction` returns null (rare). Only opted-in vaults send.
- Fix: log `payload.kind` and key names only. Never pass a payload object to `error()`. Add a unit test that the Sentry capture receives no clipboard text.

**F2. medium. Keybinding-triggered commands have no id, so a single hook misses them.**
- Evidence: `utils/keybindings.ts:73` (`binding.handler()`), `app/global-keybindings.ts:224` (the `command` field is removed before registration). Bindings with no `command` at all: slash search (`global-keybindings.ts:40`), zoom (`:178-181`), source mode (`:183-188`).
- Fix: wrap `global-keybindings.ts:224` so the handler reports `binding.command` when present. Give the zoom and source-mode bindings ids if they should be counted.

**F3. low. Command ids and rail keys embed note paths.**
- Evidence: `app/commands.ts:61` (`rail:go-to:${item.key}`), `commands.ts:79` (`rail:open-view:${view.path}`). Pinned rail keys are `view:<path>`, where `core/settings/rail-pin.logic.ts:8` documents the rest as an absolute path (`:15-16`). Also `features/rail-shell/lens.logic.ts:157-168`.
- Fix: record the kind (`rail:open-view`) and never the suffix. Hash or drop the suffix before storage.

**F4. low. Existing debug logs write note paths when log-to-file is on.**
- Evidence: `core/editor/editor.service.ts:103` (`ENTRY path=`), `:110`, `:118`, `:124`, `:126`, `:142`. `features/deep-link/deep-link.service.ts:201` logs the search query. `features/rail-shell/RailNoteList.svelte:282,321` and `view-lens.service.ts:39` log `${path}`.
- Gate: `appendLog` writes only while a session is active (`utils/log.service.ts`), and sessions start only when `debugLogToFile` or `debugTauriLogToFile` is on (`app/lifecycle/app-lifecycle.service.ts:218-221`). Off by default.
- Fix: any new telemetry must not call these helpers with paths. These existing lines need no change for this scout.

**F5. low. Full deep-link URL is logged.**
- Evidence: `features/deep-link/deep-link.service.ts:122` logs `Received URL:`. The `new` action accepts `content` (`resolveContent`, `:223`), so the URL can contain note text. Same gate as F4.
- Fix: log the action type only.

**F6. low. Errors sent to Sentry may carry absolute paths.**
- Evidence: `core/editor/editor.service.ts:146` passes the raw error object to `error()`, which Sentry receives.
- UNVERIFIED: whether Tauri fs error messages include the absolute path. Check with a real failing read before treating this as confirmed.

**F7. info. Plugin activation is not an event.**
- Plugins are always registered at vault open (`app-lifecycle.service.ts:247-267`, `app/boot.ts:34-60`). Settings toggles exist for some features (`settings.store.svelte.ts:244-321`: folder notes, history, auto-move, sentry), and `enabled` fields are at `settings.types.ts:116, 229, 253, 260`. Rail registrations have ids (`rail-registry.store.svelte.ts:22-40`).
- Fix: count first use at each feature's entry point, not at activation.

**F8. info. Tab open has several entry points, and the store is the wrong hook.**
- `openFileInEditor` (`editor.service.ts:99-149`) is the main path. Virtual tabs call `editorStore.addTab` directly: `plugins/graph-view/graph-view.service.ts:42`, `features/tags/tags.service.ts:131`, `features/event-calendar/event-calendar.service.ts:146`, `features/tasks/tasks.service.ts:169`. `core/filesystem/path-change.service.ts:167` restores tabs and should be excluded.
- `fileType` is a stable feature id for virtual tabs (`core/editor/editor.types.ts:12`). Real-note tabs use `name` (basename), which must not be logged.
- `editorStore.addTab` (`editor.store.svelte.ts:52`) is the single chokepoint, but CLAUDE.md keeps stores free of side effects, so hook the service sites instead.

**F9. info. Settings section open has one clean seam.**
- `settingsPanelStore.setSection` (`settings-panel.store.svelte.ts:17`) is called from `SettingsPanel.svelte:135`. Panel open or toggle has callers at `global-keybindings.ts:165`, `commands.ts:358`, and `app/tauri-listeners.service.ts:29` (native menu).
- Hook: an `$effect` on `settingsPanelStore.activeSection` in `SettingsPanel.svelte`, or the click at `:135`.

**F10. info. Quick capture entry points differ.**
- Deep link: `handleDeepLinkUrl` (`deep-link.service.ts:121`) to `resolveAndDispatch` (`:153`) to `executeAction` (`:182`, `capture` case at `:205-207`) to `executeCaptureAction` (`app/deep-link-actions.ts:133`).
- Clipboard and popover composer: `qc:capture-detected` (`quick-capture.service.ts:62`) to `dispatchCapture` (`:101-118`, kind logged at `:116`) to `executeAction` (`:117`).
- Palette and keybinding: `createNoteComposer` (`note-composer.service.ts:20`), which uses neither path.
- `CaptureKind` is `'note' | 'clip' | 'link' | 'shot' | 'file'` (`deep-link.types.ts:72`), a stable id.
- Seam: `executeAction` covers deep-link and clipboard capture. A separate hook is needed for `createNoteComposer`.

**F11. info. No existing usage telemetry.**
- A search of `src/lib` and `src-tauri/src` for analytics or telemetry terms finds only unrelated log comments (`src-tauri/src/commands/vault.rs:1283`).
