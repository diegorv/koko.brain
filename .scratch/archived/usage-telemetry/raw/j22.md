## Findings the scouts missed

- **N1. medium. The Todoist API token is in the same per-vault `settings.json`.** `TodoistSettings.apiToken` (`settings.types.ts:245`) is persisted beside the DSN. Unlike the DSN, this token gives read/write access to the user's Todoist account. If the vault is ever synced or committed, this exposure matters more than s7-F1. Any analytics key copied into the same file gets the same exposure.
- **N2. medium. The `error()` → Sentry path leak covers every IPC failure, not just two call sites.** Rust commands return `Result<_, String>` with paths in the message (`semantic_repo.rs:93`, `commands/semantic.rs:1491`, among others). `call()` is a bare `invoke` (`contracts/ipc.ts:21-27`) and does not wrap the rejection in an `Error`. So `error(tag, 'msg:', err)` with a string `err` sends that path-bearing string as the event (`debug.ts:31`), and `beforeSend` does not scrub exception values (`sentry.service.ts:28-36`). Unverified, from memory: that Tauri's `invoke` rejects with the raw `Err` string and that `captureException(string)` turns the string into the event message. Fix: send only `Error` instances with a fixed message, or scrub `exception.values[].value` and `message` in `beforeSend`.
- **N3. medium. The privacy gate never reads the files that control network access.** The scanner roots are `src` and `src-tauri/src` (`privacy.yml:35,85`). `tauri.conf.json` is only a path trigger, and its CSP is never scanned. `src-tauri/capabilities/**` is in neither path list (`privacy.yml:6-14`, `pr.yml:58-65`). A new analytics host added to `connect-src` or to an `http:allow-fetch` scope passes CI. Also, `pr.yml`'s filter leaves out `PRIVACY.md`, which `privacy.yml:12` includes.
- **N4. low. Fixing s8-F1 alone turns the build red.** With the skip anchored to `:[0-9]+:\s*//`, these lines become unknown: `theme-catalog.service.ts:9` (raw.githubusercontent), `UpdateSection.svelte:24,27` (github.com/diegorv/koko.brain), and possibly the canvas `https://${...}` link builders (`CanvasLinkInput.svelte:21`, `LinkNode.svelte:55`). The TS `known` list has neither host, so the fix has to add known entries in the same change. The stale `cdn\.jsdelivr\.net/npm/chart\.js` known entry (`privacy.yml:75`) can go.
- **N5. low. `19-settings.md:268` repeats the overclaim of s7-F4** ("to confirm the DSN reaches your project").

## Verdict for this area

- **Sentry settings are sound on consent and storage.** Monitoring is off by default, opt-in is strict (`=== true`) and per vault, and Sentry is disabled when switching vaults. The browser SDK's integrations and data collection are trimmed correctly.
- **The weak spots are honesty and enforcement.**
  - The test button and the help copy promise delivery the code cannot confirm (s7-F4, N5).
  - "Unhandled errors" understates what is sent (s7-F9). Path strings can leak through `error()` (N2).
  - The privacy CI that PRIVACY.md cites as the guarantee does not check TS URLs (s8-F1). It also does not read the CSP or capability files that are the real controls (N3).
  - PRIVACY.md's list of network calls is stale (s8-F3, s8-F4) and leaves out remote images (s8-F5).
- **For part B:** the Sentry section works as a UI template if the parse-block caveat (s7-F8) is kept in mind. But any third-party usage service contradicts `PRIVACY.md:8` and needs an ADR beyond 0015's "opt-in layer later" note. The gate as it stands would not catch it either (s8-F1, N3). A local-only counter in `.kokobrain/kokobrain.db` needs no CSP, capability or scanner change.
- **Fix the gate first.** Fix s8-F1 together with N4 and N3 before adding any new endpoint, and correct PRIVACY.md at the same time.
