## Summary

- **Option names all exist in the installed SDK.** `@sentry/browser` and `@sentry/core` are 11.9.0. Every key in `dataCollection` used by `sentry.service.ts` is declared in the installed typings. The six kept integration names match the SDK, and the test at `sentry.service.test.ts:84-96` checks them against real defaults.
- **`sendDefaultPii` is not a v11 option.** It is absent from the installed typings and runtime, and the Sentry docs call it deprecated. The real PII control is `dataCollection.userInfo`, which is set to `false`.
- **Stack traces will not be readable in production.** `vite.config.js` does not set `build.sourcemap` (Vite default `false`), and the repo has no Sentry source-map upload step.
- **Event scrubbing is incomplete.** `beforeSend` removes breadcrumbs, extra, request and user, but leaves `message` and `exception` values untouched. Those can carry note text or vault paths.
- **`environment` is unset.** Dev and production builds may be tagged the same way.
- I did not write the findings file, because the subagent rules say to return findings directly.

## Findings

**F1, high: production stack frames are not symbolicated.**
- Claim: frontend events will show minified frames with no source-map resolution.
- Evidence: `vite.config.js` has no `build` block and no `sourcemap` setting. A repo-wide search of `.github`, `scripts` and `vite.config.js` finds no `sentry-cli` or sourcemap upload. The only Sentry workflow reference is `.github/workflows/privacy.yml`. Vite's documented default is `build.sourcemap: false` (https://vite.dev/config/build-options, checked this session).
- Fix: set `build.sourcemap: 'hidden'` in `vite.config.js` and upload the maps with `sentry-cli` in the release workflow, with the same release string the app sends. Otherwise, accept unreadable frames for now.

**F2, high: message and exception values reach Sentry unscrubbed.**
- Claim: `removeSensitiveEventData` (`sentry.service.ts:28-36`) does not touch `message`, `exception.values[].value` or the stack frames. Note text or vault paths can therefore leave the machine.
- Evidence:
  - `src/lib/utils/debug.ts:31` passes `args.find(arg instanceof Error) ?? args.at(-1)` to `captureSentryException`. The last argument of `error()` can be any value, such as a string or object containing note content.
  - `GlobalHandlers` is kept (`sentry.service.ts:63-70`), so uncaught errors and unhandled rejections are sent through `beforeSend` with their original messages.
  - `captureSentryException` (`sentry.service.ts:112-118`) sends whatever it is given.
  - `sentry.service.test.ts:98-109` only covers the four fields that are removed. It does not check messages.
- Fix: in `beforeSend`, drop or replace `message` and `exception.values[].value` (or send only the error class name). Also pass only `Error` instances to `captureSentryException`, and add a test that a message containing a path is not sent.

**F3, info: `sendDefaultPii` does not apply.**
- Claim: the option is not present in v11, so the question has no bearing on this code.
- Evidence: a grep of `@sentry/core` and `@sentry/browser` `build/types` and runtime build finds no `sendDefaultPii`. The Sentry options page says it is a deprecated fallback inside `dataCollection`, and that "from version 11 onward, the new defaults always apply" (https://docs.sentry.io/platforms/javascript/configuration/options/, checked this session).
- Fix: none. Keep `dataCollection.userInfo: false`.

**F4, info: every `dataCollection` key is valid.**
- Evidence: `core/build/types/types/datacollection.d.ts:27-131` declares `userInfo`, `cookies`, `httpHeaders`, `httpBodies`, `urlQueryParams`, `graphQL`, `genAI`, `databaseQueryData`, `queues`, `stackFrameVariables` and `frameContextLines`. Each value in `sentry.service.ts:71-83` fits its declared type. `httpBodies: []` disables body collection per the typings.
- Fix: none. `mcp` is not set, but the MCP integration is not in the kept list, so this is harmless.

**F5, info: the integration filter works as intended.**
- Evidence: `integrations` as a function is supported (`@sentry/core` `integration.js:27-29`). The names are `EventFilters` and `FunctionToString` (core), `Dedupe` (core), `BrowserApiErrors`, `GlobalHandlers` and `LinkedErrors` (browser). Dropped defaults are `Breadcrumbs`, `Console`, `BrowserSession`, `HttpContext`, `CultureContext` and `ConversationId` (`@sentry/browser` `build/npm/esm/prod/sdk.js`). Sessions and breadcrumbs are therefore off.
- Fix: none.

**F6, medium: `environment` is never set.**
- Claim: dev builds that have a DSN configured will be tagged with the same environment as production.
- Evidence: `sentry.service.ts:58-85` does not pass `environment`. The typings say the default is `"production"` (`options.d.ts:193`). The Sentry docs say the default "depends on whether the application is packaged", which conflicts with the typings. Runtime behavior is UNVERIFIED.
- Fix: pass `environment` from `import.meta.env.DEV` or from `__APP_CHANNEL__` (defined in `vite.config.js:94`).

**F7, low: `release` is meaningful but does not carry the channel.**
- Evidence: `sentryRelease()` (`sentry.service.ts:19-22`) takes the first token of `__BUILD_INFO__`. `formatBuildInfo` (`src/lib/utils/build-info.js`) produces `<version> (<sha>) (<time>)` for stable and `<version>-nightly.<n>.<sha> (<time>)` for nightly. Stable and nightly builds therefore do not carry a channel tag. The Rust side receives the same string through `configure_sentry`. I did not check that the Rust side uses it unchanged.
- Fix: include `__APP_CHANNEL__` in the release or as a tag.

**F8, low: `sendClientReports` is on by default.**
- Evidence: `options.d.ts:169` default is `true`. The SDK sends outcome reports to Sentry, which contain no note content but are an extra outbound channel. This sits beside the "error monitoring only" comment at `sentry.service.ts:61-62`.
- Fix: set `sendClientReports: false` if you want the narrowest channel. This is optional.

**F9, info: close, flush and reconfiguration are sound.**
- Evidence: `close(timeout?)` and `flush(timeout?)` are declared at `@sentry/core` `exports.d.ts:142` and `:152`. Calls are serialized by `configurationQueue` (`sentry.service.ts:96-97`). `activeDsn` is cleared before re-init (`sentry.service.ts:45-48`).
- Fix: none.

**F10, info: normalization and stack defaults are acceptable.**
- Evidence: `attachStacktrace` defaults to `true` (`options.d.ts:162`). `normalizeDepth` defaults to 3 and `normalizeMaxBreadth` to 1000 (`options.d.ts:280`, `:291`). These apply to `extra` and `contexts`, and `extra` is already removed.
- Fix: none required.
