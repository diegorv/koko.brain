## Summary

- No high-severity issues. Both Sentry pins are behind the latest release but within their semver ranges. The local Rust and JS init code avoids the 11.x and 0.49.x API changes that matter.
- `@sentry/browser` is pinned at 11.9.0 and the latest is 11.11.0. The Rust `sentry` crate is pinned at 0.49.3 (Cargo.toml requires 0.49.2) and the latest is 0.49.5. Both bumps are routine.
- There is no official `@sentry/tauri` package. The npm registry returns 404 for it, and a search of Sentry's docs found no Tauri SDK.
- `tauri-plugin-sentry` (timfish) is active and supports Tauri 2, but it would not replace the current setup. It injects its own browser SDK at startup, while the app's per-vault opt-in re-initializes the client at runtime. Its real advantage is native minidump crash capture, which the `sentry` crate's `minidump` feature also provides.

## Findings

**S20-1: `@sentry/browser` is one minor behind. Severity: low.**
- Claim: the lockfile pins 11.9.0. The npm `latest` tag is 11.11.0. `^11.9.0` already allows the bump.
- Evidence: package.json:46 (`"@sentry/browser": "^11.9.0"`). pnpm-lock.yaml:695 and :2854 (`@sentry/browser@11.9.0`). npm dist-tags `latest` = 11.11.0 ([registry](https://registry.npmjs.org/@sentry/browser)). Release table: 11.11.0 on 05 Nov, 11.10.0 on 28 Oct, 11.9.0 on 23 Oct ([releases](https://github.com/getsentry/sentry-javascript/releases)).
- Changelog items relevant here:
  - 11.7.0 extended `dataCollection.urlQueryParams` to page URLs, span names, LCP URL attributes, and fetch, XHR and navigation breadcrumbs. This helps: the config at sentry.service.ts:71-84 sets `urlQueryParams: false`, so the setting covers more URLs after the bump.
  - 11.10.0 renamed span origins `auto.http.browser.{lcp,cls,inp}` to `auto.ui.browser.{lcp,cls,inp}`. No impact, since tracing is off (see the filtered integration list at sentry.service.ts, around line 60).
- Suggested fix: run `pnpm update @sentry/browser`, then the frontend gate (`pnpm check` and `pnpm vitest run`), then `pnpm build` because `pnpm-lock.yaml` changes. Commit as a dependency bump.

**S20-2: The Rust `sentry` crate is behind. Severity: low.**
- Claim: the lock pins 0.49.3. The Cargo.toml requirement is `0.49.2` (meaning `^0.49.2`). The latest is 0.49.5 (published 2026-10-28).
- Evidence: src-tauri/Cargo.toml:72. src-tauri/Cargo.lock:4702-4703 (`sentry` 0.49.3). crates.io ([API](https://crates.io/api/v1/crates/sentry)).
- Changelog check against the APIs used (error_monitoring.rs:49-55: `sentry::init((dsn, ClientOptions::new().release(..).send_default_pii(false).max_breadcrumbs(0)))`, plus `Hub::main/current().bind_client`, `Client::close`):
  - No change to these builder setters, `init`, `Hub`, or `bind_client` is listed in 0.48.0 through 0.49.5 ([changelog](https://raw.githubusercontent.com/getsentry/sentry-rust/master/CHANGELOG.md)).
  - 0.49.0 made `ClientOptions` `#[non_exhaustive]`. The code uses builder setters, not struct literals, so it still compiles.
  - 0.49.0 enabled the `logs` and `metrics` features by default. Cargo.toml:72 sets `default-features = false`, so nothing changes.
  - Deprecated items the code does not use: `enable_logs`, `enable_metrics`, `Hub::with`, `is_sampled`. Removed items it does not use: `sample_rate`, `traces_sample_rate`.
  - 0.49.4 raised the MSRV to 1.89.0. docs/DEV-ENVIRONMENT.md:19-21 already requires rustc 1.95 for `sysinfo`, so the floor is met.
- Suggested fix: `cargo update -p sentry` to reach 0.49.5, or edit Cargo.toml to `0.49.5` first. Afterwards check `cargo tree --locked` for unrelated edge changes, then run `cargo test --manifest-path src-tauri/Cargo.toml`.

**S20-3: `dataCollection.mcp` is not set and defaults to true. Severity: low, UNVERIFIED impact.**
- Claim: the JS `dataCollection` block sets every documented key except `mcp`. Since 11.9.0, `mcp` defaults to `true`. The current pin 11.9.0 already includes it.
- Evidence: sentry.service.ts:71-84. Sentry docs: "`dataCollection`... since `10.57.0`", "Starting with version 11, the defaults always apply", `mcp` default both true, "Available in SDK version `11.9.0` and above" ([options](https://docs.sentry.io/platforms/javascript/configuration/options/)).
- Why it is low: the integration filter (sentry.service.ts, around line 60) keeps only six integrations, and no MCP integration is in that list. Whether `mcp` data is collected without an MCP integration is UNVERIFIED.
- Suggested fix: add `mcp: { ... false }` to the block to match the file's explicit style. Add a test asserting the config passed to `Sentry.init`.

**S20-4: `sendDefaultPii` has no effect on the JS side. Severity: info.**
- Claim: the JS init does not set `sendDefaultPii`. The docs say the deprecated option acts only as a fallback when `dataCollection` is absent, and `dataCollection` is set.
- Evidence: sentry.service.ts:71 (`dataCollection` present). Docs quote: "Without it, the deprecated `sendDefaultPii` option controls data collection."
- Suggested fix: none required.

**S20-5: No official `@sentry/tauri` package exists. Severity: info.**
- Claim: nothing found by the npm registry or by web search.
- Evidence: `https://registry.npmjs.org/@sentry/tauri` returned HTTP 404. A search of docs.sentry.io and GitHub surfaced only community plugins ([search](https://github.com/timfish/sentry-tauri)).
- Suggested fix: keep the hand-rolled setup or the community plugin. Do not add `@sentry/tauri`.

**S20-6: `tauri-plugin-sentry` is maintained and Tauri 2 only, but a poor fit. Severity: medium (design).**
- Maintenance: latest 0.9.0 (2026-11-04). Before that, 0.8.0 (2026-10-13), 0.7.0 (2026-09-28), 0.6.0 (2026-08-04). Repository: 34 commits, 235 stars, 5 open issues. No license is visible in the fetched page, so the license is UNVERIFIED ([crates.io](https://crates.io/api/v1/crates/tauri-plugin-sentry), [repo](https://github.com/timfish/sentry-tauri)).
- Compatibility: 0.9.0 requires `tauri ^2.12` and `sentry ^0.49.5`, with default features off. Our `tauri` is 2.12.5 (src-tauri/Cargo.lock:5372-5373), so Tauri matches. The `sentry` crate needs the bump in S20-2 ([deps](https://crates.io/api/v1/crates/tauri-plugin-sentry/0.9.0/dependencies)).
- What it adds: native minidump capture through the `minidump` feature (README, [repo](https://github.com/timfish/sentry-tauri)). It bundles a pre-minified `@sentry/browser` into every webview, and it forwards browser user, tags, extra and contexts into the Rust SDK. Its own privacy defaults are narrow: window titles are not captured unless `capture_window_titles` is set, and resize, move and drag events do not create breadcrumbs. There is no general PII policy.
- Fit against the current code:
  - Per-vault opt-in: error_monitoring.rs:42-63 unbinds, closes, and re-inits the client when settings change. The plugin's README shows Sentry init and plugin init at app startup. Per-vault toggling would fight it.
  - Privacy: the JS config at sentry.service.ts:55-84, with its integration filter and `beforeSend`, would need `no_injection()` and a custom init to keep. That is what the plugin is meant to avoid.
  - Crash coverage: the current Rust feature list (Cargo.toml:72: `backtrace`, `contexts`, `panic`, `transport`) has no `minidump`. Native crashes such as segfaults are not captured. This is the real gap.
- Suggested fix: keep the hand-rolled setup. If native crash capture is wanted, add `minidump` to the `sentry` features (the 0.49.3 changelog lists it as a new `sentry-minidump` integration), then test it. That is a smaller change than the plugin and keeps the per-vault control.
