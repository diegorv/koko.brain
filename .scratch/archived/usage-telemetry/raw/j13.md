## Summary

- **Sentry config is mostly sound.** The JS filter in `sentry.service.ts` strips sessions, breadcrumbs, console, HTTP context, and conversation IDs, which backs PRIVACY.md's claims. The Rust side sets `send_default_pii(false)` and `max_breadcrumbs(0)`.
- **The privacy gate is weaker than PRIVACY.md says.** The scanner's `:\s*//` skip rule drops every TypeScript `https://` line (341 of 341 in `src`), so the URL pattern never blocks in TypeScript. The approvals are library-name regexes, so a new endpoint sent through the already-approved `@tauri-apps/plugin-http` passes silently.
- **PRIVACY.md is stale in several places.** It omits Todoist and the updater, names a nonexistent Chart.js file, and states a PR trigger the workflow does not have.
- **The CSP does not describe what the app does.** `connect-src` lists hosts no webview code calls. `img-src https:` lets remote markdown images load from any HTTPS host, and that is undisclosed.
- **Adding an opt-in analytics endpoint touches about 12 files** (listed under Open questions). If the data stays on the machine, no CSP, scanner, or capability change is needed.

## Findings

**F1. high. Scanner URL check is disabled for TypeScript.**
- Claim: `https?://` never reports a TypeScript match, because the skip pattern `:\s*//` matches every URL.
- Evidence: `.github/workflows/privacy.yml:57` (pattern `https?://`) and `:69` (skip `:\s*//`). Reproduced read-only: `grep -rnE 'https?://'` over `src` returns 341 TS/Svelte/JS lines, and all 341 match `:\s*//`. Sample hits include `src/lib/core/settings/theme-catalog.service.ts:9` and `sections/UpdateSection.svelte:24`, which are never reported.
- Fix: anchor the comment skip to the grep output's line-number prefix, e.g. `:[0-9]+:\s*//`, then re-run the scan on `src` to confirm the known URLs still appear as expected.

**F2. high. Scanner cannot see a new analytics endpoint.**
- Claim: a new analytics SDK, or a new host reached through `tauriFetch`, would pass the gate without a finding.
- Evidence:
  - No pattern for common analytics packages (posthog, amplitude, mixpanel, plausible, aptabase). `privacy.yml:37-58`.
  - `@tauri-apps/plugin-http` is in both `patterns` (`:55`) and `known` (`:78`), so any file importing it gets only a `::notice::`. `src/lib/features/tasks/tauri-fetch-adapter.ts:1` and `src/lib/core/settings/theme-catalog.service.ts:1` both import it.
  - `tauri-fetch-adapter.ts:16` passes a runtime `url` variable, so no literal host appears in the scanned line.
  - The Rust scanner has no pattern for `sentry::`, so the Rust Sentry transport is not in its scope either (`src-tauri/src/error_monitoring.rs:49` has no URL literal).
- The only enforcement that catches a new host through plugin-http is the capability scope: `src-tauri/capabilities/default.json:224-266` (four `http:allow-fetch*` grants, each listing `api.todoist.com/**` and `raw.githubusercontent.com/diegorv/koko.brain-themes/**`).
- Fix: add analytics package names to the patterns, and add a test or CI step that checks the capability host list against an approved list.

**F3. medium. Todoist package name and endpoint are stale or missing.**
- Claim: the workflow and the PRIVACY.md table name the wrong Todoist package, and PRIVACY.md omits Todoist entirely.
- Evidence: `privacy.yml:54` and `:77` name `@doist/todoist-api-typescript`. Code imports `@doist/todoist-sdk` (`src/lib/features/tasks/todoist-client.ts:1`, `package.json:33`). The new name matches no pattern, so the import is not scanned. PRIVACY.md's table (`PRIVACY.md:12-18`) has no Todoist row. The SDK's base endpoint is `api.todoist.com`, reached through `tauri-fetch-adapter.ts`; the only host check is the capability scope (F2).
- Fix: rename in `privacy.yml` and add a Todoist row to PRIVACY.md.

**F4. medium. PRIVACY.md table and trigger claims are inaccurate.**
- Chart.js row: the cited file `src/lib/plugins/queryjs/dv-ui.ts` does not exist. `src/lib/plugins/queryjs/kb-ui.ts:67` says Chart.js is bundled ("bundled, no CDN"), and `src` has no CDN URL. The JSDoc at `kb-ui.ts:558` still says "Lazy-loads Chart.js from CDN", which is a stale comment. Also, the CSP `script-src 'self'` (`tauri.conf.json:29`) would block a CDN script anyway.
- Missing row: the auto-updater GET to `https://github.com/diegorv/koko.brain/releases/latest/download/latest.json` (`src-tauri/tauri.conf.json:54-56`).
- Trigger: PRIVACY.md says the check "runs on every push and pull request". `privacy.yml:3-5` runs only on push to `main`. Pull requests run it only when `pr.yml:58-66` path filters match, via `pr.yml:90-94`.
- Fix: correct the table, the Chart.js comment at `kb-ui.ts:558`, and the trigger wording.

**F5. medium. Remote images are loaded and not disclosed.**
- Claim: any `https:` image in a note is fetched by the webview, from any host.
- Evidence: `src/lib/core/markdown-editor/extensions/live-preview/widgets.ts:164-166` sets `img.src = this.url` when `isSafeUrl(this.url)` is true. `src/lib/utils/sanitize-url.ts:5-14` allows `http:` and `https:`. `tauri.conf.json:29` has `img-src 'self' asset: http://asset.localhost data: https:`. PRIVACY.md has no row for this.
- A note that embeds a remote image sends the viewer's IP and timing to that host when the note renders. That is not "no tracking" in practice.
- Fix: decide whether this is intended. If not, restrict `img-src` or gate remote images behind a setting. If yes, add a PRIVACY.md row.

**F6. low. CSP `connect-src` lists hosts that no webview code calls.**
- Evidence: a grep of non-test `src` finds no `fetch(` and no direct use of `api.todoist.com`, `huggingface.co`, `github.com`, or `objects.githubusercontent.com`. All HTTP goes through `@tauri-apps/plugin-http`, which runs in Rust and is governed by the capability scope, not the CSP. The Rust calls (`semantic/model.rs`, updater) are also outside the CSP. The only `connect-src` entries that govern the webview are `ipc:`, `http://ipc.localhost`, and the three Sentry ingest wildcards.
- Fix: trim the listed hosts that the webview does not use. Keep the Sentry entries.

**F7. low. Sentry region check and CSP disagree on the bare host.**
- Evidence: `src/lib/core/settings/sentry.logic.ts:16-17` accepts `hostname === 'ingest.sentry.io'` (and the `us`/`de` equivalents). The CSP `https://*.ingest.sentry.io` (`tauri.conf.json:29`) does not match the bare host. A DSN with the bare host would be accepted, then its events blocked silently. Real DSNs carry an org prefix (`oNNN.ingest...`), so impact is minimal. `src/tests/lib/core/settings/sentry.logic.test.ts` has no bare-host case.
- Fix: require a subdomain in `isValidSentryDsn`, and add the bare-host case to the test.

**F8. low. Rust accepts any Sentry host.**
- Evidence: `src-tauri/src/error_monitoring.rs:46-48` parses any DSN with `sentry::types::Dsn`, and `src-tauri/src/commands/sentry.rs:7-13` accepts any string. The CSP does not apply to Rust transports (general browser behavior; from memory, not verified against the Tauri docs). The frontend check in F7 is the only host restriction.
- Fix: apply the same host check in Rust, or pass only validated DSNs through the command.

**F9. medium. Settings help and UI overstate what is reported.**
- Claim: `help/documentation/19-settings.md:266` and `SentrySection.svelte:50` say "unhandled errors are sent".
- Evidence: `src/lib/utils/debug.ts:31` calls `captureSentryException` from `error()`, and `sentry.service.ts:112-118` captures handled exceptions. So any `error(...)` call is also reported.
- Fix: say "errors logged through the app" or similar, or restrict what `error()` reports.

**F10. info. Verified consistent: Sentry data reduction.**
- Evidence: `@sentry/browser` 11.9.0 default integrations (`node_modules/@sentry/browser/build/npm/esm/prod/sdk.js:15-29`) include `browserSessionIntegration`, `breadcrumbsIntegration`, `consoleIntegration`, `httpContextIntegration`, `cultureContextIntegration`, and `conversationIdIntegration`. `sentry.service.ts:63-70` keeps only six, so these are removed. `dataCollection` at `:71-83` disables user info, cookies, headers, and bodies. `beforeSend` at `:84` strips breadcrumbs, extra, request, and user.
- Not verified: whether Rust panic messages can contain note text. Rust has no `before_send` scrub (`error_monitoring.rs:49-55`).

**F11. info. Theme catalog is consistent.**
- `raw.githubusercontent.com` is not in the CSP, and it does not need to be: `theme-catalog.service.ts:1,39` uses plugin-http, and `capabilities/default.json:228-231` allows that URL.
