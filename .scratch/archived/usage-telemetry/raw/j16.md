## Summary

- **Local-only counters are the cheapest fit.** For one user, counting feature use in a local log or store answers the question with no vendor, no CSP change, and no PRIVACY.md change. Nothing I found beats that on the owner's privacy rules.

**F4. info. Plausible: good event fit; self-host Events API support is unverified.**
- Claim: `POST https://plausible.io/api/event` takes `domain`, `name`, and `url` as required fields, and `props` is optional with a maximum of 30 key-value pairs. `domain` does not need to be a real domain, so an app name works. The endpoint always returns 202, even for dropped events.
- Evidence: https://plausible.io/docs/events-api. Self-hosting: https://plausible.io/docs/self-hosting says Community Edition is "free, self-hosted, AGPLv3" with no fees. The same page does not list the Events API as missing from CE.
- Fix or risk: UNVERIFIED whether CE includes the Events API, and UNVERIFIED how heavy CE's infrastructure is. Plausible's "cookieless" claim was not checked in this session. Localhost events get dropped unless the domain is added in the account.

**F5. info. Umami: MIT, the simplest self-host of the set, custom events via `/api/send`.**
- Claim: `POST /api/send` takes `type`, `payload.website` (website ID), `payload.url`, `payload.name`, `payload.data` (optional object), and `payload.hostname`. No auth token is needed, but the request must carry a real `User-Agent`. Event names are limited to 50 characters.
- Evidence: https://docs.umami.is/docs/api/sending-stats (fields, auth, User-Agent). https://docs.umami.is/docs/track-events (50-character limit; `data-umami-event-*` attributes store strings only; the JS `umami.track` keeps types). License and self-host: https://github.com/umami-software/umami (MIT; self-host from source with Node 18.18+ and PostgreSQL 12.14+, or Docker).
- Gap: the docs do not say whether `payload.website` must match a registered site or whether `hostname` is validated (UNVERIFIED). Umami Cloud pricing and retention are UNVERIFIED.

**F6. info. TelemetryDeck: best privacy wording and simplest payload, but hosted only.**
- Claim: Ingest v2 is `POST https://nom.telemetrydeck.com/v2/namespace/<namespace>/` with a JSON array of signals. Required fields: `appID`, `clientUser` (hashed), `type`. Optional: `sessionID`, `isTestMode`, `floatValue`, `payload` (flat object of primitives). The client hashes `clientUser` and the server hashes it again.
- Evidence: https://telemetrydeck.com/docs/ingest/v2/ (via search result; the page itself was not fetched). Anonymization: TelemetryDeck's own docs, cited in search results (https://telemetrydeck.com/docs/articles/anonymization-how-it-works/, not fetched).
- Self-host: none found. I checked the public org page, which lists 10 of 25 repos. The client SDKs are visible; no server was. The other 15 repos are UNVERIFIED. Source: https://github.com/TelemetryDeck.
- Pricing conflict: a TelemetryDeck blog post (seen in search results, not fetched) says the free plan includes 100,000 signals per month. Some TelemetryDeck comparison pages say 50,000. Retention months: UNVERIFIED from primary sources. Pricing page `telemetrydeck.com/pricing/` returned 404 when fetched.
- Risk: the owner's usage events leave the machine to a third party, even with no note content. This needs the PRIVACY.md change in F1.

**F7. info. OpenPanel: AGPL-3.0 with a modified Section 7, Docker self-host, server-side track API.**
- Claim: `POST https://api.openpanel.dev/track` with headers `openpanel-client-id` (and `openpanel-client-secret` for server-side calls). The body has `type: "track"`, `name`, `profileId`, and `properties` (arbitrary JSON). Special `__`-prefixed properties are reserved.
- Evidence: https://openpanel.dev/docs/api/track (via search result), https://github.com/openpanel-dev/openpanel (AGPL-3.0, self-host via docker compose). Cookieless default for the browser script: https://openpanel.dev/docs ("Tracking is cookie-less by default").
- Gap: the modified Section 7 wording was not read (the repo's LICENSE file was not fetched), so its effect is UNVERIFIED. Infrastructure weight and free tier: UNVERIFIED. The `profileId` requirement means the owner must generate a stable pseudonymous ID.

**F8. info. Countly Lite: rich segmentation, ambiguous license, heavier to run.**
- Claim: Events are sent to `GET /i` with `app_key` and `device_id` as mandatory parameters, plus an `events` JSON array. Each event has `key`, `count`, and an optional `segmentation` object.
- Evidence: https://api.count.ly/reference/i (via search result), https://github.com/Countly/countly-server (Lite is "free to use under an open-source, non-commercial license"; the repo says AGPL-3.0 with a modified Section 7; the two terms differ and the LICENSE file was not read).
- Gap: the page wording "Lite... self-hosted only" is from the repo README. The server's infrastructure requirements and retention are UNVERIFIED.
