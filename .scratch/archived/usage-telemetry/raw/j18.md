## Summary

- **Local store is the better fit.** The app already has a per-vault SQLite DB (`{vault}/.kokobrain/kokobrain.db`, `src-tauri/src/db/mod.rs:37`) that the file watcher ignores. A `usage_counts(day, feature, count)` table there needs no network, no new dependency, and no PRIVACY.md change.
- **Existing logs are the wrong vehicle.** The frontend log is an unstructured per-launch text file outside the vault, and the Rust `debug_log` is a no-op unless debug mode is on. Neither is usable for always-on counting.
- **QueryJS can host the view but has no DB access today.** Its API reads the in-memory vault index only, so a `kb.usage()` method needs a new IPC command. Charts already render offline because Chart.js is bundled.
- **Rough estimate, not measured:** the local option is about 2 to 4 focused days, mostly on call sites and the view. A third-party service costs similar code plus network, CSP, privacy-policy, and privacy-check work, and it conflicts with the "no analytics" promise.
- **Doc drift found:** PRIVACY.md lists a Chart.js CDN call that the code no longer makes.

## Findings

**F1, info. Session log files are unsuitable for usage counting.**
- Claim: `appLogDir()` writes one text file per launch, with lines formatted `[HH:mm:ss.SSS] [TAG] message`.
- Evidence: `src/lib/utils/log.service.ts:2,67-68,79-89`. The file lives in `~/Library/Logs/`, outside the vault. I found no rotation or retention code in the files I read.
- Fix: do not parse these files. Use a structured store.

**F2, info. The Rust logger is not a usage channel.**
- Claim: `debug_log` returns immediately unless debug mode is on. When enabled it prints to stderr and forwards to a sink that emits a Tauri event.
- Evidence: `src-tauri/src/utils/logger.rs:54-57` (early return), `:62-66` (stderr and sink). The sink is installed at `src-tauri/src/lib.rs:287`.
- Fix: none. Usage events need their own recorder.

**F3, info. The vault DB already has the right shape.**
- Claim: one WAL-mode DB per vault with two connections, `DB` for history/semantic and `FTS_DB` for search. Tables are created idempotently with `CREATE TABLE IF NOT EXISTS`.
- Evidence: `src-tauri/src/db/mod.rs:17,27` (two `Mutex<Option<Connection>>`), `:48-49` (WAL), `:71-75` (second connection), `src-tauri/src/db/schema.rs:21-60` (`snapshots`, `app_meta`, `chunks`, `semantic_meta`), `Cargo.toml:54` (`rusqlite 0.41`, bundled).
- Fix: add a `usage_counts` table in `create_tables`. `app_meta` (`schema.rs:35-38`) is key/value and fits counters but not time series, so a new table is cleaner.

**F4, medium. Usage writes must be batched.**
- Claim: `DB` is one `Mutex<Connection>` shared by history and semantic writers. A write per click would queue behind them, and `with_db_transaction` issues `BEGIN IMMEDIATE`.
- Evidence: `src-tauri/src/db/mod.rs:17` (mutex), `:121-135` (`BEGIN IMMEDIATE` and commit).
- Fix: buffer in memory and flush in one transaction on a timer, matching the 250 ms batching in `log.service.ts:26-27`. Using `FTS_DB` for the writes is a possible alternative, but the FTS connection is a search path, so I would not share it. This is a judgment call.

**F5, medium. The vault DB already stores note content.**
- Claim: `snapshots.content` is a full copy of note text, so the vault DB holds the same sensitive data as the notes. A usage table in it inherits that boundary and any sync or backup of the vault folder.
- Evidence: `src-tauri/src/db/schema.rs:21-27`. Vault folders sit under `$DOCUMENT/kokobrain-vaults` (`src-tauri/capabilities/default.json`).
- Fix: record only feature IDs and day buckets. Never record note paths, titles, or search query text (search text is note content). This is a requirement for either option.

**F6, low. The watcher ignores the DB directory.**
- Claim: dot-prefixed paths at any depth are filtered, so DB writes do not trigger reindexing.
- Evidence: `src-tauri/src/vault/watcher.rs:60-75` (`is_inside_hidden_dir`, which names `/vault/.kokobrain/db` as filtered).
- Fix: none needed.

**F7, medium. QueryJS has no path to the DB.**
- Claim: the KB API reads only the in-memory vault index. The QueryJS service imports only `readTextFile` from the fs plugin. A usage view in a note therefore needs a new `KBAPI` method and a new IPC command.
- Evidence: `src/lib/plugins/queryjs/kb-api.ts:118-144` (`pages`, `pagePaths`, `current`, `page`), `src/lib/plugins/queryjs/queryjs.service.ts:1` (only import). The chart path is bundled, `src/lib/plugins/queryjs/kb-ui.ts:67-68` ("bundled, no CDN").
- Fix: add `kb.usage()` backed by one narrow command that returns aggregated rows. Do not expose raw SQL. Feasible, and it works offline.

**F8, low. PRIVACY.md is stale on Chart.js.**
- Claim: PRIVACY.md lists a Chart.js CDN call in `src/lib/plugins/queryjs/dv-ui.ts`. That file does not exist, and Chart.js is bundled. The CSP `script-src 'self' 'unsafe-eval'` would also block a CDN script.
- Evidence: `PRIVACY.md` table row (Chart.js CDN). `src/lib/plugins/queryjs/kb-ui.ts:67-68`. `src-tauri/tauri.conf.json:29` (CSP).
- Fix: remove or correct the Chart.js row in PRIVACY.md. This is a doc-only change.

**F9, info. Retention pattern already exists.**
- Claim: file history uses tiered retention (keep all within N days, one per day for the next 30, delete the rest) in a single transaction.
- Evidence: `src-tauri/src/commands/history.rs:153-170` (`cleanup_history`), `src-tauri/src/db/history_repo.rs` (`delete_old_snapshots`, `delete_medium_duplicates`).
- Fix: reuse the same approach for `usage_counts`, or simply cap it by day.

**F10, info. A new IPC DTO triggers the generated-bindings gate.**
- Claim: a summary struct with `#[ts(export)]` changes `src/lib/contracts/generated/`, so the task needs `cargo test` plus `pnpm check`.
- Evidence: `CLAUDE.md` rule 6 (project file). Existing example: `src-tauri/src/db/history_repo.rs:4-5` (`#[ts(export)]` on `SnapshotInfo`).
- Fix: budget for regenerated bindings in the effort estimate.
