## Summary

- **Biggest gap: the Rust client sends the machine hostname on every event.** `send_default_pii(false)` does not stop it. `server_name` comes from the hostname through the default `contexts` integration, and nothing in the repo clears it. PRIVACY.md does not mention it.
- **The frontend scrubber covers only four fields.** `removeSensitiveEventData` clears `breadcrumbs`, `extra`, `request` and `user`. It never touches `exception.values[].value`, `message`, or stack filenames. Those carry Rust `Err(String)` text and template literals, which contain absolute paths and note paths.
- **Concrete leak sites exist.** Single-argument `error()` calls interpolate vault, note and restore paths, and some Rust write errors embed the temp path under the vault.
- **Rust panics go out unscrubbed.** The panic payload becomes `exception.value` and the stack is attached. There is no `before_send` anywhere in `error_monitoring.rs`.
- **Good baseline:** the browser integration list is pruned to six integrations, so the HTTP, culture, console, breadcrumb and session contexts are gone. Tags are limited to `source` and `synthetic`, and every `source` value is a static string literal. Rust has no debug-images integration compiled in.
- **Proposed fix:** a small scrubber on both sides that clears `server_name`, `user` and `device`, and replaces the home-directory segment and the active vault root in every text field before send. Details are at the end.

## Findings

**F1. high. Rust events always carry the hostname as `server_name`, regardless of `send_default_pii`.**
- Evidence: `src-tauri/src/error_monitoring.rs:49-55` builds `ClientOptions` with `release`, `send_default_pii(false)` and `max_breadcrumbs(0)` only, with no `server_name` and no `before_send`. `src-tauri/Cargo.toml:72` enables the `contexts` feature. The contexts integration sets `options.server_name = hostname::get()` when it is unset (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sentry-contexts-0.49.3/src/integration.rs:75-77`, `utils.rs:112-114`). `sentry-core-0.49.3/src/client/mod.rs:360-361` copies `options.server_name` into every event that lacks one. The default integrations are on (`sentry-core-0.49.3/src/clientoptions.rs:907` sets `default_integrations: true`), and `defaults.rs:51-67` adds the contexts integration. Nothing on this path checks `send_default_pii`. `PRIVACY.md:18` lists what is disabled and does not mention the hostname.
- Suggested fix: in the Rust `before_send`, set `event.server_name = None`, `event.user = None`, and remove the `device` context (its `model` is the `hw.model` sysctl, `utils.rs:188-196`). Add a test that calls the scrubber directly.

**F2. high. The frontend `beforeSend` does not scrub exception text, messages or frame filenames.**
- Evidence: `src/lib/core/settings/sentry.service.ts:28-36` clears only `breadcrumbs`, `extra`, `request` and `user`, and `:84` is the only `beforeSend`. `src/lib/utils/debug.ts:31` sends `args.find(Error) ?? args.at(-1)` to `captureSentryException`, which captures it at `sentry.service.ts:112-117`. Rust `Err(String)` values reach the frontend as plain strings. For a string, the SDK creates `new Error(exception)` and sets `ex.message = \`${exception}\`` (`node_modules/.pnpm/@sentry+core@11.9.0/.../utils/eventbuilder.js`, `getException`). That text is then stored in `exception.values[0].value`, which the scrubber never touches.
- Concrete paths that reach Sentry through the last argument or the `Error` argument:
  - `src-tauri/src/utils/fs.rs:27` returns `write failed for {tmp}`. `commands/vault.rs:995` (`create_note`) calls `write_atomic`. `src/lib/core/filesystem/fs.service.ts:208` calls `create_note`, and `fs.service.ts:221` runs `error('FS', 'Failed to create file:', err)`. The temp path sits under the vault root.
  - `src/lib/core/filesystem/link-updater.service.ts:77` forwards `result.reason`. Its content is unverified.
  - `src/lib/core/editor/editor.service.ts:146` and `:200` forward errors from the file read and write plugin calls. Their message text is unverified.
- Suggested fix: in the scrubber, replace the home segment (`/Users/<name>`, `/home/<name>`, `C:\Users\<name>`) and the active vault root in `exception.values[].value`, `message`, and each frame's `filename` and `abs_path`.

**F3. medium. Rust panic events carry the raw payload and stack with no scrubbing.**
- Evidence: `sentry-panic-0.49.3/src/lib.rs:106-135` sets `exception.value` to the panic message and attaches `current_stacktrace()`. The `panic` default integration is on through `defaults.rs:71`. No `before_send` exists. `Cargo.toml:88` sets `strip = true` for release, which removes most DWARF filenames. `release-fast` (`Cargo.toml:98-103`) has `strip = false`, so local fast builds may keep more frame detail. Whether that exposes absolute paths is UNVERIFIED.
- Suggested fix: the same Rust scrubber as F1, applied to `exception.values[].value` and each frame's `abs_path` and `filename`.

**F4. medium. Single-argument `error()` calls interpolate paths or names directly.**
- Evidence:
  - `src/lib/core/vault/vault.service.ts:44`: `error('VAULT', \`Cannot open vault — path does not exist: ${path}\`)` sends the absolute vault path.
  - `src/lib/core/trash/trash.service.ts:167`: `restorePath` (a note or folder path).
  - `src/lib/features/deep-link/deep-link.service.ts:156`: the user-supplied vault name.
- Note: `debug.ts:31` captures the first `Error` argument, or the last argument otherwise. A template string in the middle of the argument list is dropped when another argument is captured. Only the single-argument forms leak their template directly.
- Suggested fix: change these to pass the variable as a separate argument with a fixed message, or drop the path, or rely on the scrubber in F2.

**F5. low. Parse errors may echo file content, depending on the webview engine.**
- Evidence: `src/lib/core/filesystem/fs.service.ts:53` and `:67` (folder-order JSON, `FS` tag). `src/lib/features/properties/bookmark-migration.service.ts:25` and `:27` (bookmarks JSON, `BOOKMARKS` tag). Chromium's `SyntaxError` message can include a snippet of the input. JavaScriptCore (WebKit, used by Tauri on macOS) is UNVERIFIED on this point.
- Suggested fix: in the scrubber, strip any quoted fragment after `is not valid JSON`, or pass only the error name for `SyntaxError`.

**F6. low. PRIVACY.md under-describes what is sent.**
- Evidence: `PRIVACY.md:18` says "error events and stack traces" and lists disabled fields. It does not mention the hostname (F1), device model, OS version, or that panic messages and error strings may contain paths and note names (F2 to F4). `PRIVACY.md:8` says "no telemetry", but the Sentry paragraph is the sole exception.
- Suggested fix: add a line listing the data that is sent (release, device model, OS version, Rust version, hostname until scrubbed, error text after scrubbing) and state that the scrubber replaces home and vault paths.

**F7. info. Verified clean: the frontend contexts and the tags.**
- Evidence: `sentry.service.ts:63-70` keeps only six integrations. The browser defaults at `node_modules/.pnpm/@sentry+browser@11.9.0/.../prod/sdk.js:15-29` include `httpContext`, `culture`, `breadcrumbs`, `console` and `browserSession`, and all of them are dropped. The only dynamic-tag site is `debug.ts`, which passes the caller's tag through.

**F8. info. The Rust debug-images integration is absent.** `grep sentry-debug-images src-tauri/Cargo.lock` returns 0 matches, so there is no `debug_meta.images` list with `code_file` paths.

**F9. info. Release string.** `sentry.service.ts:19-22` builds `kokobrain@<version>`. `vite.config.js:26` and `src/lib/utils/build-info.js:69-73` add the git hash and build time. Neither contains personal data.

None of this is checked in the repo. Confirm in the Sentry project settings (Security and Privacy, Data Scrubbing, and "Store IP addresses") before the owner relies on it.

## Proposed minimal scrubber

Frontend (`sentry.service.ts`), applied inside `removeSensitiveEventData`:
```ts
const HOME_DIR = /(\/Users\/|\/home\/)[^/\s'"]+|[A-Za-z]:\\Users\\[^\\\s'"]+/g;
function scrubText(text: string, vaultRoot: string | null): string {
	let out = text.replace(HOME_DIR, (_m, prefix = 'C:\\Users\\') => `${prefix}<user>`);
	if (vaultRoot) out = out.split(vaultRoot).join('<vault>');
	return out;
}
// Apply scrubText to: event.message, each exception.values[i].value,
// and each stacktrace frame's filename and abs_path. Set event.server_name = undefined.
```
`vaultRoot` must come from the vault store at send time. Export `removeSensitiveEventData` so it can be unit-tested.

Rust (`error_monitoring.rs`), via `ClientOptions::before_send`:
```rust
fn scrub_event(mut event: Event<'static>) -> Option<Event<'static>> {
    event.server_name = None;
    event.user = None;
    event.contexts.remove("device");
    // replace /Users/<name> and /home/<name> in exception.value and frame abs_path/filename
    Some(event)
}
```
Test first, per the repo rules: a `src-tauri/tests/error_monitoring_test.rs` case that passes an event with a hostname, a `/Users/<name>/...` message and a frame path, and asserts all three are gone.
