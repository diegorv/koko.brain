## Findings

1. **blocker** — src/lib/core/file-explorer/FileTreeItem.svelte:118-123 (with `onblur={commitRename}` at :253). A successful rename with Enter now shows an error toast. Enter calls `commitRename`, which sets `renamingPath` to null and awaits `renameItem`. Svelte's flush then removes the focused input. Chromium fires `blur` synchronously on removal, and Svelte 5.57.2 removes the DOM before it tears down the listeners (node_modules/svelte/src/internal/client/reactivity/effects.js:521-542). So `commitRename` runs a second time: `renameCancelled` is false and `node.path` is still the old path, and it calls `renameItem(old, new)` again. The second disk rename fails because the source is gone, and the user sees `Could not rename "a.md": No such file or directory (os error 2)` after a rename that worked. Reproduced in jsdom by dispatching `blur` after Enter: 2 `rename` calls and that toast. On main the same double call happened but failed silently, so this branch makes it visible. `TypeNoteList.commitRename` is not affected, because it reads `fsStore.renamingPath`, which is already null on the second call (TypeNoteList.svelte:388-390). Not checked: whether WKWebView fires blur on removal. Fix: make `commitRename` run once per rename session. For example, set `renameCancelled = true` (or a `committing` flag) before the first await, or return early when `fsStore.renamingPath !== node.path`. Add a FileTreeItem test that presses Enter, dispatches `blur` on the input, and asserts one `rename` call and no `toast.error`. The same applies to the pending-creation flow (new file, then Enter).
2. **minor** — src/tests/lib/core/file-explorer/FileTreeItem.test.ts:107. No test covers a successful rename (no toast, one disk rename). Only failures and cancels are tested, which is why finding 1 got through. Fix: add the success-path test from finding 1.
3. **minor** — src/tests/lib/features/type-definitions/TypeNoteList.view.test.ts. The branch adds a toast to the TypeNoteList rename handler (TypeNoteList.svelte:394), but only the duplicate and delete toasts are tested. Fix: add a rename-collision test that asserts the toast text.

Create failures from the palette now throw into CommandPalette.svelte:28-32, which shows the generic `Command "New File" failed.` without the reason. The `if (filePath)` / `if (folderPath)` checks can no longer be false. Fix (optional): leave as is, or toast with `fileOperationErrorMessage` and drop the dead checks.
5. **nit** — src/lib/core/file-explorer/FileExplorer.svelte:210, src/lib/features/type-definitions/TypeNoteList.svelte:420. The verb template produces `Could not move to trash "a.md": ...`, which reads awkwardly. Fix (optional): `Could not move "a.md" to the Trash: ...`.
