## Acceptance criteria

- [met] A WebSocket endpoint speaks a small JSON-RPC protocol: a hello/welcome exchange carrying the server version and the vault root the Mac has open, then request/response calls. The stand-in forwards `invoke` calls over it with a per-call timeout; on connection loss pending calls are rejected and never replayed. The upgrade's `Origin` must match the host exactly — `remote/rpc.rs` run_session (hello -> welcome `{proto, serverVersion, vaultRoot}`, invoke -> result/error); `server.rs` upgrade_response needs one Host `127.0.0.1:<port>` and one Origin `http://127.0.0.1:<port>`; `remote-transport.ts` 30 s timer per call, `lose()` rejects pending calls and later calls, nothing is resent. Tests: remote_ws_test `upgrade_requires_the_exact_origin_and_host`, `welcome_carries_*`, `invoke_round_trips_*`; remote-transport.test.ts timeout and "never replays" cases. The timer starts only after the welcome (finding 4).
- [met] The host knows the open vault root from the desktop side (set when the desktop opens a vault, cleared when it closes one). With no vault open the browser shows a no-vault state. If the desktop closes or switches vaults while a browser is connected, the browser is told and reloads — `commands/db.rs` sets `desktop_vault_root()` after `open_database` and clears it in `close_vault_db`; the remote `open_vault_db`/`close_vault_db` are Virtual and never touch the cell. `NotConnectedBanner.svelte` `no-vault-banner`; `remote-session.ts` onVaultChanged -> reload. Tests: remote_ws_test `a_vault_change_is_pushed_to_the_session`, `welcome_reports_no_vault_as_null`; remote-session.test.ts; NotConnectedBanner.test.ts.
- [met] One Rust table classifies every Tauri command AND every plugin command the frontend sends (`plugin:fs|*`, `plugin:dialog|*`, `plugin:opener|*`, `plugin:window|*`, `plugin:event|*`, and the rest) as Read, Virtual or Denied (Write arrives in 08). The existing parity test fails when a command registered with Tauri is missing; a second test fails when a plugin command the frontend uses is missing. - [met] The read side of the fs plugin is forwarded here (read text file as bytes, exists, read dir, stat), because settings and other boot code read `.kokobrain/*.json` through it. `exists` rejects on a transport error and never resolves `false` because the connection failed — `dispatch.rs` read arms for `read_text_file`/`read_file`/`exists`/`read_dir`/`stat`; tauri-bridge-stand-in.test.ts runs the real `@tauri-apps/plugin-fs` `readTextFile`, `writeTextFile` and `exists` (rejects on drop) against the stand-in; remote_ws_test `fs_reads_are_forwarded`.

Met for the canonical spelling only: `//` and case variants get through the prefix check (finding 2).
- [met] Virtual commands are acknowledged with a plausible result and no shared-state effect: `open_vault_db`, `close_vault_db`, `shutdown_semantic`, `init_semantic_search`, the model download commands, watcher start/stop, `save_vault_cache`, `cleanup_history`, `build_search_index`, the per-note index updaters, `configure_sentry`, `set_tauri_debug_mode`, `check_for_update_on_channel`. `scan_vault_v2_cached` is Virtual too: today it always rebuilds and emits, so the Virtual version builds its `CachedScanResult` from the current index without rebuilding or emitting — every name is a Virtual row in POLICY; `dispatch.rs` virtual_result never calls a command and gets no Sentry, logger, db or watcher handle; `scan_vault_v2_cached` returns `source: cache` with the current `entries().len()`. remote_ws_test `virtual_commands_leave_the_index_alone`.

## Findings

1. **major** `src/tests/lib/app/remote/browser-cold-start.test.ts:74-94` and `src-tauri/tests/remote_cold_start_test.rs:90-92,136-137`: the recorded cold start is not "the real command sequence", and its flag checks are vacuous.
   - (a) The browser's real boot runs `vaultStore.open(welcome.vaultRoot)` (`remote-session.ts`) before the layout calls `initializeVault`. The recorder skips it, so `buildSearchIndex` returns early on `!vaultStore.path` and `build_search_index` never reaches the fixture. I checked this with a throwaway copy of the recorder that adds `vaultStore.open(VAULT)` after the welcome: the sequence gains `build_search_index` at index 29 (51 calls vs 50).
   - (b) Canned settings are `{}`, so `set_tauri_debug_mode` is never replayed. The desktop side starts with `SentryState::default()` (inactive), and the replayed `configure_sentry` sends `enabled: false`. Both "flags unchanged" asserts would still pass if those commands ran for real.
   - Fix: drive the recorder through `startRemoteSession({ open })`, or call `vaultStore.open(VAULT)`, so the welcome opens the vault the way it does in the browser. Have the canned `settings.json` turn on `debugMode` (and Sentry, with a DSN), then re-record with `UPDATE_COLD_START=1`. In the Rust replay, start the desktop with debug off and Sentry in the opposite state from what the browser sends, so a non-Virtual `set_tauri_debug_mode` / `configure_sentry` would flip a flag. Also assert that `build_search_index` appears in the fixture.
2. **major** `src-tauri/src/remote/policy.rs:159-178` and `src-tauri/src/remote/dispatch.rs:243-244`: the prefix rule and the settings redaction only match the exact lowercase, single-slash spelling.
   - I ran a probe of `fs_path_rule("/v", …, Read)`. `/v//.kokobrain/trash/x.json`, `/v//.kokobrain` (read_dir), `/v/.KOKOBRAIN/settings.json` and `/v/.Kokobrain/kokobrain.db` all come back `Allow`. The same gap reaches `read_files_batch` through `require_vault_path`.
   - macOS APFS is case-insensitive by default, so `read_text_file("<root>/.KOKOBRAIN/settings.json")` returns the file unredacted, because `redact_settings` checks `ends_with("/.kokobrain/settings.json")`. That leaks the Todoist token, which criterion 8 says is redacted.
   - Loopback-only today. 03 brings canonical containment, but redaction must not depend on how the client spells the path.
   - Fix: deny empty segments (`//`) in `fs_path_rule`, and compare the `.kokobrain` segment case-insensitively (deny any case variant other than the canonical one). Redact on the file actually read: a case-insensitive file-name match, or a canonicalized path compared with `<root>/.kokobrain/settings.json`. Add a remote_policy_test / remote_ws_test case for each variant.
3. **major** `src-tauri/src/remote/server.rs:106-112,217`: `RemoteServer::shutdown` only stops the accept loop. A `/ws` session started with `run_session` lives on its own thread and keeps answering Read calls (vault tree, note contents, settings) after the user turns Browser access off or moves it to another port. Fix: have the server track live sessions (for example a list of `TcpStream` clones, or a shared stop flag the session read loop checks) and `shutdown(Both)` them on stop. Add a remote_ws_test case: stop the server, then show that an open session's next invoke fails.
4. **minor** `src/lib/app/remote/remote-transport.ts:138-145`: the per-call timer starts only after `await ready()`. If the socket opens but no welcome ever arrives (a host that accepts the upgrade but hangs), every call waits forever, and the banner stays hidden because the status stays `connecting`. Fix: start the timeout before `ready()`, or give the welcome its own timeout that calls `lose()`.
5. **minor** `src-tauri/src/remote/server.rs:8-10`: the change removes the module's "Do not grow WebSocket or other routes on this module" note. It grows `/ws`, a hand-written RFC 6455 codec and SHA-1 on the std server, where proposal step 1.1 / 4.5 chose axum + tower-http. The only record of the deviation is this code comment and discovery.md. Fix: record the decision (keep std until 04, or move to axum) in the proposal or an ADR, so 03/04 do not assume axum.
6. **nit** `src/lib/app/remote/remote-transport.ts` (`if (message.method === 'welcome')`) and `src-tauri/src/remote/rpc.rs` (hello handling): both sides send `proto` but neither checks it, so a version mismatch goes unnoticed. Fix: reject or flag a welcome whose `proto` differs from `REMOTE_PROTO`, or drop the field until it is checked.
7. **nit** `src-tauri/src/remote/dispatch.rs:198`: `exists` uses `symlink_metadata`, so a dangling symlink reports `true`. plugin-fs `exists` follows links and reports `false`. Fix: use `Path::try_exists` / `metadata`, the same check the desktop uses.

## Resolution

All seven findings were fixed; none rejected.

1. **Fixed** in `1f63473e`. The recorder now boots through `startRemoteSession({ open, reload })`, so the welcome runs `vaultStore.open(VAULT)` as the browser does. The canned `settings.json` turns on `debugModeTauri` and Sentry (valid DSN). The recorder asserts that `build_search_index`, `set_tauri_debug_mode {enabled: true}` and `configure_sentry {enabled: true}` are in the sequence. Re-recorded fixture: 53 calls. The Rust replay asserts that the fixture carries those calls, starts with debug off and no client bound to `sentry::Hub::main()`, and checks that both are still off afterwards. Mutation check: dispatching `configure_sentry` or `set_tauri_debug_mode` to the desktop code failed the replay ("a Sentry client was bound" / "debug mode was turned on"), then reverted.
2. **Fixed** in `b665a1a2`. `fs_path_rule` denies empty, `.` and `..` segments (one trailing `/` allowed) and refuses any case variant of `.kokobrain` other than the canonical one. `is_meta_path` matches that segment case-insensitively and is used by `require_vault_path`, which also refuses any name for the settings file. Redaction decides on the file actually read: a case-insensitive match of `<root>/.kokobrain/settings.json`, or the same dev/inode, so symlinks and hard links are covered too. Tests: remote_policy_test `empty_segments_are_denied`, `kokobrain_case_variants_are_denied`, `meta_paths_match_the_kokobrain_segment_in_any_case`; remote_ws_test `settings_spellings_never_leak_the_token`, `a_link_to_the_settings_file_is_redacted_or_refused`. All failed before the fix.
3. **Fixed** in `ae9d488a`. `RemoteServer` keeps the socket of each open `/ws` session. `shutdown` marks the list stopped and shuts every socket down, and a session that registers after the stop is refused. Test: remote_ws_test `stopping_the_server_ends_open_sessions` (failed before the fix).
4. **Fixed** in `fdf1d766`. A welcome timer (the call timeout) starts when the socket opens. If no welcome arrives in time, the transport closes the socket and treats the connection as lost: pending calls reject and the status goes to `disconnected`, so the banner shows. Tests: remote-transport.test.ts "drops the connection when no welcome arrives in time" and "keeps the connection when the welcome arrives in time".
5. **Fixed** in `80bdbae6`. A deviation note under M1 in `architecture-proposal-2026-11-02.md` records the std server plus hand-written `ws.rs` in place of axum (1.1, 4.5): the reason, the limits, that 03 and 04 must not assume axum, and that the choice is revisited at Issue 04. The module comment in `server.rs` points to the note.
6. **Fixed** in `fdf1d766`. The transport refuses a welcome whose `proto` is not `REMOTE_PROTO`, and the host closes a session whose hello `proto` is missing or not `PROTO`. Tests: remote-transport.test.ts "refuses a welcome from another protocol version"; remote_ws_test `a_hello_with_another_protocol_is_closed`.
7. **Fixed** in `b665a1a2`. `exists` uses `Path::try_exists`, which follows links. Test: remote_ws_test `exists_reports_a_dangling_link_as_missing` (failed before the fix).
