## Findings

1. **major** `src-tauri/src/remote/server.rs:44`: a port held by another process on the wildcard address is not reported. Rust's `TcpListener::bind` sets `SO_REUSEADDR` on Unix (std `sys/net/connection/socket/mod.rs:562`). On macOS that lets a bind to `127.0.0.1:P` succeed while another socket listens on `0.0.0.0:P` or dual-stack `[::]:P`. Repro: Python held `[::]:47471` (V6ONLY=0) and listened. The review probe binary (`RemoteServer::start(47471, ...)`) then started with no error, and `GET /` to `127.0.0.1:47471` was answered by Kokobrain (`HTTP/1.1 200 OK` + CSP). Settings shows the URL, not "already in use". The other server silently loses all loopback clients. **Fix:** before the loopback bind, probe-bind `(Ipv4Addr::UNSPECIFIED, port)` with std `TcpListener::bind`, drop it at once without accepting, and map `AddrInUse` to the same "Port N is already in use" message. A Python probe confirmed it fails with errno 48 against both a `0.0.0.0` holder and a `::` holder. It succeeds after our own stopped server leaves TIME_WAIT sockets, so off/on toggles do not report a false error. The alternative is a `socket2` bind without `SO_REUSEADDR` (socket2 0.6.5 is already in Cargo.lock), but that reports a false in-use error for ~30 s after a stop (TIME_WAIT from `Connection: close`). If the brief unlistened `0.0.0.0` bind is unwelcome next to criterion 2, say so in the code comment or pick the socket2 route. Add Rust tests that hold the port on `0.0.0.0` and on `[::]` and expect the error.
2. **minor** `src-tauri/src/remote/server.rs:1-6`: the server is hand-written on `std::net`, but proposal step 1.1 (`architecture-proposal-2026-11-02.md:246`, also line 102) plans axum + tower-http with a Host **and Origin** allowlist, and the later phase-1 Issues need WebSocket on the same server. The Issue 01 criteria do not name a crate, so this is not a criterion failure. Either expect Issue 02/07 to replace this module, or record the deviation (discovery says "Defaults taken" but not why axum was dropped). **Fix:** add a line to the discovery or module docs saying whether the server is a placeholder to be replaced by axum, so the next Issue does not grow a WebSocket implementation on top of it.
3. **nit** `src-tauri/src/remote/csp.rs:37-38`: the doc comment says the policy "Mirrors the desktop policy in `tauri.conf.json` minus the Tauri-only `ipc:` / `asset:` sources". It also drops every `https://` `connect-src` host (todoist, huggingface, github, sentry), and it adds `blob:` to `img-src` plus `object-src`, `base-uri` and `frame-ancestors`. **Fix:** describe what the policy actually allows.
4. **nit** `src-tauri/src/commands/remote.rs:23,34`: both commands are sync, so Tauri runs them on the main thread. `stop` does a self-connect (`connect_timeout` up to 1 s) and joins the accept thread, so the UI can stall. **Fix:** `#[tauri::command(async)]`, or accept it and leave a comment.
5. **nit** `src/lib/app/lifecycle/app-lifecycle.service.ts:207`: the server keeps running after the vault closes, and Settings cannot be reached from the vault picker, so there is no UI to see or stop it. This is harmless here (no vault data is served) and documented as a default in the build report. It becomes material once Issue 02 serves the tree. **Fix:** none needed for 01; revisit in 02 (for example, stop it in `teardownVault`).
