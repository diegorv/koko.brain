## Findings

1. minor — `src-tauri/src/remote/dispatch.rs:63-64`: `check_path_args` skips a `PATH_ARGS` arg that is missing or `null` and leaves it to "the command's own parse", but Virtual commands do no parse. So `update_note_in_index {}`, `start_vault_watcher {}` or `scan_vault_v2_cached {}` are acknowledged with no vault open (the first returns the index version, the last the entry count), which is a path-taking command that is not refused. No file is read and nothing outside the vault is touched, so this is not a blocker. Fix: refuse a missing or `null` value for a required (non-`?`) `PATH_ARGS` arg, or at least call `root(ctx)?` once at the top of `check_path_args` when the command has any row, and add one Virtual no-path case to `every_path_command_is_refused_with_no_vault_open`.
2. minor — `src-tauri/tests/remote_containment_test.rs:235-237`: the comment says this is an NFD spelling that APFS treats as the NFC one, but `.kokobrain\u{0301}` normalizes to `.kokobraiń`, which is another folder, not `.kokobrain`. The test passes for any reason at all (the file does not exist). The real NFC/NFD case is the KELVIN SIGN one at line 220. Fix: drop the `\u{0301}` case or reword it as "an unrelated non-ASCII dot-dir is refused", and note at line 219 that U+212A is also the NFD/NFC variant.
3. nit — `src-tauri/src/remote/policy.rs:185`: "every Unicode spelling of `.kokobrain`, which all start with an ASCII `.`" holds on APFS but, from memory (Apple TN1150, not checked), not on HFS+, whose case-insensitive compare ignores some code points (for example U+200D). There `\u{200D}.kokobrain` would get past the lexical dot rule. The canonical pass should still catch it, since Darwin `realpath` returns the on-disk name, but that was not tested on an HFS+ volume. Fix: make the comment say that the canonical re-check is the guarantee and the ASCII-dot rule is the first line, or add an HFS+ note to discovery's open questions.
4. nit — `.scratch/ios-app/work/03/discovery.md:6` says "max 40 hops" while `policy.rs:263` has `MAX_LINKS = 32`. This is the workflow's own record, so it is noted for accuracy only.
5. nit — check-then-use race (also in the build report): `std::fs::read(canonical)` still follows any link that is swapped in after the check. This needs a local writer on the Mac, because the browser cannot create links (every create, rename and real write is Denied or dropped). It is acceptable for this Issue. Revisit with `O_NOFOLLOW`/`openat` before browser writes land (Issue 08).
