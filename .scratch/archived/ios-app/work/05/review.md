## Findings

1. minor — `src/tests/lib/app/remote/fake-host.ts:84`: the fake host answers every command it does not list with `null`, Denied ones included. The browser read path can therefore send a command the real host refuses and the integration test still passes. The probe shows this already happens: the boot sends `plugin:fs|mkdir` (Denied in `policy.rs:105`) because the fake vault has no `.kokobrain/`. Fix: make the unknown-command default throw "denied" (or mirror the policy classes), list the Virtual commands the boot uses explicitly, and give the fake vault a `.kokobrain/` so the boot matches a real vault.
2. minor — `src-tauri/tests/remote_ws_test.rs:224`: the link-panel Read commands `get_backlinks_v2`, `get_relationship_backlinks_v2`, `get_outgoing_links_v2` and `get_outgoing_unlinked_mentions_v2` are only tested for refusal (in `remote_containment_test.rs`), never for returning data over the dispatcher. `browser-open-note` does not mount the backlinks or outgoing panels, so "work over the WebSocket" for them rests on the earlier dispatch arms with no test. Fix: extend `read_commands_return_the_desktop_data` so `get_backlinks_v2` on `folder/other.md` returns `note.md` (the fixture links `[[other]]`) and `get_outgoing_links_v2` on `note.md` returns `other`.
3. nit — `src/lib/app/remote/tauri-bridge-stand-in.ts:84-90`: a listen registration is recorded only when the host's `plugin:event|listen` reply arrives. The host runs each call on its own thread (`rpc.rs:146`), so an `emitBridgeEvent` raised before that reply is dropped silently. Today the boot order makes this unlikely, since the listener `$effect` runs well before the `scan_vault_v2_cached` that follows `initializeVault`'s earlier round trips. Fix: note the ordering assumption in the comment, or keep the registration pending by handler until the id arrives.
4. nit — `src/lib/app/remote/device-local.ts:38-39`: `open_url` hands any string to `window.open` with no scheme check. All current callers check `isSafeUrl` first, but `isSafeUrl` accepts relative URLs, which would open a page of the loopback app in a new tab. Fix: restrict to `http(s):` / `mailto:` here, or reuse `isSafeUrl` and reject relative URLs.
5. nit — `src-tauri/tests/remote_containment_test.rs:241`: `get_unlinked_mentions_v2` was added to the outside-path list but not to `every_path_command_is_refused_with_no_vault_open`. Fix: add `("get_unlinked_mentions_v2", json!({ "path": note }))` there.
6. nit — `src/lib/app/remote/RemoteDialog.svelte:15`: proposal 1.9 calls for an in-app AlertDialog. This uses the plain `Dialog`, since `components/ui/` has no alert-dialog. So the role is `dialog` rather than `alertdialog`, and an outside click dismisses it (answering the last button, No / Cancel, which is the safe answer). That is acceptable for the PoC; it is recorded here as a deviation from the proposal.
