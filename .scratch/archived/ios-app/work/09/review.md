## Findings

1. **blocker** `src/lib/app/remote/remote-log.ts:49-51` (used at :64 and :68). `describe()` returns `reason.stack` whenever it is set. Only V8 starts `stack` with `Name: message`. JavaScriptCore (Safari) and SpiderMonkey start with the first frame (MDN `Error.prototype.stack` examples: `new Error('Function failed').stack` in JSC is `anonymous@\nglobal code@filename.js:1:65`). So in Mac or iOS Safari, `throw new Error('save failed')` or `Promise.reject(new TypeError('x is undefined'))` reaches the Mac log as `BROWSER:UNCAUGHT foo@http://...:1:2\n...` with no `save failed` and no `TypeError`, which is what the owner needs to see. The tests miss it: the uncaught test passes `error: null` and the rejection test passes a string. Fix: always start with `${reason.name}: ${reason.message}`, then append the stack when it does not already start with that text. Add tests for an `Error` reason whose `stack` has no message (set `stack` by hand to a JSC-style string) for both `error` and `unhandledrejection`.
2. **minor** `src/lib/utils/log.service.ts:96-103` together with `src/lib/app/remote/remote-session.ts:82`. With the sink set, `appendLog` forwards every line. That includes the raw callers that do not go through `debug()` (`FE-STARTUP-PROBE` in `editor.service.ts` / `note-creator.service.ts` / `periodic-notes.service.ts` / `AppShell.svelte`, `QJS-PROFILE`, `PERF-BASELINE`, `PROPERTIES`, `VIEW-LENS`, `RAIL-SHELL`), and it does so whatever the settings say. On the desktop these lines are written only while a log session is active, which needs `debugLogToFile || debugTauriLogToFile` (`app-lifecycle.service.ts:228`). Every browser keystroke path that probes now costs a WS frame. With the Mac's Tauri log on, those lines land in the file even when the vault's `debugLogToFile` is off. Fix: in the sink installed by `remote-session.ts`, forward only while `settingsStore.debugLogToFile || settingsStore.debugTauriLogToFile`, the browser's equivalent of an active log session. The `UNCAUGHT` / `UNHANDLED-REJECTION` / `CSP` pushes can stay ungated. Alternatively, record the deviation in the Issue Notes.
3. **minor** `src-tauri/src/remote/rpc.rs:244-250` (`call_path`). plugin-fs sends the `path` header percent-encoded (`node_modules/@tauri-apps/plugin-fs/dist-js/index.js:756,784`, `encodeURIComponent(path)`), and `dispatch.rs:271-277` decodes it, but the call line writes it raw. So every real write shows as `path="%2FUsers%2F...%2Fnote.md"`. The test passes an unencoded header (`"/v/call-marker.md"`) and does not show this. Fix: decode the header with the same `percent_decode` before `one_line` (falling back to the raw text when it does not decode), and send an encoded header in the test.
4. **nit** `src-tauri/src/remote/rpc.rs:276-288`, `server.rs:322-330`. `one_line` does not escape `"`. A path, login or error message holding `" ok 0ms` can fake fields inside its own line. It cannot add a line, so the criterion holds. Escaping `"` (or using `{:?}`-style quoting) would make the fields unambiguous.
5. **nit** `src-tauri/src/remote/server.rs:297`. `log_request(&head, 101)` runs before `register_session` and the `101` write. When either fails, the log reports a 101 that was never sent, followed by no session lines. Log after the write succeeds, or log the failure.

## Resolution

All five findings fixed; none rejected.

1. **blocker, fixed** in `e82cc306`. `describe()` (`src/lib/app/remote/remote-log.ts`) always starts with `${name}: ${message}` and adds the stack on the next line unless the stack already starts with that text (V8). Tests in `remote-session.test.ts`: "names the error and its message when the stack has neither (Safari)" covers `error` and `unhandledrejection` with a JSC-style stack and no message in it (failed before the fix). "does not repeat the name and message of a V8 stack" covers the V8 case.
2. **minor, fixed** in `f25ecfa8`. The sink `remote-session.ts` installs pushes an `appendLog` line only while `settingsStore.debugLogToFile || settingsStore.debugTauriLogToFile`. The `UNCAUGHT`, `UNHANDLED-REJECTION` and `CSP` pushes go straight to `log.push` and stay ungated. Tests: "drops appendLog lines while neither log-to-file setting is on, but not page errors" (failed before the fix) and "sends appendLog lines while only the Tauri log-to-file setting is on". The log suite turns `debugLogToFile` on in a `beforeEach`, and `afterEach` resets the settings store. Side effect: `appendLog` lines raised before the browser's settings load are not sent, the same as on the desktop before its log session starts.
3. **minor, fixed** in `9e0d6b7c`. `call_path` decodes the `path` header with dispatch's `percent_decode` (now `pub(super)`) and keeps the raw text when it does not decode. The session test sends `%2Fv%2Fcall-marker.md` and expects `path="/v/call-marker.md"`. The new `a_path_header_that_does_not_decode_is_logged_as_sent` covers the raw-text case. The session test's `wait_line` predicate now also matches `call-marker.md`, because the new test logs a second `write_text_file` call in parallel.
4. **nit, fixed** in `9e0d6b7c`. `log_text::quoted` writes a field inside double quotes, escaping `"` and `\` on top of `one_line`'s escapes. The call line's `path=` and `error=` fields and the request line's `login=` field use it. Browser log messages keep `one_line`, because they are not quoted fields. Test: `quoted_escapes_quotes_and_backslashes_inside_its_quotes`.
5. **nit, fixed** in `471d2c0f` and `5e89e3e3`. The 101 is logged after `write_all` succeeds. A failed write logs `-> 101 not sent: <error>`, and a session `register_session` refused logs `-> upgrade dropped, no session registered (101 not sent)`. `request_summary()` holds the method, path and source text. `5e89e3e3` makes the session test wait for `GET /ws loopback -> 101`. The two failure paths have no test (a failing 101 write or a shutdown racing the upgrade cannot be provoked deterministically). `471d2c0f` carries a `Test-Exempt` trailer for that reason.
