## Findings

1. **major**, `help/documentation/mods/07-events-and-reactivity.md:443` (also `28-mods.md:195`, `13-api-reference.md:110`): the docs say periodic notes always fire `onNoteCreated`. The most common periodic create, the daily note auto-opened at vault open, usually fires before any mod has subscribed. `app-lifecycle.service.ts:530-543` starts `autoOpenDailyNote()` and `startModsHost(vaultPath)` in the same macrotask. The daily note's `openOrCreateNote` needs `exists`, `create_folder`, a template read, `create_note` and the tab open. The host meanwhile reads every mod's folder, imports each `main.js` and runs `onload`. A pending deep-link action (`:519`) starts before the host. A mod that stamps new daily notes therefore misses the note created at launch, without any error. Fix (docs only, no lifecycle change): add a "When it runs" bullet and a table row saying that notes created while the vault opens can be created before mods load and are then not reported. Name the auto-opened daily note and a deep link that launched the app, and point mods at `ctx.watch`/`onload` checks for that case.
2. **minor**, `help/documentation/mods/07-events-and-reactivity.md:445`: the row "A deep link that creates a note without `silent`, `overwrite` or `append`" leaves out two cases that are reported. A non-silent `append` or `prepend` to a missing note falls through to the create branch (`deep-link.service.ts:283` for prepend, `:302` for append, then `openOrCreateNote` at `:340`), so it is reported. The row says it is not. Fix: "A deep link that creates a note, without `silent` or `overwrite` (an `append` or `prepend` to a missing note creates it too)".
3. **minor**, `help/examples/mods/kokobrain-mod.d.ts:504-505` (copied verbatim from mod-core `fdfcc90` `mod-api.v1.ts`): the contract JSDoc says "deep links" are not reported. The host reports a deep link's default create, and the brain docs say so. A mod author reading only the types gets the wrong answer. This file has to match the contract (`mods-types.test.ts`), so it cannot be fixed here. Fix: file a mods-repo follow-up that narrows the wording to "a deep link with `silent` or `overwrite`", then adopt it in a later SHA bump. If the owner wants all deep links unreported, as answer 1 literally says, `openOrCreateNote` needs an opt-out for the deep-link caller instead.
4. **nit**, `help/documentation/mods/07-events-and-reactivity.md:199` (existing text, not in this diff): the `onNoteSaved` table says "Deep links that write (`kokobrain://new` with content ...) yes". The default non-silent create goes through `openOrCreateNote` -> `create_note` and never calls `notifyAfterSave`, so that case fires `onNoteCreated` and not `onNoteSaved`. Fix: in a follow-up, narrow the row to the `silent`/`overwrite`/`append`/`prepend` writes.
5. **nit**, `.scratch/mods-power/issues/08-on-note-created.md`: `relay review-lint` fails with `relay: no acceptance criteria in .scratch/mods-power/issues/08-on-note-created.md` (exit 1).
