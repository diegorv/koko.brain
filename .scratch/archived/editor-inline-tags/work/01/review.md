## Findings

1. **major** — `src/lib/core/markdown-editor/extensions/live-preview/styles.ts:210` — In the default dark theme, the pill background does not show. `--accent` comes from `ui.accent` (`theme.logic.ts:120`, `#242835`), the theme's hover/border shade, which is a hair darker than `editorBg` `#2a2e3d` (`theme.logic.ts:87`). Measured contrast is 1.09:1, and the text color equals body text. The Issue's own "Why" (a typed `#tag` looked like plain text) is still true for the default theme. Fix: use a background derived from the editor colors so it follows every preset, the way `app.css:275` does for meta-bind buttons, e.g. `color-mix(in oklab, var(--editor-fg) 12%, var(--editor-bg))`, or tint it with `--primary` (`color-mix(in oklab, var(--primary) 20%, var(--editor-bg))`, text `var(--primary)` or `var(--editor-fg)`). Then check it by eye in KokoBrain Default and Lavender Haze. The criterion names "accent", so if the owner wants `--accent` kept literally, that needs a theme-side change (an `--accent` that differs from `--editor-bg`), which is wider than this Issue. Ask before going that way.
2. **minor** — `src/lib/core/markdown-editor/extensions/live-preview/inline/handlers/tag-handler.ts:24` — The Issue says "Something the indexer counts as a tag gets styled", but the editor and indexer still disagree in places, because the indexer strips text before it matches and the editor matches each raw line. In a probe, the indexer counts and the editor does not style: `` a `x`#tag `` and `a <!-- c -->#tag` (stripping puts the `#` after a space), `~~~` fences, `$$` math blocks and HTML blocks (`BLOCK_CONTEXT_TYPES`). The build report lists the last three. This does not block, because the criterion checklist only requires "nothing styled" inside code, frontmatter and comments. Fix: record it as a follow-up (the indexer is probably the side to change for the strip-joins-context cases), or state it in the help text.
3. **nit** — `help/documentation/07-sidebar-panels.md:126` — The text says the Tags view does not count tags in "code blocks". It does count them in `~~~` fences and `$$` blocks (finding 2), so the sentence overstates the parity. Fix: say "``` code blocks", or drop the "Tags view does not count" framing for the code-block item.
4. **nit** — `src/tests/lib/app/editor-host.test.ts:233` — The diff changes the indentation of the existing `it('openLink opens the note and queues the scroll to its heading'` line from one tab to two. Fix: restore the single tab.
5. **nit** — `src/lib/core/markdown-editor/extensions/live-preview/click-handler.ts:69` — The tag handler runs before the link handler, so Cmd+click on a tag inside markdown link text (`[see #tag](https://x)`) opens the tag search instead of the URL. Cmd+click on the rest of the link text still opens the URL. This is defensible. Fix: none required, but a test pinning the chosen order would document it.
