## Facts for the agent reference (CONFIRMED unless marked)

**What runs**
- The rail runs one view of the file. It is the view `_rail_view` names, else the first. The index is clamped with `Math.max(0, viewIndexByName(...))` (`collection/yaml-parser.ts:142-144`, `LL:792`).
- The view's `type` is never read; calendar views show as a flat list.
- CORRECTED: `resolveViewLens` also reads `filterError` and `includesArchived` (`LL:837,843`), not only the four fields A07 lists.
- CORRECTED: a `_rail_view` that names no view is silent only in the rail. With several views the rule line says `first view`, and the navigator shows a grey mark (`rail-shell/view-lens.service.ts:34,44`, `TSL:427-441`).

**Row set** (`viewRowSet`, `LL:704-721`)
- Shared by the rail, the editor and the navigator count.
- It drops the system folder, `_type: Type` notes, `.view` files (`TSL:74-76`), records with no entry, and archived notes unless the filters cite archived (`TSL:126,130`).
- It orders the rows, then applies `limit` last. `executeQuery` hands the limit step to it (`collection/collection.logic.ts:124-125,208-212`).

**Order** (`TNL:96-98`)
- A non-empty `sort:` keeps the query order, and no pins apply.
- Otherwise `_sort` orders the list (`modified`, `created`, `modified-asc`, `created-asc`, `title`). Any other value falls back to `modified` (`TSL:395,462-465`), and the notes' `_order` pins go on top.
- Two readers of `_order` must stay separate in the reference:
  - A note's `_order` pin accepts a number or a numeric string (`TSL:137-140`).
  - The `.view`'s own `_order` (its position in the navigator) accepts a number only, default 50 (`TSL:409,453-456`).

**Load states, in order** (`RNL:233-286`)

| Order | State | What the user sees |
|---|---|---|
| 1 | Index not ready, or first read in flight | `Loading...` |
| 2 | `.view` not in the tree | `This view no longer exists`, no button |
| 3 | Parse error | Heading `This view cannot be shown` + parser message |
| 4 | Any throw | `Could not read the view: ...` (also for query bugs) |
| 5 | `filterError` | `Invalid filter "<expr>": <reason>` |
| 6 | No view to run | `The .view has no views to run` |
| 7 | Ran, zero rows | `No notes here` / `No matching notes` |

- State 6 is CONFIRMED unreachable: the parser rejects a missing or empty `views` (`yaml-parser.ts:27-37`).
- The `Open view` button shows only in the error states. Parse failures are not logged.
- Parser messages give a view index, not a line (`yaml-parser.ts:18-79`).
- The count shows `0` in the error and missing states. It is counted after `limit` and after search (`RNL:546,717`).

**Writers**
- The rail toolbar writes one key per edit: top-level `filters`, the rail view's `filters`, or the rail view's `sort`.
  - Clearing all filters removes the key, and Reset removes `sort` (`TNL:128-140`).
  - An edit is refused as a conflict if that key's canonical value changed underneath it (`TNL:187-199`). Comments are lost on every write.
- Sort-menu picks write `file.mtime`, `file.ctime`, `file.name`, `status` or `<key>` (`list-view-sort.logic.ts:33-46`). Clicking the active row without an arrow writes nothing (`RailSortMenu.svelte:62`).
- Writes go through `rewriteViewFile`, one at a time per path. A dirty tab's buffer is the base, and that tab is saved at once (`TDS:350-440`).
- An empty `_list_properties_display` removes the key (`TDS:481-487`). That write passes `promptIndexRefresh`; toolbar writes do not (`TDS:486` vs `TDS:524`).

**Rows**
- Pills render `note.frontmatter[key]` only (`NoteRow.svelte:100`), so `file.*` and formula pills can never show. Pills show values with no property name.
- The type chip uses the same style as a value pill (`NoteRow.svelte:95` vs `:116`).
- The subtitle always shows the modified time, frozen when the row is built (`LL:251-259`).
- Context menu items: Open in new tab, Duplicate, Show in Views, Copy path, Change icon, Reveal in Finder, Rename, Move to Trash. None is specific to views (`NoteRowMenu.svelte:209-262`).
- CORRECTED: a full-text search failure logs through `debug()` only (`RNL:537`), so it reaches the log only with the debug settings on.

## Surviving findings, ranked

1. **G1 New here may create a note that is not in the list.** Medium. Tags: visualization, edit-dialog, reference.
   - Widened: a compound string filter like `'type == "Project" && status == "active"'` is the docs' own example (help25:396). It parses to one binary `&&` node, which becomes a `raw` row (`expression/parser.ts:48-51`, `toolbar/filter.logic.ts:30,385-387`).
   - `viewNoteType` skips raw rows (`LL:883`), so New here creates an untyped plain note and every row shows its type chip.
   - Typed notes land in the type's `_folder` (`new-note.service.ts:28`). A misspelled type value is used as written (`LL:889-892`).
   - Even a matching note appears only after the entries refresh (`LL:716-719`).
2. **G3 The sort is only partly explained.** Medium. Tags: visualization, edit-dialog.
   - Any pick in the rail sort menu other than a plain click on the active row writes `sort:`. That silently disables `_sort` and every `_order` pin (`RailSortMenu.svelte:62-64`, `TNL:96-98`).
   - A view ordered by `_sort` alone shows no tint and no Reset. Picking a row collapses a multi-column sort to one column.
3. **G2 `limit` is invisible in the rail.** Medium. Tags: visualization, edit-dialog.
   - The count and search both see only the capped list (`LL:720`, `RNL:717`), and the rule line never mentions the limit.
4. **G6 A working list has no route to the collection editor or Edit view.** Medium. Tags: visualization, edit-dialog.
   - `openFileInEditor` appears only in the error state (`RNL:871`). Open view and Edit view exist only in the navigator's context menu (`TypesNavigator.svelte:310,314`).
5. **G7 No switcher between the views of a multi-view file.** Medium. Tag: visualization.
6. **G4 Pills have no names, and the picker's sources are limited.** Medium. Tags: visualization, edit-dialog.
   - The picker offers only frontmatter keys of the rows listed now, after `limit` (`list-properties.logic.ts:29-38`, `RNL:556-558`).
7. **M1 (new) A filter that does not parse locks the rail toolbar.** Medium. Tags: visualization, edit-dialog.
   - The error state hides Sort and Filter (`RNL:193,860`), so recovery is only through Open view.
   - Whether the Filter panel can write such a filter is not verified. The dialog's preview should catch `filterError` before Save.
8. **G8 Toolbar edits persist at once, and a rail edit saves a dirty `.view` tab.** Re-rated from medium to low-medium. Tags: visualization, edit-dialog.
   - The tab save is real (`TDS:388,410-414`), but the tab autosaves anyway.
   - Permanent filters are a documented design choice (help25:470).
   - CORRECTED A07 implication 9: "the later write wins" holds only when the dialog writes second. A rail edit queued after a dialog Save that changed the same key is refused with `This view changed. Your edit was not saved.` (`TNL:190`, `RNL:323`).
9. **M2 (new) Raw rows also break the type chip and row editing.** Low-medium. Tags: visualization, reference.
   - The reference should advise `and:` lists of simple expressions over one `&&` string.
10. **M6 (new) A dialog preview needs a draft `_sort` in the context.** Low. Tag: edit-dialog.
    - `viewRowSet` reads `_sort` from `ctx.entries` (`LL:711,714`), so a preview of a draft `_sort` must inject it there. Draft `limit`, `filters` and `sort` go in through the definition and the overrides.
11. **M3 (new) `_sort` changes show later than other edits.** Low. Tag: reference.
    - `_sort` comes from the entries snapshot, while `sort`, `filters` and `limit` come from the disk parse. A `_sort` edit takes effect on the next entries refresh.
12. **G5 The subtitle ignores the sort key.** Downgraded from low-medium to low.
13. **The remaining low findings, all confirmed:**
    - G9: the error and missing states show count `0`. The editor's heading is `Filter error` (`CollectionView.svelte:689`), not the rail's `This view cannot be shown`.
    - G10: query bugs are labelled as read errors.

    - G13: rapid edits can chain a false conflict toast. The base is captured when the edit is queued (`RNL:308-310`).

    - G15: the file is re-read from disk on every entries bump.
    - G16: the help docs have gaps.
