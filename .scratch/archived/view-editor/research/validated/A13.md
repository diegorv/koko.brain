## Facts for the agent reference (confirmed or corrected)

**Parse rules** (`yaml-parser.ts`):
- The root must be a map with a non-empty `views` list (:21-37).
- A file holding only `_visible: false` and `_open_in_editor: true` fails with `Missing required field: views` (:27-29).
- Each view needs a `type` that is exactly `table`, `calendar` or `linear-calendar`, case-sensitive (:47-55, :333).
- Each view needs a `name` that is a YAML string. An unquoted `name: 2026` is a number and fails as `missing "name"` (:56-58). [new]
- `sort` items need a `column` (`property` is accepted as an alias) and a `direction` of exactly `ASC` or `DESC`. The direction is required (:64-80). The column is never checked, so a misspelled column silently does nothing. [new]
- `limit` must be a number >= 1 (:86-88). `2.5` is allowed and keeps 2 rows.
- `order` must be a list; its items are not checked.
- `columnSize` must be a map. It, `groupBy` and `summaries` are kept but nothing reads them.
- Root `filters` are not checked when the file is parsed. They are checked when the view runs (`collection.logic.ts:136-141, 227-249`), and a falsy value counts as no filter.
- `formulas` must be a map of strings. A formula that fails to parse or throws becomes `null` with no message (`collection.logic.ts:147-155, 176-189`).
- Calendar keys are never checked.
- Every writer saves the whole parsed object again, so unknown keys survive but comments do not. The writers also use two different line widths: `lineWidth: 0` at :329 and in `buildNewViewYaml`, the default elsewhere (:261, 355, 378, 406, 429).

**Which notes a `.view` lists** (`lens.logic.ts:704-721`):
- System-folder notes, `isA === 'Type'` entries and `.view` files are dropped, and archived notes unless a filter cites `archived` or `_archived`.
- The view's own `sort` keeps the query order, with no pins. Without one, the file's `_sort` (default `modified`) applies, and each listed note's own `_order` pins it on top. A note's `_order` accepts a quoted number, but a `.view`'s own `_order` must be a bare number (`type-sidebar.logic.ts:136-140` vs :453-456). [clarified]
- `limit` is applied last, and records with no index entry are dropped.
- **CORRECTED:** A13 said the editor's row-set port is registered per active tab. It is registered once, app-wide, at boot (`app/boot.ts:61`). Every editor tab without its own `sort` is therefore ordered by the file's `_sort` (`CollectionView.svelte:272`).

**Inline blocks:**
- A block renders only `views[0]` and reads none of the underscore keys, `_rail_view` included (`collection-block-widget.ts:110`).
- It can draw a calendar or linear calendar (:149-157).
- The table stops at 50 rows with a plain "Showing 50 of N" footer (:54, :170-175). The linear calendar shows at most 3 lanes (:56-63).
- It keeps records that have no index entry yet (`view-row-set.port.ts:19`).

**Menu keys** (`type-sidebar.logic.ts`):
- `_visible` hides the view only when it is the boolean `false` (:378-380). `_open_in_editor` works only when it is `true` (:361). `_rail` pins only when it is `true` (`lens.logic.ts:222`), and pins ignore `_visible`.
- `_group` is trimmed and compared exactly. Ungrouped views come first, groups follow in natural order, and inside a group views go by `_order`, then label, then path (:489-499).
- `_order` defaults to 50. `_sort` takes one of five values and defaults to `modified`.
- Only `_order`, `_open_in_editor`, `_sort`, `_visible`, `_group`, `_rail` and `_rail_view` get the "ignored key" mark (:408-424). A bad `_sidebar_label` falls back to the file name with no mark. [new]

**Creating views:**
- New table writes no `_sidebar_label` and no `_sort` (`collection.service.ts:18-23`). New view writes `_sidebar_label`, `_sort: title`, and its filters under `views[0]` (:351-354).
- Both items sit in the same menu: a right-click on the vault row and on the empty space below the folders both target the vault root (`FilesNavigator.svelte:316-321, 343-360`). This settles A13's open question.
- Wikilinks never point to a `.view` (`wikilink-resolution.logic.ts:15-20`). Confirmed; A13 had left this unverified.

9. **[visualization] medium:** a calendar `.view` picked in Views shows as a plain list. The docs state this, so it is low as a doc gap.
