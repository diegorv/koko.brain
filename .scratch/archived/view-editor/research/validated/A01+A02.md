# V01: Validation of A01 (parse and validation) and A02 (writers)

## Facts for the agent reference (CONFIRMED unless marked)

**Parsers**
- **Two parsers.**
  - TS: `parseCollectionYaml` (`src/lib/features/collection/yaml-parser.ts:13-123`).
  - Rust: any `.view` path goes to `parse_frontmatter_raw_yaml` over the whole file (`src-tauri/src/vault/entry.rs:241-243`, `src-tauri/src/vault/parsing.rs:576-578`). It then builds `from_view_frontmatter` (`entry.rs:294-313`), so `is_a`, links, tags and tasks stay empty.
- **A01's error-message table (rows 1-18) is exact.** Checked line by line against `yaml-parser.ts:15-111`.
  - An array root fails with `Missing required field: views` (run).
  - An empty file fails with `YAML must be an object`.
- **Strictness in the TS parse (run):**
  - Duplicate map keys throw `Map keys must be unique` at any depth, so the whole file fails.
  - Multiple documents throw.
  - Tab indentation throws.
- **The same inputs in Rust:**
  - Duplicate keys are last-wins (`parsing.rs:538-539`, fixture `src/tests/fixtures/frontmatter-parity.fixture.json:231-236`).
  - Multi-document and tab-indented files go to the subset parser `parse_yaml_lines`, which reads only unindented lines (`parsing.rs:596-607`, `:614-639`, `:855-858`).
- **`limit` holes (run):**
  - `.nan` and `.inf` pass the parse check (`yaml-parser.ts:86`).
  - NaN then applies no limit, because `view.limit > 0` is false (`src/lib/features/rail-shell/lens.logic.ts:720`, `src/lib/features/collection/collection.logic.ts:210`).
  - Infinity returns every row. `2.5` truncates to 2 through `slice`.
- **`name` and `type` rules.** `name` and `type` must be YAML strings, so an unquoted `name: 2026` or `name: true` fails with `missing "name"` (`yaml-parser.ts:47`, `:56`). A whitespace-only name passes.
- **Sort rules.** Sort `direction` must be exactly `ASC` or `DESC` and has no default (`:78`). `property` is copied onto `column` only inside sort items (`:70-74`).
- **Number divergence (from comment, not run in Rust).** Rust keeps `0x1F` and `.inf` as strings (`parsing.rs:540-541`). TS yaml gives `0x1F` as 31 (run). A hand-written `_order: 0x1F` therefore reads as a string from the index and falls back to the default 50.

**Rust projection**
- Every mapping at any depth becomes `null` (`parsing.rs:815`). In the index, `views` is therefore an array of nulls.
- An unquoted `[[X]]` becomes the string `"[[X]]"` (`:818-834`).
- Aliases fold at root only (`src-tauri/src/vault/aliases.rs:9-28`, `parsing.rs:799`). `rail`, `rail_view`, `group` and `open_in_editor` have no alias.
- **CORRECTED (A02).** `title_color` is an alias of `_title_color` (`aliases.rs:22`). A02's sentence that `_title_color` "has no alias" is wrong.

**Readers of the index**
- The readers and defaults in `src/lib/features/type-definitions/type-sidebar.logic.ts:337-481` match A01's table. `_rail` pins only on boolean `true` (`lens.logic.ts:222`, `:233`).
- **CORRECTED (A01), icon readers.** There are two:
  - A full rebuild reads the Rust entries (`buildFrontmatterIconIndex`, `src/lib/app/lifecycle/watcher-handler.service.ts:73`).
  - The per-file update re-parses the raw body with TS yaml (`src/lib/features/file-icons/file-icons.service.ts:240-242`, `src/lib/features/file-icons/file-icons.logic.ts:190-203`).
  - So a file with duplicate keys keeps its icon after a rebuild but loses it on an incremental update.
- **CORRECTED (A01 gap 10), timing of the `_rail_view` mark.**
  - The index-based note runs on `entry.frontmatter` (`lens.logic.ts:655`), and there `views` is an array. A blank `_rail_view` is therefore flagged at once, from the index.
  - Only a name that matches no view, or an unquoted `[[X]]` (a string in Rust, `railViewIgnored` in TS, `yaml-parser.ts:120`), waits for the parse (`src/lib/features/rail-shell/view-lens.service.ts:33-34`).
- **CORRECTED (A01 gap 12), read cost.** `countViewNotes` calls `refreshViewDefinition` and not the cached read (`view-lens.service.ts:33`). Every count pass reads every `.view` from disk, not only the first one. The hash check only skips the re-parse (`src/lib/features/type-definitions/view-parse-cache.ts:49-51`).

**Writers**
- **Serializer.** Every writer parses, mutates and re-stringifies. The default `lineWidth` folds long strings at 80 columns. Only `buildNewViewYaml` (`type-sidebar.logic.ts:353`) and `updateViewEditYaml` (`yaml-parser.ts:329`) pass `lineWidth: 0` (run confirms the fold).
- **Comment-preserving write exists.** `yaml` 2.9.1's `parseDocument` with `setIn` and `toString` keeps both a head comment and an inline comment (run). This answers A01 open question 6 and A02 open question 1. `toString` also folds unless it is given `lineWidth: 0`.
- **Two creators make different shapes.**
  - `buildNewViewYaml` writes `_sidebar_label`, `_sort: title` and one table view.
  - `NEW_TABLE_TEMPLATE` writes `_visible: false`, `_open_in_editor: true` and a view named `All`, with no `_sidebar_label` (`src/lib/features/collection/collection.service.ts:18-23`, caller `src/lib/features/rail-shell/FilesNavigator.svelte:87`).
- A02's walk-through of `rewriteViewFile` (`src/lib/features/type-definitions/type-definitions.service.ts:350-441`) and of the writer table is CONFIRMED.
- **Failure behaviour differs by writer:**
  - The icon and color writers return the input, which is a silent no-op (`type-sidebar.logic.ts:534-537`, `:558-560`).
  - The rail, visibility and list-properties writers throw (`:583-586`, `:606-608`, `:626-629`).
  - `updateViewEditYaml` returns `{ok:false}` (`yaml-parser.ts:286-310`).

## Surviving findings, ranked

1. **[edit-dialog] medium. Edit view clobbers concurrent edits (A02-1, CONFIRMED).**
   - The prefill is a disk read (`src/lib/features/type-definitions/ViewDialog.svelte:83`, `view-parse-cache.ts:46`).
   - The write base is a dirty tab's buffer (`type-definitions.service.ts:388`).
   - Save always sends `viewFilters` (`ViewDialog.svelte:145-149`), and there is no base check (`yaml-parser.ts:320-327`). Compare the toolbar's base check (`src/lib/features/type-definitions/type-note-list.logic.ts:190`).
   - Consequence: unsaved tab edits, or toolbar edits made while the dialog was open, are overwritten silently.
2. **[edit-dialog] medium. NEW: an unchanged Save renames the view.**
   - The dialog's name is the row label (`ViewDialog.svelte:76`). That label falls back to the file name (`lens.logic.ts:650`, `type-sidebar.logic.ts:337-340`, `:330`).
   - Save writes the label into the rail view's `name` (`yaml-parser.ts:318`).
   - Example: New table's `Untitled.view` has a view named `All`. Opening Edit view and pressing Save renames the tab to `Untitled` and adds `_sidebar_label`.
   - A hand-written file with label "Projects" and views "Table" and "Calendar" gets "Table" renamed to "Projects".
3. **[edit-dialog, visualization] medium. Renaming or removing the rail view leaves `_rail_view` stale (A02-3, CONFIRMED).**
   - `renameView` and `removeView` never touch `_rail_view` (`yaml-parser.ts:364-407`). The tab's inline rename calls `renameView` (`src/lib/features/collection/CollectionView.svelte:476`).
   - `railViewIndex` then falls back to 0 (`yaml-parser.ts:142-144`), so the rail list, its count and Edit view all move to `views[0]` silently.
4. **[reference, visualization] medium (raised from low/unverified). Duplicate keys split the two parsers (A01-3, CONFIRMED by run).**
   - Rust is last-wins, so the row keeps its label, icon and pin.
   - TS throws, so the rail shows an error, Edit view is blocked, and every structured writer refuses or no-ops.
5. **[edit-dialog] medium. One bad entry blocks the whole dialog (A01-1, CONFIRMED).** The parse returns at the first bad entry (`yaml-parser.ts:39-95`), and the dialog blocks on it (`ViewDialog.svelte:65`, `:92-95`).
