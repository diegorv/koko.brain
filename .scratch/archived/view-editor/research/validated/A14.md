## Facts for the agent reference (confirmed or corrected)

**Aliases**
- Rust folds aliases on each top-level key; the later spelling wins (`docs/adr/0027-...md:11`, `src-tauri/src/vault/aliases.rs:9-34`).
- Keys with an alias: `_order`, `_sort`, `_icon`, `_color`, `_title_color`, `_sidebar_label` (two aliases), `_visible`, `_list_properties_display`.
- `_rail`, `_rail_view`, `_open_in_editor` and `_group` have none (`0027:17-34`).

**Two kinds of sort (A14 missed this)**
- Top-level `_sort` is one string from `modified, created, modified-asc, created-asc, title` (`type-sidebar.logic.ts:395-400`). The rail list uses it when the view has no `sort` of its own (`0027:30`).
- A view's own `sort` is a list of `{column, direction: ASC|DESC}`, with `property` accepted for `column` (`yaml-parser.ts:61-81`).
- A bare top-level `sort:` is folded to `_sort` (`aliases.rs:17`). An agent that writes a sort list at the top level gets an "ignored key" note, not a sorted view.

**What the TS parser refuses (A14 missed this)** (`yaml-parser.ts:27-113`)
- `views` missing, not a list, or empty.
- A view with no string `type`, or a type other than `table`, `calendar` or `linear-calendar` (`:333`).
- A view with no string `name`.
- A bad `sort`, an `order` that is not a list, a `limit` that is not a number of at least 1, or a `columnSize` that is not a map.
- A formula whose value is not a string.
- Any YAML that does not parse, which covers a second document after a `---` line.

**`_rail_view`**
- Matching is exact and case-sensitive; the first match wins. A blank, non-text, missing or unknown name runs the first view (`yaml-parser.ts:117-144`, `0027:40-42`).
- Only the rail reads it.

**Ignored-value checks are not reader rules (corrected)**
- `RESERVED_KEY_RULES` (`type-sidebar.logic.ts:408-428`) only checks the kind of value. `_rail: false` passes and pins nothing; `_group: "  "` passes and stays ungrouped.
- The dialog's "not set" rule must follow the readers (`getViewOrder`, `getViewGroup`, `getViewVisible`, `getViewSort`, `:368-471`).
- Those readers take index entries where aliases are already folded. Code that reads raw YAML must fold them itself (`canonicalizeKey`, `src/lib/utils/frontmatter-aliases.ts`).

**Alias dropping already exists (corrected)** for `icon`, `color` and `title_color` (`type-sidebar.logic.ts:539-541`), `visible` (`:610`) and `list_properties_display` (`:632`). Only `sort` and `order` lack it, because nothing writes them yet.

**Wikilinks in system keys (wider than A14 said)** `_group`, `_rail`, `_rail_view` and `_open_in_editor` are all missing from Rust `SYSTEM_KEYS` (`entry.rs:438-445`). A wikilink in any of them becomes a relationship field.

**Pins** (`0033:109-123`)
- The stored key is `view:<path>`, and restoring it does not check the target.
- `_visible` is not read.
- A pinned view moved to Trash falls back at once; a moved or renamed `.view` is not followed.
- A pinned `_open_in_editor` view opens the editor instead (A14 missed this).

**`rewriteViewFile` (corrected in detail)** (`type-definitions.service.ts:341-441`)
- The file is written directly with no tab, and also when a clean tab's saved bytes already equal the result.
- A tab closed before its queued save runs gets the rewrite redone on the file.
- Write errors propagate as-is unless the file vanished.
- An error thrown by the transform propagates, which is how the updaters refuse an edit.

**Line width (corrected)** `lineWidth: 0` is used by the Edit view writer and by `buildNewViewYaml` (`type-sidebar.logic.ts:353`). Every other writer uses the default width.

**Test citations**
- The `updateViewEditYaml` tests run from `yaml-parser.test.ts:956` to about 1150, not to 1023. They include alias cases (1027) and a `_rail_view` group (1079-1141).
- `rail-list-toolbar.spec.ts` tests sort on Inbox (`:101`) and Show in note list on a type file (`:170`). No toolbar E2E writes a `.view`.

**Comments and a proposed fix** Comments are lost on every save (`0029:74`). That ADR line says yaml@2.9.1 "with our options" does not keep comments through `Document.toString`, so A14's `parseDocument` fix may not work. Not verified.
