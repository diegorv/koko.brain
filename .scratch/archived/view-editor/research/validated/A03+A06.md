## Facts for the agent reference

**Parsing**
- **CONFIRMED.** A `.view` is parsed as bare YAML by Rust (`src-tauri/src/vault/parsing.rs:573-576`, `entry.rs:241-243`).
- **CONFIRMED.** Value rules (`parsing.rs:~805-818, ~942-972`):
  - Empty, `null` or `~` become null.
  - Only `true/True/TRUE` and `false/False/FALSE` become booleans.
  - Whole numbers, then finite decimals, become numbers. `inf` and `NaN` stay strings.
  - Any quoted scalar is a string.
  - A map becomes null.
  - A lone `[[X]]` becomes the string `"[[X]]"`.
- **ADDED: two parsers read the file.**
  - Menu keys are read from the Rust projection.
  - `views`, `filters`, `formulas` and the running `_rail_view` are read from a separate TS `yaml` parse (`yaml-parser.ts:13-123`).
  - On save, the view icon is also read from a TS parse (`file-icons.logic.ts:190-202`).
- **ADDED, plausible (library default, not run): duplicate keys.** Rust keeps the last one. The TS parse uses default options (`yaml-parser.ts:16`), and the repo passes `uniqueKeys: false` explicitly elsewhere (`properties.logic.ts:257`). So an exact duplicate key likely fails `parseCollectionYaml`.

**Aliases**
- **CONFIRMED.** `order`, `sort`, `icon`, `color`, `title_color`, `sidebar_label`, `sidebar label`, `visible` and `list_properties_display` fold onto their `_` keys. The last one in the file wins (`aliases.rs:9-28`).
- **CORRECTED.** `type`, `organized`, `archived`, `favorite`, `favorite_index`, `template` and `view` also fold in a `.view`. `from_view_frontmatter` reads `_archived`, `_favorite` and `_organized` (`entry.rs:302-307`).
- **CONFIRMED.** `_group`, `_open_in_editor`, `_rail` and `_rail_view` have no alias.

1. **HIGH [edit-dialog] (scope, the PRD premise).** The dialog edits only the name and the rail view's filters. There is no view type, sort, columns, limit, calendar fields, group, order, icon or visibility. Evidence: `ViewDialog.svelte:140-149`, `yaml-parser.ts:265-272`. Writers for view-level fields already exist in `updateCollectionYaml` (`yaml-parser.ts:147-262`).

2. **MEDIUM [edit-dialog], new, plausible.** Every Edit save, even a rename-only one, rewrites the rail view's filters through the visual round-trip, because the dialog always sends `viewFilters` (`ViewDialog.svelte:147`).
   - `due == date('X')` loads as `is` (`filter.logic.ts:390-396, 531`) and saves as `due == 'X'` (`:45-46`).

   - `{and: []}` saves as the invalid string `{"and":[]}` (`filter.logic.ts:133-137`).
   - No test covers this.
