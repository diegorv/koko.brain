## Findings

1. **minor**, `src/lib/features/rail-shell/Rail.svelte:134`. The `_open_in_editor` pin rule is written twice. A rail click on such a pin runs `openFileInEditor(pin.path)` inside `Rail.svelte` and never reaches `onSelect`/`selectRailItem`, while the Go to command runs the copy at `app/rail-navigation.ts:18`. The behavior is the same today, and the split keeps `Rail.test.ts:303` ("opens a pinned _open_in_editor view in the editor instead of selecting it", asserting `onSelect` is not called) green, as criterion 1 requires. The risk is that a later change to the rule (Issue 24's hidden items, for example) updates one copy and not the other. Fix, in a later Issue that may touch `Rail.test.ts`: have `Rail` hand the pin to `onSelect` (`onSelect(key, pin)`) and let `AppShell` call `selectRailItem({ key, pin })`, so the branch lives only in `rail-navigation.ts`. Not a blocker.
2. **nit**, `help/documentation/20-keyboard-shortcuts.md:109`. The Go to row says "Shows the panels if `Cmd+1` hid them" for every item, but Go to on a pinned `_open_in_editor` view opens it in the editor and leaves the layout alone (`rail-navigation.ts:18-21`). Fix: add "(a pinned view that opens in the editor leaves them as they are)".
3. **nit**, `src/lib/app/commands.ts:78`. Two `.view` files with the same `_sidebar_label`, or the same file name in different folders, get identical "Open view: X" rows. They can only be told apart by order. The Issue specifies this label, so this is only a follow-up idea (for example a folder hint) if the owner wants one.
