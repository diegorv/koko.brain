## Findings

1. minor — `src/lib/app/boot.ts:59-64` / `src/lib/features/rail-shell/lens.logic.ts:562-576`: in the editor a `.view` now filters on `collectionStore.propertyIndex` (updated per save) but keeps and orders rows by `typeDefinitionsStore.entries` (refreshed on the throttled `vaultIndexVersion` bump, ~2-10 s). A note just created or saved can be missing from the editor's `.view` list, or sit in its old `modified` position, until the next bump, and a `.view` opened by session restore shows "0 results" until the entries snapshot loads. This is the rail's existing behavior and the owner decision says the rail's rule wins, so no change is required; fix only if it shows up: mention it in the help text or derive `modifiedAt` from the record's `mtime` when the entry is older.
2. nit — `src/lib/features/type-definitions/type-sidebar.logic.ts:371`: `VIEW_SORTS` repeats the case labels of `buildSecondaryComparator` (`type-sidebar.logic.ts:214-228`); a new sort mode added to one and not the other would be reported as ignored, or silently fall to title. Fix: derive one from the other, or add a test that every `VIEW_SORTS` value gives a non-title order where it should.
3. nit — `src/lib/features/collection/CollectionView.svelte:229,240`: `getViewRowSetPort()` reads a plain module variable inside `$derived`, so a port registered after a `.view` editor mounted is not picked up until something else invalidates the derived. `registerAppPorts()` runs at boot before any editor mounts, so this does not happen today; no change needed.

## Resolution

1. Not changed. The editor now follows the rail's rule for a `.view` (the owner decision), and the delay comes with that rule. A fix would mean changing how the rail itself reads entries, which is outside this Issue.
2. Fixed with a test. `type-sidebar.logic.test.ts` "orders by each VIEW_SORTS mode, not by the title fallback" checks that `VIEW_SORTS` lists exactly the five modes, and that each mode, run through `getNotesForViewPaths`, gives its own order rather than the title fallback. If a mode is added to one list and not the other, the test fails.
3. Not changed, as the reviewer said. `registerAppPorts()` runs at boot, before any editor mounts.
