## Findings

1. minor — `src/lib/core/markdown-editor/extensions/live-preview/widgets.ts:1063` — a number input value beyond 2^53 is rounded by `Number(input.value)` and written as the rounded integer, and that integer then makes the note's frontmatter "lossy", so every later meta-bind (and Properties panel) write on the note is refused. Probe (jsdom, real widgets, removed after the run): typing `12345678901234567890` over `count: 5` wrote `count: 12345678901234567000`; a toggle write on the same note was then refused with the toast "Cannot set done: the note's frontmatter could not be parsed; fix it in the note". Before this branch the string kept every digit, and ADR 0029's 2026-11-02 amendment has integers beyond 2^53 "keep their digits". The likelihood is low (it needs a value of more than 16 digits typed into a number field), so this does not block. Fix: when `Number.isInteger(n) && !Number.isSafeInteger(n)`, write the string, or refuse it in `validateNow` with the invalid message, and add a writers test for it.
2. nit — `e2e/specs/live-preview/click-reveal/meta-bind-text-input.spec.ts:86-87` — the comment "The write may quote the value (`count: \"7\"`)" and the tolerant `/count: "?7"?\n/` regex now describe behaviour the branch removed. Change the comment and tighten the regex to `count: 7`, or leave the regex and drop the stale comment.
3. nit — `src/tests/lib/core/markdown-editor/extensions/live-preview/plugins/meta-bind-button-field.test.ts:236` — the edit removed the file's trailing newline (`\ No newline at end of file`). Restore it.
