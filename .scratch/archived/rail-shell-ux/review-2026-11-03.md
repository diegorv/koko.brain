# Rail Shell UX review (2026-11-03)

Scope: the Rail Shell (ADR 0033), its lenses, note list and navigators, the type system, `.view` and `.collection` files, QueryJS, meta-bind and Settings. Code and docs only. The app was not run and no tests were run. Every finding cites code read by a verifier, and the highest-severity ones were spot-checked again before writing (see section 7).

## 1. Summary

1. **You cannot build your own menus yet.** Rail items, their order and visibility are constants (`Rail.svelte:40-53`, `lens.logic.ts:140-148`). The only user-made navigation is a `.view` row under Types > Views. A `.collection`, a queryjs dashboard or a meta-bind button cannot become a rail item or lens. Settings has no Rail section (F52, F53, F55).
2. **`.view` menus are fragile.** A broken, missing or still-loading view shows the same "No notes here" as an empty match, with the toolbar hidden and the reason only in the log (F32). A filter with a typo matches nothing, and inside a NOT group it matches everything (F66). Date operators (before/after) never match frontmatter dates (F65). Toolbar edits rewrite the YAML and drop your comments (F13).
3. **One `.view`, two answers.** The editor and the rail list the same `.view` with different rows, counts and order (archived and `_system` notes, `_sort`, `views[0]` only), and the rail never says which rule it uses (F10, F02).
4. **The organized flag has two defaults.** Rust, the Inbox, the badges and collections treat a missing `_organized` as organized. The note action bar treats it as not organized, so the first Cmd+E click changes nothing visible (F09). Separately, Settings > "Explicit organization" is read by no code, while Settings and help promise an Inbox workflow (F71).
5. **Meta-bind writes and reads the wrong thing.** Toggles and number inputs write quoted strings (`done: "true"`, `count: "7"`), which every boolean reader ignores, so a toggle on `_favorite` or `_archived` never changes a lens (F67). Bind targets that are aliases (`archived`, `type`) never show the stored value, including the help page's own example (F68).
6. **Non-notes leak into note lists.** `.view` files and type definitions show up as "Note" rows in Today, the Day lens, calendar dots, Untyped and unfiltered views. The Inbox and the Types navigator exclude them (F72, F11). `kb.pages()` includes them too (F17).
7. **A JSON typo in settings.json wipes every setting** to the defaults with no backup and no message. Hand edits made while the app runs are overwritten on the next click (F70, F31).
8. **Docs drift.** Type `_view` and the built-in type icons do nothing, ADR 0026 still describes a removed sidebar, help 25 says the Untyped row hides at 0, and the "Always" QueryJS policy does not re-run on render (F61, F62, F63).

## 2. How it works today

**Rail.** `AppShell.svelte` renders the 48 px `Rail.svelte`, then (when `layout.railPanelsVisible`) a navigator pane and `RailNoteList.svelte`, then the editor. Items: Search, Inbox (count badge), Today, Favorites | Types, plugin navigators (only Calendar), Files | Archive at the bottom. A click writes `layout.railItem`. `restoreRailItem` (`lens.logic.ts:159-172`) accepts built-in keys and registered navigator ids and falls back to Today.

**Lenses.** A lens is `{kind, target}` resolved by `resolveLens` (`lens.logic.ts:344-353`).
- Inbox (not organized, not archived, not a type definition), Favorites, Archive: predicates over the Rust entries snapshot, `_system` excluded, newest modified first.
- Today: a "Pinned" group (favorites) plus a "Today" group (note date is today). Note date = frontmatter `date`, else `created`, else disk creation time (`entryNoteDate`, `lens.logic.ts:183-190`).
- Type / Untyped: newest modified, note `_order` pinned first. Type `_sort` is ignored.
- Folder: direct files of every kind, tree order, `_system` and archived not excluded.
- View: the `.view` is parsed, only `views[0]` plus top-level `filters` runs, archived and `_system` notes are dropped. `_sort` applies only when `views[0]` has no sort.
- Day (Calendar plugin) and Neighbourhood.
Rows show `type · YYYY-MM-DD · folder`; the modified-time footer in `NoteRow` never renders.

**Navigators.**
- Types: a Views section (every `.view` in the tree, by `_order` then name) above the type rows (by `_order` only), plus Untyped when `showUntypedNotes` is on. `+` writes `Untitled.view` at the vault root. A view with `_open_in_editor: true` opens in the editor.
- Files: a folder-only tree. Right-click is the only create path (note, canvas, collection, kanban, folder). No New view.
- Calendar (plugin): month grid writing `layout.railDay`, dots from note dates, periodic notes list.

**Types.** A type definition is any note with `_type: Type`; its name is the file stem. Keys read: `_icon`, `_color`, `_title_color` (via Change icon), `_order` (number, default 50), `_sidebar_label` (default `{Name}s`), `_visible`, `_folder`, `_template`, `_list_properties_display`, `_archive_to` (needs Auto Move on), `_hub`. `_sort` and `_view` are parsed but have no effect.

**`.view` and `.collection`.** Same YAML format, same parser, same editor (`CollectionView`, `editor.service.ts:137`). Only `.view` is indexed by Rust (`fs.rs:114-117`) and listed in Types > Views (`type-sidebar.logic.ts:297-315`). `.view` top-level keys: `_sidebar_label`, `_order` (number only), `_sort`, `_open_in_editor` (YAML boolean only), `_list_properties_display`, `_icon` / `_color` / `_title_color`. Per-view keys: `type` (table | calendar | linear-calendar), `name`, `filters`, `sort`, `order`, `limit`, `dateProperty`, `endDateProperty`, `weekStartDay` (default 1), `colorProperty` (linear only). `columnSize`, `groupBy`, `summaries` are parsed and unused. The note-list Sort and Filter popovers write `views[0]` back to disk. A `.collection` is reachable only as a Files row that opens in the editor. Inline ```` ```collection ```` blocks render `views[0]` only, 50 rows, no toolbar.

**QueryJS.** ```` ```queryjs ```` blocks run against the Rust entries snapshot plus the property index. `kb.pages()` accepts `#tag` or `"folder"`. Results are cached per file and block text and cleared vault-wide on any save, watcher event or restore. Settings > QueryJS: auto-run policy (`first-open` default, `always`, `manual`) and Clear cache. QueryJS has no link to the rail.

**Meta-bind.** Inline `INPUT[type(args):prop]` (inlineSelect, number, date, toggle, boolean) and ```` ```meta-bind-button ```` blocks with three actions (`updateMetadata`, `open`, `createNote`). Writes go to the open note's frontmatter only. No link to the rail, views or types.

**Plugin extension.** `rail-registry.store.svelte.ts` (`registerNavigator`, `registerLensProvider`, `registerTodaySection`, `registerFolderCreator`) is code-only and wired unconditionally in `app-lifecycle.service.ts:246-261` (Calendar, My people, Kanban).

**Keys.** Cmd+Shift+B ("Toggle Left Sidebar") toggles the panels, Cmd+1 hides and Cmd+2 shows them (no command id, not in the palette). No palette command picks a rail item or view.

**Workaround for dashboards today:** a markdown note with queryjs, meta-bind and collection blocks marked `_favorite: true` appears under Favorites and Today > Pinned; a `.view` with `_open_in_editor: true` opens a full table or calendar from Types > Views.

**Only in settings.json (no UI):** `layout.railItem`, `railTypesLens`, `railFolder`, `railExpandedFolders`, `railDay`, `railPanelsVisible`, `navigatorSize`, `noteListSize`. Hand-editing is unsafe: the file is read once per vault open, rewritten on any change, unknown keys are dropped, and a JSON error resets everything (F31, F70).

**Missing:** a Rail page (start item, panel visibility, width reset, hide/order items, pins), a way to turn off plugin parts (Calendar navigator, My people, New Kanban Board), a Views or Collections page, a type editor, settings search, and "Configure" links from the navigators (`settingsPanelStore.open(section)` exists but only tests call it).

## 5. Customization design

**Today.** The owner can build custom lists only as `.view` files under Types > Views (label, order, sort, pills, icon, open-in-editor). Dashboards are markdown notes with queryjs, meta-bind and collection blocks, reachable through `_favorite: true`. Two facts make most options cheap: `RailNoteList` already treats any `kind: 'view'` lens as a view (`RailNoteList.svelte:107`), and `resolveLens` already handles `type` and `folder` lenses, so a rail item pointing at one needs no note-list changes and shows no navigator pane, like Inbox.
