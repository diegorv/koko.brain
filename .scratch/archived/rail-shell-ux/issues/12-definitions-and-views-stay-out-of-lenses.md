# 12: Type definitions and `.view` files stay out of note lenses (except Favorites) and out of `kb.pages()`

**What to build:** A type definition (a note with `_type: Type`) and a `.view` file are never listed as notes by the rail. They leave Inbox, Today (both groups, the Pinned group included), Archive, the Day lens, the calendar navigator's dots, a type's row and the Untyped row (lists and counts), the neighbourhood lens's linked groups and the results of a view (type definitions; Issue 01 already drops `.view` files there). Favorites is the one exception: a favorited type definition or `.view` still shows there, so a user can keep one at hand. Inbox, Untyped and a type's row already leave type definitions out, but not `.view` files; the other lenses keep both. This makes every lens follow one rule. The Files navigator, the folder lens and the Types navigator's Views section keep listing every file. The same rule reaches QueryJS (formerly Issue 15, merged here because it reuses the predicate this Issue extends): QueryJS `kb.pages()` (and `dv.pages()`, the same object) returns notes only: `.view` files, type definitions (`_type: Type`) and notes under the system folder (Settings > Templates > System folder, `settingsStore.templates.systemFolder`) are left out of the list, also when it is filtered by `'#tag'` or `'"folder"'`. Archived notes stay in the result, as today; help 13 gains a sentence saying so and showing how to drop them (`kb.pages().where(p => !p.archived)`, where `archived` is the page-root boolean Rust always sets). The page list then matches the rail's rule above apart from archived notes. `kb.page(path)`, `kb.current()` and link resolution keep seeing every indexed file (see Notes).
