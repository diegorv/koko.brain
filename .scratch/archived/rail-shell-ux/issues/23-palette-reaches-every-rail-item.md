# 23: The command palette reaches every rail item and view; a rail click shows hidden panels

**What to build:** The command palette gets one "Go to <item>" command per rail item and one "Open view: <label>" command per `.view` file. Rail items are the built-in ones (Search, Inbox, Today, Favorites, Types, Files, Archive), each navigator a plugin registered (Calendar) and each pinned item (Issue 21); the Neighbourhood item has no rail button and gets no command. Go to does what a click on that rail button does, and a rail click while the panels are hidden (after Cmd+1) now shows them, as Search already does. Open view picks the view in the Types navigator, or opens the `.view` in the editor when it has `_open_in_editor: true`, as its Views row does. Cmd+1 and Cmd+2 become palette commands with ids `layout:hide-rail-panels` ("Hide Rail Panels") and `layout:show-rail-panels` ("Show Rail Panels"), each showing its shortcut. The palette label "Toggle Left Sidebar" becomes "Toggle Rail Panels" (the command id `layout:toggle-left-sidebar` stays), and the theme editor group "Left Sidebar" becomes "Rail and Panels".

## Notes

- **Main-session decisions (owner accepted 2026-11-04):**
  - No keybinding rebinding exists in the app (`GLOBAL_KEYBINDINGS` is a constant, `shortcutFor` only feeds palette labels, `registerGlobalKeybindings` strips `command`), so this Issue adds command ids for Cmd+1 / Cmd+2 and does not build rebinding.
  - Open view uses the Types navigator pick (`railItem: 'types'` + `railTypesLens`), the same layout a Views row click writes plus `railItem` and `railPanelsVisible`, so it works for every `.view`, pinned or not. A pinned view also has its Go to command, which writes the pin key `view:<path>` (Issue 21); both are kept.
  - Open view is built from the tree, not from `viewNavigatorRows`, because Issue 20 drops `_visible: false` views from those rows and promises they stay reachable from the palette.
  - Theme group label "Rail and Panels": its tokens (`fileExplorer*`) also color the rail buttons and border (`Rail.svelte`), not only the panels.
- **Reactivity:** the palette gets its list from `getBuiltInCommands()` in a prop expression (`app/AppOverlays.svelte:15`), which Svelte re-runs when state read during the call changes. Read `railRegistryStore.navigators`, `fsStore.fileTree` and `typeDefinitionsStore.entriesByPath` (and the pins builder's input) while building the list, not inside the actions, so the palette follows registrations, pins and view files. Recent command ids of a removed view are already skipped (`command-palette.logic.ts`, `filterAndRankCommands`).
