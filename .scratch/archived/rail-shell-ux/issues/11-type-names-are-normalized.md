# 11: A type name typed in lowercase is normalized, so it never splits into two rows

**What to build:** New type and Rename type store the type name the way the index groups notes: first letter uppercase, rest as typed (the rule `normalize_type_casing` applies in Rust, mirrored in TS by `normalizeTypeCasing`). Typing `book` creates the type `Book` (definition `Book.md`, label `Books`), so notes created from it land in the same Types row with its icon, folder, template and pills. Type metadata and the definition-path index are keyed by the normalized name, so an existing definition named `book.md` still attaches to the `Book` row, and renaming that type passes `Book` as the old name, which the Rust rename already matches against notes written `_type: book` and `_type: Book`.
