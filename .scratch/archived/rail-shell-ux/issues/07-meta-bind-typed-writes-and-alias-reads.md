# 07: Meta-bind writes typed values, reads alias keys, works in table cells, and has accessible names

**What to build:** Meta-bind controls write typed YAML values: a toggle writes `done: true` / `done: false`, a number input writes `count: 7`, a select option that is a plain number or `true` / `false` is written typed (`humor: 3`), and a button's `updateMetadata` accepts number and boolean `value`s and writes them typed. Date inputs and every other select option still write strings. A control bound to an alias key (`INPUT[toggle():archived]`, `favorite`, `type`, `order`) shows the stored value of the canonical key (`_archived`, ...). As a result, a toggle on `_favorite` or `_archived` writes the YAML boolean the Rust index reads, so the Favorites and Archive lenses follow it like the action bar. It also makes four meta-bind fixes (formerly Issue 25, merged here so one review covers the same widgets). (1) An `INPUT[number():...]`, `INPUT[date():...]`, `INPUT[toggle():...]` or `INPUT[boolean():...]` inside a markdown table cell renders the same control it renders in a paragraph and writes through it; today every input in a cell becomes an inline select, empty when it has no options. (2) An inline select whose stored value is not one of its options shows that value as the selected, disabled first option, so the control does not claim a value the note does not hold, and picking any real option writes it. (3) A button `open` action follows every wikilink a body wikilink follows (`[[Note|alias]]`, `[[Note#heading]]`, a missing note created the same way a body link creates it), and an `open` whose link is empty, unparseable or an unsafe URL shows a toast and stops the action chain instead of reporting success. (4) Every meta-bind select, text input and toggle has an accessible name and a tooltip naming the property it writes (for example "status").
