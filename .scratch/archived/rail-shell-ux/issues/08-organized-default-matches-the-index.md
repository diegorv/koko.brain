# 08: The note action bar treats a missing `_organized` as organized, like the index

**What to build:** A note with no `_organized` key is organized everywhere. Today Rust, the Inbox, the rail and dock badges and collections treat a missing key as organized, while the note action bar and `getLifecycleState` treat it as "inbox": the bar offers "Set note as organized" on a note that is not in the Inbox, and the first Cmd+E writes `true` and changes nothing visible. After this, the bar shows the organized state for such a note and Cmd+E moves it to the Inbox (writes `_organized: false`). The Rust doc comment and the generated binding stop saying "Default `false`".

What changes: `isOrganized` (`features/properties/lifecycle.logic.ts:22-24`) and the organized branch of `getLifecycleState` (`lifecycle.logic.ts:10-11`) read `_organized` the way Rust does: only a boolean `false` is not organized; a missing key or a non-boolean value is organized (`entry.rs:246-249` `.as_bool().unwrap_or(true)`, `collection.logic.ts:101-108` `boolFlag(..., true)`). `_archived: true` still wins in `getLifecycleState`. The bar reads `isOrganized` (`note-action-bar.logic.ts:37`), and Cmd+E, the palette "Toggle Organized" and the bar button all call `toggleActiveNoteOrganized` (`lifecycle.service.ts:63-65`, `!isOrganized(props)`), so `lifecycle.service.ts` needs no edit. The JSDoc that the change makes wrong is updated: `ActionBarState.organized` ("`_organized` is true.", `note-action-bar.logic.ts:15`) and `isOrganized` (`lifecycle.logic.ts:21`).

## Notes

- **Cause (traced):** `src-tauri/src/vault/entry.rs:246-249` reads `_organized` with `.unwrap_or(true)` while its doc comment (`entry.rs:193`) says default `false`. `features/properties/lifecycle.logic.ts:7-24` returns `inbox` unless `_organized === true`. `features/note-action-bar/NoteActionBar.svelte:62,155-158` builds on it.
- **Interaction with Issue 16 (Explicit organization):** that Issue makes new notes write `_organized: false` when the switch is on, so the Inbox stays the place for new notes; this Issue only aligns how a missing key reads.
- **Main-session decision (non-boolean values):** a non-boolean `_organized` (a string such as `"false"` or `yes`, a number, null) reads as organized in TS too, because Rust (`entry.rs:892-894`, "non-boolean _organized falls back to true"), collections (`collection.service.test.ts:222-226`) and the e2e index mock (`e2e/mocks/vault-index.ts:243-244`) already do; the Issue's goal is that every surface matches the index. Only a YAML boolean `false` is "not organized".
- **Rust side is doc-only:** `entry.rs:843-848` (`from_content_lifecycle_flags_defaults`) already asserts that a missing key gives `organized == true`, so no new Rust test is needed; the doc comment change still makes the Gate "both" because `NoteEntry` is `#[ts(export)]`.
- **Interaction with Issue 07 (meta-bind typed writes):** Issue 07 changes how meta-bind writes `_organized`. The rule here (only a boolean `false` is not organized) holds for values written before and after it; a quoted `"false"` written by the old meta-bind reads as organized on both sides, as it already does in Rust.
