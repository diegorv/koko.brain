## Findings

1. minor, `src/routes/composer/+page.svelte:113-115`: the success path runs `text = ''` (which also drops the draft) and does not check that the text is still what was submitted. The wait can now last up to 3 s, much longer than the old 180 ms flash. Text typed after Cmd+Enter and before the result arrives is cleared, and the draft that should protect it is removed. Fix: clear only when the text has not changed (`if (text === body) text = ''`), or keep the part typed after the submit.
2. minor, `src/routes/composer/+page.svelte:122-131`: `resetForShow` resets `saving` and `dismissing` but leaves the pending wait running. Here is the failure: Cmd+Enter, Esc during the wait, a new summon, and then the late `ok: true` arrives. `handleSave` flashes, calls `dismiss()` (which `resetForShow` has re-armed) and so hides the newly summoned composer, then runs `text = ''` and wipes what the user started typing there. This race already existed (the build report and discovery say so), but the round trip widens its window from 180 ms to as much as 3 s. Fix: tag each show with a counter and have `handleSave` drop its result handling when the show changed (or settle `pending` with `null` in `resetForShow`). Otherwise record it as a follow-up.
3. nit, `src/lib/plugins/quick-capture/quick-capture.service.ts:117` / `src/lib/app/deep-link-actions.ts:211-220`: `ok` is false whenever `executeCaptureAction` throws, and that includes throws from `notifyAfterSave` / `addToTree` after `writeTextFile` has already succeeded. In that case the composer says "Could not save" while the note exists, and a retry writes a duplicate. This is rare and no worse than the documented timeout trade-off. Fix if wanted: none needed now. Mention it in the ADR amendment's trade-off line, or have the capture handler report written once `writeTextFile` resolves.
4. nit, `.scratch/audit-2026-11-04/issues/12-composer-keep-text-until-written.md`: the first criterion says the reject test "fails today", but Issue 01 already fixed that path on main. No code change is needed. The build report's "composer 7 failed first" refers to the other new tests.

## Resolution

1. Fixed. `+page.svelte` drops only the written text: `withoutWritten(text, body)` strips the submitted body when the text still starts with it, so what was typed during the wait stays in the text and the draft (an edited text is kept whole). Test: "keeps the text typed while the save waited".
2. Fixed. `resetForShow` bumps a `show` counter; a save whose show changed while it waited (or during the flash) does not flash, hide, report or reset `saving` on the new show, and on `ok: true` it only drops the written text from it. Test: "leaves a new summon open when the earlier save is reported late".
3. Accepted as a documented trade-off: the ADR 0028 amendment now names the post-write throw (`notifyAfterSave`, `addToTree`) that reports a written note as failed, so a retry duplicates it. No code change.
4. No change needed: the criterion text is the Issue's history; the test is present and correct.
