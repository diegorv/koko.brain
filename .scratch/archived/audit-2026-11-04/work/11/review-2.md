## Findings

1. nit - src-tauri/src/db/semantic_repo.rs:283-310. The chunk and `mtime:` collision checks are separate. If the destination has an `mtime:` key but no chunks, the old chunks are moved onto it and stay under the newer mtime. That happens when `update_semantic_file` ran at the new path for a note that is now empty: its empty-chunks branch (semantic.rs:1309-1317) writes only the mtime. `build_semantic_index` then treats the file as unchanged, and semantic search returns stale chunks for it until the next save. This needs an autosave of a note emptied between `diskOp` and the re-key, a very small window, and the fix report names the gap. Fix (optional): decide the collision per file, so a file whose destination has chunks or an mtime key gets its old chunks and mtime dropped together.
