## Summary

Palette commands are a closed, built-in list. getBuiltInCommands() in src/lib/app/commands.ts:93-374 returns a static array of AppCommand {id, label, category, shortcut?, action} (command-palette.types.ts:1-7), passed in at src/lib/app/AppOverlays.svelte:15. There is no register/unregister API for palette commands; the only runtime-varying entries are the "Go to <rail item>" commands (commands.ts:56-66) and "Open view" commands (commands.ts:73-85), both derived from stores. A mod therefore cannot register a palette command today. Keybindings are a module-level constant list, GLOBAL_KEYBINDINGS (src/lib/app/global-keybindings.ts:62-203), registered once per app-layout mount via registerGlobalKeybindings() (global-keybindings.ts:222-229, called from src/routes/(app)/+layout.svelte:42), each becoming a document keydown listener through registerKeybinding (src/lib/utils/keybindings.ts:57-81). Palette shortcut labels come from shortcutFor(command) (global-keybindings.ts:211-216), which throws if no binding names the command. The only runtime registration point is the rail registry (src/lib/features/rail-shell/rail-registry.store.svelte.ts:1-79): registerNavigator, registerLensProvider, registerTodaySection, registerFolderCreator, each returning an unregister function, with plugins using it (calendar-rail.service.ts:26, kanban.service.ts:28). A registered navigator automatically gains a "Go to" palette command (commands.ts:60).

- Mods cannot add palette commands or keybindings at runtime: both lists are closed in code. Only the rail registry is runtime-extensible, and it requires a navigator with a component and a lens (rail-shell.types.ts:175-186), so a button that only opens a modal has no existing registry kind (INFERRED).
- shortcutFor() throws for an unknown command id (global-keybindings.ts:213), so a mod command with a shortcut label needs a keybinding registered in the same list first. Keybindings have no conflict detection and no user override found (grep for keybindingOverride/customKeybind/keymap in src/lib returned nothing).
- The slash-to-search listener (global-keybindings.ts:40-50) is a separate document listener outside GLOBAL_KEYBINDINGS, so a single shortcut registry does not exist today.
- The palette store holds only open state and recent command ids in localStorage (command-palette.store.svelte.ts:4-57). Recents are keyed by command id, so mod command ids would persist there even after the mod is removed. resetCommandPalette (command-palette.service.ts:4-6) runs at teardown (app-lifecycle.service.ts:644).
- Command failures are caught in the palette and surfaced as a toast (CommandPalette.svelte:24-36), so a mod action that throws is contained there, but the palette's catch is the only error boundary.
