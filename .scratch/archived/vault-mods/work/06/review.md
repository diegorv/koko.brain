## Findings

1. **major** `src/lib/plugins/mods/ModActionPicker.svelte:56` (and the Stop/Close buttons at `:96`-`:99`): the run view renders inside `Command.Dialog`'s bits-ui `Command` root, whose root `keydown` handler calls `e.preventDefault()` on every non-composing Enter (`node_modules/bits-ui/dist/bits/command/command.svelte.js:956-966`). So Enter on a focused Stop or Close button never clicks it; only the mouse and Space work. A probe test (deleted afterwards) mounting the real picker, starting Slow job and dispatching a bubbling, cancelable Enter `keydown` on `[data-mod-run-stop]` and `[data-mod-run-close]` got `defaultPrevented === true` for both. The same probe found focus on `BODY`, outside the dialog, right after the switch to the run view (the focused `Command.Input` is removed). Fix: stop Enter (and the other Command keys) from reaching the Command root in the run view, e.g. `onkeydown={(e) => e.stopPropagation()}` on the run view container, or render the run view outside the `Command` root (a plain `Dialog.Content`). Move focus to Stop (or Close once the run has ended) when the view appears. Add a component test that Enter on Stop cancels the run.
2. **minor** `src/lib/plugins/mods/ModActionPicker.svelte:31`: every pick, including instant actions, now ends in a modal run view that stays open until the user closes it. With "Say hello" (toast only) or "New idea note" (`ctx.workspace.openNote`), the note opened behind the dialog cannot be edited until Close is pressed. That is an Issue 03/05 behavior change. It follows the Issue's wording and is recorded as a default in `work/06/discovery.md`, but nothing shows the owner chose it. Fix: get an owner decision. Two options: close the view on `done` when the run logged nothing and set no progress, or keep the current behavior and say so in the Issue 07 docs.
3. **nit** `src/lib/plugins/mods/mods-runs.store.svelte.ts:61`, `:65`: the `runs` and `liveRuns` getters have no caller in app code (only tests; the app uses `runFor`, `isBusy`, `isReloadPending`, `reset`). Drop `liveRuns` or keep it for a known next consumer. `runs` is still useful for tests and `reset` coverage.
4. **nit** `src/lib/plugins/mods/ModActionPicker.svelte:79`: the log box (`max-h-64 overflow-y-auto`) does not follow new lines. On a long run the newest lines fall below the fold. Fix: scroll it to the bottom when `run.lines` grows, unless the user scrolled up.
