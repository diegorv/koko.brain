## Findings

1. minor, `src/lib/features/todoist-sync/fields.logic.ts:119`. When the line was inserted with content that failed the round-trip check, `local_base.description` holds the raw Todoist content (`pulledTask` stores it, e.g. `Fix #42`), while the parsed `fields.description` is `Fix`. On the next Todoist edit (`Fix issue 42`), the check always sees "both sides changed". It logs a false `conflict` with "Brain value: \"Fix\"" and replaces only the word span, so the line becomes `- [ ] Fix issue 42 #42 🆔 td-a`: the old `#42` from the content stays as a tag Todoist does not have. My probe reproduced both effects. Fix: when `remoteBase.contentProblem` is set, skip the both-sides conflict log. Also decide whether such a line should get a `description-conflict` (leave the line, log it) rather than a partial replace. Add a test either way.
2. nit, `src/lib/features/todoist-sync/fields.logic.ts:63,72` together with `sync-now.service.ts:187`. Over the cap in auto mode, the skipped close and reopen commands are removed from `completion.commands` before `planFields` runs. Those links then do get field sync this cycle, which contradicts the default "a link with a close or reopen planned this cycle gets no field sync". I found no wrong write: the link keeps its old status base, so the close is planned again. Either note it in the `planFields` JSDoc or pass the skipped anchors in.
3. nit, `src/lib/features/todoist-sync/fields.logic.ts:134-143`. When Todoist removes the due of a recurring task, the `📅` goes but the `🔁 <rule>` text stays, so the line shows a recurrence Todoist no longer has. This is a documented default (build report and discovery). A one-line note in the `planFields` JSDoc would keep Issue 09 from reading it as a local change.
4. nit, `src/lib/features/todoist-sync/pull.logic.ts:460-462`. The `anchor-mismatch` guard in `planPull` can no longer be reached: content with a signifier is skipped first, recurrence text with a signifier is dropped, labels are ASCII tag names and the due is checked by regex. No test covers it. Keep it as a last check or remove it; no action needed for this Issue.
