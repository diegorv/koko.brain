## Findings

1. **blocker** `src/lib/features/todoist-sync/fields.logic.ts:316` and `:330-332`. Brain text that fails the round-trip check is treated as ticket 06's raw-inserted content, so the line stops syncing in both directions, mostly with no log.
   - How it happens: brain text with a non-tag `#` (`Fix C# bug`, `Review [[Spec#Goals]]`, a URL with `#fragment`) is logged once as `content-not-pushed`, and `local.description` takes that text (`:332`). From then on, `contentRoundTripProblem(localBase.description) !== null` at `:316` treats the line as flagged on every cycle.
   - Probe (temporary test on `planFields`, deleted afterwards). Cycle 1: brain text becomes `Review [[Spec#Goals]]` → 0 updates, log `content-not-pushed`. Cycle 2: the brain changes the priority → 0 updates and an empty log, so the edit never reaches Todoist and nothing says why. Cycle 3: Todoist changes the content to `Review spec` → no line change, and the `:235-242` branch logs "The line was written from Todoist text that does not survive a parse back" on every such edit. That message is wrong, and Todoist→brain text sync for this line no longer works, which is a regression of Issue 08's behaviour (on main, `local_base` never takes brain text, so the Todoist text is written with a conflict log).
   - Fix: keep "brain text not pushed" apart from "line inserted from raw Todoist content". For example, do not move `local.description` for a round-trip failure; dedupe the log another way, such as a marker in `local_base`. Or flag raw inserts explicitly, not by re-checking `local_base.description`. The other fields of such a line must still push. Add a test: after the `C#` text, a priority edit pushes, and a Todoist content edit is handled as on main.
2. **minor** `src/lib/features/todoist-sync/fields.logic.ts:245`. With the conflict log moved above the `replaced` check, the mid-sentence case now logs `conflict` ("Todoist wins") together with `description-conflict` ("the Todoist text was not written"). The two messages contradict each other, because the line keeps the brain text. Fix: in that branch, log one entry that names both values, or say in the `conflict` text that neither side was written.
3. **nit** `src/lib/features/todoist-sync/fields.logic.ts:327`. The limit counts code points (`[...text].length`), while discovery.md says UTF-16 units. Make the two agree, and note which unit Todoist counts (or that it is unverified).
4. **nit** `src/lib/features/todoist-sync/fields.logic.ts:369`. Line tags that differ only by case (`#next #Next`), and are not on the task yet, are both sent as labels. Dedupe `minus(lineTags, remote.labels)` case-insensitively.
