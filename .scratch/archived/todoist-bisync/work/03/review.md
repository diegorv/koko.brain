## Findings

1. **major** `src-tauri/src/vault/task_lines.rs:155` (and the removal loop at :170): two edits whose different anchors sit on the same line both locate that line, and nothing rejects the collision. Two removals (`td-1` and `td-2`, both expecting `- [ ] a 🆔 td-1 b 🆔 td-2`) push the same index twice, so `lines.remove(at)` runs twice and also deletes the next, unrelated line. A probe on `"<that line>\n- [ ] keep me 🆔 td-3\n"` returned `Applied("")`: the `td-3` line was silently lost. Two replacements on that line keep only the last one (`Applied("N2 🆔 td-2\n")`), and a replace plus a remove drops the replacement. That breaks the guarded writer's main promise of never touching a line it was not asked to change. Today the engine reads only the first `🆔` per line (`anchor.logic.ts::readAnchor`), so a sync caller is unlikely to send such a batch. But this is a general IPC that 122 will reuse, and `task_lines.rs` already treats lines carrying several `🆔` values as real (`apply_task_line_edits` doc). Fix: in the locate loop, record each located index in a `HashSet<usize>` and return `Stale(AnchorDuplicated, anchor)` (or an `Err`, matching "an anchor named by two edits") when an index is located twice. Add a Rust test with the two-removals case that asserts nothing is written.
2. **minor** `src-tauri/src/vault/task_lines.rs:184-190`: the CRLF default is only half applied. Replacements and removals on a CRLF note go stale (the `\r` stays on each split line), but inserts still apply: `HEADING_RE` matches `## Work\r` (the text is trimmed) and `end` inserts work, so lines go in without `\r` and the note ends up with mixed line endings. Fix: refuse any non-empty batch on content that contains `\r\n` (for example `Stale` with a dedicated reason or `LineDiffers`), or give inserted lines the note's line ending. Add a test.
3. **minor** `src-tauri/src/commands/vault.rs:928`, `src/lib/features/todoist-sync/closed-note-writer.service.ts:45`: an empty batch, or inserts whose `lines` are all empty, against a missing note comes back `missing`, so the wrapper creates an empty note on disk and then reports `unchanged`. Fix: in Rust, return `unchanged` (content `None`) when the applied result equals `""` for a missing note, or have the wrapper skip creation when the batch has no lines. Add a test for the empty batch.
4. **nit** `docs/agents/indexing-watcher-rules.md:5`: rule 2 lists the commands after which Rust emits `vault-index-updated` (`toggle_task_status` among them) and does not name `write_task_lines`, although rule 6 and the `task` source comment were updated. Add it to the list.
5. **nit** `src/tests/lib/features/todoist-sync/closed-note-writer.service.test.ts:22`: the criterion says "mocking only `invoke` and plugin-fs", and the test also mocks `#lib/utils/debug.js`. That mock is a side-effect logger (Sentry, log file), which `docs/TESTING.md` allows, and it is what lets the test assert that errors are logged. No change needed beyond noting the deviation.
