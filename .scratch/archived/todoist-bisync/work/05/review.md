## Findings

1. minor — `src-tauri/tests/todoist_state_test.rs:210-236`: the mismatch test's "other" vault has no `.kokobrain/kokobrain.db`, so the refusal comes from the failed `canonicalize` (`db/mod.rs:169`), not from the `open != expected` comparison (`db/mod.rs:170`). The test would still pass with the comparison removed. That comparison is the real vault-switch case (rule 9), where both vaults have a database. Fix: in the test, open and close the other vault first (`db::open_database(other.path())`, `db::close_database()`), then open the main one, so `other/.kokobrain/kokobrain.db` exists. My probe of exactly this case passes, so the code is correct today.
2. minor — `src/lib/core/settings/settings.logic.ts:164-168`: `clampSyncIntervalMinutes(null)` returns 1, not the default 5, because `Math.round(null)` is 0. A `settings.json` with `"syncIntervalMinutes": null` loads as 1 minute. The doc comment says only "a non-finite value becomes 5". Fix: return 5 when `typeof minutes !== 'number'` (or before rounding), and add a `null` case to `settings.logic.test.ts`.
3. nit — `src/lib/features/todoist-sync/TodoistSection.svelte:182-189`: `syncFolder` is stored untrimmed and an empty field is kept as `''` in the store until reload (`normalizeTodoist` runs on load and on save, not on update), so the store and `settings.json` can differ. Nothing reads `syncFolder` yet. The engine ticket that writes into the folder should read the normalized value and reject `..` and absolute paths (rule 12).
4. nit — `src/tests/fixtures/todoist-sync.fake.ts:233-236`: a full sync (`*`) returns checked items as well. The real `/sync` full sync returns only uncompleted items. The counts filter `checked`, so the check is unaffected. Later engine tickets that extend the fake should drop checked items from full syncs so adoption tests match the API.
