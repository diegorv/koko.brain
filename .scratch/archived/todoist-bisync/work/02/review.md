## Findings

1. **minor** `src/lib/features/todoist-sync/task-line.logic.ts:186-188`. `standaloneTagRe` is narrower than what the parser reads as a tag. Rust `TASK_TAG_RE` (`#([A-Za-z0-9_][A-Za-z0-9_-]*)`, parsing.rs:1577) has no left boundary, so the parser reads `shop` from `(#shop)`, `milk#shop`, `[[Note#shop]]` and `https://x.io/#shop`. Probed: `removeTag('- [ ] Buy milk (#shop)', 'shop')` returns the line unchanged, so after a remote label removal `parse(line)` still has the tag, and rule 3 then either never converges or reads it as a local add and pushes the label back. `addTag` on such a line adds a second `#shop`. Fix: keep links and wikilinks untouched as the Issue asks, but match the parser's boundary outside link tokens (the `tokenize` link spans already exist), or document in the JSDoc that removal can leave a tag the parser still reads so later tickets compare the parsed result. Add tests for `(#shop)` and `word#shop`.
2. **minor** `src/lib/features/todoist-sync/task-line.logic.ts:124-126`. `insertToken` adds no space before the token when the text before `🆔` does not end in whitespace. Probed: `addTag('- [ ] Buy milk🆔 td-x', 'shop')` gives `- [ ] Buy milk#shop 🆔 td-x`, and a second `addTag` gives `milk#shop #shop`, because the result is not a standalone tag (finding 1). Fix: add a space when the char before `idIndex` is not whitespace, and add a test.
3. **minor** `src/lib/features/todoist-sync/task-line.logic.ts:35`. In JS, `.` does not match `\r`; in the Rust `regex` crate it does. A CRLF line split on `\n` (`'- [ ] Buy milk\r'`) is a task to `parse_task_line` but makes every patch here return null (probed for `setTaskStatus` and `setDueDate`), so the sync would skip it without logging anything. Fix: use `([^\n]*)` for the text group (the Rust semantics), or remove a trailing `\r` and add it back. Add a test.
4. **nit** `src/lib/features/todoist-sync/task-line.logic.ts:256-260`. A tag or link before the first word is treated as mid-sentence (the literal reading of rule 4, recorded in discovery.md). Replacing first..last word would not lose it, and design Scope (b) syncs lines tagged `#todoist`, which users often write first (`- [ ] #todoist Call bob`): such lines never accept a remote description edit. Nothing to change now; it is worth confirming with the owner before ticket 08.
5. **nit** `src/lib/features/todoist-sync/task-line.logic.ts:273`. `contentRoundTripProblem('')` returns null, but an empty description makes `parse_task_line` drop the task (parsing.rs: empty or whitespace-only text returns `None`). Todoist content is rarely empty, so a one-line rule or an `'empty'` problem would close it.
6. **nit** `src/lib/features/todoist-sync/anchor.logic.ts:33-47`. For `🆔 td-` (bare prefix), `readAnchor` returns null and `hasForeignId` returns false, so the line looks like an ordinary unanchored line. A later create path would then append a second `🆔` while the parser keeps the first (`td-`). Fix: count a bare `td-` value as foreign.
