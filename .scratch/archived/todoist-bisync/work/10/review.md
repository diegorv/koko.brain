## Findings

1. minor — `src/lib/features/todoist-sync/create.logic.ts:337-344` (`addAnchor`) and `:218` (`content`). A task line that ends with a block id (` ^abc123`, which `copy-block-link` appends at the end of the line) gets its anchor after the block id: `- [ ] Call Bob ^abc123 🆔 td-xxxxxxxx`. Block ids are recognised only at the end of a line (`live-preview/parsers/block-reference.ts:2` `/ \^([\w-]+)$/`, `embed-resolver.logic.ts:46`). After the write, the live preview stops hiding the marker, an embed of the block shows `^abc123 🆔 td-...`, and copy-block-link no longer sees the existing id. The Rust parser does not strip `^id` from `description` either, so the Todoist task is created as `Call Bob ^abc123`. Fix: in `addAnchor`, insert the token before a trailing ` ^[\w-]+`, and leave a trailing block id out of the `item_add` content (or skip such a line as `create-skipped`). Add a test for each.
2. minor — `src/lib/features/todoist-sync/create.logic.ts:155, 162` and `sync-now.service.ts:489`. Skipped lines (user `🆔`, over 500 chars, `#` or a signifier in the content, empty text) are logged on every cycle, and so is a create that went stale. With automatic cycles (5-minute default plus focus and save triggers), a few such lines fill the 1000-row `todoist_sync_log` within a day. That pushes out the conflict losers, which the design keeps only in that log. The pull's own `content-skipped` and `unmatched` entries already repeat each cycle, so this adds to an existing pattern. Fix: log a skipped line only on a manual cycle, or only when its text is not already among the latest entries of the same kind. Alternatively, record this as a follow-up Issue.
3. nit — `src/lib/features/todoist-sync/sync-now.service.ts:328-354`. If the cycle stops after `writeBatches` but before `todoist_commit_state` (a crash, or `assertVault` throwing at `:350` after a vault switch during the last note write), the line keeps an anchor with no link row. Normal mode then never creates it and logs nothing about it (the `unmatched` log is rebuild-only, `pull.logic.ts:512`). The build report and discovery list this risk. A follow-up could log brain-born-format anchors (`td-` + 8 base36) that have neither a link nor an item, so the user learns to remove the `🆔`.
4. nit — `src/lib/features/todoist-sync/detach.logic.ts:79` (unchanged, now reached by pending adds). A pending add whose line is deleted before Todoist ever received it is never resent, paired, detached or logged. Its link row stays active forever and counts in the `belowLineBrake` denominator. This is harmless in practice. It could be closed by letting `planDetach` count misses for `todoistId === null` pending adds too.
