## Findings

1. **major** `src/lib/features/todoist-sync/sync-now.service.ts:182` - The line brake has no way past it, so the sync can stall for good. Every link stays active forever, including links of tasks completed long ago. An owner who deletes a batch of old `[x]` lines, or a project note they no longer want, so that fewer than half of the attached links still have a line, trips the brake on every cycle, manual "Sync now" included. The 3-miss detach that would clear those links never runs, because the brake stops the cycle first. The only ways out are restoring the lines or losing the database. The build report names only the 1-2 link case. The behavior matches design rule 9 to the letter, so it is not a blocker, but the recovery path is an owner decision. Fix: keep the brake as built in this Issue and open a follow-up `.scratch` Issue that asks the owner which recovery to use. One option is a manual "Sync now" over the brake that pauses and asks, naming the missing count, the same way the caps do; a yes runs the cycle and counts the misses. Another is a minimum link count before the brake applies.
2. **minor** `src/lib/features/todoist-sync/detach.logic.ts:61` - "Moved out of the tree" is decided only by `!treeIds.has(item.projectId)`, so an item whose project is unknown or not live is detached for good, just like one moved to a real outside project. Two ways this happens: (a) the incremental items pull runs after the full projects pull (`sync-now.service.ts:165-173`), so a task moved into a subproject created between the two requests carries a project id the tree has never seen; (b) `treeProjectIds` leaves archived subprojects out (sync-scope.logic.ts:54-64), so if Todoist reports an item of an archived project, it is detached, which contradicts Issue 11's "`is_archived`: links kept; unarchive resumes" (API behavior for archived items is unverified, `live-check.md` does not cover it). Fix: detach as moved out only when `item.projectId` names a known, live project of `projects` that is outside the tree. Leave items whose project is unknown or archived alone, with a test for each case. Alternatively, record this as a constraint for Issue 11.
3. **minor** `.scratch/todoist-bisync/issues/10-brain-tasks-created-in-todoist.md` - "A detached anchor is never re-created in Todoist" is only checked indirectly today: there is no create path to exercise (`commandRequests()` is empty because nothing sends `item_add` yet). Issue 10's create planner must skip any line whose anchor has a link row, detached ones included (`isDetached` / owned anchors), or a vault-side detached line that comes back is sent as a new task. Fix: add a criterion to Issue 10 (or a note in the ledger hand-off) saying a line whose anchor has a detached link is never created, with a test.
4. **nit** `src/lib/features/todoist-sync/sync-scheduler.logic.ts:69` - The diff breaks the spacing of an unrelated line: `const pad2 =(n: number)` (was `const pad2 = (n: number)`). Fix: restore the space.
