## Findings

1. minor — `src/lib/features/todoist-sync/pull.logic.ts:307`: a rebuild that pairs nothing leaves the link table empty, so every later run is a rebuild again. New Todoist tasks then never come in, and the toast reports success each time ("rebuilt 0 links from the vault; nothing was created"). Probe: on a fresh table, one line `- [ ] Old 🆔 td-gone` with no open item behind it (for example a task completed in Todoist, which a full sync leaves out) gave this result on two runs in a row, and nothing was created. Fix: leave rebuild mode once a rebuild has run (for example a `todoist_kv` flag committed with the token), or have the toast say that unmatched anchored lines block creation. It needs an owner call, since rule 1 does not say how rebuild mode ends.
2. minor — `src/lib/features/todoist-sync/sync-now.service.ts:132-139`: the `sync_token` is committed even when an insert went `stale`, whose items then have no link. Today every run is a full sync, so the next run retries them. Once a later ticket pulls incrementally from this token, those items are not sent again, and the comment at line 123 ("the next run pairs or retries these lines") stops being true. Fix: skip the token when any insert went stale, or record the limit in the incremental-pull ticket.
3. minor — `src/lib/features/todoist-sync/pull.logic.ts:338-340`: a paired link stores `local_base: null`. Rule 3 defines `local_base` as the values parsed from the line "as last written/seen", and Issues 07 and 09 compute local change as parse(line) vs `local_base`, which is undefined for null. Recorded in discovery.md, and acceptable for a pull-only ticket because no TS line parser exists yet. Fix: say in Issue 07 or 09 what a null `local_base` means (for example: fill it from the line on the first cycle, with no push).
4. minor — `src/tests/lib/features/todoist-sync/sync-now.service.test.ts:290-309`: the vault-switch test switches during the fetch, so it covers only the check before the first IPC. Nothing tests a switch between writes (the rechecks at `sync-now.service.ts:112, 116, 131`). My probe (switch after the first `create_note`) passed, so the code is correct today. Fix: add that case.
5. minor (plausible, not probed against Rust) — `src/lib/features/todoist-sync/pull.logic.ts:161-167`: `normalizeSyncFolder` keeps `.` and empty segments (`./Todoist`, `Todoist//Sub`). The notes are then created at `/vault/./Todoist/Work.md`, and `create_note` indexes them under that string, while the watcher reports the canonical path. That can leave two index entries with the same `todoist_project`, which `projectTargets` treats as a duplicate project note and stops writing to. Fix: drop `.` and empty segments, or refuse them.
6. nit — `src/lib/features/todoist-sync/pull.logic.ts:163`: the criterion says "surrounding slashes removed", but a leading `/` is refused as absolute (`/Todoist/` gets an error toast). This is safer: stripping would turn `/Users/me/vault/Todoist` into nested folders inside the vault. It is recorded in discovery.md. Mentioned so the owner can confirm.
7. nit — `src/lib/features/todoist-sync/pull.logic.ts:306`: items are sorted by `childOrder` across the whole project, but `child_order` counts among siblings under the same parent. A subtask with `child_order: 0` was written above its parent and every other task (probe). Fix: order by parent, then `childOrder`, or leave it to ticket 12.
8. nit — `src/lib/features/todoist-sync/todoist-sync.store.svelte.ts:1`: `import type { PullCounts } from './pull.logic'` has no `.js` extension, unlike every other import in the folder.
9. nit — `src/lib/features/todoist-sync/pull.logic.ts:24-37, 53-77`: most fields of `PullItem`, `LocalBase` and `RemoteBase` have no JSDoc, which CLAUDE.md asks for on interface fields.

No scope creep: `createNoteFile` (an existing helper, exported with a `content` argument), `codeFence`/`taskLineText` exports and `mapPriorityFromTodoist` all serve this Issue. `layer-baseline.json`, `BASELINE_SIZE` and the composition roots are unchanged. Rule 9's caps and the 50% abort are not in this Issue's criteria.
