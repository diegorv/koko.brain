## Findings

1. major — `src/lib/plugins/queryjs/contract/kb-api.v1.ts:102-104`: the new `KBPageV1` doc says "Frontmatter values are the same whether the record came from the Rust parser (vault scan) or the TS parser (edit fast path)". That is false outside the fixture. I fed the same frontmatter to `buildNoteRecord` (TS, `yaml`) and to `NoteEntry::from_content` + `project_note_record` (Rust, `yaml-rust2`) through throwaway probes (since removed). Results: `oct: 0o17` gives TS `15` and Rust `"0o17"`; `inf: .inf` gives TS `Infinity` and Rust `".inf"`; a nested map `nested: {a: 1, b: [x]}` is absent on the TS record and `null` on the Rust one. So `page.oct`, `page.inf` and `page.nested` change after a rebuild, which is exactly the divergence the Issue's Notes describe (sidebar-redesign 26). The criterion offers "record the known differences in the contract doc", and the contract now claims there are none. Fix: limit the sentence to what the fixture pins (block scalars, plain multi-line scalars, quoted commas in flow and block arrays, `_type`), and list the known differences (YAML 1.2 octal and `.inf`/`.nan`, nested maps: TS drops them, Rust gives `null`) as current contract behaviour until sidebar-redesign 26. Optionally pin one difference in the fixture with a `record` value.
2. minor — `src/tests/lib/plugins/queryjs/kbapi-firewall.test.ts:325-329`: the parity test selects its fixture case by exact name inside `it.each(...)`. If that case is renamed or removed, `it.each([])` registers no test and the suite stays green. I checked this: a vitest file with an empty `it.each` reports only its other tests as passed. Fix: look the case up with `find`, and add an `expect(case).toBeDefined()` in a plain `it`. Alternatively, run every case that has a `record`.
3. minor — `src/tests/lib/plugins/queryjs/kbapi-firewall.test.ts:311-317`: the page-root check sees only keys that some fixture case with an `injected` map triggers. The Rust golden test also filters out a key whose injected value equals the frontmatter value (`vault_file_ops_test.rs:406`). So a new conditional injection that no `injected` case exercises passes both suites. The new case has only `record`, not `injected`, so it does not widen coverage. Fix: none needed now, since every current injection fires in case 1. Optionally mention in the test's doc comment that a new conditional injection also needs a fixture case that fires it.
4. nit — `src/tests/lib/plugins/queryjs/kbapi-firewall.test.ts:203-225`: `fullRecord()` is documented as "The record `project_note_record` makes from `fullEntry`", but `project_note_record` keeps the frontmatter `type: 'person'` key (it clones `entry.frontmatter`) and `fullRecord()` has no `type`. The frozen root key set is therefore not the real Rust one. Fix: add `['type', 'person']` to the map and `'type'` to the expected key list, or change the comment.
5. nit — `src/tests/lib/plugins/queryjs/kbapi-firewall.test.ts:151-157`: the signature check looks for DTO import names written in the signature, so a local alias in `kb-api.ts` (`type Raw = NoteEntryV2`) used in a public signature gets past it. Fix: optional. Also collect the local type aliases and interfaces whose text names a DTO, and add them to `dtoNames`.
