## Findings

1. **major** — help/examples/queryjs-globals.d.ts:12-13 and src/lib/plugins/queryjs/contract/kb-api.v1.ts:261. The script globals type `kb`/`dv` as `KBApiV1`, whose `pages()` returns a plain `DataArrayV1<KBPageV1>`. That makes the Proxy shorthand a type error in editor tooling, and it is the first idiom the docs teach (`kb.pages('#project').file.name`, 13-queryjs.md:396). The Issue asks for a script-facing `DataArrayV1<T> & { [k: string]: … }` type for exactly this case, but `ScriptDataArrayV1` is used nowhere (grep finds only its declaration), so it is dead code. Even if it were used, it covers one level only: `where(...)` returns a plain `DataArrayV1` again. I checked this with tsc on a probe that references the globals file:
   - `dv.pages('#x').file.link` gives `TS2339: Property 'file' does not exist on type 'DataArrayV1<KBPageV1>'`.
   - `kb.pages().where(...).status` gives `TS2551`.
   - On a `ScriptDataArrayV1<KBPageV1>`, `x.where(() => true).file` gives `TS2339`.
   Fix: add a script-facing view of the API to the contract, for example a `KBScriptApiV1`. It would map the DataArray-returning members of `KBApiV1` (pages, pagePaths, array, getDaysInRange) and DataArrayV1's chain methods to a recursive `ScriptDataArrayV1`, and the globals file would declare `kb`/`dv` with that type. Add a tsc probe that pins `kb.pages().file.link` and `kb.pages().where(...).file`. If that is out of scope, the other fix is to delete `ScriptDataArrayV1` and say in 13-queryjs.md that the globals do not type the property shorthand.
2. **minor** — help/examples/queryjs-globals.d.ts:12-13 and help/documentation/13-queryjs.md:1131. The globals file reaches the contract through a repo-relative `import('../../src/lib/...')`. `help/examples` is also used as vault content (`/vault/Resources/help/examples/...` in src/tests/help/type-definitions-views.test.ts:51). From a vault copy that path resolves to nothing, so `kb` silently becomes untyped. The docs tell script authors to reference the file with no caveat. Fix: say that it works only from a checkout of the repository, or make the file self-contained.
3. **nit** — help/documentation/13-queryjs.md:150 and contract/kb-api.v1.ts:28. These say `display` is the basename, or the alias for outlinks. An outlink without an alias actually gets the raw wikilink target as written (`queryjs.logic.ts:137`, `display: wl.alias ?? wl.target`), which can differ in case or path from the basename. Fix the wording to "the wikilink alias or target text, for outlinks".
4. **nit** — src/tests/lib/plugins/queryjs/kb-api-contract.test.ts:224-230. `shape()` records `typeof`, so `tags`, `inlinks`, `outlinks`, `tasks` and `link` all read as `'object'`. A change from an array to a non-array object (or the reverse) on any of them would pass. Fix: map arrays to `'array'` (`Array.isArray(v) ? 'array' : typeof v`).
