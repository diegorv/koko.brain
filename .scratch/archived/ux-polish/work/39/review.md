## Findings

1. **blocker**, src/app.css:303-365 (41 declarations inside the `.dark` block, lines 193-381). Removing `dark` from `<html>` on a light theme also removes 41 theme-derived custom properties. They are declared only inside `.dark`, are not in either `:root` block, and are not emitted by `themeColorsToCssVars`: all `--lp-codeblock-{border,header-bg,lang,copy,copy-hover,text}`, every `--lp-syntax-*` token color, and every `--lp-meta-bind-{select,btn,error}-*`. Their values are `var()`/`color-mix()` over theme variables (for example `--lp-syntax-keyword: color-mix(in oklab, var(--callout-important) 45%, var(--editor-fg))`). On main, `html.dark` is always present, so they resolved against the light theme's inline variables. On this branch they are undefined under Lavender Haze, Sakura or any other light theme.
   - Result: code-file syntax highlighting has no colors (`highlight-styles.ts:62-82` uses bare `var(--lp-syntax-*)`). Meta-bind selects, inputs and buttons lose their background, text and border colors (`live-preview/styles.ts:711-763`, `:667-683`). The code block header, border and language label also lose their colors (`styles.ts:801-814`). The owner uses meta-bind daily.
   - Reproduced: with a temporary E2E probe on this branch, Lavender Haze active, `getComputedStyle(html)` returned `--lp-syntax-keyword=[] --lp-meta-bind-select-bg=[] --lp-codeblock-header-bg=[]` while `--editor-bg=[#F3F0F8]`.
   - Fix: move these mode-independent declarations out of `.dark` into a block that applies to every theme. The `:root` event-calendar block at app.css:390 already exists for exactly this reason, as its comment says.
   - Test: add a regression test written failing first. One option is a css-contract case asserting that every custom property declared in `.dark` is either emitted by `themeColorsToCssVars` or also declared outside `.dark`. Another is a check in the Lavender case of theme-mode.spec.ts that `--lp-syntax-keyword` and `--lp-meta-bind-select-bg` are non-empty.
2. **minor**, e2e/specs/theme-mode.spec.ts:26-29. The light-theme E2E checks only the class and `color-scheme`. It would have caught finding 1 if it had read one `dark:`-independent derived variable or one rendered color. Covered by the test suggested in finding 1.
3. **nit**, src/lib/core/settings/applied-theme.store.svelte.ts:1-18. The store has no test file of its own (CLAUDE.md rule 11). Its getter and setter are covered only through theme.service.test.ts (`defaults to dark` and the mode cases). That is acceptable for a two-member store. Optionally add a small store test, or note the coverage in the commit message.
