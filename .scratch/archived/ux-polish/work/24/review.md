2. nit, `src/tests/lib/core/settings/settings-controls.test.ts:18`: `/<input\b([^>]*)>/` stops at the first `>`, including the one in an `=>` arrow handler. A `type="color"` or `type="file"` written after an arrow-function attribute would therefore read as `text` and be flagged. The scan errs strict (a false failure, never a false pass), and no such site exists today. Fix (optional): read `type` from a capture that skips `{...}` expressions, or leave as is.
3. nit, `src/tests/lib/core/settings/SettingItem.test.ts:38-46`: the inline test does not assert the `has-[[data-slot=input]:not([type=number])]:w-1/2` class on the control column. Only the E2E "setting rows" case covers it (Templates folder at 0.471). Fix (optional): assert that the class is present, so a reader of the unit test sees the rule.
