# Editor data-safety audit (2026-11-02)

Scope: the markdown editor and every path that writes note bytes (editor save, tabs, watcher,
frontmatter writers, live-preview widgets that dispatch changes, deep links, trash, file history,
kanban, canvas, Rust write paths).

Method:
1. 22 haiku mappers (one area each) + 8 opus cross-cutting hunters: 194 raw candidates.
2. Opus adversarial verification per cluster: 72 duplicates, 6 refuted, 116 kept.
3. Opus coverage critic + gap hunter: 8 more candidates (G1-G8).
4. Deep dive: every critical/high/medium + gap finding was re-judged blind by a second opus,
   which wrote a vitest repro asserting the CORRECT behavior. 95 repro tests, 83 fail, all on
   an `AssertionError` (none on import/mock errors). 75 low findings re-checked by haiku.
5. Main session read the code of the P0/P1 items and checked F35, F47, F78, F79 by hand.

Repro tests live in the throwaway worktree `.claude/worktrees/editor-audit-repro`
(`src/tests/audit-repro/<group>/`, not committed). Run them with
`cd .claude/worktrees/editor-audit-repro && ./node_modules/.bin/vitest run src/tests/audit-repro/`.
They are the red tests for the fixes below.

Priority: P0 loses note content. P1 silent corruption of note bytes, or editor crash/freeze.
P2 wrong behavior without loss. P3 polish. Likelihood is how often normal use hits it.

Proof: REPRO = a failing vitest test on the real code. TRACE = no unit test possible
(Rust / OS / timing); full path traced, library source included, not refuted.

## Refuted (false positives removed)

- **F5** (was rated critical): "canvas unmount flush writes canvas JSON into the newly active note". The chain exists, but Svelte 5.57.2 returns pre-flush values to teardown code, so the flush hits the canvas tab itself. Safe today only through undocumented Svelte teardown semantics; the fix for F21 (key the canvas branch by path, path-keyed persist) removes the dependency. Side bug kept: Cmd+W within 300 ms of a canvas edit closes without a prompt.
- First-round verifiers refuted F10, F68, F88, F91, F102, F112.
- Low sweep refuted F52 (scan ordering is serialized) and F147 (documented template behavior).

## Decision to revisit: ADR-0029 drops

ADR-0029 (Drops, Consequences, amendments 2026-10-28 and 2026-11-01) accepts that panel and
meta-bind writes drop nested maps and comments, and says comment preservation is "not feasible
with yaml@2.9.1". A read-only check with the installed yaml 2.9.1 shows that editing the parsed
document in place (`parseDocument` + `doc.set` + `toString`) keeps comments, nested maps and
`9.90`; `0042` still becomes `42`. Options:
1. Cheap: call `detectLossyFrontmatter` in `commitChanges` and `dispatchMetaBindUpdate` and
   refuse with a toast, like favorite/icon already do.
2. Better: write through the parsed `Document` so untouched keys keep their bytes. Needs an
   ADR-0029 amendment, the canonical-form snapshot tests and the Python generator re-checked.

## Suggested fix order

Grouped by shared root cause so one change closes several items:
1. **Quit path** (F189): intercept Quit (custom menu item + `RunEvent::ExitRequested` /
   `applicationShouldTerminate:`), reuse the close handler. Also add `maxWait` to the body
   debounce to bound any loss window.
2. **External writers vs dirty tab** (F2, F7, F45, F3, F155, F158, F35): never mark a dirty
   tab saved from disk-derived content. Writers should flush or apply their change to
   `tab.content`; reload must re-check dirtiness after its await; add a disk-hash check
   before autosave to detect conflicts.
3. **Frontmatter writers** (G2, F97, F53, F103, G7): guard or switch to in-place Document
   edits (see the ADR section).
4. **Writes keyed by "active tab" instead of a path** (F67, F104, F21, F5 latent): pass the
   target path explicitly.
5. **Destructive file ops** (F126, F165, F43, G6, F151): exists-checks, save-before-delete,
   case-insensitive name generation, refuse to persist an unparseable canvas, prompt on
   vault switch.
6. **Editor robustness** (F105, LP1, LP2, F84): `try/finally` around the suppress flags,
   guard widget `toDOM`, `ignoreEvent` for form controls, reset history per note.
7. **Table and kanban rewrites** (F98, F99, F100, F143, F144): edit the source minimally
   instead of re-serializing the model.
8. **Atomic writes and encoding** (F182, F54, F184): route note writes through a Rust
   `write_atomic` command; refuse to open non-UTF-8 files for editing.
9. P2 items, then the low appendix.
