## Findings

1. minor — `src-tauri/tests/remote_events_test.rs:26`: the `EventMap` parser only picks up lines that start with a tab and a single-quoted key (`\t'name':`). A key added unquoted (`fooBar: X`), double-quoted, or optional (`'x'?:`) is skipped without a sound. The parity test would then pass with an unclassified name, and the only guard is `names.len() >= 8`. Fix: count every member line of the interface body (for example `^\t["']?[\w:-]+["']?\??:`) and assert that the parsed names cover all of them, or accept all three key forms.
2. minor — `src/lib/core/editor/editor.service.ts:407-408` (existing code, now reached over the network): after the async read, `reloadExternallyChangedTabs` checks the tab again only against `savedContent` and does not check `isTabDirty`. If the user types into a clean tab during the read's round trip (`readTextFile` is now a tailnet call), the Mac content overwrites those keystrokes, which conflicts with "Dirty tabs are never replaced". The browser cannot save yet (08), so today the loss is a few unsaved characters. Fix, in this Issue or in 08: `if (!tab || isTabDirty(tab) || diskContent === tab.savedContent) continue;`, with a test that dirties the tab between the read's start and its reply.
3. minor — `src/tests/lib/app/remote/browser-mac-changes.test.ts:154`: the dirty-buffer test also passes when no event is forwarded at all (the build report confirms this). On its own it does not show that the forwarded event ran and skipped the tab. Fix: in the same test, keep a second clean tab open (Bravo), emit `{ paths: [ALPHA, BRAVO] }`, and assert that Bravo reloads while Alpha's buffer is kept.
4. minor — `src/lib/app/remote/remote-session.ts:94`: a failed `refreshAfterReconnect` is only logged (`error('REMOTE', …)`). The banner clears on `connected`, so the user sees a page that looks live but may be stale, with no sign of it. CLAUDE.md § Error Handling asks for a toast on user-facing errors. Fix: show a toast ("Could not refresh after reconnecting; reload the page") in the catch.
5. minor — `src-tauri/src/remote/rpc.rs:94`: nothing tests the stalled-session path (a full queue shuts the socket down, which ends the session and unsubscribes it), although the module doc relies on it ("a session that falls behind is closed"). Fix: a test with a small queue, or a client that never reads, that publishes past the bound and asserts `subscriber_count() == 0` and that the socket is closed.
6. nit — `src-tauri/src/remote/events.rs:93`: once the server has started, `listen_any` stays registered for the whole process, and `publish` parses every forwarded payload even when no session is subscribed (a full-rescan `vault-index-updated` lists every upserted path). Fix: return early when the sink map is empty, before `serde_json::from_str`.

## Resolution

All six findings were accepted and fixed:

1. `remote_events_test.rs`: `frontend_event_names` now reads every member line of the `EventMap` body (single-, double- or unquoted keys, optional `?`) and panics on a member line it cannot read, so an unclassified name can no longer be skipped. `the_event_map_parser_reads_every_key_form` covers the key forms.
2. `editor.service.ts::reloadExternallyChangedTabs` re-checks `isTabDirty(tab)` after the read. `editor.service.test.ts` "keeps keystrokes typed while the read was in flight" dirties the tab mid-read (failed before the fix).
3. `browser-mac-changes.test.ts` dirty-buffer test keeps a clean Bravo tab open, emits both paths in one event and asserts Bravo reloads while Alpha's buffer is kept.
4. `remote-session.ts`: a failed refresh after reconnect also shows a toast telling the user to reload; `remote-session.test.ts` asserts it (failed before the fix).
5. `remote_events_test.rs::a_session_that_never_reads_is_closed_and_unsubscribed`: a client that never reads, published past the queue bound, ends with `subscriber_count() == 0` and a socket whose writes fail.
6. `EventHub::publish` returns before `serde_json::from_str` when no session is subscribed. Not observable from a test (no behavior change); covered by the existing hub tests.
