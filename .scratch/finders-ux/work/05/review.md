1. minor — `src/lib/features/search/SearchPanel.svelte:140-142` (status text) with `search.store.svelte.ts:18` (`resultsCapped`): the store has one `resultsCapped` flag for the last search, not one per mode. Fix (optional, or as a follow-up): keep the flag per mode (`{ text, semantic, hybrid }`) and set the entry for the mode that ran. 2. minor — `src/lib/features/search/SearchPanel.svelte:254` (input class `pr-8`) with `:258-264`: in Text mode the spinner sits at `right-7` (1.75rem to about 2.6rem from the edge), but the input reserves only 2rem on the right. Typed text therefore runs under the spinner for about 0.6rem. The precedent the Issue cites, `RailListSearch.svelte:89`, widens the input to `pr-12` for the same spinner and button pair. Fix: use `pr-12` in Text mode (or only while `searchSlow`). The build disclosed this as a default it took.
3. nit — `help/documentation/06-search-and-navigation.md:145`: the sentence says Hybrid returns at most 20. That holds for the Rust `search_hybrid` path, but the legacy merge fallback (`search.service.ts:298-302`, `mergeResults` over up to 50 FTS rows and 20 semantic chunks) can show up to 70. Fix: either cap the legacy merge or word the sentence around the main path. This is low impact, since the fallback only runs when `search_hybrid` throws.
