## Findings

1. **Medium: the docs test list can silently run fewer tests in this repo's shell (`implement-issue.js:54`, `:169`).** The classifier prints `docs tests: every file listed by: grep -rlF ... src/tests` and leaves the agent to turn that list into `pnpm vitest run <files>`. Agents run in zsh, and zsh does not word-split unquoted `$var`. So `files=$(grep -rlF ...); pnpm vitest run src/tests/help/ $files` passes every grep hit as one argument with newlines in it. That argument matches nothing, and vitest exits 0 after running only `src/tests/help/`. I hit this myself: the first run gave `Test Files 4 passed`, and `pipeline-dom.test.ts` and `event-calendar-keys.logic.test.ts` never ran. Fix: have the classifier print one ready-to-run `run:` line for the docs case, such as `run: grep -rlF -e help/examples src/tests | xargs -r pnpm vitest run src/tests/help/`. `-r` stops BSD/GNU xargs from running a bare `pnpm vitest run` (the full suite) on empty input; drop the leading dir when `helpEx` is unset. Print no `run:` line when there is no search key and no `help/examples` change. Step 2 then needs no extra instruction for the docs case.
2. **Low: the comment's claim "an unknown input is never under-gated" is false (`implement-issue.js:29`, `:42`).** Unknown paths get only the frontend gate. `.tool-versions` holds `rust stable`, so a toolchain pin change there would skip `cargo test`. Fix: add `.tool-versions` to both rules (set `rust = 1; fe = 1`), or reword the comment to say that unknown paths get the frontend gate.
3. **Low: the rule is in two places (`CLAUDE.md:311` and `implement-issue.js:26`).** The comment says `GATE_CLASSIFIER` is "the only place it lives", but the CLAUDE.md Gate bullet now restates the whole path list (`src/`, `static/`, `e2e/`, `scripts/`, root configs, `.scratch/`, `help/`, `docs/`). When the classifier changes, the two copies will drift apart. Fix: shorten the CLAUDE.md bullet to the four outcomes and point to `GATE_CLASSIFIER` in `.claude/workflows/implement-issue.js` for the path list.
