# Rail note list toolbar

Every rail note list gets the header actions Tolaria has: a Sort dropdown, an inline search, a "Show in note list" property picker, and the existing create button. Behavior reference only, from `/tmp/tolaria-menu/src/components/{SortDropdown.tsx,note-list/NoteListHeader.tsx,note-list/ListPropertiesPopover.tsx}`. Write Svelte 5 code from this spec; do not port React code.

## Owner decisions

- **Sort on views:** the dropdown is on every list. On a view, a pick writes one column to the `.view`'s `sort:`. A last menu item, "Multiple sort...", opens the existing `SortPanel`, so multi-column sort stays editable. A pick from the dropdown replaces a multi-column sort.
- **Persistence:** a view saves in its `.view`, a type in its definition note, everything else in `settings.json` (`layout.railListPrefs`). All folders share one preference.

## Defaults applied

- The view lens keeps its existing Filter popover (`data-note-list-filter`). The sliders icon is the property picker, not a filter.
- No saved sort keeps the lens's native order. The trigger shows `defaultLensSort`, or "Default" when the lens has none.
- An explicit sort ignores `_order` pins on a type list.
- Sorting and searching a grouped lens (Today, Neighbourhood) works inside each group; group headers stay. Today's plugin sections hide while a query is active.
- Search matches title, the row's visible property pills, and full-text hits from `search_fts`. A failed FTS call falls back to the local match.
- A type's sort is saved under a new key, `_list_sort`. `_sort` only accepts `VIEW_SORTS` and `RESERVED_KEY_RULES` flags anything else. It shows in the Properties panel of the definition note, like `_sort` and `_list_properties_display`.
- Mixed value kinds order by kind (numbers, booleans, dates, text), not as strings: text comparison across kinds is not a total order. Text uses `Intl.Collator`, so accented titles sit with their base letter.
- A customized sort offers "Reset to default" (`onReset`), the only way back to a type's `_order` pins.
- Writes to one file go through `serializeListWrite`.

## Modules (all in `src/lib/features/rail-shell/`, tests in `src/tests/lib/features/rail-shell/`)

Types: `list-toolbar.types.ts` (written).

### T1 `list-sort.logic.ts`
- `BUILT_IN_SORT_OPTIONS: readonly { value: ListSortOption; label: string }[]`: Modified, Created, Title, Status, in that order.
- `defaultSortDirection(option)`: `desc` for modified and created, else `asc`.
- `sortOptionLabel(option)`: the built-in label; for `property:<key>` the key without its leading underscores.
- `formatListSort(config)`: `<option>:<direction>`, e.g. `modified:desc`, `property:budget:asc`.
- `parseListSort(raw: unknown): ListSortConfig | null`: inverse of format. The direction is after the LAST colon, so a property key may hold colons. Null for a non-string, an unknown built-in, an empty property key, or an unknown direction.
- `propertySortOption(key)`: `property:<key>`.

### T2 `list-sort-compare.logic.ts`
- `sortLensNotes(notes: readonly LensNote[], config): LensNote[]`: a new array. Values: modified `modifiedAt`, created `createdAt`, title `title`, status `frontmatter.status`, property `frontmatter[key]`.
- A missing value (undefined, null, `''`, `[]`, or 0 for the two times) sorts LAST in both directions. Ties break by `naturalCompare` of title, then path, both ascending in both directions.
- Number numeric; boolean false before true; strings starting `YYYY-MM-DD` by time; arrays by items joined with `, `; else `naturalCompare` (from `#lib/core/filesystem/fs.logic.js`). Mixed kinds compare as strings.
- `applyListSort(resolved: ResolvedLens, config): ResolvedLens`: sorts `notes` and each group's notes. With groups, `notes` is each grouped note once, in group order (the `ResolvedLens.notes` contract).

### T3 `list-search.logic.ts`
- `normalizeListQuery(query)`: trimmed, lower case.
- `noteMatchesListQuery(note, normalizedQuery, listProperties: readonly string[], fullTextPaths?: ReadonlySet<string>)`: true for an empty query, a path in `fullTextPaths`, or a case-insensitive substring of the title or of a pill's text (`splitPropertyIntoPills(note.frontmatter[key])` from `#lib/features/type-definitions/type-sidebar.logic.js`). Not the subtitle: it holds relative times.
- `filterResolvedLens(resolved, query, listPropertiesFor: (note: LensNote) => string[], fullTextPaths?)`: empty query returns `resolved` itself. Filters `notes` and each group, keeping empty groups.

### T4 `list-properties.logic.ts`
- `availableListProperties(notes: readonly LensNote[], selected: readonly string[])`: the union of keys not starting with `_`, the relation keys `_belongs_to`, `_related_to`, `_has_many` when present, and `selected`; sorted by `naturalCompare`.
- `propertyDisplayLabel(key)`: without leading underscores.
- `orderedPropertyItems(selected, available)`: selected first in their order, then the rest; a selected key that is not available is dropped.
- `filterPropertyItems(items, query)`: case-insensitive substring of the display label; a blank query keeps all.
- `toggleListProperty(current, key)`: removes it, or appends it. New array.
- `moveListProperty(current, fromKey, toKey)`: moves `fromKey` to `toKey`'s index. Returns `current` unchanged (same reference) when either key is not in it or they are equal.

### T5 `list-prefs.logic.ts`
- `listPrefsKey(lens: Lens)`: `folder` for every folder lens, `type:<target>` for a type lens with a target, else `lens.kind`.
- `parseRailListPrefs(raw: unknown): Record<string, ListPrefs>`: `layout.railListPrefs` is loaded unvalidated. Stored shape per key: `{ sort?: string; properties?: string[] }`. Drops non-object entries, an unparsable sort, non-string property items, and entries left empty. Never throws.
- `withListPrefs(raw: unknown, key, patch: { sort?: ListSortConfig | null; properties?: string[] | null })`: the next stored record (plain JSON, `sort` formatted). A field not in the patch stays; null or an empty array removes it; an emptied key is deleted.
- `defaultLensSort(kind: string): ListSortConfig | null`: `modified:desc` for inbox, today, favorites, archive, type, untyped; else null.

### T6 `list-view-sort.logic.ts`
- `sortDefToListSort(def: SortDef)`: `file.mtime` modified, `file.ctime` created, `file.name` and `file.basename` title, `status` status, else `property:<column>`. ASC asc, DESC desc.
- `listSortToSortDef(config)`: inverse, title to `file.name`.
- `viewListSort(sorts: readonly SortDef[], frontmatterSort: string)`: the first sort def; with none, `_sort`: `modified` modified desc, `created` created desc, `modified-asc`, `created-asc`, `title` title asc, anything else modified desc.

### T10 `LensNote.createdAt`

### T11 `list-fulltext.service.ts`

A blank query returns an empty set with no IPC. Logs with `error` from `#lib/utils/debug.js` and rethrows. Check how `search.service.ts` imports `call`.

### T12 `RailSortMenu.svelte`
- Props: `config: ListSortConfig | null`, `extraCount: number` (trigger shows `+N`), `properties: string[]`, `onSelect(config)`, `onMultipleSort?: () => void`.
- Trigger: `button[data-note-list-sort]`, an up or down arrow plus the label; with a null config, `ArrowUpDown` plus "Default". Same trigger classes as the other header actions, `text-meta`, truncates.
- Panel: `Popover`, `role="menu"`. Each row is `menuitemradio` with `aria-checked`, the label, and two icon buttons (`data-sort-dir="asc"|"desc"`) inside it. Clicking a row picks it with its current direction when active, else `defaultSortDirection`. Clicking an arrow picks that direction. Picking closes the menu. A separator comes before property rows (`data-sort-separator`), present only when there are properties. `onMultipleSort` renders a last item "Multiple sort..." (`data-sort-multiple`) after another separator.
- Keyboard: focus the active row on open; ArrowUp, ArrowDown, Home, End move focus; Enter and Space pick; Escape closes.

### T13 `RailListSearch.svelte`
- Props: `value: string`, `loading: boolean`, `onChange(value)`, `onClose()`.
- A row under the header (`data-note-list-search`), `border-b border-file-explorer-border`, using `#lib/components/ui/input`, placeholder "Search notes...", autofocus on mount.
- Keeps a local draft. `onChange` fires 180 ms after typing, or at once when the draft goes blank. Clear button (`data-note-list-search-clear`) only with text: clears, fires at once, keeps focus. Spinner (`data-note-list-search-loading`) while debouncing or `loading`. Escape calls `onClose`. Cancel the timer on destroy.

### T14 `RailPropertiesPicker.svelte`
- Props: `available: string[]`, `selected: string[]`, `onChange(next: string[])`.
- Trigger `button[data-note-list-properties]`, `SlidersHorizontal`, title and aria-label "Show in note list", active color when `selected` is non-empty.
- Panel `Popover` `w-64`: heading "Show in note list", search input "Search properties..." focused on open, list `max-h-60 overflow-y-auto` from `orderedPropertyItems` and `filterPropertyItems`; empty text "No matching properties". Row: native checkbox (`aria-label` = display label), label, `GripVertical` handle only on selected rows.
- Reorder with native HTML drag on the handle, disabled while a query is active (a filtered list has no stable indexes), via `moveListProperty`. Also Alt+ArrowUp and Alt+ArrowDown on a selected row's checkbox. Query clears on close.

## Integration (opus)

`RailNoteList.svelte`: header reads title, count, Sort, Search, Properties, Filter (views only), header action, New. Sort and Properties appear when the lens resolved with no `status`. Resolve the shown sort and properties per lens (view: `.view`; type with a definition: its file; else settings under `listPrefsKey`), optimistic until the entries refresh catches up, rolled back with a toast on a failed write. Search state resets when the lens changes. `notes.length` in the count is the shown list. Update `RailNoteList.view.test.ts` and `e2e/specs/rail-shell.spec.ts` for the dropdown path to `SortPanel`.

## Rules for every worker

- Tabs. JSDoc on exports. `.logic.ts` imports only `.logic.ts`, `utils/`, types. No `$state` in logic. No em-dashes or emojis. English.
- Test first: write the test, run it, see it fail, implement, see it pass. Cover the happy path, empty or null input, and errors. Never mock stores or `.logic.ts`.
- Comments state why, never what changed.
- Touch only your listed files. No git commands. Report assumptions and anything the spec got wrong.
