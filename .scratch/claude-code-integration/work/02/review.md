## Findings

1. **minor**, `src-tauri/src/commands/claude/turn.rs:226` and `:243`. The run leaves `ClaudeRuns` at stdout EOF, but `finish` then blocks on `stderr_reader.join()` until stderr closes. A process that inherits claude's stderr but not its stdout (for example a stdio MCP server or a background job started with `>/dev/null &`) and outlives claude holds back `Done` for as long as it lives. During that time `cancel` is a no-op, because the run is already gone, and the vault accepts a new turn while the old one never sent `Done`. The probe confirmed all three. The build report says "cancel still kills the whole group", which is wrong for this case. Fix: once `wait` returns, bound the stderr join (the reader sends its tail over a channel, the runner waits for it with `recv_timeout` of about 1 to 2 s and uses what arrived), or keep the run listed until `Done` is emitted. Add a test with a stderr-holding grandchild that expects `Done` within the bound.
2. **minor**, `src-tauri/src/commands/claude/turn.rs:78-79`. `-p` is the boolean `--print` flag, and the prompt is a positional argument. A prompt the user types that starts with `-` (a Markdown list item `- [ ] ...`, or `--help`) is parsed by the CLI as an option. That gives an "unknown option" Error, or for `--help` a help text on stdout that the parser skips, then a bare `Done { exitCode: 0 }` with nothing shown. The build recorded this risk. Fix (needs the owner's OK, because the criterion lists `-p <prompt>` first): put `--` and then the prompt at the end of the args, or refuse or escape a leading `-` in Issue 03. Either way, add a unit test for a prompt that starts with `-`.
3. **minor**, `src-tauri/src/commands/claude/turn.rs:189`. On a spawn failure, `Error` and `Done` are emitted on the calling thread before `claude_run_turn` resolves. The frontend therefore gets them for a `runId` it does not know yet, and a panel that filters events by the returned id drops them and waits forever. The `onClaudeEvent` doc comment and the discovery note say so. Issue 03 must buffer events for unseen ids, or the runner could emit them from a spawned thread after a short handoff. Record this in Issue 03's acceptance criteria so it is not lost.
4. **minor (owner decision)**, `src-tauri/src/commands/claude.rs:140-149`. Only the parent directory is canonicalized, and the name check runs on the link name, so a symlink named `claude` that points at `/bin/sh` is accepted (`is_executable_file` follows the link). The criterion's wording ("its canonicalized path is an executable file named `claude`") and the spec's claim that the commands "only run a binary named `claude`" therefore hold for the link name, not for the target. The deviation is recorded and reasoned: the native installer's `~/.local/bin/claude -> versions/<ver>` would be refused otherwise. No app command creates symlinks, so the practical exposure is small. The owner should confirm it, or the spec sentence should say "a file or link named `claude`".
5. **nit**, `src-tauri/src/commands/claude/turn.rs:181`. The one-run-per-vault check compares raw strings, so `/v/vault` and `/v/vault/` (or a path with a symlink in it) count as different vaults. The frontend always sends one form today. Normalize the path if Issue 03 ever builds it in two ways.
6. **nit**, `src-tauri/tests/fixtures/claude/stream.ndjson`. The fixture is hand-written from the spec's probe description, not captured from a real `claude 2.1.325` run, so drift in field names (`thinking` in `thinking_delta`, `total_cost_usd`, `tool_use_id`) would not be caught. Replace it with a captured run when one is made for Issue 03's manual check.

The stderr reader sends its tail over a channel; `finish` waits for it with `recv_timeout(STDERR_DRAIN_TIMEOUT)` (2 s) after `wait()` returns and sends `Done` without the tail past that (`turn.rs`). Test `grandchild_holding_stderr_does_not_hold_back_done` (a `sleep 8 >/dev/null &` job holds stderr): failed with Done after 8.27 s before the fix, passes in well under 5 s after it.
2. Deferred to Issue 03, not changed here: the fix either breaks this Issue's stated arg order (`-p <prompt>` first) or lives in the panel, and both need the owner's choice. Added as an Issue 03 acceptance criterion with an "Owner decision recorded in Notes" clause and a test requirement.
3. Accepted as stated: added to Issue 03's acceptance criteria (buffer events for an unseen `runId` until `claude_run_turn` resolves). No runner change.
4. Left for the owner, as the finding says: the current behavior (parent directory canonicalized, link name checked) is the recorded choice that keeps the native installer symlink working. No code change.
5. Not changed (nit): the frontend sends one form today. Recorded in Issue 03's Notes so the panel keeps sending one form.
6. Not changed (nit): no captured run is available in this step. Recorded in Issue 03's Notes to replace the fixture during its manual check.
