## Findings

1. minor — `src/lib/features/claude-code/ClaudeCodeSection.svelte:15-20`. With a shared store, opening Settings after the panel has checked shows the panel's earlier status (for example "Not installed: ...") while the refresh runs, which can take up to the 10 s capture deadline. "Checking for the claude command..." no longer appears, and only the disabled button shows that a check is running. Fix (optional): return the "Checking..." text while `checking` is true, or show it next to the old status.
2. nit — `src/lib/features/claude-code/claude-code.service.ts:18-27`. There is no ordering guard on store writes, so a slower, earlier `claude_status` call can overwrite a newer result. This needs a panel mount check and a Settings check in flight at once with different override paths. `discovery.md` records the risk, and it is unlikely while the Settings overlay is open. Fix (optional): a request counter that drops responses older than the latest.
