## Findings

1. **major** `src/lib/app/lifecycle/app-lifecycle.service.ts:640-686` (and `src/lib/features/claude-code/claude.store.svelte.ts:45`): `teardownVault` never resets `claudeStore`. The store's own JSDoc says `reset()` is for "tests, vault close", but nothing calls it on a vault switch. After switching vaults, the chat, the old vault's `sessionId` and its vault-relative chips carry over: the next send passes `--resume <old session>` with the new vault as cwd (from memory: the CLI keys sessions by project directory, so this likely fails with "No conversation found") and names notes from the other vault in the system prompt. A turn still running in vault A also keeps streaming into the panel shown for vault B. It is recoverable (New chat), so not a blocker. Fix: call `claudeStore.reset()` (and cancel a running turn) in `teardownVault`, with a lifecycle test; or correct the JSDoc and record the limitation in the Issue Notes.
2. **minor** `src/lib/features/claude-code/ClaudePanel.svelte:55-61`: the mount effect re-attaches the active note every time the panel mounts, and the panel remounts whenever the right sidebar is hidden by a canvas, kanban or view tab and shown again (`isRightSidebarShown`). A chip the user removed comes back after visiting such a tab, against "Chips persist for the chat until removed". Fix: attach on open only when the panel was hidden by the user's toggle (for example from `toggleClaudePanel`/`showClaudePanel` instead of the component mount), or remember a removed active note for the chat.
3. **minor** `src/lib/features/claude-code/claude.service.ts:51-53`: `stop()` is a silent no-op while `claude_run_turn` has not resolved yet (saving dirty tabs, spawning), yet the Stop button already shows. A click in that window is lost and the turn runs on. Fix: remember a pending stop and call `claude_cancel_turn` from `startRun`, or disable Stop until `runId` is set. Discovery lists it as a known risk; flagging it so it is tracked.
4. **minor** `src/lib/features/claude-code/claude.logic.ts:813-814` and `ClaudePanel.svelte:120-123`: an `Error` event before `Done`, or a failed cancel (`failTurn`), sets `status: 'error'` while the process may still be running. `isRunning` becomes false, so Stop disappears and Send is enabled. A new send then hits the runner's one-run-per-vault refusal, and after `failTurn` (`runId` null) the old run's later events are ignored. Fix: keep `running` until `Done` for the current run id and show the error alongside it; on a failed cancel keep the run id.
5. **minor** `.scratch/claude-code-integration/issues/03-claude-chat-panel.md` Notes: replacing the hand-written `src-tauri/tests/fixtures/claude/stream.ndjson` with a real `claude -p ... --output-format stream-json` capture (Issue 02 review, finding 6) was not done; it needs a paid manual run. It is not an acceptance criterion, but it should not be lost: move it to a follow-up Issue or record it in the ledger at delivery.
6. **nit** `src/lib/features/claude-code/claude.logic.ts:880-887`: `wikilinksToLinks` runs over the raw Markdown, so `[[x]]` inside inline code or a fenced block becomes the literal text `[x](#wikilink=x)` in the rendered code. Fix: skip code spans and fences, or convert after rendering.
