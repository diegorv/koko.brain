## Findings

1. **minor** `src/lib/features/claude-code/claude.service.ts:43` with `claude.logic.ts:84-89`: the fix note says a vault switch before `claude_run_turn` returns leaves that run's "events ignored". They are not. `resetClaude` sets the chat to `EMPTY_CHAT`, then `claude_run_turn` resolves and `claudeStore.startRun(runId)` sets the run id on the idle chat without checking it still waits for one. The old vault's events then match `runId` and apply: `Init` replaces `slashCommands`, an error sets the panel's error, and `Result` writes the old vault's `sessionId`, so the next send in the new vault passes `--resume` with a session from the other directory. That is finding 1's symptom, in a narrow window (save plus spawn). Fix: in `sendPrompt`, when the store no longer waits for a run id after the call (`!claudeStore.isRunning`, or a turn token changed), cancel `runId` and skip `startRun`; or make `startRun` a no-op unless `status === 'running' && runId === null`. Add a service test that resets between the call and its resolution.
2. **nit** `src/lib/features/claude-code/claude.logic.ts:233`: the fence pattern closes only on a fence of exactly the opening's length (`^\1[ \t]*$`). CommonMark also closes on a longer fence, so a block opened with three backticks and closed with four is treated as running to the end of the text, and wikilinks in the prose after it stay literal. Rare in model replies. Fix: let the closing fence be the opening fence followed by more of the same character (`^\1\2*`-style backreference on the fence character).
