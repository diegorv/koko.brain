## Findings

1. minor — `src/lib/features/rail-shell/neighbourhood.store.svelte.ts:17` (and `lens.logic.ts:303`): `notePath` changes only through `setNotePath` and `reset`, so renaming, moving or deleting the note whose neighbourhood is open leaves a blank list. The label is empty, the list says "No notes here", and no rail item is highlighted until the user clicks one. The Files navigator's pick follows path changes (`files-navigator.service.ts` `registerPathChangeConsumer`), so this lens behaves differently from the Folder lens. Fix: register a `neighbourhood` path-change consumer, wired in `initializeVault` and unwired in `teardownVault` with a lifecycle test, as files-navigator is. It should follow `from -> to` on rename/move and, when the note is deleted (`to === null`), reset the store and fall back to Today. Alternatively, record this as a follow-up.
2. nit — `src/lib/features/rail-shell/lens.logic.ts:325`: Outgoing links counts frontmatter wikilinks, so every relationship target appears both in Outgoing links and in its relationship group. In the E2E, a note with only frontmatter links shows "Outgoing links 3". This matches Rust's `extract_outgoing_links` and the existing Outgoing links panel, and it is a documented default. If the owner wants only body links there, filter out `outgoingLinks` whose `position` falls inside the frontmatter block. Otherwise no change is needed.

## Resolution

1. Fixed. `registerNeighbourhoodPathChangeConsumer` (`src/lib/features/rail-shell/neighbourhood.service.ts`) follows the open note through a rename or move of the note or a folder above it, and on delete resets the store and, while the Neighbourhood item is picked, falls back to Today. Wired in `initializeVault` next to the Files navigator consumer and unwired by `teardownVault` through the shared list. Tests: `neighbourhood.service.test.ts` (rename, move, folder rename, delete with and without the lens picked, unrelated and prefix-sibling paths, failed rename, unregister) through the real fs.service and path-change owner, and the lifecycle wiring test in `app-lifecycle.service.test.ts`.
2. No change. Counting frontmatter wikilinks under Outgoing links matches Rust's `extract_outgoing_links` and the existing Outgoing links panel; the review marks it a documented default, and changing it is an owner decision, not a defect.
