## Findings

1. minor — `e2e/specs/rail-shell.spec.ts:696`: the expected week label is `dayjs().isoWeek()`, which is only right because the fixture's `weekStartsOn` defaults to Monday. With a Sunday-first setting, the navigator labels a Sunday by the next Monday's ISO week (by design, see `calendar.logic.ts:129-131`), so the test would fail every Sunday. The four labels also come from the Playwright process clock, so a run that crosses midnight can flake. Fix: pin `eventCalendar.weekStartsOn: 1` in the restarted settings (or compute the expected week from the row's Monday), and accept the midnight risk or restart near a fixed date.
2. nit — `src/lib/plugins/calendar/CalendarNavigator.svelte:41,80`: `pickedDayLens(...).target` is always a string (`day-lens.logic.ts:25` falls back to `todayKey`), so `?? null` on line 41 and `?? eventCalendarViewStore.todayKey` on line 80 never apply. The behavior is right. Fix: drop the dead fallback on line 80, or leave it as is.
3. nit — `src/lib/plugins/calendar/CalendarNavigator.svelte:83-85`: the grid's existing week-number button still sends failures only to `console.error`, while the new weekly entry, which opens the same note, shows a toast. This was there before and is outside this Issue, but the same action now fails in two different ways. Fix (follow-up): route `openWeeklyNote` through `openPeriodicEntry`-style toast handling.
4. nit — no file: nobody has checked the new section by eye in each built-in theme. It uses the same region tokens as the existing navigator, so the risk is low. Fix: deliver or the owner looks at it once in the light, dark and custom themes.
