## Findings

1. **major**, help/documentation/02-file-explorer.md:19. "If the name is taken, a toast says so" is false. The folder menu's New note / Canvas / Collection / Kanban Board / folder all call `createFile` or `createFolder`, and those dedupe the name with `generateUniqueName` (fs.service.ts:121-124, 150-152), so the result is `Untitled 1.md` or `Untitled 1` and no toast appears. This breaks the "no page promises behavior the app lacks" criterion. Fix: replace the sentence with "If the name is taken, Kokobrain adds a number (for example `Untitled 1.md`)."
2. **major**, src/lib/core/settings/settings.logic.ts:10-14. The move to Rail leaves the persisted rail pane sizes alone, so the users being migrated never get the new width. `loadSettings` writes the full merged layout back on every load, on main as well (settings.service.ts:169), so every vault opened since Issues 07/12 already has `navigatorSize: 15`, `noteListSize: 22`, `rightSidebarSize: 25` on disk. An existing Classic user moved to Rail therefore opens at the 528 px editor that commit 0d28f8e3 measured as too narrow (PRD Risks, Width). The 14/20/20 defaults only reach brand-new vaults. The build report names this as a choice, but it defeats the reason for the size check for the population this ticket moves. Fix: when the saved shell was not `rail` (a real Classic to Rail move), also reset `navigatorSize` and `noteListSize` to `DEFAULT_SETTINGS.layout` values. Those two keys are rail-only, so a Classic user never chose them. Optionally reset `rightSidebarSize` when it still equals the old default 25. Then add a `loadSettings` test with a settings.json that carries `shell: 'classic'` and 15/22/25, asserting 14/20/20 afterwards, and that a saved `shell: 'rail'` layout keeps its sizes.
3. **nit**, e2e/specs/search.spec.ts:29,37,43. The result rows are found by the Tailwind class `.h-20` (SearchResult.svelte:135), so a styling change breaks the spec silently. Fix: add a `data-search-result` attribute to the row and select on that.
4. **nit**, docs/adr/0026-type-definitions-relationships-lifecycle.md:35. The diff adds a stray blank line after the 2026-05-28 amendment, which has nothing to do with this change. Fix: drop it.
5. **nit**, e2e/specs/calendar-plugin.spec.ts. The classic-only E2E cases (double-click a day opens the day view, Open Calendar in the files and types headers) were deleted rather than pinned to `shell: 'classic'` the way sidebars.spec did. The unit tests still cover them (CalendarPanel.test.ts, CalendarGrid.test.ts), so this is only lost E2E coverage while Classic stays selectable. Fix (optional): keep them in a `test.describe` with `test.use({ shell: 'classic' })`.
