## Findings

1. minor — `src/lib/features/properties/properties.logic.ts:355` — the "already linked" test compares the raw link text with the person name, so a template that writes the link path-qualified or with the extension (`_related_to: "[[Work/_people/<% person %>]]"`, `"[[Alice.md]]"`) gets a second link to the same person. Probe: `ensureFrontmatterLink('---\n_related_to: "[[Work/_people/Alice]]"\n---\n', '_related_to', 'Alice')` returns `_related_to: ["[[Work/_people/Alice]]", "[[Alice]]"]`. Fix: compare the link's stem (drop the folder prefix and a trailing `.md`) against the target, and add a test for both forms.
2. minor — `src/lib/features/properties/properties.logic.ts:345` — `FRONTMATTER_REGEX` does not match an empty block `---\n---` or a block after a leading blank line, so the helper prepends a second block. Probe: `'---\n---\n# x\n'` becomes `'---\n_related_to: "[[Alice]]"\n---\n---\n---\n# x\n'` (the old delimiters render as two rules in the body). Fix: treat a leading `---\r?\n---` as an empty block and insert into it; add a test.
3. minor — `src/lib/features/properties/properties.logic.ts:348` — a template whose rendered frontmatter does not parse (probe: `title: 1:1: Alice`) used to produce a note and now makes both New 1:1 and the Cmd+Shift+N picker fail with the generic "Failed to create 1:1 note." toast, which does not say the template is the cause. Throwing is defensible (Rust could not read the link either), but the user cannot tell what to fix. Fix: let the toast name the cause (the template's frontmatter cannot be read), or document it on help page 09.
4. nit — `src/lib/features/properties/properties.logic.ts:352` — the inserted line always ends in `\n`, so a CRLF template gets mixed line endings (probe: `'---\r\n_related_to: "[[Alice]]"\ndate: x\r\n...'`). Fix: reuse the line ending captured in `open`.
5. nit — `src/lib/features/note-action-bar/note-action-bar.service.ts:96-98` — if `createFile`'s `refreshTree` throws after `create_note` wrote the note, the user sees "Could not create a note linked to ..." while the complete note exists and is not opened; a retry makes `Untitled 2.md`. Inherited from `createFile` and disclosed by the build. Fix (optional): accept it, or have `createFile` swallow and log the refresh failure as `openOrCreateNote` does.
6. nit — `src/lib/features/properties/properties.logic.ts:359` — with the key present and a plain non-link value (`_related_to: Team`), `computeAddRelationshipValue` replaces the value with the link, dropping "Team" (probe confirmed). Rare in a 1:1 template. Fix: keep the old value in a list, or leave it and note it in the JSDoc.
7. nit — `src/lib/features/note-action-bar/note-action-bar.logic.ts:106` — `HUB_ACTION_WIDTH = 120` is an estimate; "New linked note" at `text-xs` plus icon, gap, `px-2`, border, `mr-1` and the flex gap comes to roughly 135 px (not measured), so the file name gives up the difference before the actions fold. No overflow, since the name truncates. Fix: measure the button or raise the constant.

## Resolution

1. Fixed: `ensureFrontmatterLink` compares each link's stem (folder prefix, `.md`, `|alias` and `#heading` dropped) with the target; test with `[[Work/_people/Alice]]`, `[[Alice.md]]` and `[[Work/Alice.md|Al]]`.
2. Fixed in part: an empty `---`/`---` block (LF or CRLF) gets the key inserted into it; test added. Rejected the "block after a leading blank line" half: that block is not frontmatter (Rust `parsing.rs` and `FRONTMATTER_REGEX` both require `---` at offset 0), so prepending a real block is the correct result.
3. Fixed by documentation: help page 09 says an invalid template frontmatter (with the `title: 1:1: Alice` example) stops the note and shows "Failed to create 1:1 note.", and what to fix. The toast text is unchanged.
4. Fixed: the inserted line reuses the opening delimiter's line ending; CRLF tests added.
5. Rejected (optional): the refresh failure path is inherited from the shared `createFile`, which every file-explorer create also uses; changing its error contract is outside this Issue.
6. Fixed: a plain non-link value is kept next to the link in a list (`['Team', '[[Alice]]']`); test added, JSDoc updated.
7. Fixed: `HUB_ACTION_WIDTH` raised to 136 to cover the reviewer's ~135 px estimate for "New linked note" (still an estimate, not measured in the app).
