## Findings

1. **blocker** — src/lib/features/note-list/NoteRowMenu.svelte:213 (exposed by src/lib/features/rail-shell/lens.logic.ts:526 `fileToLensNote`). The folder lens is the first note-list lens with non-markdown rows, but the row context menu still offers "Favorite" on every row. `toggleFavoriteForPath` calls `updateNoteFrontmatter`, which reads the file as text and writes YAML frontmatter in front of it. I confirmed this with a throwaway vitest probe (since deleted) that called `toggleFavoriteForPath('/vault/Board.canvas', true)` on `{"nodes":[],"edges":[]}`. It wrote `---\n_favorite: true\n---\n{"nodes":[],"edges":[]}`, so the canvas stopped being valid JSON. The same happens to `.view` / `.collection` YAML, and a PDF or image read lossily as text gets rewritten. That is user data destroyed by one menu click. The PRD itself says non-markdown files cannot carry frontmatter (Bookmark migration). "Change icon" on the same rows does nothing, because `setIconForPath` ignores non-markdown files. **Fix:** offer Favorite (and Change icon) only on markdown rows. For example, pass the row's `kind` to `NoteRowMenu` or check `isMarkdownFile(target.path)`. Add a RailNoteList/NoteRowMenu test: a canvas row's menu has no Favorite item, and `writeTextFile` is never called for a non-markdown path.
2. **minor** — src/lib/core/layout/AppShell.svelte:162. `staleFolderPickFix` trusts `fsStore.fileTree` at the moment the index turns ready. In `initializeVault` (app-lifecycle.service.ts:300-316), a rejected `loadDirectoryTree` is caught (toast "Failed to load vault contents"), and `markIndexReady()` still runs when `buildIndex` succeeded. The check then sees an empty tree. It clears the saved pick, moves the rail from Files to Inbox and empties `railExpandedFolders` for good, all after a transient tree-load failure. **Fix:** skip the folder half of the fix when the tree is empty (a vault with a saved non-root pick cannot have an empty tree), or gate it on a successful tree load. The cost is only lost navigator state, so this is minor.
3. **minor** — src/lib/features/rail-shell/RailNoteList.svelte:213 with lens.logic.ts:340. Mid-session, a picked folder can disappear (deleted, or renamed from the classic tree or an external tool). Then `resolveLens` returns null and the list shows no label, no rule and "No notes here", but `newNoteRule` still returns a rule, so "New here" stays visible. Clicking it runs the recursive `create_folder` and silently re-creates the deleted folder. **Fix:** hide New here while the folder lens does not resolve (for example `canCreate = rule !== null && (lens.kind !== FOLDER_LENS_KIND || resolved !== null)`), or handle it in Issue 15, where folder rename/delete should also update `railFolder`. If deferred, note it in Issue 15.
