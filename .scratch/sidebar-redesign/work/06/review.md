## Findings

1. minor — `src/lib/features/note-list/NoteRowMenu.svelte:76-91`: commit e69cde47 gives the reason the rename state lives in the menu: a virtualized row remount, or a refresh of the `notes` list, must not reset a rename in progress (the `renamePrefilledPath` guard). No test pins this. The refactor moved exactly this state across a component boundary, and the rail list will lean on it. Fix: add a test to `NoteRowMenu.test.ts` that starts a rename, types a new value, passes a fresh `notes` array (same paths) through the harness props, and asserts the input still holds the typed value. A second test could unmount and remount the row with the same `renamingPath` and assert the same.
2. minor — `src/lib/features/note-list/NoteRow.svelte:8`, `NoteRowMenu.svelte:22-23`: the shared `features/note-list` imports generic helpers and `toggleFavoriteForPath` from `features/type-definitions`, and `TypeNoteList` imports `note-list`. That gives a two-way folder dependency, and the "shared" row stays tied to the Types feature that the rail list is meant to replace. ADR 0003 lists only `core/` and `utils/` as imports for `features/`; the repo already breaks that in many places, so this is not a blocker. Fix (follow-up is fine): move `splitPropertyIntoPills` / `formatRelativeTime` / `formatNoteDate` / `buildRenameFileName` to a `note-list` `.logic.ts` or to `utils/`, together with their tests, before the rail note list ticket adds more consumers.
3. nit — `src/tests/lib/features/note-list/NoteRowMenu.test.ts:339-352`: "cancels on Escape without renaming, even when the input then blurs" would pass without the `renameCancelled` guard. After Escape, `fsStore.renamingPath` is already null, so `commitRename` returns at `if (!note) return` anyway. The title promises more than the test proves. Fix: reword the title to the outcome it checks (no rename after Escape), or drop the "then blurs" part. Do not remove the guard, which comes from main.
4. nit — `src/tests/lib/features/note-list/NoteRowMenu.test.ts:221-275`: the open, copy path, favorite and reveal tests assert only a mocked-service call. docs/TESTING.md rule 5 says not to make a call assertion the sole one. The calls check exact arguments and the service is the component's real boundary, so this is defensible, and the TypeNoteList.view tests follow the same pattern. Fix: also assert a rendered outcome in each, for example that no `[role="menuitem"]` is left once the item is clicked.
5. nit — `src/lib/features/note-list/NoteRow.svelte:52-64`: PRD § Theming asks the rail shell's note list to use the `file-explorer-*` region tokens. The shared row keeps `primary` / `muted-foreground`, which is right for this prefactor ("Nothing visible changes in the classic shell"). The rail note list ticket has to decide how the row takes region tokens without changing the classic shell, for example through a class or variant prop. Not a change for this branch.

## Resolution

1. Fixed. `NoteRowMenuHarness.svelte` exports `setNotes()`, and `NoteRowMenu.test.ts` adds "keeps the typed name when the notes list refreshes mid-rename": it types `Gamma`, hands the menu a fresh notes array with the same paths and asserts the input still reads `Gamma`. With the `renamePrefilledPath === path` check removed the test fails (checked), and with it in place the test passes. The remount variant was not added: remounting the harness also recreates the menu, so the state resets by design.
2. Deferred to a follow-up, as the review allows. Moving `splitPropertyIntoPills` / `formatRelativeTime` / `formatNoteDate` / `buildRenameFileName` and their tests out of `type-definitions` is a move across features with no behavior change. It fits the rail note list ticket, which adds the second consumer, better than this prefactor.
3. Fixed. The test is renamed to "cancels on Escape without renaming and shows the row again". The `renameCancelled` guard stays.
4. Fixed. The open, copy path, favorite and reveal tests now also assert that the menu closed. In jsdom, bits-ui leaves the closed content in the DOM because the exit animation never ends, so `menuIsOpen()` reads `data-state` on `[role="menu"]`. "lists every item in order" asserts the open state, so the helper is shown to tell the two states apart.
5. No change on this branch, as the review says. The rail note list ticket owns the region tokens.
