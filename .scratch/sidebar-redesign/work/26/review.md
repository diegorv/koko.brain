## Findings

1. **minor** `src-tauri/src/vault/parsing.rs:587`. `load(&mut buffer, false)` reads only the first YAML document, so a `...` line cuts the frontmatter short without a word. `a: 1\n...\nb: 2` now gives `{a: 1}`: `b` is lost and no `FRONTMATTER` log is written. The subset parser gave `{a: 1, b: 2}` and `yaml.parse` throws ("Source contains multiple documents"), both checked with a probe. This behaviour change is not on the approved list and no fixture case pins it. Fix: add a fixture case (`tsThrows: true`) that pins the chosen Rust value. A better fix is to treat anything after the first document as a rejection, so the block goes to the subset parser and logs once like every other input `yaml.parse` cannot read.
2. **nit** `src-tauri/src/vault/parsing.rs:735`. The `[[X]]` rule, as the Issue words it, also collapses a block list holding one single-item flow list: `items:\n  - [a]` gives the string `"[[a]]"` (probe), while yaml@2.9.1 gives `[["a"]]`. Neither the fixture nor the ADR amendment lists this divergence. Fix: add a fixture case with a `divergence` note and mention it in the ADR 0029 amendment.
3. **nit** `src/tests/fixtures/frontmatter-parity.fixture.json:283`. The criterion says `0x1F` / `0o14` / `.inf` use `rustExpected`. The fixture puts the Rust value in `expected` and the yaml value in `tsExpected`, and no case uses `rustExpected`. Both sides check the same thing, so nothing is weaker. The integer case above 2^53 has no `divergence` note, and the ADR amendment does not mention it. Fix (optional): add a one-line `divergence` note on that case, or leave it, since the fixture `description` explains the convention.
