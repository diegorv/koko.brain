## Findings

1. **minor** `src/lib/features/properties/lifecycle.service.ts:44` (with `lifecycle.logic.ts:54`): on an archived note whose `_organized` is not true, the Organized button (and Cmd+E) shows "Set note as organized", and turning it on also removes `_archived`, so the note is silently restored without the user picking "Restore this archived note". The old row hid Organize on archived notes, so this path is new to users, and a Cmd+E slip can now unarchive a note (and fire the type's Unarchive auto-move rule). Fix: either keep `_archived` when the bar turns Organized on (pass a variant that does not drop it), or say in `help/documentation/03-editor.md` / `25-types-and-relationships.md` that Organized on an archived note restores it, and add a bar test for that state.
2. **minor** `src/tests/lib/features/note-action-bar/note-action-bar.service.test.ts:35`: the confirmed Delete path is checked only through mock calls (`ask` and `deleteItem` `toHaveBeenCalledWith`), which docs/TESTING.md rules out as the sole assertion; `NoteActionBar.test.ts` covers only the declined case. Nothing shows the tab closes or the note reaches the trash from the bar. Fix: in `NoteActionBar.test.ts`, confirm the dialog with the real `fs.service` (mock only the Tauri trash/`invoke` boundary) and assert `editorStore.tabs` no longer holds the path, or add an E2E step that deletes from More and checks the file left the vault.
3. **nit** `src/tests/lib/features/properties/lifecycle.service.test.ts:199`: the "keeps a frontmatter edit" test never seeds `propertiesStore` with the pre-edit properties, so it does not stage the stale write-back the criterion names (it passes because the old code dropped the write, not because it refused stale data). Fix: `propertiesStore.setProperties([{ key: 'status', value: 'todo', type: 'text' }], A)` before `onContentChange`, then keep the same assertions.
4. **nit** `src/lib/features/note-action-bar/note-action-bar.logic.ts:30`: re-implements the first-letter casing that `type-definitions.logic.ts:154` (`normalizeTypeCasing`) already mirrors from Rust, and adds a `trim()` that Rust's `extract_is_a` (`entry.rs:356`) does not apply. Fix: export and reuse `normalizeTypeCasing` so the label always matches `is_a`.
5. **nit** `e2e/specs/note-action-bar.spec.ts:76`: the "no lifecycle row" check looks for `Organize`, `To Inbox`, `Unarchive`, `Favorited`, but not the old row's `Archive` and `Favorite` buttons, which were the ones shown on a fresh note like `Welcome.md`. Fix: add `Archive` and `Favorite` to the list (exact names do not collide with the bar's "Add to favorites" / "More note actions").
