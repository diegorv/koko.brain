## Findings

1. **blocker** — `src/lib/features/properties/bookmark-migration.service.ts:60-72`: the migration writes to any path the bookmarks file names, including notes outside the open vault. Bookmark paths are absolute and read from a file (a real boundary), and the Tauri fs scope is all of `$DOCUMENT/kokobrain-vaults/**`, so a vault folder that was copied (bookmarks.json still pointing at the original vault) makes opening the copy add `_favorite: true` to the ORIGINAL vault's notes, run `notifyAfterSave` / `update_note_in_index` for a foreign path, and then delete the copy's bookmarks file, so the copy never gets its favorites. Confirmed with a throwaway probe (`/other-vault/Note.md` bookmarked from `/vault`: the note was rewritten; probe removed). Fix: treat a path that does not start with `${vaultPath}/` as dropped (named in the toast) before any `exists` / write, and add a unit test for it. CLAUDE.md's "a path that is not inside the vault ... is skipped - never fall back to the absolute path" is the same rule.
2. **minor** — `src/lib/features/properties/bookmark-migration.service.ts:73-79`: a vault switch while the migration runs makes `updateNoteFrontmatter` throw `vault-changed`; it is counted in `failed`, so the user sees "Could not mark these bookmarked notes as favorites ..." about the vault they just left, on top of the new vault. Fix: on `FrontmatterWriteError` with reason `vault-changed`, stop and return without a toast (the file is kept, so the next open of that vault finishes it).
3. **nit** — `src/lib/features/properties/bookmark-migration.service.ts:21-31`: a bookmarks file that is not valid JSON is deleted with no toast and no log line. The old loader also treated it as empty but left the bytes on disk. Acceptable as chosen; consider at least an `error('BOOKMARKS', ...)` before the delete so the loss is visible in the session log.
4. **nit** — `CLAUDE.md:65` still lists `bookmarks` among the features, and `docs/architecture/archify/vault-lifecycle.*` / `graphify-out/*` still mention `loadBookmarks`. The build left them for the owner (CLAUDE.md is not this workflow's to edit; the maps need regenerating). Owner follow-up, not a code fix.
