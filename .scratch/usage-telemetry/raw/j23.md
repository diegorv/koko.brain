## Findings the scouts missed

- **N1 (medium, symbolication).** The debug-images feature is off, so native symbolication cannot work even with an uploaded dSYM. Fixing it requires debug-images, a dSYM upload in CI, and a privacy note about the library paths it sends. Today's privacy-friendly config and symbolicated Rust panics are mutually exclusive. Evidence: `process.rs:103,116`; `defaults.rs:59-65` (debug-images only behind the feature); the Sentry debug-meta doc above.
- **N2 (low).** `send_default_pii(false)` at `error_monitoring.rs:53` does nothing in this build (see S02-F5). The comment and `PRIVACY.md` imply it protects something. Either keep it as intent, with a comment that it gates nothing here, or rely on `before_send`.
- **N3 (low).** A panic hook flush can block the panicking thread for up to `shutdown_timeout` = 2 s (`clientoptions.rs:913`, `sentry-panic lib.rs:37`). A main-thread panic while offline stalls the UI before the process unwinds or aborts.
- **N4 (info).** Panics that are caught are still reported as `handled: false`, `fatal`, because the hook runs before unwinding. The watcher bridge (`vault/watcher.rs:288`) recovers from its panics, but Sentry shows them as fatal.
- **N5 (info, defense in depth).** The Rust side accepts any parseable DSN (`error_monitoring.rs:46-48`). The Sentry Cloud domain allowlist exists only in the frontend (`sentry.logic.ts:2-27`), and the Rust reqwest transport is not bound by the webview CSP. Only the webview's own IPC can call the command, so the risk is low.
- **N6 (info).** The JS path covers Rust errors too: every `Err(String)` passed to `error()` becomes event text. A scrubber added only on the Rust side would leave the larger leak (s5 F2 and F4) open. The JS scrubber is the higher priority.

## Verdict

Rust Sentry is configured correctly at its core: panic capture is installed, the opt-out works, and the event surface is minimal. There are three real gaps, in priority order:

1. **Paths in error text.** Absolute vault and note paths reach Sentry as error text through the JS path (s5 F2 and F4, N6). Fix this first with a JS `beforeSend` text scrubber.
2. **Hostname in `server_name`.** Every Rust event carries the hostname, and `PRIVACY.md` does not disclose it. The fix is one line plus a test: `server_name("kokobrain")`, or clear it in `before_send`.
3. **No symbolication.** JS has no source maps, and native frames are unsymbolicated, which needs debug-images plus a dSYM upload (N1). That costs a CI secret and some privacy. The owner should decide it before anyone does work on it.

The reconfigure stale-hub issue is real but rare (low). The SDK bumps are routine, but 11.11.0 is still inside quarantine. Keep the hand-rolled integration rather than adopting `tauri-plugin-sentry`.

**Not verified:** JavaScriptCore's JSON error text, server-side IP storage and scrubbing settings, a real shipped event payload, and whether `strip = true` with line-tables debug info still produces a dSYM.
