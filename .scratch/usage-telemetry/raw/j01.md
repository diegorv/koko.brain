## Findings

**F1. high. Sourcemaps are never generated or uploaded (JS symbolication impossible).**
- Evidence: `vite.config.js:57-101` (the SvelteKit/Vite config; there is no `svelte.config.js` in the repo root, and no `build` section sets `sourcemap`). Vite 8.3.5 `node_modules/vite/dist/node/chunks/node.js:34605` sets `sourcemap: false` as the build default. Kit only forces SSR sourcemaps on (`node_modules/@sveltejs/kit/src/exports/vite/index.js:377-378`). `build/` has 0 `.map` files. `.github/workflows/release.yml:122-141` runs `tauri-apps/tauri-action` with no sourcemap upload step. A grep of `.github`, `scripts`, `vite.config.js` for `sentry-cli|SENTRY_|sourcemap` finds nothing relevant.
- Docs: Sentry says "To enable readable stack traces in your Sentry errors, you need to upload your source maps to Sentry" and recommends a bundler plugin for Vite or sentry-cli (https://docs.sentry.io/platforms/javascript/sourcemaps/).
- Fix: set `build.sourcemap: 'hidden'` in `vite.config.js`. Upload the maps and inject debug IDs with `@sentry/vite-plugin` or `sentry-cli`, using a `SENTRY_AUTH_TOKEN` secret added to `release.yml`/`nightly.yml`. Delete the maps from the shipped bundle (`hidden` already keeps the `sourceMappingURL` comment out). Tradeoff: needs a CI secret and an upload step.

**F2. high. Rust release binary has no debug symbols and no dSYM.**
- Evidence: `src-tauri/Cargo.toml:84-90` sets `[profile.release]` with `lto = "thin"`, `strip = true`, `codegen-units = 1`, and does not set `debug`. Cargo docs: `strip = true` is `"symbols"`, and `debug` defaults to none for release (https://doc.rust-lang.org/cargo/reference/profiles.html). `release.yml` has no `dsymutil` or `sentry-cli debug-files upload` step. `nightly.yml` also builds with the release profile (only `codegen-units` is overridden, `nightly.yml` env block).
- Sentry's Rust SDK sends stack frames with image addresses. Without a dSYM, the server cannot name the functions.
- Fix: in the release profile, use `debug = "line-tables-only"` (or `debug = 1`) and keep `strip` only for the shipped binary, then upload the dSYM with `sentry-cli debug-files upload`. Or stop stripping and upload the dSYM. Tradeoff: larger artifacts and a CI upload step. `release-fast` (`Cargo.toml:98-102`) already has `strip = false` but is not used for shipping.

**F3. medium. Release string is per version, not per build.**
- Evidence: `src/lib/core/settings/sentry.service.ts:19-22` returns `kokobrain@${buildInfo.split(' ')[0]}`. For stable, `__BUILD_INFO__` is `4.0.0-beta.3 (<sha>) (<time>)` (`src/lib/utils/build-info.js:69-73`), so the `(<sha>)` is dropped. Every beta.3 build, including the Vite dev server (the same `vite.config.js:93` define), reports release `kokobrain@4.0.0-beta.3`. Nightlies yield `kokobrain@4.0.0-beta.3.nightly.N.<sha>`. The Rust side receives the same string (`src-tauri/src/error_monitoring.rs:52`).
- Consequence today: the release name only groups events. Once F1 is fixed, a per-version name without a build identifier can match the wrong source map.
- Fix: use `kokobrain@<version>+<sha>` (keep the sha) for the release name, and pass the same value to the upload step.

**F4. medium. No `environment` is set, so dev and shipped events are mixed.**
- Evidence: `sentry.service.ts:58-85` (`Sentry.init`) and `error_monitoring.rs:49-55` (`ClientOptions::new().release(...).send_default_pii(false).max_breadcrumbs(0)`) do not set `environment`. The channel is already available as `__APP_CHANNEL__` (`vite.config.js:94`, `build-info.js:85-90`).
- Sentry docs (Rust): `SENTRY_ENVIRONMENT`, else `development` when debug assertions are on, else `production` (https://docs.sentry.io/platforms/rust/configuration/options/). Sentry docs (JS options table): the default is `production`, with a note that it depends on whether the app is packaged (https://docs.sentry.io/platforms/javascript/configuration/options/). The exact JS v11 fallback is UNVERIFIED.
- Fix: pass `environment: __APP_CHANNEL__`, or `stable`/`nightly`/`dev`, to both clients. Consider `environment: 'dev'` when `import.meta.env.DEV` is true.

- `release`: `kokobrain@4.0.0-beta.3`. `environment`: Rust `production` (release profile, no debug assertions), JS `production` per docs (UNVERIFIED in v11 for this init).
- Frontend exception: `beforeSend` removes `breadcrumbs`, `extra`, `request` and `user` (`sentry.service.ts:28-36`). The stack frames point at the minified chunk under the webview's asset origin with minified function names and line/column numbers (exact frame URL UNVERIFIED). No source context (`frameContextLines: 0`, line 82).

- Exception `value` text is kept. `captureException(exception)` (`sentry.service.ts:116`) and `debug.ts:31` forward error messages verbatim. A message can contain a vault path or note-derived text. This is a content risk for the privacy scouts, not a symbolication issue.
