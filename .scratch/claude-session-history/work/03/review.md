## Findings

1. minor, `src/lib/features/claude-code/ClaudePanel.svelte:299`: New chat leaves the history view open. With the list showing, clicking New chat resets the chat but the panel stays on the list, so the user gets no empty chat and has to press the history button or Escape as well. Fix: have the New chat handler also call `showChat()` (and add a panel test), or record the choice in the discovery defaults.
2. minor, `src/lib/features/claude-code/ClaudePanel.svelte:354`: a chat opened from the history list shows "Restored last chat. New chat starts over.", but an older chat picked from the list is not the "last" chat. The build report records this as a deliberate default. Fix: let the notice say something neutral, such as "Restored chat.", or ask the owner. This is a copy change, so it can go to a follow-up.
3. minor, `src/lib/features/claude-code/ClaudePanel.svelte:437`: Escape in the note picker also closes the history list, because the picker's keydown does not call `preventDefault`, so `onPanelKeydown` acts on the same key. The build report names this risk. Fix: call `e.preventDefault()` in the picker's Escape handler, the way the slash menu does, and add a test next to "Escape that closes the slash menu leaves the list open".
4. nit, `src/lib/features/claude-code/ClaudePanel.svelte:149`: while the list loads, `history` is `null` and the list area is blank, with no loading line. A load dropped by `historyStale` because a turn started also leaves it blank until the view is toggled. Only the store can reach that second case today (the panel's send switches to the chat view first), so it is cosmetic. Fix, optional: show a "Loading..." line while `history === null && !historyError`.
5. nit, `src/lib/features/claude-code/ClaudePanel.svelte:16`: the panel imports `formatRelativeTime` from `features/type-definitions/type-sidebar.logic.ts`, which adds a feature-to-feature pair for a generic date helper. ADR-0003 allows it (acyclic, recorded in `featurePairs`). Moving the helper to `utils/` would be a refactor outside this Issue, so the fix is to note it for a later cleanup.

## Resolution

1. Fixed. The New chat button calls `newChat()` and then `showChat()`, so New chat from the list lands on an empty chat. Test: "New chat from the list goes back to an empty chat" in `ClaudePanel.test.ts`.
2. Deferred, not changed. The notice text "Restored last chat. New chat starts over." is fixed by `spec.md` (On vault open) and Issue 02's Notice criterion, and discovery records reusing it for a chat opened from the list. Neutral copy for that case is an owner decision; it belongs in a follow-up.
3. Fixed. The note picker's Escape handler calls `e.preventDefault()`, so `onPanelKeydown` leaves the list open. Test: "Escape that closes the note picker leaves the list open", next to the slash-menu Escape test.
4. Not changed (optional nit). The blank list during a load is brief, and the dropped-load case is reachable only through the store today.
5. Not changed. Moving `formatRelativeTime` to `utils/` is a refactor outside this Issue; noted for a later cleanup.
