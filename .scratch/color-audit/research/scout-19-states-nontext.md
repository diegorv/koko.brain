# Scout 19: interaction states and non-text contrast

Read-only audit. Area: focus rings, text selection, active line, caret, input borders, switch/checkbox/radio, disabled and placeholder text, scrollbars, dividers, selected-state indicators. All 28 themes.

Scripts and raw output: /private/tmp/claude-501/-Users-diegorv-Dev-pet-projects-koko-brain/d34954df-1fbf-4743-96fe-27db3527c128/scratchpad/audit-19-states-nontext/ (lib.mjs is scout 02's resolver; c1..c7.mjs with .out files, sel.mjs, acc.mjs, sn.mjs, ph.mjs, nofocus.mjs).

## Method

- Resolved every theme's cssVars (theme-tokens.json) plus the app.css derived vars (rail/nav/list tones, event, meta-bind, code) with scout 02's resolver (var(), color-mix oklab/srgb/oklch, relative color). WCAG 2 ratio and APCA Lc. Alpha fills (`ring-ring/50`, `bg-muted-foreground/30`, `--syntax-selection` with alpha, `#bad0f847`) composited in gamma sRGB over the real surface. Thresholds: text 4.5, meaningful non-text 3.
- Traced each color to its file:line by reading the component classes. Selection: `editor-theme.ts:58-60` sets only `background-color` on `.cm-content ::selection`; no `drawSelection()` anywhere, so CodeMirror's `hideNativeSelection` (view/dist/index.js:9696) is not active and the native selection paints, text keeps its own color. Active line: `editor-theme.ts:55-57` (source mode only; live preview forces transparent, styles.ts:83-86).
- Focus: Tailwind `ring-ring/50` compiles to the ring color at 50% alpha. Base layer `* { outline-color: var(--ring) }` (app.css:~490) only sets the color of the UA focus outline.
- Not run: no browser (WKWebView rendering of `::selection`, `accent-color` checkboxes and the UA focus outline not seen).
