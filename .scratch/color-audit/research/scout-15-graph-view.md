# Scout 15: graph view colors

Read-only audit of `src/lib/plugins/graph-view` (GraphView.svelte, GraphControls.svelte, graph-view.logic.ts) on all 28 themes.

## Method

- Traced the palette: `readPalette()` (GraphView.svelte:73-82) reads `--editor-bg`, `--foreground`, `--muted-foreground`, `--primary` from the root and calls `graphPalette()` (graph-view.logic.ts:283-300), which derives every canvas color in OKLab: label = mix(fg, muted, .5); node = muted; nodeActive = primary; nodeDimmed = mix(muted, bg, .8); edge = mix(muted, bg, .4); edgeHighlight = mix(primary, bg, .5); labelDimmed = mix(label, bg, .7). Background = `--editor-bg`. So the canvas follows the theme on light and dark. Nothing is hard-coded for dark except `FALLBACK_GRAPH_PALETTE` (graph-view.logic.ts:259), used only when a token is empty or unparseable. All 28 themes' four tokens are hex and parse, so the fallback never triggers on them. The fallback itself passes (label 6.77, node 5.09, active 6.57 on #1a1a1e), but its background is also dark, so a theme with an unparseable token would get a dark canvas inside a light app (not measured, no such theme exists in the data).
- Overlay chrome (GraphControls.svelte, the stats pill in GraphView.svelte:555) uses Tailwind tokens on `bg-background/90` over the canvas (`--editor-bg`). I flattened 0.9 alpha `--background` over `--editor-bg` (backdrop-blur and nodes underneath ignored).
- Measured with color-tools.mts `contrastRatio`, `mixColors`, `flatten`, `colorDistance`, and APCA (same constants as `labelColors`). Scripts: scratchpad `audit-15-graph-view/m.mts`, `m2.mts` (full table in `full.tsv`).
- Canvas text size: `fontSize = max(10, 11/k)` in graph space, drawn at scale k, so 11 to 13 px on screen (small text, 4.5). Edge widths: 0.5 (1.5 highlighted) graph px times zoom, default zoom 1.3.

## Findings

1. [medium] Center-note node vs ordinary node, `nodeActive` (primary) vs `node` (muted-foreground). Same radius, same alpha, differ by hue only. WCAG ratio between them under 1.5 on 23/28 themes; perceptual OKLab distance (x100) is 4.9 on KokoBrain Default (#9ba3da vs #95a0b9, ratio 1.08), 5.3 Mint Linen, 6.0 Twilight Violet, 6.2 Cool Mist, 6.5 Graphite Violet. Other themes have distance 9 to 25 (visible hue difference). The center node is the only "you are here" marker in the global graph and the anchor of the local graph. graph-view.logic.ts:295-296, GraphView.svelte:328-329. Each color alone passes 3:1 on the background (worst 4.52, so no failure there).
2. [medium] Edge hairlines: `edge` color on the canvas is 3:1 or less on 21/28 themes at full pixel coverage (worst 2.31 Zettlr Bielefeld Light #a1a1a3 on #f3f3e8, 2.41 Tolaria Light, 2.44-2.45 other Zettlr light, 2.48 Zettlr dark, 2.53 Twilight Violet, 2.73 KokoBrain Default, 2.60 Lavender Haze). The line is 0.5 graph px wide (GraphView.svelte:231), so at dpr 1 it is about half covered and the effective ratio is 1.47 to 1.9 on every theme. Links are the content of the graph, so meaningful non-text. Hover highlight (`edgeHighlight`, 1.5 px) is 1.8 to 2.5 on 27/28 and its hue is within 1.0 to 1.2 of the plain edge on 25/28; only the width distinguishes it. graph-view.logic.ts:289-290, GraphView.svelte:230-231.
3. [medium] Global/Local mode toggle selected state (GraphControls.svelte:45-47, 56-58): selected = `bg-muted` + `text-foreground`, unselected = `text-muted-foreground` on the panel (`bg-background/90`). `--muted` vs panel is 1.01 to 1.25 on all 28 (Shimmering Focus Light 1.01, Willemstad Dark 1.05, KokoBrain Default 1.06, Cool Mist 1.07), and the icon difference foreground vs muted-foreground is only 1.25 to 2.74 (1.25 Shimmering Focus Dark, 1.55 Willemstad Light, 1.58 the five Zettlr light themes). No other indicator besides `aria-pressed`. Selected-state indicator needs 3:1.
4. [medium] Form control boundaries in the filter and display panels. Search input `border-border` vs panel: 28/28 under 3:1 (1.06 KokoBrain Default, 1.13 Tolaria Light, 1.22-1.27 others; GraphControls.svelte:121). Tag and folder Select trigger `border-input` vs panel: 26/28 under 3:1 (1.06 KokoBrain Default, 1.26 Twilight Violet, 1.28 Sakura, 1.34 Lavender Haze; GraphControls.svelte:141, 159; select-trigger.svelte:22). The chevron is `opacity-50` muted-foreground: 1.94 to 2.1 on light themes, 27/28 under 3:1 (select-trigger.svelte:28). Orphans/Arrows Switch unchecked track vs panel: 26/28 under 3:1 (worst 1.25 Twilight Violet, 1.28 Sakura, 1.32 Tolaria Light, 1.38 Lavender Haze, 1.53 to 1.57 the other light themes); on 14 light themes the thumb (`bg-background`) on the track is also 1.28 to 1.67 (switch.svelte:13, 21). Text inside (foreground, placeholder, muted labels) passes. This is the same cause as scout-02 finding 10 (input) extended to the select and switch; the tokens come from the themes repo, the usage from shared ui components.
5. [low] Labels drawn over other nodes' circles: `selectLabels` only compares label rectangles (graph-view.logic.ts doc at the function, GraphView.svelte:316), so a label can overlap a neighbouring node. Label color on `node` color: 1.12 to 1.71 on every theme (worst 1.12 Shimmering Focus Dark, 1.25 on the five Zettlr light themes, 1.29 Tolaria Dark); on the active node 1.05 to 2.61 (1.05 Zettlr Bielefeld Dark). No halo or outline behind text. Label on background alone passes (see below). Density dependent, so low.
6. [low, deliberate de-emphasis] On hover, unconnected nodes use `nodeDimmed` (1.22 to 1.33 on bg, worst 1.22 Willemstad Dark, 1.29 Zettlr Bielefeld Light) and their labels `labelDimmed` (1.57 to 1.73 on every theme; APCA Lc 0 to 30, near zero on dark themes). Text at this contrast is below any threshold. Probably intended (focus mode) but the text stays drawn when the zoom gate admits it, so it reads as a faded unreadable label. graph-view.logic.ts:288, 291; GraphView.svelte:330-338.

## Passed (measured)

- `label` on `--editor-bg`: all 28 pass (worst 5.66 Zettlr Bielefeld Light, APCA Lc 53.5 minimum on Zettlr Bordeaux Dark; Lc 74-81 on light themes).
- `node` (muted-foreground) on bg: worst 4.52 (all pass 3:1); `nodeActive` on bg: worst 4.52 Shimmering Focus Light and Sakura, 4.53 Twilight Violet (all pass 3:1).
- Centered messages (`text-muted-foreground`, 14px, on `--editor-bg`): all pass, worst 4.52 Zettlr Bielefeld Light, 4.53 Zettlr Berlin/Bielefeld Dark; APCA Lc 39 minimum on the dark Zettlr themes and Twilight Violet (under 45, not raised: WCAG passes and it is the shared muted-foreground token).
- Overlay text on the panel: muted text (Orphans, Arrows, Depth, section-label 11px, stats pill 12px) worst 4.62 Tolaria Light; foreground on panel worst 7.30; input text worst 7.31; placeholder worst 4.58; select trigger text worst 7.30. Depth digit/foreground on panel passes. The same muted text on dark themes has APCA Lc 39 minimum (Twilight Violet), under 45 for 11px section labels; not raised as a finding (WCAG passes everywhere; same value as the shared muted-foreground token, covered by other scouts).
- Focus ring (`ring-ring` on the search input) vs panel: all pass, worst 4.12 Shimmering Focus Light. Switch checked track (primary) vs panel: worst 4.12.
- Fallback palette: label 6.77, node 5.09, edge 3.26, edgeHighlight 2.61 on its own dark background (active vs node only 1.29, same hue issue as finding 1).
- Disabled Depth +/- buttons are `opacity-50` (1.94 to 2.1 on light): disabled controls are exempt, not reported.
- Panel borders (`border-border` vs editor-bg 1.09 to 1.34) are decorative containers, not counted.

## Not checked

- Real rendering (browser, antialiasing, backdrop-blur and the nodes passing under the translucent panels): resolved by arithmetic only, `bg-background/90` treated as plain alpha.
- Hover color of the zoom/mode buttons (`hover:text-foreground`, no background change): foreground on panel passes, so not measured further.
- User custom themes with non-hex tokens (graph would fall back to the dark palette): not in the data.
- Button ghost hover (`hover:bg-accent`) on the Depth buttons: shared component, other scouts.
