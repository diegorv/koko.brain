## Findings

1. minor — `src/lib/features/collection/collection.types.ts:71`: the Issue lists `NoteRecord` for deletion, but the build kept it and allowlisted it. I agree with the deviation. `properties` is a `Map<string, unknown>` that `collection.service.ts:32 fromV2` builds from the wire `NoteRecordV2`. Swapping in the generated `{ [key in string]: JsonValue }` would change the runtime shape that collection and kb-api read with `.get()`. The wire side already uses the generated type. The second criterion allows an explicit allowlist, so this is not a blocker. Fix (optional, owner's call): rename it to something like `PropertyIndexRecord`, which removes the name collision and the allowlist entry, as the Issue already offers for `FileTaskGroup`. Deliver should flag the deviation to the owner.
2. minor — `src/lib/core/filesystem/fs.types.ts:10` and `src/lib/features/file-history/file-history.types.ts:3`: replacing the hand-written types dropped their per-field JSDoc, because these Rust structs have no field `///` docs. Lost: the `FileTreeNode.modifiedAt` / `createdAt` "timestamp in ms" notes, `SnapshotInfo.timestamp` "Unix ms", and `DiffLine.oldLineNum` / `newLineNum` "1-based, absent for inserts/deletes". The new `vault-v2.types.ts` header says "Field docs live on the Rust structs". That holds for the vault types but not for `FileNode`, `SnapshotInfo`, `DiffLine` or `FtsSearchResult`. Fix: in a follow-up, add `///` field docs to those Rust structs and regenerate the bindings with cargo test. Not needed for this Issue.
3. nit — `src/lib/contracts/index.ts:1`: nothing checks that the barrel stays complete. A type ts-rs generates later but leaves out of `index.ts` only shows up when an importer fails to compile. Fix: add a check to `ipc-mirrors.test.ts` that every name from `generatedNames()` appears in `index.ts`.
4. nit — `e2e/mocks/tauri-core.ts:211`: `handleBuildSearchIndex` returns only `{ totalDocuments }`, while `SearchIndexStats` now requires all five counters. `e2e/` sits outside `tsconfig`, so `pnpm check` does not see it. The app reads only `totalDocuments` (`SearchPanel.svelte:99`, `SearchStatus.svelte:22,27`), so nothing breaks. Fix: in a follow-up, have the mock return `added/updated/removed/unchanged: 0` so it matches the contract.
