# Architecture stability

Make Kokobrain easier to grow and change, with fewer bugs. This is an incremental plan: no big-bang migration, no rewrite. We stay on Svelte 5 and Rust/Tauri.

From t3code we take one idea: a contract with a single source of truth, plus boundaries that a test enforces. We do not adopt its apps/ layout, Effect, or the one-server-many-clients shape.

The order is:
1. Detect bugs.
2. Remove whole classes of bugs.
3. Limit the blast radius of each change.
4. Only then restructure.

The Issues under `issues/` go through relay-lite (`/relay-lite:run architecture-stability`), not through the plan-mode one-task-at-a-time sequence. Each Issue ships on its own; its **Blocked by** line sets the order, and cross-feature blockers use the "Also blocked by `<path>`, in another feature" line. All Issues start as `needs-triage` (or `needs-info` when deferred), so relay-lite picks none until the owner triages them. Progress lives in the relay-lite ledger; tick the checkbox here in each Issue's done commit.

- **Review gap.** In 14 of the 21 recent relay-lite squashes, app code was committed after the final review. That is the direct evidence for issue 01. The line-level fix-of-fix rate rose from 9.5% to 39% after August, but that rise came under the old implement-brain-issue workflow. Its cause is inferred, not proven.
- **Hotspots.** Raw counts overstate them: most event-calendar fixes (61 of 64) and live-preview fixes (26 of 51) were in-run review fixes made before merge.
- **Layers.**
  - 33 core files import features or plugins (76 baseline entries outside the 9 composition roots).
  - One import cycle spans 10 features.
  - There are 147 feature->feature import lines, against an ADR that forbids them.
  - No linter exists.
- **Contracts.**
  - 57 commands, 7 events and 29 DTOs are copied by hand into TS.
  - The E2E mock lacks 13 commands.
  - The Rust frontmatter parser misreads app-written YAML: `|-` block scalars and quoted commas.
- **ADR-0005.** Its premise is false: a module-level `$derived` stays fresh under vitest 5.0.5 / Svelte 5.57.2. Getters stay anyway, because Svelte forbids exporting derived state.

**Decisions.**
- Keep the repo root as the app. Add no `apps/` until a second app exists.
- Use ts-rs, not tauri-specta: tauri-specta 2.0.0-rc.26 pins tauri ^2, and the v3 branch is live.
- Not doing:
  - a React port;
  - Electron;
  - a Rust-to-TS rewrite;
  - framework-neutral stores;
  - packages/ui;
  - packages/domain.

  Revisit only on a concrete trigger: a committed mobile client, a networked multi-client server, or a blocking React-only library.
- The Rust crate split and the editor package are structure only, so they wait for a second consumer. The Tauri-free guarantee comes from issue 26's ratchet instead.

**Close-out.** When every non-deferred Issue is done, delete this plan in its own closing commit (done is recorded in the commit message). The deferred Issues (28, 29, 30, 33) and the wontfix 25 stay as files until each is closed the same way.
