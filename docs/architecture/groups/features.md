src/lib/features holds the always-loaded built-in features of the app. Most folders follow the same shape: pure .logic.ts files, a .store.svelte.ts with module-level reactive state behind getters, a .service.ts for side effects (IPC through the typed call() wrapper, Tauri plugins, core services), and Svelte components; some folders are smaller (copy-block-link is one service, note-list has only components and types, dock-badge has one logic and one service file). Most features read from the Rust VaultIndex through IPC. Backlinks, outgoing-links, tags, tasks and event-calendar refetch from their own components when vaultStore.vaultIndexVersion changes, while collection, type-definitions and the properties archived set are fed by src/lib/app/tauri-listeners.service.ts on vault-index-updated, and file-icons and collection also stay current through core/filesystem note-change consumers. A second group owns UI surfaces: rail-shell (left rail and note list), note-list (row and menu), quick-switcher, command-palette, note-action-bar, canvas. Dependencies point down to src/lib/core, with a cluster of cross-feature edges around type-definitions, collection and file-icons, which rail-shell, auto-organize, note-list, properties and event-calendar consume. Because features may not import plugins, plugin extension points live in features or core and plugins register into them: rail-shell (railRegistryStore), note-action-bar (actions store), event-calendar (daily-note store), deep-link (action handlers registered from src/lib/app) and core/rule-actions (read by auto-organize). Separate ports filled from src/lib/app/boot.ts avoid feature-to-feature edges: the collection view row-set port (the rail's row rule) and the file-icons type icon lookup (type-definitions data). Lifecycle wiring (vault open, teardown, reset functions, consumers) is done from src/lib/app, and the deep-link listener is registered from src/routes/(app)/+layout.svelte.
