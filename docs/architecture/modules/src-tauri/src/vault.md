summary: "Rust vault metadata model: note parsing, the in-memory VaultIndex with reverse indexes, task-line edits, snapshot cache and file watcher."

## Responsibility

Owns the Rust-side model of a vault's markdown metadata. It parses each note into a NoteEntry (frontmatter, wikilinks, tags, tasks, task headings) with byte-level scanners (parsing.rs, entry.rs), resolves frontmatter key aliases to canonical keys (aliases.rs), defines the task types and projections (task.rs), keeps entries in the in-memory VaultIndex with its reverse indexes for backlinks, tags, properties and wikilink resolution (index.rs), computes guarded task-line edits as pure string transforms (task_lines.rs), encodes the MessagePack index snapshot (index_cache.rs), and runs the notify-based watcher that debounces file-change events (watcher.rs). It does not own the Tauri command surface (commands/vault.rs and commands/watcher.rs), the directory tree scan, the disk reads and writes of task edits, or any frontend state.

## Key files

- `src-tauri/src/vault/mod.rs`: Declares submodules and defines VaultIndexState, the RwLock<VaultIndex> that lib.rs manages.
- `src-tauri/src/vault/index.rs`: VaultIndex: mutation only through build, build_with_root, update_entry and remove_entry; lookup methods serve the IPC commands; match_unlinked_mentions.
- `src-tauri/src/vault/entry.rs`: NoteEntry and the link, record and relationship types, with from_content as the construction point.
- `src-tauri/src/vault/parsing.rs`: Byte-level scanners for frontmatter, wikilinks, tags, tasks and task headings that mirror the TypeScript extractors.
- `src-tauri/src/vault/task_lines.rs`: apply_task_line_edits: edits located by an anchor plus the expected line, with stale-outcome reporting.
- `src-tauri/src/vault/watcher.rs`: Native file watcher: notify thread, debounce loop, hidden-directory and temp-file filters, replace_watcher and stop_watcher.
- `src-tauri/src/vault/index_cache.rs`: Versioned MessagePack snapshot of NoteEntry records, written atomically under the vault folder.
- `src-tauri/src/commands/vault.rs`: Main consumer: every vault IPC command locks VaultIndexState and calls into this module.

## State

- VaultIndexState: process-wide RwLock<VaultIndex>, in memory only (mod.rs, managed in lib.rs).
- VaultWatcherState: Mutex<Option<VaultWatcher>> holding the running notify watcher and its bridge thread (watcher.rs, managed in lib.rs).
- On-disk index snapshot at <vault>/.kokobrain/vault-index.msgpack written by index_cache.rs; reverse indexes are not persisted and are rebuilt on load.
- ts-rs bindings for the #[ts(export)] types in this folder are written to src/lib/contracts/generated by cargo test.

## Collaborators

- `src-tauri/src/commands`: commands/vault.rs holds every vault IPC command and calls VaultIndex, parsing, task, task_lines and index_cache; commands/watcher.rs wraps replace_watcher and stop_watcher.
- `src-tauri/src`: lib.rs manages VaultIndexState and VaultWatcherState.
- `src-tauri/src/utils`: entry.rs and index.rs use fs::is_view_filename; watcher.rs and parsing.rs use logger::debug_log; watcher.rs matches the utils::fs::write_atomic temp-file naming by string, without importing it.
- `src-tauri/src/search`: Not a dependency. search::fts_logic::extract_tags is a separate, broader tag extractor that intentionally differs from parsing::extract_tags_strict.
- `src/lib/contracts`: Generated ts-rs types such as NoteEntry, Task, UpdateResult, VaultFilesChangedPayload and TaskLinesWriteResult, plus the command and event maps for the vault and watcher surface.
- `src-tauri/tests`: Index, cache, watcher, alias, task, task-line, type-rename and parity tests (frontmatter and task headings against shared fixtures) import this module.
- `event:vault-files-changed`: Debounced, filtered paths from watcher.rs, emitted by commands/watcher.rs with VaultFilesChangedPayload.
- `event:vault-index-updated`: Emitted by commands/vault.rs after VaultIndex mutations with an UpdateResult.

## Gotchas

- VaultIndex fields are private. Mutation goes only through build, build_with_root, update_entry and remove_entry so entries, by_path, by_file_name, backlinks, tags_index and properties_index stay in step. The version counter is bumped on every update_entry call, including no-ops.
- properties_index is write-only in production code: it is kept populated and pruned with entries, and only the properties_index() accessor (used by tests) reads it.
- The watcher never touches VaultIndex. It emits debounced paths, and index updates come from frontend calls to update_note_in_index and remove_note_from_index.
- Watcher filtering ignores any path with a dot-prefixed segment at any depth and ignores write_atomic temp files. Ancestor paths are dropped when a deeper path is in the same burst.
- VaultWatcher::shutdown joins the bridge thread, so stopping can block for up to one debounce window.
- Task edits are located by the task anchor plus the expected line text, not by line number. The one exception is a replace with line_number, used for a line that carries no anchor yet, which still requires the expected line to match. The disk read and write for these edits happen in commands/vault.rs write_task_lines_inner.
- match_unlinked_mentions reads note files from disk without holding the index lock and is meant for spawn_blocking.
- parsing.rs states that each function mirrors a TypeScript extractor in src/lib/features. Parity tests in src-tauri/tests pin frontmatter and task headings against fixtures shared with the TypeScript tests, so changes there need matching fixture updates.
- index_cache.rs writes the snapshot through its own temp file, fsync and rename (not utils::fs::write_atomic) and stores only NoteEntry records. INDEX_SCHEMA_VERSION must be bumped when the NoteEntry shape or parser output changes, because a cache hit reuses entries whose mtime matches.
- Changing a #[ts(export)] type here changes the generated bindings in src/lib/contracts/generated, which cargo test writes.
