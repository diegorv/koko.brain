## Responsibility

Owns the frontend half of Quick Capture. note-composer.logic.ts builds capture paths, template variables and YAML-safe template processing. note-composer.service.ts creates and opens a note for Cmd+N. quick-capture.service.ts listens for qc:capture-detected from Rust, serializes handling, maps each payload to a deep-link CaptureAction, dispatches it and answers composer captures. It does not own the clipboard, global hotkeys, composer window or kind detection (src-tauri/src/quick_capture), the capture note writer (executeCaptureAction in src/lib/app/deep-link-actions.ts) or the composer page UI (src/routes/composer).

## Key files

- `src/lib/plugins/quick-capture/quick-capture.service.ts`: Listener for qc:capture-detected: serializes captures, builds a CaptureAction with buildCaptureAction, dispatches through executeAction and reports composer results.
- `src/lib/plugins/quick-capture/note-composer.logic.ts`: Pure builders buildCapturePath and buildCaptureVariables, getCaptureTitle and processCaptureTemplate with YAML-safe substitution.
- `src/lib/plugins/quick-capture/note-composer.service.ts`: createNoteComposer: builds the path and template from settingsStore.quickCapture and opens or creates the note.

## State

- No persistent storage in this folder. It reads settingsStore.quickCapture, periodicNotes and explicitOrganization and vaultStore path and name.
- A promise queue inside registerQuickCaptureListener serializes capture handling.
- Captured notes and staged shot files are written by callees (note-creator, deep-link actions), not by this folder.

## Collaborators

- `src/lib/core/settings`: settingsStore.quickCapture, periodicNotes and explicitOrganization drive paths, templates and the unorganized flag.
- `src/lib/core/vault`: vaultStore.path and name. With no vault, a capture is dropped with a toast.
- `src/lib/core/note-creator`: openOrCreateNote writes the Cmd+N note and withUnorganizedFlag is the content hook for explicit organization.
- `src/lib/core/frontmatter`: yamlScalar escapes capture text inside template frontmatter.
- `src/lib/features/deep-link`: executeAction dispatches each capture to the 'capture' handler registered in its action registry, and the CaptureAction and CaptureKind types come from deep-link.types.ts.
- `src/lib/plugins/periodic-notes`: buildWikilinkPath for the dailyNotePath variable. Allowed plugin-to-plugin import.
- `src/lib/contracts`: EVENT_NAMES, and the call and on wrappers for IPC and events.
- `src/lib/utils`: buildCaptureFolder, processTemplate and debug logging.
- `src-tauri/src/quick_capture`: The Rust half: mod.rs declares clipboard, commands, kind_detect, shortcuts and source. commands.rs holds the commands, the event emitters and LastCaptureSignature (suppresses repeated identical clipboard captures); source.rs holds PrevFrontmostPid (the app frontmost when the composer was summoned); shortcuts.rs is the closed set of global shortcut intents. Commands are registered in src-tauri/src/lib.rs.
- `IPC:report_composer_capture_result`: Called by quick-capture.service.ts to answer a composer capture with ok true or false.
- `IPC:submit_composer_capture`: Called by the composer route (src/routes/composer), not by this folder.
- `IPC:dismiss_composer`: Called by the composer route.
- `IPC:import_staged_shot`: Called by src/lib/app/deep-link-actions.ts before writing a shot note.
- `event:qc:capture-detected`: Emitted by Rust and listened to by quick-capture.service.ts.
- `event:qc:open-composer`: Emitted by the Rust show_composer helper and listened to by the composer route.
- `event:qc:composer-capture-result`: Emitted by report_composer_capture_result and listened to by the composer route.
- `src/lib/app`: deep-link-actions.ts registers the 'capture' deep-link handler (executeCaptureAction) and imports the logic functions, and commands.ts and global-keybindings.ts call createNoteComposer.
- `src/routes/(app)`: +layout.svelte calls registerQuickCaptureListener and returns its cleanup.

## Gotchas

- Rust builds capture payloads with json!, so no TypeScript type is generated. QuickCaptureDetectedPayload is hand-written and must match them. ComposerCaptureResult is generated by ts-rs.
- The listener chains captures on a promise queue. A multi-file clipboard capture emits one event per file in a tight loop, and concurrent writes could resolve the same timestamp filename.
- Only a payload with composerRequestId gets an answer through report_composer_capture_result. The composer keeps its text until it receives ok true. Clipboard and hotkey payloads get no answer.
- The composer runs in a separate webview, so it cannot call executeAction or read vaultStore. Its text reaches the main window through the qc:capture-detected event.
- With no vault open, dispatchCapture shows a toast and returns false, and the Rust dispatch_shortcut handler returns early when crate::db::is_open() is false.
- buildCaptureVariables seeds empty provenance variables so a Cmd+N template resolves the same placeholders. executeCaptureAction in src/lib/app/deep-link-actions.ts overrides every one of them with real per-kind values, so the defaults only take effect for the Cmd+N note.
- processCaptureTemplate escapes capture text only when the placeholder is the whole value of a key or list item in the template frontmatter.
- open_composer and capture_clipboard_now are registered commands, but no source file under src invokes them. The Rust hotkey path calls the helpers directly.
