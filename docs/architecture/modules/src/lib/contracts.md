## Responsibility

Owns the TypeScript side of the Tauri boundary. It holds the wire DTOs generated by ts-rs from Rust (re-exported by hand from index.ts), the CommandMap and the COMMAND_ARGS runtime manifest for every command registered in generate_handler, and EVENT_NAMES and EventMap for every event Rust emits. ipc.ts wraps invoke as call() and listen as on() so argument, result and payload types follow the command or event name, and it keeps the optional invoke-timing buffer used for queue-wait reporting. It is a leaf layer: it imports no #lib module and every layer may import it. It does not own the Rust command bodies or the Rust DTO definitions (src-tauri owns them and ts-rs emits them here), or feature-level TypeScript domain types.

## Key files

- `src/lib/contracts/index.ts`: Hand-maintained barrel that re-exports every generated type; ts-rs writes no index, so a new exported Rust type needs a line here.
- `src/lib/contracts/commands.ts`: CommandMap (args and result per command), derived CommandArgs and CommandResult types, and the COMMAND_ARGS runtime manifest read by the parity test.
- `src/lib/contracts/ipc.ts`: Typed call() over invoke and on() over listen, plus the invoke-timing buffer (setInvokeTracking, takeQueueWait).
- `src/lib/contracts/events.ts`: EVENT_NAMES mirror of src-tauri/src/events.rs and the EventMap payload type per event.
- `src/lib/contracts/generated`: ts-rs output for Rust DTOs, written by cargo test and never edited by hand.
- `src/tests/lib/contracts/ipc-parity.test.ts`: Checks COMMAND_ARGS and CommandMap against the Rust generate_handler list and the Rust command signatures.
- `src/tests/lib/contracts/events-parity.test.ts`: Checks EVENT_NAMES against the event registry in src-tauri/src/events.rs.
- `src-tauri/src/events.rs`: Rust registry of every event name; EVENT_NAMES must mirror it.

## State

- src/lib/contracts/generated/ on disk: one ts-rs output file per exported Rust type, plus generated/serde_json/ for the JsonValue type. Written by cargo test using the TS_RS_* settings in the root .cargo/config.toml.
- ipc.ts module state: the trackInvokes flag and the pendingInvokes map of per-command invoke timestamps, capped per command and cleared when tracking is turned off. Nothing is persisted.

## Collaborators

- `src-tauri/src/lib.rs`: Holds the generate_handler list that CommandMap mirrors; ipc-parity.test.ts compares the two.
- `src-tauri/src/events.rs`: Rust event-name registry that EVENT_NAMES mirrors; events-parity.test.ts compares the two.
- `src-tauri/src/commands`: Command modules whose DTOs (vault, files, history, search_index, update_channel) carry ts(export).
- `src-tauri/src/db`: Repository row types (fts, history, todoist) that carry ts(export).
- `src-tauri/src/vault`: Vault index, entry, task and task-line types and the watcher payload that carry ts(export).
- `src-tauri/src/semantic`: Semantic search types that carry ts(export).
- `src-tauri/src/quick_capture`: The composer capture result type that carries ts(export).
- `src-tauri/src/utils`: The DebugLogPayload type in logger.rs that carries ts(export).
- `src/lib/app`: Lifecycle, deep-link, editor-host and listener services import contract types and the ipc and events wrappers.
- `src/lib/core`: Filesystem, settings, vault and note-creator modules import contract types and the ipc and events wrappers.
- `src/lib/features`: Feature services and types import contract types and the ipc wrappers.
- `src/lib/plugins`: Mods, quick-capture, graph-view and templates import contract types and the ipc wrappers.
- `src/lib/types`: vault-v2.types.ts re-exports generated types from index.ts under V2 names.
- `src/lib/utils`: debug.ts uses call(), on(), setInvokeTracking, takeQueueWait and EVENT_NAMES; log.service.ts uses call().
- `src/routes`: The composer page invokes composer commands and listens to composer events through call() and on().
- `event:vault-index-updated`: Emitted after every VaultIndex mutation; typed as UpdateResult in EventMap.
- `event:vault-files-changed`: Emitted per debounced watcher burst; typed as VaultFilesChangedPayload.
- `event:semantic-index-progress`: Emitted during model download and index build; typed as SemanticProgress.
- `event:tauri-debug-log`: Emitted per Rust debug_log line; typed as DebugLogPayload.
- `event:menu:settings`: Emitted when the user picks Settings in the app menu; payload type is null.
- `event:app:exit-requested`: Emitted when quit is requested so the frontend can flush before confirm_exit; payload type is null.
- `event:qc:capture-detected`: Emitted with a detected clipboard capture; typed unknown in EventMap and narrowed by the quick-capture plugin.
- `event:qc:open-composer`: Emitted when the composer is shown so it resets and focuses its textarea; typed as string.
- `event:qc:composer-capture-result`: Emitted with whether the main window wrote one composer capture; typed as ComposerCaptureResult.

## Subfolders

- `src/lib/contracts/generated`: ts-rs output for every Rust type marked with ts(export), one file per type with no index. Written by cargo test, never edited by hand; CI fails the Rust job when the committed bindings are stale.
- `src/lib/contracts/generated/serde_json`: ts-rs output for the serde_json JsonValue type, which other generated types import.

## Gotchas

- generated/ is written by cargo test and must not be edited by hand. Commit the regenerated files, because the CI Rust job regenerates them and fails when they differ from the commit (.github/workflows/ci.yml); the folder is also exempt from tab indentation (CLAUDE.md, Quick Reference).
- Run cargo from the root of the checkout being changed. The ts-rs export directory and options come from the root .cargo/config.toml (TS_RS_EXPORT_DIR is relative), and cargo reads config from the current directory, not from --manifest-path, so running from another root writes bindings into that root's src/ (docs/DEV-ENVIRONMENT.md, Generated TS bindings).
- index.ts is a hand-maintained barrel because ts-rs writes no index. A newly exported Rust type is not importable from #lib/contracts until its re-export line is added, and src/tests/lib/architecture/ipc-mirrors.test.ts fails while the barrel misses a generated type.
- The contract files import nothing from #lib (ADR-0003, index.ts header); the only outside import is @tauri-apps/api, used by ipc.ts. scripts/import-graph.mjs treats contracts as an open layer that every layer may import.
- Plugin commands such as plugin:updater|download_and_install are outside CommandMap and stay raw invoke calls. src/lib/core/settings/sections/UpdateSection.svelte is the only allowlisted raw-invoke file besides ipc.ts (src/tests/lib/architecture/raw-invoke.test.ts).
- Raw listen and once from @tauri-apps/api/event are forbidden outside ipc.ts in src/lib and src/routes (src/tests/lib/architecture/event-listen.test.ts). Window events such as onCloseRequested and onFocusChanged are not in EventMap and bypass on().
- CommandMap lists commands that Rust registers but TypeScript never invokes (scan_vault_v2, capture_clipboard_now, open_composer). Their doc comments say so, and the parity test still requires them to match Rust.
- ipc-parity.test.ts and events-parity.test.ts each enforce a minimum-count floor so a parser that stops matching fails instead of comparing empty sets. Lower the floor in the same change that removes a command or event.
- Invoke-time tracking in ipc.ts pairs invokes and Rust enter lines first-in first-out per command. An invoke that never logs an enter shifts later pairings and over-reports queue wait until newer invokes push it out.
- EventMap types qc:capture-detected as unknown because Rust builds that payload with json! and no type is generated; the quick-capture plugin narrows it.
- ipc-mirrors.test.ts fails when a file under src/lib outside contracts declares its own type under a generated or mirror name, unless allowlisted; re-exports are allowed. src/tests/lib/contracts/contracts.types.test.ts is compile-time only, so pnpm check is what fails when a hand-written mirror drifts from the Rust struct.
- Todoist commands in CommandMap refuse a vaultPath that is not the open vault; the rule is stated in commands.ts and enforced through db::with_vault_db in src-tauri/src/db/mod.rs.
