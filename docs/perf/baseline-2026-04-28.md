## Notes / observations

- **`updateIndexesForFile` is the dominant cost.** p95 42.8 ms, max 203 ms,
  median 13 ms across 19 samples. The 3-phase orchestration runs synchronously
  on the JS main thread; the 1 000 ms layout-effect debounce exists to mask
  this. Phase 1-3 migrate this work to Rust; the long tail (203 ms max)
  should disappear once `update_note_in_index` is the only writer.
- **`updateActiveTabLinks` p95 13 ms, max 40 ms.** Fires on every tab switch
  via the 150 ms debounced layout effect. Phase 3 replaces this with a
  consumer-pattern `get_backlinks_v2` invoke on `vault-index-updated` events.
- **`contentSyncEffect:noop` is the keystroke tax.** 361 samples (one per
  keystroke during the 500-char burst) at 0 ms median. The toString
  round-trip is fast in absolute terms but unnecessary work happening on
  the keystroke path. Phase 5 eliminates it via `syncExternalContentToEditor`
  + signal-based effect.
- **`switchTab:sync` is essentially free** (3 samples, 0 ms each). The
  expensive part of a tab switch is the doc-replace + decoration rebuild
  inside `MarkdownEditor.svelte`, which is not yet probed under
  `PERF-BASELINE`. Phase 4.1 will capture that decomposition before any
  Phase 4 changes.
- **`openFileInEditor:fresh` p95 4.1 ms** is healthy. The Phase 0.1 probe
  also has a `:cached` variant (8 samples, 0 ms each), confirming that
  cached re-opens are essentially free.
- **`closeTab` p95 1 ms** is healthy. Probe added in Phase 0.1 (no probe
  existed before).

These numbers form the comparison baseline for every per-phase
`docs/perf/phase-<n>-comparison.md` file. Negative deltas in subsequent
phases = improvement.
